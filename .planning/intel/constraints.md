## Runtime AI architecture — Planner → Executor → Renderer (§1.1–§1.4)
- source: .planning/product/PRODUCT_SPEC.md (§1)
- type: api-contract
- content: Runtime is a bounded coordinator-based agent platform; the Planner→Executor→Renderer loop is the single-role engine. Planner returns exactly one Zod-validated decision: {action:'answer', reasonCode} | {action:'run_tool', toolName, input} | {action:'ask_clarification', question ≤200, options ≤4×60}. Planner uses fast tier, JSON-only, 3 s timeout, one malformed-JSON repair, fallback {action:'answer', reasonCode:'planner_failed'} after two failures; ExecutorService narrows toolName to a closed z.enum of registered tools. Executor is deterministic: reject unknown tools, validate input schemas, check permission + capability, run with timeout, validate output schema, return ToolExecutionResult<T>. Renderer uses balanced tier, must not invent tool results, structured output for cards/tables/checklists, 5 s timeout, max 512 tokens normal output. Tier caps table — tiny ≤4K: 1 planner/1 tool/no MCP/minimal mode; small 8K–16K: 2/1/no chaining; medium 32K–128K: 3/2/chaining; large ≥200K: 5/3/chaining. AgentOrchestrator is the only module allowed to enforce caps. `ask_clarification` options carry RICH-C-01 chips with no second LLM call; Renderer structured path is the substrate for RICH-C-05/H-19.

## Provider routing, fallback, retry, circuit breaker (§1.5, §20.10)
- source: .planning/product/PRODUCT_SPEC.md (§1.5, §20.10)
- type: api-contract
- content: ProviderRouter selects by cost, latency, reliability, privacy mode, configured priority, availability. RouterAttemptState tracks operationId, attempts[], hasStreamedFirstToken, circuitBreakerOpen. Single provider ⇒ retry once only for retryable pre-first-token failures. Never switch provider after hasStreamedFirstToken === true. Do not silently switch local→cloud when allowCloudFallbackFromLocal=false. Retryable: TIMEOUT, PROVIDER_5XX, NETWORK, RATE_LIMITED. Non-retryable: AUTH, MODEL_UNKNOWN, SCHEMA_INVALID, HOST_NOT_PERMITTED. Circuit breaker: 3 consecutive failures/provider within 60 s ⇒ open for 5 minutes (AUTH votes 3 = open immediately). Every attempt recorded in AITransactionLog.

## Persistent memory architecture (§3)
- source: .planning/product/PRODUCT_SPEC.md (§3)
- type: schema
- content: Memory is system-owned; three layers — Conversation (continuity), User (durable cross-session facts/preferences/patterns), Preference (behavioural settings). Framework: Zustand + IndexedDB/idb + MiniSearch + MemoryEngine; do NOT use LangChain, LlamaIndex, MemGPT, remote vector DBs or embedding downloads. ConversationMemory: keep last 2 turns tiny / 4 small / 6 medium-large; summarise older every 12 messages; bodies in IndexedDB only; optional observational rolling summary in ConversationMemory.summary (single-writer, within history budget). UserMemoryFact fields (content, type fact|preference|pattern, tags, confidence 0..1, source explicit|inferred|system, timestamps, useCount); scoring weights keyword 0.45 / tag 0.25 / recency 0.15 / useCount 0.10 / confidence 0.05, all normalised [0,1]. Injection: top-5 (top-3 tiny), ≤1000 tokens total, never inject secrets/raw customer data. UserPreferences: responseStyle, preferredLanguage, preferStructuredOutput, allowCloudFallbackFromLocal, defaultProviderId, toolAutonomy, defaultSurface, personaId/personaOverrides — theme is NOT a preference field (np_theme/np_theme_pack in storage.sync are the single source of truth). Working memory: single Markdown block (fixed template) in UserMemoryStore, ≤300 tokens recommended, resource-scoped, single-writer via MemoryEngine, redacted, never written to notes/.md backups.
