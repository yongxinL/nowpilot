# NowPilot — Review Prompts for the GSD ⇄ Reviewer Loop

**Purpose:** Insert a stronger-model review gate between GSD (OpenCode + cost-effective model, e.g. DeepSeek V4 Flash) stages, where cheap models are weakest (discussion/planning). GSD generates the artifact → paste it here for review → apply fixes → hand the corrected artifact back to GSD for execution.
**Location:** keep this file in `.planning/`.
**Ground rule:** `PRODUCT_SPEC_v0_1.md` is the single authoritative source. Always attach it alongside the GSD doc when requesting a review (the review sandbox resets between turns; the spec is the reviewer's ground truth).

---

## The loop (where the gates go)

```
GSD discuss (cheap) ──▶ [GATE 1: review context/decisions] ──▶ GSD plan (cheap)
        └──────────────▶ [GATE 2: review plan, pre-execution] ──▶ GSD execute (cheap) ──▶ GSD verify (deterministic)
```

- **Gate 1 (after discuss-phase):** catch decisions that contradict the spec, unresolved ambiguities, scope creep.
- **Gate 2 (after plan-phase):** catch invented paths/types, undefined constants, missing tests, dependency-order errors, cheap-model implementability gaps.
- **Execute / verify:** usually no review needed — mechanical + deterministic gates (`verify:phase-N`).

**Which gates are worth it:** Gate 1 + Gate 2 give ~90% of the value. Skip review on execution unless a phase is unusually complex (e.g. agent orchestrator, extraction, memory governance, collaboration).

---

## How to run a gate (checklist)

1. Let GSD finish the stage and commit its artifact (e.g. `01-CONTEXT.md`, `02-PLAN.md`).
2. Open a review turn and **attach BOTH**: (a) the GSD artifact, (b) the current `PRODUCT_SPEC_v0_1.md`.
3. Paste the matching prompt below (A for discussion, B for plan, C for fast inline fix).
4. Save the returned findings file into `.planning/` (e.g. `Phase-<N>-REVIEW-FINDINGS.md`).
5. Apply the fixes (or take the handed-back corrected doc) and feed it to the next GSD stage.
6. Only advance the phase when the artifact is clean AND (for Gate 2) the plan matches the §18 DONE-when + required tests.

## Prompt A — Review a GSD **discussion / context** doc (Gate 1)

```
Attached is the GSD-generated discussion/context doc (01-CONTEXT.md + decision log) for Phase <N> of NowPilot, produced by a cost-effective model in OpenCode. Also attached: the authoritative PRODUCT_SPEC_v0_1.md.

Treat PRODUCT_SPEC_v0_1.md as the single authoritative source. Review the attached doc and:
1. Flag every decision that contradicts, duplicates, or drifts from the spec (cite the § it violates).
2. Flag unresolved ambiguities or missing phase-boundary calls a cost-effective model (DeepSeek/Haiku) would guess at during execution.
3. Flag any "new capability" that belongs to a later phase (scope creep — the spec says one phase per response, no premature capability).
4. For each issue: give severity (Blocker / Ambiguity / Nit), the problem, and the exact fix I can apply.
Output as a review-findings file (Phase-<N>-REVIEW-FINDINGS.md), bucketed Blockers / Confirmations / Deferred. Do not lose any context from the original doc.
```

---

## Prompt B — Review a GSD **plan** doc, pre-execution (Gate 2)

```
Attached is the GSD plan for Phase <N> of NowPilot (file list, tasks, tests, verify script), generated by a cost-effective model. Also attached: the authoritative PRODUCT_SPEC_v0_1.md.

Spec = PRODUCT_SPEC_v0_1.md (authoritative). Review for cost-effective-model implementability and:
1. Verify every file path against §8.5/§18 and every type import against Appendix C.1 (@/types/harness) — flag invented paths/types (risk R-1).
2. Flag any constant / enum / error-code used but not defined in Appendix C / C.2.
3. Confirm the plan matches the phase's DONE-when list and required tests in §18; list anything missing.
4. Flag dependency-order errors (a step needing an earlier phase's contract that isn't built yet).
5. Flag anything a DeepSeek/Haiku implementer would ambiguously interpret; give the disambiguating instruction.
For each: severity + problem + exact fix. Output Phase-<N>-PLAN-REVIEW-FINDINGS.md, then give me the corrected plan ready to hand back to GSD.
```

---

## Prompt C — Fast "just fix it" variant (either artifact)

```
Attached: GSD Phase <N> <discussion|plan> doc + the authoritative PRODUCT_SPEC_v0_1.md.
Review, then hand back the UPDATED doc with fixes applied inline (surgical edits only, preserve everything else), plus a short bulleted list of what you changed and why. Focus on blockers a cost-effective model would trip on.
```

---

## Prompt D — (optional) Cross-artifact consistency check

Use when a phase spans multiple GSD docs, or to confirm the plan honors the reviewed decisions.

```
Attached: Phase <N> context doc + Phase <N> plan doc + PRODUCT_SPEC_v0_1.md.
Confirm the plan faithfully implements every decision (D-01…D-n) from the context doc AND the spec's §18 requirements for this phase. List any decision that the plan drops, contradicts, or only partially implements. Severity + fix for each.
```

## What the reviewer checks (reference)

| Category | Gate | Examples |
|---|---|---|
| Spec contradiction | 1 | Decision violates a §0.2 DO-NOT rule; wrong surface placement; theme/persona in the wrong store |
| Scope creep | 1 | A "new capability" that belongs to a later phase; more than one phase's work |
| Ambiguity | 1,2 | Undefined threshold/trigger a cheap model would guess; missing phase-boundary call |
| Invented identifiers (R-1) | 2 | File path not in §8.5/§18; type not from `@/types/harness`; tool name not in the executor enum |
| Undefined constants/codes | 2 | Using a constant/error-code absent from Appendix C / C.2 |
| DONE-when / tests mismatch | 2 | Plan omits a required test or a DONE-when bullet from §18 |
| Dependency order | 2 | Step depends on a contract from an unbuilt later phase |

## Reminders specific to this project

- **Always attach `PRODUCT_SPEC_v0_1.md`** with the GSD doc — it is the reviewer's ground truth and the sandbox resets between turns.
- **Model policy (§0.3a):** the spec mandates no build-agent model. Any `claude-sonnet-*` at plan time is your OpenCode/GSD config, not the spec. Configure GSD subagents to your chosen model (e.g. `deepseek-v4-flash`) per stage.
- **Phase numbering is flat 1–19** (§18) — reference phases by their linear number.
- **Keep findings in `.planning/`** so each gate is traceable and feeds the next GSD stage.
- **Higher-scrutiny phases** (worth a closer plan review): 3 (AI runtime), 4 (reliability/evidence), 6 (extraction), 7 (trust-aware context), 10 (memory governance), 13 (verified evolution), 14 (collaboration), 18 (tool governance).
