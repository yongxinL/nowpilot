<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chrome.storage.session → SessionStore | Session tokens read from/written to session-only storage; tokens cleared on browser close |
| chrome.storage.local → WorkspaceStore | Workspace state persisted in chrome.storage.local; available across surfaces via BroadcastBus sync |
| Extension pages → chrome.storage.session | MV3: chrome.storage.session is per-extension, isolated from other extensions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11 | Information Disclosure | SessionStore | high | mitigate | Session tokens stored ONLY in chrome.storage.session (D-04); chrome.storage.session is cleared on browser close; tokens never written to disk-backed storage (verified by test: no np_session key in chrome.storage.local mock) |
| T-02-12 | Information Disclosure | WorkspaceStore | low | accept | Workspace state contains non-sensitive data (conversation ID, active provider name, pinned tab URLs); URLs may contain query parameters but no secrets; acceptable tradeoff for cross-surface sync |
| T-02-13 | Tampering | WorkspaceStore (cross-surface) | low | mitigate | BroadcastBus WORKSPACE_UPDATED events trigger re-read from chrome.storage.local (source of truth); other surfaces cannot inject state directly, only notify that state changed |
| T-02-14 | Information Disclosure | sessionStorageAdapter fallback | medium | mitigate | sessionStorage fallback (web API) is per-tab and cleared on tab close; it does NOT persist to disk; acceptable for dev environments without chrome.storage.session |
</threat_model>
