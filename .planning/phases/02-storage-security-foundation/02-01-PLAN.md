**CryptoService.ts (per D-01, D-02, D-03):**
Implement the CryptoService class from RESEARCH.md lines 555-639 verbatim — module-scoped singleton. The class has:
- `INSTALL_SECRET_KEY = 'np_install_secret'` (D-01: key name contract)
- `SESSION_CACHE_PREFIX = 'np_derived_key_'` (D-02: derived key cache in chrome.storage.session)
- `async getInstallSecret(): Promise<Uint8Array>` — generate 32 random bytes via `crypto.getRandomValues(new Uint8Array(32))` if not in chrome.storage.local; otherwise read, base64-decode, and return. Store as base64 string (chrome.storage.local only supports JSON-serializable values per RESEARCH.md Pitfall 1).
- `async deriveKey(salt: Uint8Array): Promise<CryptoKey>` — import raw key material from `base64(installSecret) + chrome.runtime.id` (D-02: extensionId binding), then `crypto.subtle.deriveKey({ name: 'PBKDF2', salt, iterations: 100000, hash: 'SHA-256' }, keyMaterial, { name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt'])`. Per D-02: 100000 iterations, SHA-256, AES-GCM-256, non-extractable.
- `async encrypt(plaintext: string): Promise<{ ciphertext: ArrayBuffer; salt: Uint8Array; iv: Uint8Array }>` — generate random 16-byte salt and 12-byte IV via `crypto.getRandomValues()`, derive key, encode plaintext via `new TextEncoder().encode()`, encrypt via `crypto.subtle.encrypt({ name: 'AES-GCM', iv }, key, encoded)`, return { ciphertext, salt, iv }.
- `async decrypt(ciphertext: ArrayBuffer, salt: Uint8Array, iv: Uint8Array): Promise<string>` — derive key from stored salt, decrypt via `crypto.subtle.decrypt({ name: 'AES-GCM', iv }, key, ciphertext)`, decode via `new TextDecoder().decode()`. Wrap in try/catch, throw `new Error('Decryption failed: ...')` on failure (per PATTERNS.md error handling).
- `private bytesToBase64(bytes: Uint8Array): string` — binary-safe base64 encode for chrome.storage.local (Pitfall 1).
- `private base64ToBytes(base64: string): Uint8Array` — binary-safe base64 decode.

Export: `export const cryptoService = new CryptoService();` (module-level singleton per PATTERNS.md Shared Patterns §Module-Scoped Singleton).

**Key derivation detail per D-02:** The combined material for PBKDF2 is `bytesToBase64(installSecret) + extensionId`. Use `chrome.runtime.id` for the extension ID (per spec; never navigator.userAgent per RESEARCH.md Anti-Patterns).

**Base64 conversion helpers:**
Add to ApiKeyStore.ts or a shared utility (prefer inline in ApiKeyStore.ts for now — one less file):
```typescript
function arrayBufferToBase64(buffer: ArrayBuffer): string {
  const bytes = new Uint8Array(buffer);
  let binary = '';
  for (let i = 0; i < bytes.length; i++) binary += String.fromCharCode(bytes[i]);
  return btoa(binary);
}
function base64ToArrayBuffer(base64: string): ArrayBuffer {
  const binary = atob(base64);
  const bytes = new Uint8Array(binary.length);
  for (let i = 0; i < binary.length; i++) bytes[i] = binary.charCodeAt(i);
  return bytes.buffer;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chrome.storage.local → CryptoService | Untrusted stored data (ciphertext+salt+IV could be tampered) crosses here; AES-GCM authentication detects tampering |
| CryptoService → memory | Decrypted plaintext API keys exist in JS heap; garbage collection is the only cleanup |
| Extension page → chrome.storage.local | Other extensions cannot read this extension's chrome.storage.local (Chrome isolates by extension ID) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | chrome.storage.local | high | mitigate | AES-GCM-256 encryption at rest (D-01); ciphertext+salt+IV stored, never plaintext; install secret is per-extension-instance (32 random bytes) |
| T-02-02 | Elevation of Privilege | CryptoService.deriveKey | high | mitigate | PBKDF2 with 100000 iterations (D-02); extensionId binding prevents key reuse across installs; per-key 16-byte salt prevents rainbow table attacks |
| T-02-03 | Tampering | chrome.storage.local (ciphertext) | medium | mitigate | AES-GCM authentication detects any ciphertext modification; decrypt throws on tampered data |
| T-02-04 | Information Disclosure | ApiKeyStore | medium | mitigate | Zustand `partialize` only persists `keys` record (no action methods exposed); `getKey` decrypts on-demand, never caches plaintext in persisted state |
| T-02-05 | Denial of Service | CryptoService.encrypt | low | accept | PBKDF2 derivation takes ~100ms per key; acceptable for infrequent API key configuration (not a hot path) |
| T-02-SC | Tampering | npm install (idb, fake-indexeddb) | high | mitigate | Package legitimacy audit verified (RESEARCH.md §Package Legitimacy Audit); idb: 11 yrs, 22M/wk, spec editor authored; fake-indexeddb: 8 yrs, 1.7M/wk. Neither flagged [SUS]. |
</threat_model>
