**Module structure:** Standalone utility module — pure function export, no class, no state.

**Redaction patterns (per PATTERNS.md lines 475-484):**
```typescript
const API_KEY_PATTERN = /(?:sk|api[_-]?key)[=:]\s*([a-zA-Z0-9_-]{20,})/gi;
const BEARER_PATTERN = /bearer\s+([a-zA-Z0-9._-]+)/gi;
const JWT_PATTERN = /eyJ[a-zA-Z0-9._-]{20,}/g;
```

**Function signature:** `export function redactSensitive(input: string): string`

**Implementation:**
- Apply API_KEY_PATTERN: replace matches with `'$1=***REDACTED***'` (preserving the key name for context).
- Apply BEARER_PATTERN: replace with `'Bearer ***REDACTED***'`.
- Apply JWT_PATTERN: replace with `'***REDACTED_JWT***'`.
- Return the redacted string.
- Handle edge cases: empty string → return empty string; non-string input → return empty string (graceful degradation).

**Additional patterns to include (beyond PATTERNS.md basic set):**
- `SERVICENOW_JSESSIONID` — `/(?:JSESSIONID|jsessionid)=([a-zA-Z0-9]+)/gi` → `'JSESSIONID=***REDACTED***'`
- `SERVICENOW_SYSPARM_CK` — `/(?:sysparm_ck|g_ck)=([a-zA-Z0-9]+)/gi` → `'sysparm_ck=***REDACTED***'`
These ServiceNow-specific patterns are needed for Phase 8 (Add-on Ecosystem) but safe to add now — they won't produce false positives in non-ServiceNow contexts.

| AI output / tool output → redactSensitive | Untrusted content from AI providers and MCP tools may contain secrets; redactSensitive must strip before logging/display/export |
| DiagnosticsStore → DiagnosticsPanel (Phase 6) | Redacted logs displayed to user; redactSensitive must run BEFORE persistence |
| MessageStore → IndexedDB (Phase 7) | Message bodies stored in IndexedDB; no redaction at store level (messages are user content, not secrets) |
