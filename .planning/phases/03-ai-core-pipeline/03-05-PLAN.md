    **1. PersonaProfile schema (Zod v4):**
    ```typescript
    import { z } from 'zod/v4';

    export const PersonaProfileSchema = z.strictObject({
      id: z.string(),
      name: z.string().min(1).max(64),
      tagline: z.string().max(128).optional(),
      avatar: z.string().max(256).optional(), // emoji or URL
      tone: z.enum(['professional', 'casual', 'friendly', 'direct', 'playful', 'academic']),
      brevity: z.enum(['concise', 'balanced', 'detailed']),
      coreValues: z.array(z.string().max(80)).max(5),
      languageStyle: z.string().max(200).optional(),
      behavioralDrivers: z.string().max(300).optional(),
      responseFormatRules: z.string().max(300).optional(),
    });

    export type PersonaProfile = z.infer<typeof PersonaProfileSchema>;
    ```

    **2. DEFAULT_PERSONA — runtime seed (per CONTEXT.md § Persona Injection Scope):**
    Define a well-formed default persona constant. This is used when no user-configured persona exists (Phase 7 will allow customization). Per PROJECT.md Key Decisions: "Persona as user config in PreferenceMemoryStore, NOT an inferred fact."

    ```typescript
    export const DEFAULT_PERSONA: PersonaProfile = {
      id: 'default',
      name: 'NowPilot',
      tagline: 'Your privacy-first AI assistant',
      tone: 'friendly',
      brevity: 'balanced',
      coreValues: ['Be helpful', 'Respect privacy', 'Keep it concise', 'Admit uncertainty'],
      languageStyle: 'Clear and conversational. Use Markdown for formatting. No emoji in code blocks.',
      behavioralDrivers: 'Prefer actionable answers over theoretical explanations. When uncertain, ask clarifying questions rather than guessing. For tool operations, explain what you are doing before executing.',
      responseFormatRules: 'Use bullet points for lists. Use code blocks with language tags for scripts/queries. Cite sources when available.',
    };
    ```

    - `getExecutorPersona(): null` — returns null (ExecutorService receives no persona per D-09).

    These helpers are called by PersonaInjector — not directly by consumers. The injector is the single source of truth for which fields go where.

  <action>
    Create `src/core/ai/persona/PersonaInjector.ts` — a pure-function module (no class, no state).

    **1. `buildPersonaBlock(profile: PersonaProfile): string` — per RESEARCH.md Pitfall 5:**
    - MUST be byte-stable for the same PersonaProfile input. No timestamps, no random IDs, no conversation context.
    - Format as a [PERSONA] section block:
      ```
      [PERSONA]
      Name: {name}
      Tone: {tone} | Brevity: {brevity}
      Core Values: {values joined by comma}
      Language: {languageStyle}
      Behavior: {behavioralDrivers}
      Response Rules: {responseFormatRules}
      ```
    - Omit optional fields (tagline, avatar) when null/undefined — do NOT include empty lines for missing fields (this would break byte-stability if a field is later populated).
    - For optional fields that ARE present: include them in their own line.
    - Use `JSON.stringify` for field values that contain special characters to ensure deterministic output.

    **2. `buildPlannerPersonaBlock(profile: PersonaProfile): string` — per D-09:**
    - Extracts behavioral attributes only.
    - Format:
      ```
      [PERSONA - BEHAVIORAL]
      Brevity: {brevity}
      Clarification Strategy: {from behavioralDrivers}
      Reasoning Style: {from behavioralDrivers}
      ```
    - Derives `clarificationStrategy` and `reasoningStyle` from `profile.behavioralDrivers` text (use first sentence as strategy, rest as reasoning style heuristic).

    **3. `inject(stage: 'planner' | 'executor' | 'renderer', baseSystemPrompt: string, opts?: { profile?: PersonaProfile }): string`:**
    - `profile = opts?.profile ?? DEFAULT_PERSONA`
    - Stage routing per D-09:
      - `'planner'` → prepend `buildPlannerPersonaBlock(profile)` + newline + baseSystemPrompt
      - `'executor'` → return baseSystemPrompt unchanged (no persona for executor)
      - `'renderer'` → prepend `buildPersonaBlock(profile)` + newline + baseSystemPrompt
    - The persona block comes BEFORE the [SYSTEM] section. This ensures Anthropic/Gemini prompt caching works on the persona block (which is cache-stable) while the system section may vary per context.

    **4. Byte-stability guarantee (RESEARCH.md Pitfall 5):**
    - No dynamic content (timestamps, IDs, counters) in the persona block output.
    - Deterministic ordering of fields.
    - Deterministic joining of arrays (`coreValues.sort().join(', ')`).
    - Test: call `buildPersonaBlock(DEFAULT_PERSONA)` twice and assert strict string equality.

    **5. Tests (`tests/core/ai/persona/PersonaInjector.test.ts`):**
    - 7 tests as specified in `<behavior>`.
    - Use a custom PersonaProfile for the "different profiles" test.
    - The byte-stability test is critical: call `buildPersonaBlock` twice in the same test, assert `===`.
    - Verify the inject output always contains the original baseSystemPrompt.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PersonaProfile data → AgentOrchestrator → AI system prompt | User-configured persona text is injected into AI system prompts; could contain prompt injection payloads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Elevation of Privilege | PersonaInjector | medium | mitigate | Persona text is placed in a clearly delimited [PERSONA] section, separate from the [SYSTEM] instructions. The persona block is structurally isolated — it cannot override system instructions like tool lists, output format requirements, or safety constraints. User cannot inject content that escapes the [PERSONA] block because the block uses deterministic formatting (no user-controlled delimiters). Strings are passed through JSON.stringify to escape special characters. |
| T-03-11 | Information Disclosure | PersonaProfile | low | accept | Persona profile fields (name, tone, values) are non-sensitive user preferences. The profile does not contain API keys, PII, or authentication data. Accept low risk: persona content is designed to be sent to AI providers as part of the system prompt. Phase 7 will add UI validation on persona field lengths to prevent abuse. |
</threat_model>
