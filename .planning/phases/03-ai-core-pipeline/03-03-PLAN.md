  <action>
    **Expand `src/core/ai/ProviderRouter.ts`** (keep existing single-provider logic, add new capabilities):

    **1. Provider discovery and selection:**
    - Define a `PROVIDER_ORDER: PipelineProviderId[] = ['openai', 'anthropic', 'gemini', 'ollama']` — the fallback priority order.
    - `selectProvider(preferred: PipelineProviderId): Promise<{ adapter: ProviderAdapter; providerId: PipelineProviderId }>` — Attempts providers in order starting from `preferred`, then cycling through `PROVIDER_ORDER`. For each:
      - Check `isCircuitBreakerOpen(providerId)` — skip if open.
      - Call `useApiKeyStore.getState().getKey(providerId)` to get encrypted key. For 'ollama', key is not required (local provider).
      - If key is null/undefined and provider is not ollama → skip to next provider.
      - Create adapter via the appropriate factory: `createOpenAIAdapter(apiKey)`, `createAnthropicAdapter(apiKey)`, `createGeminiAdapter(apiKey)`, or `createOllamaAdapter()`.
      - Return `{ adapter, providerId }`.
    - If no provider is available (all skipped or failed): throw `new PipelineError('CIRCUIT_OPEN', 'All providers are temporarily unavailable. Please try again in a few minutes.', { attemptedProviders: [...] })`.

    **2. Circuit breaker state (per RESEARCH.md Pattern 4):**
    - `interface CircuitState { failureCount: number; lastFailureTime: number; openUntil: number | null }`
    - `circuitBreakers: Map<PipelineProviderId, CircuitState>` — in-memory, per-provider.
    - `recordFailure(providerId: PipelineProviderId, error: PipelineError): void` — increments `failureCount`, records `lastFailureTime`. If `failureCount >= 3` and all failures within `CIRCUIT_BREAKER_WINDOW_MS = 60_000`, sets `openUntil = Date.now() + CIRCUIT_BREAKER_COOLDOWN_MS = 5 * 60_000`.
    - `recordSuccess(providerId: PipelineProviderId): void` — resets `failureCount = 0`, `openUntil = null`.
    - `isCircuitBreakerOpen(providerId: PipelineProviderId): boolean` — returns true if `openUntil !== null && Date.now() < openUntil`. If cooldown expired, reset state and return false.

    **3. Error classification and routing (per D-10, D-11):**
    - `isRetryable(error: PipelineError): boolean` — checks `error.retryable` (derived from `error.category === 'retryable'` per PipelineError construction).
    - `executeWithFallback<T>(preferredProvider: PipelineProviderId, operation: (adapter: ProviderAdapter, providerId: PipelineProviderId) => Promise<T>): Promise<T>` — core fallback method:
      1. Call `selectProvider(preferredProvider)`.
      2. Execute `operation(adapter, providerId)`.
      3. On success: `recordSuccess(providerId)`, return result.
      4. On error: `recordFailure(providerId, error)`. If `isRetryable(error)` → retry `selectProvider` with next available. If NOT retryable → re-throw immediately (per D-11: terminal errors surface to user).
      5. If retryable error and `operation` is streaming (indicated by `hasStreamedFirstToken` flag): do NOT retry — return the error as-is (RESEARCH.md Pitfall 4).

    **4. Streaming guard (per RESEARCH.md Pitfall 4):**
    - Per-operation state object: `{ hasStreamedFirstToken: boolean; attempts: Array<{ providerId: string; error?: PipelineError }> }`.
    - `markFirstTokenStreamed(operationId: string): void` — sets the flag.
    - `hasStreamedFirstToken(operationId: string): boolean` — checks the flag.
    - In `executeWithFallback`: if `hasStreamedFirstToken` is true and error is retryable, return the error without fallback. The stream has already started sending tokens to the user.

    **5. Tests (`tests/core/ai/ProviderRouter.test.ts`):**
    - Mock `useApiKeyStore` to return controlled API keys per provider.
    - Mock all 4 adapter factories to return stub adapters (or throw).
    - Use `vi.useFakeTimers()` for circuit breaker timing tests.
    - Test the 10 behaviors listed above.
    - Use `vi.stubGlobal('fetch', ...)` to mock connection validation calls in adapters.
