The `userFacingMessage` field is a contract for Phase 7 UI rendering — it carries a human-readable string that Phase 7 Chat UI will display verbatim. Example codes:

| Error Code | Category | userFacingMessage (contract) |
|------------|----------|------------------------------|
| `PROVIDER_AUTH` | terminal | "Authentication failed for {provider}. Check your API key in Options." |
| `PROVIDER_TIMEOUT` | retryable | "Provider timed out. Trying fallback..." |
| `CIRCUIT_OPEN` | terminal | "All providers are temporarily unavailable. Please try again in a few minutes." |
| `TIER_CAP_REACHED` | terminal | "I reached the maximum number of steps for this request. Here's what I have so far." |
| `SCHEMA_INVALID` | terminal | "The AI returned an unexpected response format. Please try again." |
| `NO_SUCH_TOOL` | terminal | "An internal error occurred — the requested tool is not available." |
| `ABORTED` | terminal | "Request cancelled." |

**Note:** These `userFacingMessage` strings are a design contract for Phase 7. They are stored in `PipelineError` objects (Phase 3) and consumed by the Chat UI error rendering (Phase 7). Exact wording may be refined in Phase 7.

### Streaming Contract (for Phase 7 consumption)

Phase 3 produces a `StreamEvent` union type (D-13) consumed by `ChunkBuffer` (D-14). This is the **visual contract** between the pipeline and future UI:

```typescript
// Contract: StreamEvent union from StreamAdapter (D-13)
type StreamEvent =
  | { type: 'text-delta'; content: string }          // → appended to message bubble
  | { type: 'tool-call'; toolName: string; input: unknown }  // → tool call indicator
  | { type: 'tool-result'; toolName: string; output: unknown } // → tool result block
  | { type: 'error'; error: PipelineError }           // → error inline or toast
  | { type: 'done'; usage?: TokenUsage }              // → finalize message, stop spinner
```

**ChunkBuffer** (D-14, UI layer at `src/core/ai/ChunkBuffer.ts`) provides:
- `requestAnimationFrame` batching for smooth rendering
- Message accumulation buffer
- **Stage indicators** (strings for Phase 7 rendering): "Reading page context…" → "Planning response…" → "Generating…"
- Token counting from AI SDK `usage` object
- Render throttling

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| streaming-stage-indicators | ChunkBuffer stage strings | 🧪 backstop | Stage indicator text strings defined in Phase 3, but visual rendering (spinners, progress bars, animated transitions) deferred to Phase 7. Phase 3 provides: `'idle' → 'reading-page' → 'planning' → 'generating' → 'done'` state machine exposed via `getStage(): StageLabel`. Exact labels: `"Reading page context…"`, `"Planning response…"`, `"Generating…"` |

**No empty/loading/error/populated/partial/overflow states in this phase** — those are Phase 7 Chat UI concerns. The pipeline only produces semantic events; the UI controls presentation (D-14 boundary).
