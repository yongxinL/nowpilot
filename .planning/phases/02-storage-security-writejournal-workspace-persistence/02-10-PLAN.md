<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Storage/election failure → user notice | Failure copy is the user's evidence about system state; it must be truthful and carry no diagnostics. |
| Onboarding credential field → persistence | The field holds a credential in memory only; the notice must not become a channel for it. |
| Entrypoint → background worker | The background worker must remain free of storage and database imports. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-51 | Repudiation | migration notice | high | mitigate | The migration notice states the outcome truthfully and names no content; the suite asserts the exact string and the absence of completion claims. |
| T-02-52 | Information Disclosure | notice content | high | mitigate | Notices carry pinned strings only; the suite injects a payload full of ids, keys, stages and codes and asserts none reaches a description. |
| T-02-53 | Spoofing | false capability claim | high | mitigate | The capability notice states a capability, not an outcome; the forbidden-claim assertions run over every onboarding step. |
| T-02-54 | Information Disclosure | credential echo | high | mitigate | The notice is asserted invariant while a sentinel sits in the field, and the flow still never imports a storage or vault module. |
| T-02-55 | Denial of Service | notice stacking | low | mitigate | Stable keys plus `maxCount` configuration; the repeated-failure case asserts one notification. |
| T-02-56 | Elevation of Privilege | background contamination | high | mitigate | The entrypoint task touches no background module and the isolation suite runs in the task's verify. |
| T-02-SC | Tampering | npm installs | high | mitigate | No install in this plan. |
</threat_model>
