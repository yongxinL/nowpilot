Fix CR-02 (BLOCKER, from 02-VERIFICATION.md truth 5 / 02-REVIEW.md CRITICAL-02): the election heartbeat is never published, so the standalone-wins tie-break demotion and the lone-surface 'solo' detection are dead in production.

Purpose: `runHeartbeatTick` (WorkspaceElection.ts:246-284) writes the session record but NEVER calls `notifyWorkspaceHeartbeat` (zero call sites). `WORKSPACE_HEARTBEAT` is therefore never broadcast, `foreignSurfacesEverSeen` stays false, and the standalone-wins demotion rule (WorkspaceElection.ts:348-363) — and the election-demotion mirror path (SidepanelChat.tsx:226-241) — never fire. The existing WorkspaceElection.test.ts Test 5 bypasses this by manually injecting `publish(..., _sender:'foreign-instance-id')`, so the suite is green while production never sends a heartbeat. This plan publishes the heartbeat from the production tick and proves the two-surface handoff through the real tick.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| surface↔surface (BroadcastChannel) | Election heartbeats cross the `np_workspace` BroadcastChannel between sidepanel and standalone surfaces. Any surface on the channel can emit a `WORKSPACE_HEARTBEAT`; the demotion rule trusts the `surface` field. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09-01 | Spoofing | `WORKSPACE_HEARTBEAT.surface` field | medium | mitigate | The demotion rule only demotes to `secondary` (read-only mirror, D-27) — it never grants write access. A spoofed standalone heartbeat can at most demote a real primary to mirror, which is a benign, recoverable state (the demoted surface stops writing; the spoofed surface cannot write without the election record). No privilege escalation. Heartbeat `workspaceId` is not trusted by any consumer in Phase 2. |
| T-02-09-02 | Tampering | session record `np_workspace_primary` | high | mitigate | Election CAS + 6 s stale threshold already re-elect on a tampered/stale record; the fix does not weaken this. The heartbeat publish is additive; self-suppression by instance id prevents a surface from observing its own heartbeat as foreign. Mitigation is unchanged from the existing CAS design. |
| T-02-09-03 | DoS | heartbeat flood on `np_workspace` | low | accept | One heartbeat per 3 s tick per primary/solo surface (≤ 1/3s/surface), far under the ~120/min chrome.storage boundary and the D-43 write-rate budget. Broadcast is in-memory; no persistence cost. Accepted as within normal traffic. |
| T-02-09-04 | Information Disclosure | workspaceId in heartbeat payload | low | accept | `workspaceId` is a non-secret coordination identifier already present in `np_workspace` and broadcast messages; it is not a credential. Accepted. |
| T-02-09-SC | Tampering | npm installs (BroadcastBus change introduces no new deps) | low | mitigate | No new package installed by this plan; package-legitimacy gate N/A. |

No high-severity threat is left unmitigated; the two high rows (T-02-09-02) rely on the pre-existing CAS/stale-re-election design which this plan does not weaken.
