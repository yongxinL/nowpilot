<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Store status → rendered region | A rendering decision is the user's evidence about stored data; it must not over-claim. |
| Election state → banner | A surface may look authoritative without being elected. |
| Click → election | A user gesture must not change local state before the authority confirms. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-46 | Repudiation | empty-before-hydration | high | mitigate | The empty presentation renders only for the `empty` status and the suite asserts the other five statuses never render its copy. |
| T-02-47 | Spoofing | banner without authority | high | mitigate | Visibility is a pure function of `writerState`; the suite asserts absence for every non-mirror state and exactly-once presence for `mirror`. |
| T-02-48 | Repudiation | optimistic refocus | medium | mitigate | The click changes no local state; the suite asserts the banner stays mounted on both success and failure paths. |
| T-02-49 | Information Disclosure | rendered diagnostics | medium | mitigate | Every rendered string resolves from the pinned map with no interpolation of ids, keys, stages or codes; the shell suite asserts the copy verbatim. |
| T-02-50 | Denial of Service | unreachable recovery | low | mitigate | The failed path renders an actionable `common.retry` calling the store's retry, so a failure is always recoverable from the region. |
| T-02-SC | Tampering | npm installs | high | mitigate | No install in this plan. |
</threat_model>
