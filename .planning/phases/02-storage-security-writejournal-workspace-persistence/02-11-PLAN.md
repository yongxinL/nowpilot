<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Simulated surface A → simulated surface B | Cross-document messages cross a boundary where forgery, staleness and duplication are possible. |
| Harness → production code | A harness that mocks production decisions would produce a vacuous green. |
| Test fixtures → persisted artefacts | Synthetic secrets and bodies must never leak into an artefact that a later phase reads as evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-57 | Spoofing | cross-surface envelope | high | mitigate | The harness injects a deterministic transport but runs the real envelope validators; invalid source/target and unsupported-version cases assert rejection. |
| T-02-58 | Repudiation | vacuous harness | high | mitigate | The mock-only-environmental rule is stated in the harness header and the suite drives real election, persistence and migration implementations. |
| T-02-59 | Information Disclosure | sentinel leakage | high | mitigate | The suite injects a synthetic sentinel and asserts its absence from the URL, every envelope, the journal, the error store and the log buffer. |
| T-02-60 | Tampering | stale writer after handoff | high | mitigate | The stale-writer case runs the real election and asserts the losing surface cannot write authoritative state. |
| T-02-61 | Denial of Service | flaky timing | medium | mitigate | All timing uses the harness clock; no arbitrary sleep exists, and `dispose()` clears every timer. |
| T-02-62 | Repudiation | test-order dependence | medium | mitigate | Each case builds its own harness instance and disposes it; the suite is asserted to pass alone and in the full-directory run. |
| T-02-SC | Tampering | npm installs | high | mitigate | No install in this plan; the harness uses only the test double added in 02-01. |
