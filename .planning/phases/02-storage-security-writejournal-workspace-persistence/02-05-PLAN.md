<objective>
Deliver STORAGE-02's storage-layer concepts folded into a single `Setting.ts` per D-09: a per-key permissioned typed wrapper over chrome.storage (permission table: key → { area, encrypted?, writeAllowed }), serialized writes (never two Setting<T> keys concurrently), and migrate-on-read via np_schema_version (D-10) using per-key sanitizers. Session tokens are declared keys-only with no accessors (D-11).

Purpose: One canonical KV layer so every chrome.storage consumer (ThemeStore, KeyVault, providers, workspace) writes through a permissioned, serialized, shape-validating path instead of ad-hoc chrome.storage calls.
Output: Setting.ts + Setting.test.ts (permission enforcement + serialization + migrate-on-read).

Flagged assumptions (specless probe):
- A-11: The permission table is the enforce-point for "no secrets in chrome.storage unless encrypted" — np_providers maps to { area: 'local', encrypted: true } and its write path must route ciphertext through EncryptedStorage (02-03) rather than raw values.
- A-12: np_schema_version defaults to the current schema version when absent (fresh install); migrate-on-read is additive/normalizing, never destructive.
</objective>
