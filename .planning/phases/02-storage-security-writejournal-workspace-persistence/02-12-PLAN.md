<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Credential field → any persisted or broadcast surface | A key typed in one controller must not reach storage, a channel, a journal or a log. |
| Two surfaces → one onboarding attempt | A joining surface must not start a second flow or a second completion write. |
| Verification records → release decisions | The traceability record is what a release gate reads; an inaccurate record hides outstanding work. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-63 | Information Disclosure | API-key propagation | critical | mitigate | Sentinel-absence assertions across storage, envelopes, journal, error records, logs and evidence; the vault boundary is exercised only through a direct authorised adapter. |
| T-02-64 | Tampering | competing onboarding controller | high | mitigate | Presentation is gated on authoritative writer state and the suite counts presentations across both surfaces. |

| T-02-67 | Tampering | duplicate completion | medium | mitigate | Duplicate-event and idempotency cases assert a single stored completion. |
