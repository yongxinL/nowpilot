<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Election state → UI | A rendering decision must follow authoritative state, never the act of a surface opening. |
| Two live surfaces → one onboarding flow | Two documents may both decide to present; exactly one may. |
| String map → DOM | Copy is the user's only evidence about system state and must be canonical. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-36 | Repudiation | premature writer claim | high | mitigate | The store defaults to `election-pending` and only an applied election outcome can produce `primary`; the suite asserts no default reports primary. |
| T-02-37 | Spoofing | mirror banner rendered without authority | high | mitigate | The banner's activation is a pure function of writer state and the activation table renders it on `mirror` only; the mount (02-09) consumes state, not an event. |
| T-02-38 | Tampering | competing onboarding flows | medium | mitigate | Presentation requires the authoritative writer state; the predicate's truth table is asserted for every state. |
| T-02-39 | Information Disclosure | copy leakage | medium | mitigate | Every string is a pinned canonical value with no interpolation of ids, codes, storage keys or bodies; the per-plan string discipline (02-10) asserts the notice strings contain no identifiers. |
| T-02-40 | Denial of Service | gate stuck reading | low | mitigate | A non-writer resolves `hidden` immediately rather than `reading`, so a mirror surface never waits on a competing flow. |
| T-02-SC | Tampering | npm installs | high | mitigate | No install in this plan. |
</threat_model>
