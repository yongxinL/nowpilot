<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Credential plaintext → encrypted envelope | The only place plaintext exists is component memory and this call; everything persisted is ciphertext. |
| Stored envelope → decrypt | A stored value may have been tampered with or produced by another key; the reader must fail closed. |
| Arbitrary values → log/persistence context | Error context crosses into durable records and must be redacted before it does. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Information Disclosure | credential persistence | critical | mitigate | Vault-only writes; the envelope schema has no plaintext field; the suite asserts the sentinel is absent from the storage maps and the `debugLog` ring buffer. |
| T-02-13 | Tampering | envelope integrity | high | mitigate | AES-GCM authenticates ciphertext, IV and AAD-bound metadata (version, provider, algorithm, KDF parameters); every failure maps to one indistinguishable redacted code. |
| T-02-14 | Spoofing | wrong-key decrypt | high | mitigate | A different extension id derives a different key; the suite asserts that case fails closed rather than returning garbage. |
| T-02-15 | Information Disclosure | error contexts | high | mitigate | `redactSensitive` + `redactErrorContext`; no message string and no stack is ever attached to a context, and the sentinel-absence assertions cover logs. |
| T-02-16 | Repudiation | replace semantics | medium | mitigate | A replace re-mints salt and IV and the superseded ciphertext no longer decrypts; the suite asserts it. |
| T-02-17 | Denial of Service | malformed stored envelope | medium | mitigate | Decode is total and returns a typed failure; a malformed stored value can never throw through the caller. |
| T-02-SC | Tampering | npm installs | high | mitigate | No install in this plan; WebCrypto is platform-provided and no crypto package is added. |
</threat_model>
