<objective>
Cut the chat store over to ChatHistoryDB: a body-free `np_store` v3 projection plus an explicit, asynchronous hydration lifecycle.

Purpose: ROADMAP success criterion 2's "no message body in `chrome.storage.local`" is only true once the store stops persisting the conversation collection, and D2-18's hydration states are what the surfaces render. This is the store-side half of D2-08's target storage split: after the cutover `np_store` retains only approved lightweight metadata while ChatHistoryDB owns conversations, bodies, ordering and timestamps.
Output: `np_store` v3 with the body-free allow-list, the six-state hydration contract with a typed redacted error/recovery state, and the extended store suite proving the projection and the no-fallback rule.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `np_store` blob → store | The persisted blob is pre-cutover data and may still contain bodies from any earlier version. |
| Database → hydration | A failed or partial read must not be reported as an empty conversation history. |
| Store → components | Components consume status and data and must never infer persistence success. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-42 | Repudiation | hydration status | high | mitigate | `empty` is reachable only from a successful empty read; the failure case asserts a database error never resolves empty and no fallback body path exists. |

| T-02-45 | Denial of Service | unrecoverable failure | medium | mitigate | `retryHydration()` re-drives a failed hydration without discarding recoverable journal state. |
