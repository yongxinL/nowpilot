# Phase 4a — UI Design Contract

> Visual and interaction contract for Phase 4a (PageContentService — Knowledge Acquisition). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Source-of-truth artifacts: `.planning/phases/01-*/01-UI-SPEC.md` (approved Phase-1 contract), `.planning/phases/03-cost-effective-ai-runtime-persona-seed/03-UI-SPEC.md` (approved Phase-3 contract), `.planning/DESIGN_SYSTEM.md` (§5–§13), `.planning/phases/04a-pagecontentservice-knowledge-acquisition/04a-CONTEXT.md` (D-4a-01…24), `.planning/PRODUCT_SPEC_v0_1.md` §18 Phase 4a + §26 + §5.6 + §22.1/§22.2 + §16/§20.7 + Appendix C/G, `.planning/ROADMAP.md` Phase 4a, `AGENTS.md` (approved stack + banned list + R-3/R-5/R-9/R-10).

> **Scope honesty note (must be preserved by the planner):** Phase 4a is a **core-infrastructure phase, not a UI phase**. The 11-file §18 create-list is entirely core (`src/core/extraction/**`, `src/core/content/AxDomWalker.ts`, `PageContextBridge.ts`, `ContentScriptHost.ts`, `SPANavigationWatcher.ts`) — **zero new components**. The content script stays extraction-only and **invisible** (R-5, §5.6): no UI mount, no style injection, no host-DOM writes, no badge, no toast, no shadow DOM. The panel-side pipeline is likewise silent — no spinner, no stage indicator, no notification. The only visible consequence of this phase is that the existing Phase-1 "Current page context" card in `WorkspacePageSkeleton.tsx` begins to render when the new `WorkspaceStore.currentPageContext` write path (D-4a-05 primary-writer) populates it. All extraction-status UI (capture affordance, content preview, trust toggles, stage indicators) is fenced to Phase 4b (trust controls) and Phase 7 (RICH surfaces). Do not let UI polish leak in.

## Visual Hierarchy & Focal Points

### No new focal points in Phase 4a

Phase 4a introduces **no new visual hierarchy**. The pipeline is invisible by design. The single visible change is that the existing Standalone `WorkspacePageSkeleton` "Current page context" card (already present in the DOM structure, currently rendering only when a context exists) begins to populate once the new `WorkspaceStore.currentPageContext` write path (D-4a-05 primary-writer) delivers an extraction. The card:

- Remains **display-only** — zero store mutations, zero chrome API calls (Pitfall 4, existing file header).
- Shows **title only** — no content preview, no metadata, no status.
- Swaps `title` on SPA-nav **instantly** (plain React re-render); no motion transition, no fade, no flash.
- Never renders extraction state — no "extracting…", no "✓ extracted", no error row (all Phase 7).

### Invisible-by-contract (binding negative contract)

The content script (and its serialized payload path) must render **nothing**:

- No UI mount, no Shadow DOM, no React/AntD import, no host-DOM writes, no style injection (R-5, §5.6, Appendix G isolation).
- No badge, no notification, no toast, no cursor change, no layout shift in the host page.
- The `<50 KB` bundle ships `AxDomWalker` + serializer + `SPANavigationWatcher` only (D-4a-07/10/12; isolation test `tests/isolation/no-content-script-ui.test.ts` + the retired `check-content-bundle.mjs` logic, D-4a-23).
- The panel-side pipeline is equally silent: coalesced in-flight extraction (D-4a-03) shows no spinner/skeleton; `STR.rich.stageReading` is **not** rendered.

## Interaction Contract — Silent Extraction Pipeline

Locked by 04a-CONTEXT D-4a-01…21 and spec §20.7 `TabExtractionState` (the canonical state machine this phase implements), §26.2 (layered strategy), §26.6 (reliability & privacy), §5.6 (content-script rules). The state machine is a **surface contract for future UI consumers** (Phase 7 RICH / Phase 4b trust controls); in Phase 4a **no state renders visible chrome** — the table states what each state must (not) do on the surface.

| `TabExtractionState` (§20.7) | Phase 4a surface behavior |
|------------------------------|---------------------------|
| `idle` (no tab / not subscribed) | No extraction, no UI (D-4a-01: zero extraction on unsubscribed long tail). |
| `injecting` | Silent. Content script loads at `document_idle`, ISOLATED world, non-blocking (D-4a-07, CAT-04). No UI. |
| `extracting` | Silent. 5 s hard cap (§22.1, D-4a-03), single `AbortController` threaded through the round-trip, per-tab in-flight promise dedup (coalescing). No spinner, no toast, no stage indicator (`STR.rich.stageReading` NOT rendered — Phase 7). |
| `pinned` | The extraction result is written to `WorkspaceStore.currentPageContext` via the existing primary-writer election (D-4a-05; secondary mirrors via BroadcastBus — **no new coordination path**). The existing context card populates (title only). Pinned tabs are eviction-last; never evict in-flight or subscribed tabs (D-4a-04). Pin affordances (RICH-04, max 10) and `STR` `cannotPin` are Phase 7/Phase 5 surfaces — not rendered in 4a. |
| `failed` (`UNSUPPORTED_URL` / `TIMEOUT` / `CONTENT_EXTRACT_FAILED`) | Typed failure propagates to the requesting surface and to `debugLog` (GR-9, R-10) — **no visible error UI in 4a** (Phase 7 renders the failed surface). The workspace write does not occur, so the card retains the previous successful context (or stays absent) — **stale-safe** (D-4a-03: never a silent empty result at the service contract level). |

Additional binding rules for the executor/planner:

- **No new MessageType beyond canonical additions** (Phase-1 Pitfall 5): the 4a extraction request/reply flow extends `EXTRACT_PAGE_CONTENT` + `GET_CONTENT_CAPABILITIES`/`CONTENT_CAPABILITIES` with canonical contracts; `PageContextBridge` events feed the Phase-4 D-04-02 CTX-02 re-pack seam (input-only, consumer in 4b/7).
- **Redaction before any display/index/log** (CAT-03, §26.6, R-10): TraceRedactor runs panel-side before indexing/logging; the content script strips + omits passwords **at capture** (`isPassword ⇒ value omitted`, D-4a-20) — the UI never sees a password-bearing extraction.
- **`currentPageContext` write is the ONLY store mutation 4a adds on the delivery path** — no new UI-visible state fields, no extraction-status store slice (D-18 type-drift boundary).
- **Truncation** (`PAGE_HTML_MAX_BYTES` ~2 MB, `truncated: true` provenance, D-4a-09): silent — no UI indication this phase (Phase 7 may surface `truncated` provenance; D-4a-21 metrics feed Diagnostics §4.5, Phase 6).
