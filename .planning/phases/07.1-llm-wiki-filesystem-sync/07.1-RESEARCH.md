# Phase 7.1: LLM-Wiki & Filesystem Sync - Research

**Researched:** 2026-07-17
**Domain:** LLM-powered note features, YAML frontmatter serialization, File System Access API, IndexedDB schema migration, Ant Design Tree/Bubble/Tag
**Confidence:** HIGH

## Summary

Phase 7.1 extends the existing Notes system (Phase 7) with five new core services and four new UI components. The architecture follows existing patterns: services are stateless singletons under `src/core/notes/`, LLM calls use the `generateText` from `ai` SDK (same pattern as `MemoryExtractor`), structured JSON output is validated with Zod + `StructuredOutput.ts`, and IndexedDB migrations follow the v1→v2→v3 pattern via `IndexedDBManager.ts`'s upgrade callback. The `yaml` npm package (`/eemeli/yaml` v2.9.0, 160M weekly downloads) provides frontmatter parse/stringify. The File System Access API (`showDirectoryPicker`, `FileSystemDirectoryHandle`) is supported in Chrome MV3 and handle persistence to IndexedDB is well-documented in the WICG spec. `@ant-design/x` Bubble component provides inline ephemeral answers with footer slots for citation Tags. Ant Design Tree component supports `treeData` with `fieldNames` for the category browse view.

**Primary recommendation:** Follow the `MemoryExtractor` pattern exactly for all LLM service calls — use `generateText` from `ai` SDK with Haiku/Flash tier resolution via `providerRegistry.getModelsForTier()`, validate with Zod schema via `repairAndValidate` from `StructuredOutput.ts`, retry once on failure, and never throw. For filesystem sync, use `FileSystemDirectoryHandle` with recursive `getDirectoryHandle({create:true})` for folder creation, and `createWritable()` for file writes.

## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01 — Single Haiku-tier call for tags + category + summary:** One combined LLM call (temperature 0) covering all three outputs. Prompt returns structured JSON with tags[], categoryPath, and summary.
- **D-02 — Haiku for analysis, Flash for synthesis:** Tag/category/summary extraction uses Haiku-tier. RAG Q&A answer synthesis uses Flash-tier.
- **D-03 — Dual-friendly file format:** Note body is natural language markdown. YAML frontmatter has structured metadata (id, created, updated, tags, categoryPath, summary).
- **D-04 — Category is path-based, not flat:** `categoryPath` (e.g. `InfoTech/Database/MySQL`) maps 1:1 to filesystem folders.
- **D-05 — Notes feed into MemoryEngine, not the reverse:** Extracting memory facts from notes enriches chat context. Memory is system-owned; notes are user-owned.
- **D-06 — Memory-aware RAG:** "Ask notes" queries also call `MemoryEngine.assemble()` for relevant user facts/preferences.
- **D-07 — Maintenance is user-initiated:** No background jobs in MV3. Staleness detection uses passive timestamp comparison. Bulk regeneration is explicitly triggered by the user.
- **D-08 — Backup folder handle in IndexedDB:** `FileSystemDirectoryHandle` cannot go in `chrome.storage.local`. A dedicated `notes_backup_config` IndexedDB store handles this. DB version bumps to v4.
- **D-09 — Per-save fire-and-forget sync:** Every create/update/delete triggers an immediate write to the backup folder. 50ms debounce prevents rapid-save bursts. No user-facing loading state.
- **D-10 — Title collision resolution:** Numerical suffixes on same-title notes in same categoryPath: `My Note.md`, `My Note (1).md`, `My Note (2).md`.
- **D-11 — External change detection:** On save, if `lastModified` is newer than last sync timestamp, show confirm dialog. Default is Skip. 2-second tolerance window.
- **D-12 — Import is additive, preview-first:** Restore walks backup folder, parses .md with YAML frontmatter, upserts into IndexedDB. Existing DB notes not in backup are NOT deleted. Preview modal before import.
- **D-13 — User is always the gatekeeper for LLM output:** Suggestions displayed with accept/reject UI. Chat-to-note opens pre-filled NoteEditor for review.
- **D-14 — Category normalization on save:** Leading/trailing slashes removed, duplicate slashes collapsed, whitespace trimmed per segment. Invalid segments flagged with AntD red border.
- **D-15 — Ephemeral RAG answers:** "Ask notes" answers rendered as Bubble inline, not saved as notes. Citations as clickable Tag components.

### 12. MemoryExtractor Pattern (`src/core/memory/MemoryExtractor.ts`, lines 1-175)

This is the **canonical pattern** that all Phase 7.1 LLM services must follow:

1. **Model resolution** (lines 150-173): `providerRegistry.getModelsForTier(costTier)` → pick first model → `providerRegistry.getProvider()` → `provider.instance(modelId)` → pass to `generateText`.
2. **LLM call** (lines 103-108): `generateText({ model, system: PROMPT, prompt, maxTokens })` from `ai` SDK.
3. **Response handling** (lines 110-113): Strip markdown code fences → `JSON.parse` → Zod `safeParse` validation.
4. **Retry-once pattern** (lines 101-139): Loop 1..2, return empty result on final failure, never throw.
5. **Structured output** (lines 111-113): Manual JSON parse — Phase 7.1 services should use `repairAndValidate` from `StructuredOutput.ts` for robustness.

### 13. StructuredOutput Pipeline (`src/core/ai/pipeline/StructuredOutput.ts`, lines 1-56)

**API:** `repairAndValidate<T>(text: string, schema: z.ZodType<T>, fallback: T): { result: T } | { fallback: T }`

The function:
1. Extracts JSON block from potentially noisy text (strips markdown code fences, finds first `{...}` or `[...]`)
2. Repairs malformed JSON with `jsonrepair`
3. Parses + validates against Zod schema
4. Returns result or fallback

**Usage pattern for NoteTagger:**
```typescript
const schema = z.object({
  tags: z.array(z.string()).max(5),
  categoryPath: z.string().nullable(),
  summary: z.string(),
  memoryFacts: z.array(z.object({
    fact: z.string(),
    category: z.enum(['preference', 'pattern', 'knowledge', 'goal', 'identity']),
    confidence: z.number().min(0).max(1),
    tags: z.array(z.string()),
  })).optional(),
});
const { text } = await generateText({...});
const parsed = repairAndValidate(text, schema, { tags: [], categoryPath: null, summary: '' });
```

### Pattern 1: LLM Service Pattern (NoteTagger, NoteQA, NoteChatConverter)

**What:** Stateless service class with `generateText` → Zod validation → retry-once → never-throw. Follows `MemoryExtractor` exactly.

**When to use:** All three LLM-powered services.

**Example (NoteTagger):**
```typescript
// Source: Pattern derived from MemoryExtractor.ts lines 84-143
import { generateText } from 'ai';
import { z } from 'zod';
import { repairAndValidate } from '../../ai/pipeline/StructuredOutput';
import { providerRegistry } from '../../ai/providers/ProviderRegistry';
import { debugLog } from '../../utils/debugLog';

const TAGGER_PROMPT = `You are a note analyzer...`;

const taggerResultSchema = z.object({
  tags: z.array(z.string()).max(5),
  categoryPath: z.string().nullable(),
  summary: z.string(),
  memoryFacts: z.array(z.object({
    fact: z.string(),
    category: z.enum(['preference', 'pattern', 'knowledge', 'goal', 'identity']),
    confidence: z.number().min(0).max(1),
    tags: z.array(z.string()),
  })).optional(),
});

export class NoteTagger {
  async analyze(note: { title: string; content: string }, allCategories: string[]): Promise<...> {
    await providerRegistry.initialize();
    const models = providerRegistry.getModelsForTier('haiku');
    if (models.length === 0) return { tags: [], categoryPath: null, summary: '', memoryFacts: [] };

    const provider = providerRegistry.getProvider(models[0].providerId);
    if (!provider) return fallback;

    const model = (provider.instance as any)(models[0].modelId);
    const prompt = `Title: ${note.title}\nContent: ${note.content}\nExisting categories: ${allCategories.join(', ')}`;

    for (let attempt = 1; attempt <= 2; attempt++) {
      try {
        const { text } = await generateText({ model, system: TAGGER_PROMPT, prompt, maxTokens: 500 });
        const parsed = repairAndValidate(text, taggerResultSchema, { tags: [], categoryPath: null, summary: '' });
        if ('result' in parsed) return parsed.result;
        if (attempt === 2) return parsed.fallback;
      } catch (err) {
        if (attempt === 2) { debugLog('error', '[NoteTagger] failed after retry', { error: err }); return fallback; }
        debugLog('warn', '[NoteTagger] retrying');
      }
    }
    return fallback;
  }
}
```

### Pattern 2: File System Access API Pattern (NoteFileSync)

**What:** Manage `FileSystemDirectoryHandle` lifecycle — persist to IndexedDB, verify permissions, recursive directory creation, file write/delete.

**Permission lifecycle:**
1. User picks folder via `showDirectoryPicker()` → handle stored in `notes_backup_config`
2. On every NotesPage mount, call `handle.queryPermission({mode:'readwrite'})`
3. If denied → disable sync, show banner
4. Before each write: check permission, re-request if needed

**File write pattern:**
```typescript
// Source: WICG File System Access spec (Context7)
async writeNoteFile(rootHandle: FileSystemDirectoryHandle, note: Note): Promise<void> {
  // 1. Resolve category path to directory
  let dirHandle = rootHandle;
  if (note.categoryPath) {
    for (const segment of note.categoryPath.split('/')) {
      dirHandle = await dirHandle.getDirectoryHandle(segment, { create: true });
    }
  }

  // 2. Sanitize filename: replace / \ : * ? " < > | with _
  const safeTitle = note.title.replace(/[\/\\:*?"<>|]/g, '_');
  const fileName = `${safeTitle}.md`;

  // 3. Resolve collisions (SYNC-05)
  const finalName = await resolveCollision(dirHandle, fileName);

  // 4. Check external change (SYNC-06)
  try {
    const existing = await dirHandle.getFileHandle(finalName);
    const file = await existing.getFile();
    if (file.lastModified > note.updated + 2000) {
      const shouldOverwrite = await confirmOverwrite(fileName);
      if (!shouldOverwrite) return;
    }
  } catch { /* file doesn't exist yet */ }

  // 5. Write file
  const fileHandle = await dirHandle.getFileHandle(finalName, { create: true });
  const writable = await fileHandle.createWritable();
  await writable.write(formatNoteAsMarkdown(note));
  await writable.close();
}
```

```typescript
function buildCategoryTreeData(notes: Note[]): DataNode[] {
  const root: Record<string, any> = {};
  for (const note of notes) {
    if (!note.categoryPath) {
      if (!root['__uncategorized__']) root['__uncategorized__'] = { title: 'Uncategorized', key: '__uncategorized__', children: [] };
      root['__uncategorized__'].children.push({ title: note.title, key: note.id, isLeaf: true });
      continue;
    }
    const parts = note.categoryPath.split('/');
    let current = root;
    for (let i = 0; i < parts.length; i++) {
      const key = parts.slice(0, i + 1).join('/');
      if (!current[key]) current[key] = { title: parts[i], key, children: [] };
      current = current[key];
      if (i === parts.length - 1) {
        current.children = current.children || [];
        current.children.push({ title: note.title, key: note.id, isLeaf: true });
      }
    }
  }
  // Convert to array, flatten intermediate objects
  return Object.values(root).map(normalizeTreeNode);
}
```

### Pattern 7: Category Normalization

```typescript
function normalizeCategoryPath(raw: string): string | { error: string } {
  // Trim whitespace
  let path = raw.trim();
  // Remove leading/trailing slashes
  path = path.replace(/^\/+|\/+$/g, '');
  // Collapse duplicate slashes
  path = path.replace(/\/+/g, '/');
  // Split into segments, validate each
  const segments = path.split('/').filter(s => s.length > 0);
  for (const seg of segments) {
    const trimmed = seg.trim();
    if (trimmed === '.' || trimmed === '..') return { error: `Invalid segment: "${trimmed}"` };
    if (trimmed.length === 0) return { error: 'Empty segment in path' };
  }
  if (segments.length === 0 && path.length > 0) return { error: 'Invalid path' };
  return segments.join('/');
}
```

### Pattern 8: Title Collision Resolution (SYNC-05)

```typescript
async function resolveCollision(dirHandle: FileSystemDirectoryHandle, baseName: string): Promise<string> {
  const base = baseName.replace(/\.md$/, '');
  const ext = '.md';
  let candidate = `${base}${ext}`;
  let counter = 1;

  // Check if file exists (up to 100 attempts to prevent infinite loops)
  while (counter <= 100) {
    try {
      await dirHandle.getFileHandle(candidate);
      // File exists — try next suffix
      candidate = `${base} (${counter})${ext}`;
      counter++;
    } catch {
      // File doesn't exist — use this name
      return candidate;
    }
  }
  // Fallback: use timestamp
  return `${base}-${Date.now()}${ext}`;
}
```

### Anti-Patterns to Avoid

- **Buffering writes:** Do not buffer all file writes. Fire-and-forget per D-09 means each save triggers its own async write. Batch writes would violate the "immediate" requirement and could lose data.
- **Throwing from LLM calls:** Like `MemoryExtractor`, never throw from LLM services. Always return a valid fallback. Notes should be savable without LLM features.
- **Blocking UI on sync:** Never await `NoteFileSync.sync()` in the save pipeline. Fire-and-forget. Use 50ms debounce to prevent bursts.
- **Using chrome.storage.local for handles:** `FileSystemDirectoryHandle` is a non-serializable object. Only IndexedDB can persist it.
- **Pulling MemoryEngine state into notes:** Per D-05, notes feed into memory, not the reverse. Don't auto-insert memory facts into note content.
- **Hand-rolling YAML frontmatter regex:** The `yaml` package handles edge cases (nested values, arrays, special characters, multi-line strings) that regex cannot reliably parse.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| YAML frontmatter parsing | Custom regex or manual string splitting | `yaml` package (parse/stringify) | Nested YAML values, arrays, special characters, multi-line strings are complex and error-prone to parse by hand |
| File system access | Custom Native Messaging host or legacy `<input>` fallback | `showDirectoryPicker()` / File System Access API | Browser-native API with permission model, handle persistence, recursive directory ops. Chrome MV3 supports it in extension pages. |
| LLM JSON response parsing | Manual JSON.parse with try/catch and string cleanup | `repairAndValidate` from `StructuredOutput.ts` | Handles markdown code fences, malformed JSON, missing commas, and schema validation in one call. Already in codebase. |
| Permission state tracking | Custom permission cache or polling | `handle.queryPermission({mode:'readwrite'})` | Browser-native permission API. Handle persistence in IndexedDB per WICG spec. |
| Category tree data structure | Custom recursive component | Ant Design `Tree` with `treeData` + `fieldNames` | Handles virtual scrolling, expand/collapse, selection, keyboard nav, a11y. |
| Chat-to-note LLM call | Single-message context | Full conversation + MemoryEngine context (MEM-03) | The spec requires both. Passing only one message loses context the LLM needs for accurate tagging and wikilink suggestions. |

**Key insight:** The File System Access API's `FileSystemDirectoryHandle` cannot be `JSON.stringify`'d — the size of the object is 0, and the contents are opaque. IndexedDB is the only Chrome extension storage mechanism that can persist these handles. The `notes_backup_config` store is essential for this reason.

## Common Pitfalls

### Pitfall 1: File System Access API Permission Loss After Handle Storage

**What goes wrong:** `FileSystemDirectoryHandle` stored in IndexedDB loses read/write permission after browser restart, tab close, or user clearing site data. Operations silently fail with `DOMException: permission denied`.

**Why it happens:** The browser may revoke permissions for persisted handles. The handle object survives, but the permission grant does not.

**How to avoid:** On every NotesPage mount, call `handle.queryPermission({mode:'readwrite'})`. If it returns `'prompt'` or `'denied'`, set sync status to `'error'` and show a banner. Before every write operation, check permission. If `'prompt'`, call `handle.requestPermission({mode:'readwrite'})` — the user must interact with the page first (click event context).

**Warning signs:** Sync works after folder selection but fails on next page load. Console shows `DOMException: The request is not allowed by the user agent or the platform`.

### Pitfall 2: Haiku-tier Model Unavailability

**What goes wrong:** `providerRegistry.getModelsForTier('haiku')` returns empty array. NoteTagger, NoteQA (reranking), and NoteChatConverter fail.

**Why it happens:** User has not configured any provider, or only has high-tier models (e.g., Sonnet-only). The `haiku` cost tier requires a provider model explicitly mapped to that tier.

**How to avoid:** Before making any LLM call, check `models.length === 0` and return empty fallback silently. Never throw. Log a debug warning so users can diagnose in Options → Providers. The UI should degrade gracefully: LLM features simply don't fire, no error toasts.

**Warning signs:** Tags/category never appear after save. No error in UI. Debug console shows `[NoteTagger] No haiku-tier models available`.

### Pitfall 3: MiniSearch Index Staleness After Import

**What goes wrong:** After restoring notes from backup (SYNC-09), MiniSearch index doesn't reflect imported notes. Search and wikilink resolution fail for imported notes.

**Why it happens:** `NotesDB.getAllNotes()` is called once on mount (`NotesPage.loadNotes()` line 23-34, which calls `lp.rebuildIndex(all)` on line 28). But import happens later in the same session.

**How to avoid:** After import completes, call `lp.rebuildIndex()` with all notes including newly imported ones. Same pattern as `NotesPage.loadNotes()`. Also recompute backlinks.

**Warning signs:** Imported notes not appearing in search results or wikilink autocomplete after import.

### Pitfall 4: YAML Frontmatter Injection in Content

**What goes wrong:** Note content that looks like YAML frontmatter (e.g., a note about YAML syntax) gets incorrectly parsed as metadata during import.

**Why it happens:** The `yaml` parser treats the first `---` block as frontmatter. If a note body begins with `---`, it may be misinterpreted.

**How to avoid:** On export (SYNC-04), always write frontmatter as the FIRST `---` block. On import (SYNC-09), only parse the first `---` block as frontmatter. Escape any `---` sequences in the note body during export (e.g., replace with `\-\-\-` or wrap in code fence).

**Warning signs:** Imported notes have content truncated at the first `---` in the body. Or note body content appears in frontmatter fields.

### Pitfall 5: Debounce Race Condition with NoteFileSync

**What goes wrong:** Rapid saves within 50ms debounce window — only the last one triggers sync. The first save's content is never written to filesystem.

**Why it happens:** The 50ms debounce (SYNC-03) is a leading-edge debounce — it batches writes but the first event is lost if replaced within the window.

**How to avoid:** Use a trailing-edge debounce that writes the LATEST state after the window expires. Or queue writes and flush when debounce expires. The debounce should accumulate write operations and flush the latest state for each note.

**Warning signs:** Note content in IndexedDB differs from backup file content after rapid editing (Last write wins in IndexedDB but not filesystem).

### YAML Frontmatter Serialization (SYNC-04)

```typescript
// Source: yaml package docs (Context7, /eemeli/yaml)
import { stringify, parse } from 'yaml';

export function formatNoteAsMarkdown(note: Note): string {
  const frontmatter: Record<string, unknown> = {
    id: note.id,
    created: note.created,
    updated: note.updated,
    tags: note.tags,
  };
  if (note.categoryPath) frontmatter.categoryPath = note.categoryPath;
  if (note.summary) frontmatter.summary = note.summary;

  const yamlStr = stringify(frontmatter, { lineWidth: 0, indent: 2 });
  return `---\n${yamlStr}---\n\n${note.content}`;
}

export function parseNoteFromMarkdown(md: string, categoryPath?: string): Partial<Note> {
  const frontmatterMatch = md.match(/^---\n([\s\S]*?)\n---\n/);
  if (!frontmatterMatch) return { content: md, categoryPath };

  const frontmatterYaml = frontmatterMatch[1];
  const body = md.slice(frontmatterMatch[0].length);
  const metadata = parse(frontmatterYaml) as Record<string, unknown>;

  return {
    id: metadata.id as string,
    title: extractTitle(body), // first # heading or "Untitled"
    content: body,
    created: metadata.created as number,
    updated: metadata.updated as number,
    tags: (metadata.tags as string[]) || [],
    categoryPath: (metadata.categoryPath as string) || categoryPath || undefined,
    summary: metadata.summary as string | undefined,
  };
}
```

### NoteQA RAG Pattern with MemoryEngine Integration

```typescript
// Source: Pattern from LLM-WIKI-SPEC.md §6.4 data flow diagram
export class NoteQA {
  async ask(
    query: string,
    allNotes: Note[],
    linkParser: LinkParser,
  ): Promise<{ answer: string; citations: Array<{ noteId: string; title: string; snippet: string }> }> {
    // 1. MiniSearch retrieval
    const searchResults = linkParser.search(query);
    const top5 = allNotes.filter(n => searchResults.some(r => r.id === n.id)).slice(0, 5);

    // 2. MemoryEngine context (MEM-01)
    let memoryContext = '';
    try {
      const memResult = await memoryEngine.assemble(`notes-rag-${Date.now()}`, query, 'small');
      const relevantMemories = memResult.memory.filter(m => m.score > 0.6);
      if (relevantMemories.length > 0) {
        memoryContext = '\nUser context:\n' + relevantMemories.map(m => `- ${m.content}`).join('\n');
      }
    } catch { /* memory unavailable, continue without */ }

    // 3. Flash-tier LLM synthesis
    const models = providerRegistry.getModelsForTier('flash');
    // ... model resolution (same as NoteTagger pattern) ...
    const snippets = top5.map(n => `[Source: ${n.title}]\n${n.content.slice(0, 500)}`).join('\n\n');
    const prompt = `Question: ${query}\n\nNotes:\n${snippets}${memoryContext}\n\nAnswer the question based on the notes. Cite sources.`;

    const { text } = await generateText({ model, system: QA_PROMPT, prompt, maxTokens: 500 });
    // Parse citations from text, return structured answer
  }
}
```

## Open Questions

1. **File System Access API in MV3 Service Workers**
   - What we know: `showDirectoryPicker()` requires a user gesture and a visible page context. It works in extension pages (options.html, standalone.html, popup.html) but NOT in service workers.
   - What's unclear: Whether NotesPage (which runs in standalone.html) retains the directory handle across navigation within the same tab.
   - Recommendation: Call `getBackupHandle()` on NotesPage mount (SYNC-02). If handle is valid, use it. If not, show banner. Handle is persisted in IndexedDB — retrievable on next mount.

2. **MemoryEngine.extract() with Note Content Format**
   - What we know: `MemoryEngine.extract()` (line 143) accepts `Array<{role: string; content: string}>`. It's designed for chat conversations.
   - What's unclear: Best message format for note content. Single user message? User+assistant pair?
   - Recommendation: Use a user message with formatted note content (`Note Title: ${title}\n\n${content}`) and a minimal assistant acknowledgment. Test with real MemoryExtractor to verify fact extraction quality from note content.

3. **YAML Frontmatter and Markdown Body Separator**
   - What we know: Standard frontmatter uses `---` as delimiter. Note body may contain `---` (horizontal rules in markdown).
   - What's unclear: How to reliably separate frontmatter from body when body contains `---`.
   - Recommendation: On export, test for `---` at start of any line in body. If found, wrap in code fence or escape. On import, parse ONLY the first `---...---` block as frontmatter. Everything after is body.

4. **Performance of `buildBacklinks()` After Import**
   - What we know: `LinkParser.buildBacklinks()` (lines 128-166) is O(n²) — scans every note against every other note. With 500+ notes, this could be slow.
   - What's unclear: Actual performance threshold. 100 notes × 100 notes = 10,000 comparisons — likely fine. 1,000 notes = 1M comparisons — may need optimization.
   - Recommendation: For Phase 7.1, use existing `buildBacklinks()`. If imports create >500 notes, add a note in the preview modal: "Backlink computation may take a moment for large imports."

### Known Threat Patterns for Chrome Extension + LLM + File System

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Path traversal in categoryPath | Tampering | Category normalization strips `.` and `..` segments; each segment validated before use; `getDirectoryHandle` restricts to within picked folder |
| Malicious note content in imported .md files | Spoofing | Import is additive, user must confirm via preview modal; YAML frontmatter validation rejects malformed metadata; content is treated as text, not executed |
| LLM prompt injection via note content | Tampering | LLM prompt treats note content as data, not instructions; structured JSON output enforcement via Zod schema prevents LLM from executing injected commands |
| File name injection (e.g., `../../../etc/passwd`) | Tampering | File name sanitization replaces `/ \ : * ? " < > |` with `_` before filesystem writes; `getFileHandle` only operates within the picked directory |
| Data exfiltration via backup folder | Information Disclosure | User explicitly selects backup folder; only notes explicitly saved are written; no automatic reading of filesystem beyond the picked folder |
| IndexedDB handle theft (malicious extension reads handle) | Elevation of Privilege | IndexedDB is same-origin; handle is opaque and cannot be meaningfully used without the corresponding Chrome permission grant |
