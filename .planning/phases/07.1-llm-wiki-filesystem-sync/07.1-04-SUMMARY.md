**Four new React UI components: CategoryTree (AntD Tree hierarchy), TagSuggestions (accept/reject tag UI), AskNotesInput (RAG Q&A with Bubble + citations), and NotesSection (options toggles/backup/maintenance) — 29 passing tests, 8 new files**

## Accomplishments

- **CategoryTree.tsx** — AntD Tree component displaying note hierarchy from `categoryPath` values, with a dedicated "Uncategorized" node for notes without a category. Uses `buildCategoryTreeData()` algorithm with `useMemo` and `defaultExpandAll`. Empty state handled with AntD `Empty` component.
- **TagSuggestions.tsx** — Accept/reject UI for LLM-suggested tags. Green Tag color for accepted, default color for unaccepted with inline Check icon. Tag close icon triggers reject. Loading state shows `Spin` with text. Empty state shows "No suggestions yet".
- **AskNotesInput.tsx** — RAG Q&A search input combining `Input.Search` (wrapped in form for reliable Enter-key submission) with inline `Bubble` from `@ant-design/x` for answer display. Citations render as clickable AntD `Tag` (blue) with `onSelectNote` navigation callback. Ephemeral React state per D-15. Loading spinner and error state handled.
- **NotesSection.tsx** — Options section with three sub-sections: LLM Features (4 Switch toggles: autoTag, autoCategorize, autoSummary, aiSearch persisted to `chrome.storage.local` key `np_notes_llm_features`), Backup (current folder display, change/sync buttons via `NoteFileSync`), and Maintenance (stats display, Re-analyze button). Follows `FeatureFlagsSection` pattern with `data-options-section="notes"` attribute.

## Decisions Made

- **CategoryTree defaultExpandAll**: Note titles are visible in the hierarchy by default so users can browse all notes without manually expanding folders.
- **AskNotesInput form wrapper**: Wrapping `Input.Search` in a `<form>` element allows reliable Enter-key submission testing via `fireEvent.submit(form)` in jsdom, avoiding AntD's internal event handling that varies across versions.
- **QAResult state typing**: Used `QAResult` type (with `answer` field) from noteTypes for the state, matching the actual `NoteQA.ask()` return type — avoids the bug of accessing `answer.text` which doesn't exist on `QAResult`.
- **Auto-save toggles in NotesSection**: Feature toggles save instantly on change following the existing FeatureFlagsSection pattern (no separate save button needed).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed QAResult state typing — answer.text → answer.answer**

- **Found during:** Task 2 (AskNotesInput test debugging)
- **Issue:** The component stored `NoteQA.ask()` result (which returns `QAResult` with `answer` field) but accessed it as `answer.text`. The mock returned `{ answer: '...', citations: [...] }` which was correctly set in state, but `answer.text` evaluated to undefined. Citations rendered (because `answer.citations` exists) but the Bubble text was empty.
- **Fix:** Changed state type from `{ text: string; citations: Citation[] }` to `QAResult`, renamed state variable from `answer` to `qaResult`, and updated access from `qaResult.answer` instead of `answer.text`. Also removed unused `Citation` import, added `QAResult` import.
- **Files modified:** src/components/notes/AskNotesInput.tsx
- **Verification:** All 7 AskNotesInput tests pass, answer text now renders in Bubble
- **Committed in:** 565239e (part of Task 2 commit)

## Issues Encountered

- **AntD Input.Search Enter-key handling in jsdom:** `fireEvent.keyDown(input, { key: 'Enter' })` did not trigger AntD's internal `onPressEnter` handler reliably across all tests. Fixed by wrapping `Input.Search` in a `<form>` element with `onSubmit` handler, allowing `fireEvent.submit(form)` for reliable Enter-key simulation.
- **Multiple Bubble elements rendered:** Initial test approach triggered both the form `onSubmit` and Input.Search's `onSearch` props, causing double invocation of `handleSearch`. Fixed by removing the form wrapper and relying solely on Input.Search's `onSearch` prop (triggered by both Enter key and search button click).
