# Phase 7.1: LLM-Wiki & Filesystem Sync - Context

**Gathered:** 2026-07-17
**Status:** Ready for planning
**Source:** PRD Express Path (.planning/LLM-WIKI-SPEC.md)

<domain>
## Phase Boundary

Extend the Phase 7 Notes system with LLM-powered features (auto-tagging, auto-categorization, auto-summarization, semantic search, RAG Q&A, chat-to-note conversion), a hierarchical category system that maps to filesystem folders, one-way app-to-filesystem backup with import-for-restore, and memory-aware integration with the existing MemoryEngine. This phase touches NoteEditor, NoteList, ChatMessage, SaveToNoteDialog, Options (new NotesSection), and the existing storage layer (NotesDB, IndexedDBManager). Five new core services (NoteTagger, NoteQA, NoteChatConverter, NoteFileSync, NoteMaintenance) are created. Two new npm dependencies (yaml, @types/wicg-file-system-access). The IndexedDB schema bumps to v4 for the `notes_backup_config` store.

**Surfaces affected:** Full App (all notes features + options), Side Panel (ChatMessage "Save to note" only).

**Not touched:** BacklinksPanel, NoteGraphView, WikilinkAutocomplete, NotePreview.
</domain>

<decisions>
## Implementation Decisions

### LLM Call Strategy
- **D-01 — Single Haiku-tier call for tags + category + summary:** One combined LLM call (temperature 0) covering all three outputs reduces cost vs three separate calls. The prompt returns structured JSON with tags[], categoryPath, and summary. This is a locked decision from the spec.
- **D-02 — Haiku for analysis, Flash for synthesis:** Tag/category/summary extraction uses Haiku-tier (low complexity, cost-effective). RAG Q&A answer synthesis uses Flash-tier (higher-quality output needed for multi-source answer generation). The planner must respect this tier assignment.

### Note Format
- **D-03 — Dual-friendly file format:** Note body is natural language markdown (user reads this). YAML frontmatter is structured metadata (id, created, updated, tags, categoryPath, summary). Both consumers get what they need from one file. The sync format is locked per spec §4.2 SYNC-04.
- **D-04 — Category is path-based, not flat:** `categoryPath` (e.g. `InfoTech/Database/MySQL`) maps 1:1 to filesystem folders. Flat `tags` already exist for many-to-many associations. Path-based categories avoid duplicating the tag concept.

### Memory Integration
- **D-05 — Notes feed into MemoryEngine, not the reverse:** Notes are user-curated knowledge. Extracting memory facts from notes enriches chat context without polluting notes with auto-extracted noise. Memory is system-owned; notes are user-owned. Locked spec decision.
- **D-06 — Memory-aware RAG:** "Ask notes" queries also call MemoryEngine.assemble() for relevant user facts/preferences. If a memory fact is highly relevant, included as context alongside note snippets. The LLM gets personal context.

### Maintenance & Execution
- **D-07 — Maintenance is user-initiated:** No background jobs in MV3. Staleness detection uses passive timestamp comparison (note.updated vs tagsGeneratedAt/summaryGeneratedAt). Bulk regeneration is explicitly triggered by the user. No auto-analysis.
- **D-08 — Backup folder handle in IndexedDB:** `FileSystemDirectoryHandle` is non-JSON-serializable and cannot go in `chrome.storage.local`. A dedicated `notes_backup_config` IndexedDB store handles this. DB version bumps to v4.

### Filesystem Sync
- **D-09 — Per-save fire-and-forget sync:** Every create/update/delete triggers an immediate write to the backup folder. 50ms debounce prevents rapid-save bursts. No user-facing loading state. The sync service manages `FileSystemDirectoryHandle`, permission verification, and directory tree operations.
- **D-10 — Title collision resolution:** If two notes share the same title AND same categoryPath, the second file gets a numerical suffix: `My Note.md`, `My Note (1).md`, `My Note (2).md`. Scan existing files for the highest suffix before writing.
- **D-11 — External change detection:** On save, if the file's `lastModified` timestamp is newer than the last sync timestamp, show a confirm dialog. Default is Skip. 2-second tolerance window prevents false positives from cloud-sync agents.
- **D-12 — Import is additive, preview-first:** Restore walks backup folder, parses .md with YAML frontmatter, upserts into IndexedDB. Existing DB notes not in backup are NOT deleted. Preview modal before import: "24 notes (12 new, 3 updated, 9 unchanged)".

### UI & UX
- **D-13 — User is always the gatekeeper for LLM output:** Tag/category/summary suggestions are displayed with accept/reject UI. Chat-to-note conversion opens pre-filled NoteEditor for review. No automatic content mutation without user approval.
- **D-14 — Category normalization on save:** Leading/trailing slashes removed, duplicate slashes collapsed, whitespace trimmed per segment. Invalid segments (`.` or `..`) flagged with AntD red border.
- **D-15 — Ephemeral RAG answers:** "Ask notes" Q&A answers rendered as Bubble inline, not saved as notes. Citations rendered as clickable Tag components navigating to source notes. React state only.

### the agent's Discretion
- NoteTagger internal prompt design — structured JSON output format for tags[]/categoryPath/summary/memoryFacts fields.
- NoteQA internal prompt design — synthesis prompt with source citation format and memory context injection.
- NoteChatConverter internal prompt design — how conversation context + memory facts → title, content, tags, wikilinks, categoryPath.
- NoteFileSync internal architecture — FileSystemDirectoryHandle lifecycle, permission verification, recursive directory creation, file sanitization regex.
- NoteMaintenance internal architecture — staleness detection algorithm, orphan detection (0 wikilinks + 0 backlinks), bulk analysis coordination.
- MiniSearch index extension — adding tags and summary as indexed fields for semantic search.
- yaml frontmatter serialize/deserialize implementation — using the `yaml` npm package.
- Nested category folder creation and cleanup via File System Access API.
- YAML frontmatter idempotent upsert on import.
- Exact AntD component placement (Tree for category browse, Tag for suggestions, Switch for toggles).
- LLM feature toggle persistence format in chrome.storage.local (key: np_notes_llm_features).
- v4 IndexedDB migration — add notes_backup_config store, no data migration needed.
</decisions>

<deferred>
## Deferred Ideas

| Feature | Reason |
|---------|--------|
| Bidirectional filesystem sync | Requires polling or Native Messaging. Complex, not needed for backup use case. |
| Embedding-based vector search | Large model download unsuitable for Chrome extension. LLM-routed reranking sufficient. |
| LLM wikilink suggestions in autocomplete | Minimal utility beyond existing MiniSearch. Deferred to v0.2+. |
| Real-time collaborative editing | Requires backend infrastructure. |
| Filesystem as primary note store | IndexedDB is primary. Filesystem is backup only. |
| Image/file attachments in notes | No current requirement. |
| Auto-create notes from chat (unprompted) | User must explicitly trigger "Save to note". |

None of the above are in Phase 7.1 scope.
</deferred>
