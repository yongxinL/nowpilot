    Design a prompt that instructs the Haiku-tier LLM to analyze a note (title + content) and return structured JSON with:

    - `categoryPath`: a hierarchical path like "InfoTech/Database" based on the note's topic and existing categories in the system, or null if none fit
    - `summary`: 1-2 sentence summary of the note

      5. Build prompt: `Title: ${note.title}\nContent: ${note.content}\nExisting categories: ${allCategories.join(', ')}`
      6. Loop 1..2: generateText → repairAndValidate → return result or fallback
      7. Never throw — catch all errors, log with debugLog, return fallback

    **Step A — Create the QA system prompt (`QA_PROMPT`):**
    Design a prompt for Flash-tier synthesis. The LLM receives: user's question, top-5 note snippets (with source titles), and optional memory context (user facts/preferences). The LLM must:
    - Answer the question based ONLY on the provided notes and user context
    - Cite sources inline using `[Source: Note Title]` notation after each claim
    - Say "I don't have enough information" if notes are insufficient
    - Output answer as plain markdown (no JSON wrapper for the answer — citations are parsed from the text via regex `[Source: ...]`)

    **Step B — Implement `NoteQA` class following same LLM service pattern:**
    - Same imports + provider resolution as NoteTagger, but uses `getModelsForTier('flash')` per D-02
    - Method: `async ask(query: string, allNotes: Note[], linkParser: LinkParser): Promise<QAResult>`
    - Flow per LLM-WIKI-SPEC.md §6.4 data flow diagram:
      1. `const searchResults = linkParser.search(query);` — MiniSearch retrieval
      2. Filter top-5 notes from search results: `const top5 = allNotes.filter(n => searchResults.some(r => r.id === n.id)).slice(0, 5);`
      3. Build snippets: each note → `[Source: ${note.title}]\n${note.content.slice(0, 500)}`
      4. **MemoryEngine integration (MEM-01):** `const memResult = await memoryEngine.assemble(\`notes-rag-\${Date.now()}\`, query, 'small');` — filter facts with score > 0.6, format as "User context:\n- {fact}" lines. Wrap in try-catch so MemoryEngine unavailability doesn't block Q&A.
      5. Build prompt: question + snippets + memoryContext
      6. Flash-tier LLM call with `maxTokens: 500`
      7. Parse citations from response text: regex `\[Source:\s*([^\]]+)\]` → match against note titles → build `Citation[]` array
      8. Return `{ answer: text, citations }` or fallback `{ answer: 'Unable to answer.', citations: [] }`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Note content → LLM prompt | User-written note content crosses into LLM prompt — untrusted text enters the generation pipeline |
| Conversation messages → LLM prompt | Chat messages (including assistant-generated content) cross into LLM prompt for NoteChatConverter |
| MemoryEngine → LLM prompt | System-owned memory facts cross into LLM prompt for NoteQA (MEM-01) and NoteChatConverter (MEM-03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-7.1-04 | Tampering | NoteTagger.analyze() | medium | mitigate | LLM output validated via Zod schema (taggerResultSchema) before use. `repairAndValidate` handles malformed JSON. Tags constrained to max 5; categoryPath is nullable; memoryFacts use same schema as MemoryExtractor with confidence 0-1. Invalid output returns safe fallback (empty tags, null category). |
| T-7.1-05 | Tampering | NoteQA.ask() | medium | mitigate | Flash-tier LLM output parsed for `[Source: Note Title]` citations via regex. Only matches against actual existing note titles — fabricated sources are filtered out. Untrusted LLM output is displayed as ephemeral Bubble (React state), never persisted or executed. Prompt explicitly instructs LLM to answer ONLY from provided notes. |
| T-7.1-06 | Tampering | NoteChatConverter.convert() | medium | mitigate | LLM-generated note draft is pre-filled in NoteEditor for user review per D-13. User is always the gatekeeper — no automatic save. Zod schema validates structure; invalid drafts return empty fallback. Content is plain markdown, rendered by XMarkdown (no HTML injection vector). |
| T-7.1-07 | Information Disclosure | NoteQA → LLM | medium | mitigate | Note snippets sent to LLM are truncated to 500 chars per note. Memory context filtered to score > 0.6. LLM call uses user-configured provider — data leaves the machine to the user's chosen API endpoint. This is an inherent risk of any LLM feature; mitigated by the user's explicit provider configuration and the privacy-first architecture (no NowPilot backend). |
| T-7.1-08 | Denial of Service | Haiku/Flash model unavailability | low | accept | All three services check `models.length === 0` and return fallback silently. No error toasts, no UI disruption. LLM features gracefully degrade. User can still use notes without LLM features. |
</threat_model>
