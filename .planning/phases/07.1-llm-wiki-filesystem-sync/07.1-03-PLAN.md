    **Step A — Create `formatNoteAsMarkdown()` and `parseNoteFromMarkdown()` helper functions:**
    Follow RESEARCH.md Code Examples §4 lines 892-931 exactly.
    - `formatNoteAsMarkdown(note: Note): string` — build YAML frontmatter object with id, created, updated, tags, plus optional categoryPath and summary. Use `stringify(frontmatter, { lineWidth: 0, indent: 2 })` from `yaml`. Return `---\n${yamlStr}---\n\n${note.content}`.

    **Step B — Implement `NoteFileSync` class following class+singleton pattern from NoteGraph.ts:**
    - Imports: `yaml` (stringify/parse), `getDB` from IndexedDBManager, `debugLog`, `Note` from LinkParser, types from noteTypes
    - Class methods:

    **`async setBackupFolder(): Promise<{ folderName: string } | null>`** (SYNC-01):
    - Call `(window as any).showDirectoryPicker({ mode: 'readwrite' })` — requires user gesture context
    - Persist handle to IndexedDB: `const db = await getDB(); await db.put('notes_backup_config', { id: 'primary', folderHandle: handle, folderName: handle.name });`
    - Return `{ folderName: handle.name }` or null if user cancels

    **`async getBackupHandle(): Promise<FileSystemDirectoryHandle | null>`** (SYNC-02):
    - Read from `notes_backup_config`, check permission via `handle.queryPermission({mode:'readwrite'})`
    - If 'granted' → return handle. If 'prompt' → try `requestPermission`, return handle if granted. If 'denied' → return null.
    - Follow RESEARCH.md Code Examples lines 946-958 exactly

    **`async getBackupStatus(): Promise<{ status: SyncStatus; folderName?: string; error?: string }>`** (SYNC-07, SYNC-08):
    - If no stored config → `{ status: 'off' }`
    - If handle but permission denied → `{ status: 'error', error: 'Permission revoked' }`
    - If handle and permission granted → `{ status: 'on', folderName }`

    **`async sync(note: Note, action: 'create' | 'update' | 'delete'): Promise<{ success: boolean; conflict?: boolean }>`** (SYNC-03, SYNC-04, SYNC-05, SYNC-06, SYNC-11):
    - Fire-and-forget per D-09. Returns result but caller should not await.
    - Flow:
      1. Get backup handle → if null, return `{ success: false }` (no-op per SYNC-07)
      2. Resolve directory: split categoryPath by `/`, create nested dirs via `getDirectoryHandle(segment, { create: true })` per CAT-04
      3. Sanitize filename: `note.title.replace(/[\/\\:*?"<>|]/g, '_')` + `.md`
      4. If create: resolve collision → scan existing files for `{safeTitle}.md`, `{safeTitle} (1).md`, etc. per SYNC-05 (RESEARCH.md Pattern 8)
      5. If update: check external change → try `getFileHandle`, compare `file.lastModified` with `note.updated + 2000` tolerance per SYNC-06. If conflict, return `{ success: false, conflict: true }` for caller to show dialog.
      6. Write: `createWritable()` → `write(formatNoteAsMarkdown(note))` → `close()`
      7. If delete: `removeEntry(filename)` → if category folder empty after, remove it via `removeEntry(folderName)`. Parents pruned upward if empty — up to root backup folder (not root itself).
      8. Update `lastSyncTimestamp` in backup config

    **`async importFromFolder(): Promise<{ preview: ImportPreview; notes: Array<Partial<Note>> } | null>`** (SYNC-09, SYNC-10):
    - Call `showDirectoryPicker({ mode: 'readwrite' })` → walk tree recursively
    - For each `.md` file: read via `getFileHandle` → `getFile()` → `text()`, parse with `parseNoteFromMarkdown()`, derive `categoryPath` from file's folder path
    - Compare against existing notes in DB (by id): categorize as new/updated/unchanged
    - Return preview object: `{ total, new, updated, unchanged }` and parsed notes array
    - Actual upsert happens in a separate `executeImport(notes)` method that calls `NotesDB` for each

     **`async executeImport(notes: Array<Partial<Note>>): Promise<{ count: number; allNotes: Note[] }>`** (SYNC-09):
     - For each note: if id exists in DB → updateNote; else → createNote
     - After upserting all notes, read back all notes via `notesDB.getAllNotes()` and return them alongside count
     - Caller MUST rebuild MiniSearch index via `linkParser.rebuildIndex(allNotes)` and recompute backlinks via `linkParser.buildBacklinks()` after import — RESEARCH.md Pitfall 3 explicitly warns against stale indices after import
     - Per spec: import is additive — existing DB notes not in import are NOT deleted

    **Step C — Export singleton:** `export const noteFileSync = new NoteFileSync();`

    **Step D — 50ms debounce for sync (Pitfall 5):**
    - Implement a debounce map: `private pendingSyncs = new Map<string, { note: Note; action: string; timer: ReturnType<typeof setTimeout> }>();`
    - On `sync()` call: clear existing timer for that noteId, set new 50ms timer, flush latest state when timer fires. This ensures trailing-edge behavior — the last save wins, not the first per RESEARCH.md Pitfall 5 fix.

    - Imports: `debugLog`, `Note` from LinkParser, `BacklinkEntry` from LinkParser, `NoteTagger` from NoteTagger (for bulkAnalyze only)

    **Method 1: `detectOrphans(notes: Note[], backlinks: Map<string, BacklinkEntry[]>, allNotes: Note[]): Note[]`:**
    - For each note, check if ANY other note's content contains `[[${note.title}]]` or `[[${note.title}|...]]` (wikilink to this note)
    - AND check if `backlinks.get(note.id)` is empty/undefined (no existing backlinks from LinkParser)

    - Per LLM-WIKI-08: `note.updated > note.summaryGeneratedAt` → stale summary (if summaryGeneratedAt exists)
    - Return two arrays: notes with stale tags, notes with stale summaries

    **Method 3: `getMaintenanceStats(notes: Note[], backlinks: Map<string, BacklinkEntry[]>, allNotes: Note[]): MaintenanceStats`:**

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User gesture → showDirectoryPicker() | User explicitly picks a folder; Chrome enforces that this requires a user gesture and a visible page context |
| App → Filesystem | App writes .md files to user-selected folder; user controls which folder; content is user-owned notes |
| Filesystem → App (import) | .md files read from backup folder; content is parsed as YAML frontmatter + markdown body; untrusted input from filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-7.1-09 | Tampering | File name sanitization in NoteFileSync.sync() | high | mitigate | File names sanitized via `replace(/[\/\\:*?"<>|]/g, '_')` — prevents path traversal via malicious note titles. `getFileHandle` only operates within the picked directory. Category path segments validated by `normalizeCategoryPath()` before use per CAT-05. |
| T-7.1-10 | Spoofing | NoteFileSync.importFromFolder() | medium | mitigate | Import parses ONLY the first `---...---` block as frontmatter (Pitfall 4 mitigation). YAML frontmatter validated for expected types (id: string, tags: string[], etc.). Content is treated as plain text. Import preview modal shows counts before execution per SYNC-10 — user confirms before any DB writes. |
| T-7.1-11 | Information Disclosure | Backup folder contents | low | accept | User explicitly selects the backup folder. Only notes the user has saved are written. No automatic reading of filesystem beyond the picked folder. Import only reads `.md` files — not arbitrary file types. |
| T-7.1-12 | Denial of Service | external change detection race | low | accept | SYNC-06 shows confirm dialog for overwrite — user controls the decision. Default action is Skip. 2-second tolerance window prevents false positives from cloud-sync agents (iCloud, Drive). If dialog is dismissed, sync proceeds without write. |
| T-7.1-13 | Elevation of Privilege | FileSystemDirectoryHandle theft | low | accept | Handle stored in same-origin IndexedDB. Opaque browser object — unusable without corresponding Chrome permission grant. Other extensions cannot access this IndexedDB. Even if handle is extracted, `queryPermission` would return 'denied' for a different origin context. |
</threat_model>
