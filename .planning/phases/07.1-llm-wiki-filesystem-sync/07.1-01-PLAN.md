    Add four optional fields after `tags: string[]`:

    - `tagsGeneratedAt?: number;` — timestamp for staleness detection (per LLM-WIKI-08)

    Also add optional field `export function normalizeCategoryPath(raw: string): string | { error: string }` that implements the category normalization algorithm from RESEARCH.md Architecture Patterns §7: trim whitespace, remove leading/trailing slashes, collapse duplicate slashes, validate each segment is not `.` or `..` or empty.

    In `rebuildIndex()` method (~line 171): add `tags: n.tags, summary: n.summary` to the map.
    In `addToIndex()` method (~line 212): add `tags: note.tags, summary: note.summary` to the add() call.

    **Step C — Bump DB_VERSION and add v4 migration in IndexedDBManager.ts:**
    Change `export const DB_VERSION = 3;` → `export const DB_VERSION = 4;` on line 246.
    Add `notes_backup_config` store to `NowPilotDB` interface (after `notes_concepts`, before `memory_messages`):
    ```
    notes_backup_config: {
      key: string;
      value: {
        id: string;
        folderHandle: FileSystemDirectoryHandle;
        folderName: string;
        lastSyncTimestamp?: number;
        totalNotesBackedUp?: number;
      };
    };
    ```
    Add v4 migration block in the upgrade callback (after the closing `}` of the v3 block at line 301):
    ```
    if (oldVersion < 4) {
      db.createObjectStore('notes_backup_config', { keyPath: 'id' });
    }
    ```
    Per D-08, this store is required because `FileSystemDirectoryHandle` is non-JSON-serializable and cannot go in `chrome.storage.local`. The new `Note` optional fields follow the v2 schemaless pattern — no IndexedDB schema change needed for those (RESEARCH.md §3 line 185 confirms: "new fields are added via put() at runtime with defaults").

    **Step D — Add optional fields and `getNoteByTitle()` to NotesDB.ts:**

    Add `getNoteByTitle(title: string, categoryPath?: string): Promise<Note | undefined>` method. Pattern follows `getNote()` (lines 21-38): `getDB()` → `getAll('notes_notes')` → `.find(n => n.title === title && (!categoryPath || n.categoryPath === categoryPath))` → return with debugLog error handling. Used for SYNC-05 title collision resolution. Linear scan is acceptable (no IndexedDB index for title exists, per RESEARCH.md §2).
