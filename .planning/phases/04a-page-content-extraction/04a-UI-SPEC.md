# Phase 04a — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Summary

Phase 04a (Page Content Extraction) is a **zero-UI core infrastructure phase** (PAGE-01). It builds PageContentService — layered extraction (Defuddle primary → Readability fallback for `default` mode; APC-lite DOM+ARIA walk for `actionable` mode), ephemeral per-tab MiniSearch index, per-tab cache with SPA-nav invalidation, and an extraction-only content script host.

**No user-facing UI is created in this phase.** Per PRODUCT_SPEC §5.6 (canonical), content scripts in v0.1 are extraction-only: they MUST NOT render React/UI, MUST NOT create Shadow DOM roots for UI, MUST NOT inject CSS or `<style>` tags, MUST NOT modify host-page DOM except non-visible read operations (e.g., cloning a node into memory), and MUST NOT write back into host-page fields/editors. Deferred ideas (v2 host-page automation, Shadow DOM widgets, floating UI) are explicitly out of scope per 04a-CONTEXT `<deferred>` — do not design for them.

What this contract **does** govern:

1. **Negative UI contracts** (§5.6) — the hard "never render / never inject / never write-back" rules for the content bundle, enforced by `tests/isolation/no-content-script-ui.test.ts` + `<50KB` bundle-size assertion (D-13, §22.1).
2. **Presentation-neutral data contracts** the extracted content feeds downstream surfaces: `ContextOptimizerInput.pageContext` (Phase 4 D-05/D-18 → AI chat context, surfaced in Phase 7) and per-extraction diagnostics metrics (§4.5, consumed by Phase 6 DiagnosticsPanel).
3. **Standing design system carry-forward** — the Phase 01 contract (status: verified) remains canonical for any rendering of extraction output; this phase introduces zero new tokens, components, or copy.

### Data-Shape State Contract (non-UI — feeds future UI, not UI itself)

For planner/executor use only. These are **interface-level robustness states** on the extraction pipeline — they do NOT create UI states, but downstream surfaces (Phase 7 Chat context, Phase 6 Diagnostics) will render from them. Prescribed behavior:

| State | Condition | Prescribed behavior |
|-------|-----------|---------------------|
| zero-content | Defuddle yields no content / `< ~500 chars` | Fall back to Readability (D-05); record `source` in result |
| error / timeout | parse exception or `>5s` hard cap (§13, §26.6) | Fall back (Defuddle→Readability, AX→DOM); record source; concurrency guard coalesces duplicate per-tab extractions into one in-flight promise (D-11) |
| partial / overflow | extracted tokens exceed 2,000-token webpage budget (§22.2) | Inject only `selectRelevant(query)` results; mark `compressionApplied: 'topk'` (D-09); minimal mode always routes through `selectRelevant` |
| overflow (capture) | serialized HTML exceeds ~2MB size cap (D-01) | Truncate at capture; password-field values omitted at source (`input[type=password]`, `isPassword`, `autocomplete=current-password` heuristic — D-02) |
| redaction | API keys / bearer tokens / emails present in extracted text | TraceRedactor-style redaction before indexing or logging (§4.4/§16, D-12); metrics carry no content payloads |
| populated | successful extraction | `PageContext` shape below; per-tab cache keyed by URL; SPA nav (`wxt:locationchange`) + `tabs.onUpdated` invalidate lazily (D-10) |

**Downstream data contract — `ContextOptimizerInput.pageContext` (Phase 4 D-05, D-18):**

- Phase 4a wires PageContentService output into the optional `pageContext` field (`z.unknown().optional()` in `src/core/context/ContextOptimizer.ts`; serialized as compact JSON into the `[CONTEXT]` PromptSection, `kind: 'context'`, `stable: false`).
- `sourceId` per D-18 format: `context.page.current-url` (logical origin; not a file path).
- Result shape includes: `url`, `title`, `capturedAt`, `size`, `source` (`defuddle` / `readability` / `apc-lite`), markdown and/or APCLiteNode tree, `truncated` flag, `compressionApplied` (`'topk'` when budget-forced).
- No UI rendering, no user-visible state changes, no host-page mutation accompany this handoff — it is a data flow into the AI context pipeline.
