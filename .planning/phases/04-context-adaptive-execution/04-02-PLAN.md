<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| section text → compressor | Untrusted content (page content, tool output, user input) flows through section operations — a bug could corrupt or drop content |
| tool schema refs → trim | The in-scope predicate decides which tool schemas survive — over-trimming removes capability, under-trimming risks oversized prompts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Tampering | ContextCompressor drop/trim | high | mitigate | Section-granularity only (D-04-13): a drop removes a WHOLE section, never a text slice — user_input is never truncated by caps; the CONTEXT_TOO_LARGE honest terminal (04-04) is the only 'lossy' outcome and it surfaces, never silently drops content (P4-10) |
| T-04-07 | Information Disclosure | compressor no-op markers | low | accept | compressionApplied markers carry no content — nothing sensitive leaves the module |
| T-04-08 | DoS | trim-tool-schemas predicate | low | mitigate | The predicate is caller-supplied (optimizer passes the in-scope set); tests pin that non-matching sections drop whole — no partial schema text ever emitted |
| T-04-09 | Elevation of Privilege | ContextPack stability flags | medium | mitigate | stable flags mirror CACHED_KINDS/TASK_KINDS exactly (tested) — a wrong flag could poison the anthropic prompt cache (F-5/P4-8); the drop-in-identity regression in 04-04 re-pins byte-stability |
| T-04-10 | Tampering | npm installs | low | mitigate | No packages installed by this plan (R-9) |
