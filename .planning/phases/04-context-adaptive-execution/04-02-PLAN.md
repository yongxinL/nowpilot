<objective>
Create the TokenEstimator module — a lightweight, stateless service that provides character-based token estimation with CJK detection and a 10% safety margin. Per D-05, this is the pre-flight estimator used before AI calls; no provider-native token counting (those come post-hoc from AI SDK `result.usage`).

Purpose: Give ContextOptimizer a fast, synchronous token counter for budget enforcement without any external dependencies. Separable for independent testing per D-06.
Output: TokenEstimator class + singleton export + comprehensive test file.
</objective>

  <action>
Create `src/core/context/TokenEstimator.ts` with a stateless class and singleton export per D-06 and D-07 (class+singleton pattern):

1. **Module-level CJK_REGEX constant**: `/[\u4e00-\u9fff\u3040-\u309f\u30a0-\u30ff\uac00-\ud7af]/` — covers CJK Unified Ideographs, Hiragana, Katakana, Hangul per RESEARCH.md assumption A2.

2. **TokenEstimator class** — No constructor arguments (stateless). Following PromptCacheManager class structure:
    - **estimateTokens(text: string): number** — Synchronous pure function. **Rationale (per RESEARCH Pitfall 2): Provider-native token counts are only available POST-flight from AI SDK `result.usage` — the ContextOptimizer runs PRE-flight, before any AI call is made, so char-based estimation is the ONLY option for budget enforcement.** Post-hoc provider-native counts are a Phase 6 telemetry concern, not TokenEstimator. Implementation:
     - Count CJK characters via regex match
     - Non-CJK count = text.length - cjkCount
     - Return `Math.ceil(nonCjkCount / 4) + Math.ceil(cjkCount / 3)`
     - Handle edge cases: empty string → 0, whitespace-only → ceil(len/4)
   - **estimateTokensBatch(texts: string[]): number** — Convenience: sums estimateTokens for each string.
   - **applySafetyMargin(estimatedTokens: number): number** — `Math.ceil(estimatedTokens * 1.10)`. Can be a static method or instance method.
   - **isCJK(text: string): boolean** — Returns true if CJK_REGEX tests the text. Used by ContextCompressor for heuristic decisions.

3. **Singleton export**: `export const tokenEstimator = new TokenEstimator();`

4. **debugLog integration** (HARD-09): Edge case logging only — log a warning if estimateTokensBatch is called with >1000 items (potential perf issue). Use `debugLog('warn', '[TokenEstimator] ...')` prefix.

5. **No AI SDK imports, no async, no network calls.** This module is purely computational. If someone later wants provider-native post-hoc counts, that's a separate telemetry concern (Phase 6), not TokenEstimator.
</action>
