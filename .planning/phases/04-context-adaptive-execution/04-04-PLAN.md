<objective>
Create the ContextOptimizer — the central gatekeeper that wraps every AI call with tier-aware token budgets, dynamic section distribution, an 8-step degradation pipeline, and minimal mode for tiny models. Per D-07, it's a class+singleton with constructor DI accepting TokenEstimator, ContextCompressor, and a provider/model lookup. Exposes a single `.optimize()` method returning an `OptimizedContext` with a full provenance manifest per D-10 and D-15.

Purpose: This is the core of Phase 4. Every AI call from AgentOrchestrator must consume an OptimizedContext. The ContextOptimizer ensures no model receives an oversized prompt, applies graceful degradation, and records all decisions in the provenance manifest for diagnostics (Phase 6) and UI inspection (Phase 7).
Output: ContextOptimizer class + singleton + comprehensive test file covering budget, distribution, degradation pipeline, minimal mode, and provenance assembly.
</objective>

Implement the 8-step degradation pipeline as private methods on ContextOptimizer. Per RESEARCH.md Pattern 5, the pipeline is a linear state machine where each step attempts reduction, re-estimates tokens, and proceeds to the next step if still over budget. Steps must be idempotent — after each step, re-estimate and compare to previous; if tokens increased, skip to next step (Pitfall 3).

**applyDegradation(sections, input, tier): Promise<{ sections, provenance }>** — Master method:
```
1. Start with input sections and empty provenance list
2. For each step 1-7:
   a. Apply the step transformation
   b. Re-estimate total tokens
   c. If within budget → return { sections, provenance with degradation entries }
   d. If tokens did NOT decrease (Pitfall 3) → log warning, skip to next step
   e. Record step in provenance
   f. Continue to next step
3. Step 8: Still over budget → throw ContextTooLargeError
```

**Step 1: dropDebugContext(sections)** — Remove sections with kind `'debug_data'`. Record each as `outcome: 'dropped'`, `reason: 'degradation_step_1'`.

**Step 2: dropNotesMetadata(sections)** — Remove sections with kind `'notes_metadata'`. Record as dropped, `reason: 'degradation_step_2'`.

**Step 3: summariseHistory(sections, input, tier)** — Per D-03:
- Find section with kind `'conversation_history'`
- If not found → skip step
- Call `this.compressor.compressHistory(history, tier, input.providerId, input.modelId)`
- Replace section content with compressed result
- Record as `outcome: 'compressed'`, `compressionMethod: tier === 'tiny' || tier === 'small' ? undefined : 'summarise'`, `reason: 'degradation_step_3'`

**Step 4: compressContext(sections, input)** — Per D-03:
- Find section with kind `'page_context'`
- Call `this.compressor.compressContext(section.content)`
- Replace content with compressed result
- Record as `outcome: 'compressed'`, `compressionMethod: 'structural'`, `reason: 'degradation_step_4'`

**Step 5: trimToolSchemas(sections, input)** — Per CTXT-05:
- Find section with kind `'tool_schemas'`
- If `input.selectedToolSchemas` is provided, keep only those schemas; drop the rest
- Record dropped schemas individually
- Record kept schemas as `outcome: 'truncated'`, `reason: 'degradation_step_5'`

**Step 6: reduceMemoryInjection(sections)** — Per CTXT-05:
- Find section with kind `'memory'`
- If memory is an array of scored items, keep only top-5 by score (top-3 if already near budget)
- Drop lower-scored memory items
- Record kept items as `outcome: 'truncated'`, `reason: 'degradation_step_6'`

**Step 7: activateMinimalMode(sections, input)** — Per CTXT-06/D-13:
- Set flag `minimalMode = true` on return
- Compact system_prompt: truncate to 300 estimated tokens
- User memory: keep top-3 only
- Conversation history: truncate to last 1-2 turns, ≤200 token summary
- Tool schemas: `input.selectedToolSchemas` → keep first only per D-13 (drop the rest)
- Notes/metadata: drop all
- Debug data: drop all
- Record all changes as `reason: 'minimal_mode'` or `'degradation_step_7'`

**Step 8: Final check** — After step 7, if still over budget, throw:
```
throw new ContextTooLargeError(estimatedTokens, input.inputBudget);
```
Per D-11, this is a typed error that AgentOrchestrator catches and yields as `{ type: 'context-error', code: 'CONTEXT_TOO_LARGE', ... }`.

**Idempotency guard (Pitfall 3)** — After each step transition, compute `newTokens`. If `newTokens >= previousTokens`, log warning via debugLog and skip to next step (don't loop).
