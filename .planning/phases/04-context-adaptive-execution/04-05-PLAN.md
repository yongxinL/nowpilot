Extend `OrchestratorEvent` in `src/core/ai/pipeline/pipelineTypes.ts` with two new event variants per D-11:

1. **context-degraded event** — emitted for significant degradation and minimal mode activation:
   ```
   | { type: 'context-degraded'; level: 'info' | 'warning'; message: string; step?: number; tier?: ModelContextTier }
   ```
   - `level: 'info'` for: degradation steps 3-6 (history summarization, context compression, tool trimming, memory reduction)
   - `level: 'warning'` for: minimal mode activation (degradation step 7)
   - `step`: the degradation step number (3-7)
   - `tier`: the ModelContextTier at time of degradation
   - `message`: human-readable description (e.g., "Conversation history summarized to fit budget")

2. **context-error event** — emitted for unrecoverable overflow:
   ```
   | { type: 'context-error'; code: 'CONTEXT_TOO_LARGE'; estimatedTokens: number; budget: number; message: string }
   ```
   - `code`: literal `'CONTEXT_TOO_LARGE'`
   - `estimatedTokens` and `budget`: from ContextTooLargeError properties
   - `message`: from the error (includes token counts only, never model/provider IDs per ASVS V7)

3. **Import ModelContextTier type** (import type only) from `../../context/contextTypes`.

4. **Update file documentation** — add a comment above the union noting Phase 4 additions.

**New imports** — Add to file header:
```
import type { OptimizedContext, PromptSection, ModelContextTier } from '../../context/contextTypes';
```

**New method: async *runWithContext(optimizedContext: OptimizedContext): AsyncGenerator<OrchestratorEvent>** per D-01:

1. **Inspect provenance** (before pipeline):
   - Check `optimizedContext.provenance` for degradation
   - If `provenance.degradationSteps` is non-empty and contains steps 3-6: yield `{ type: 'context-degraded', level: 'info', message, step, tier }`
   - If `provenance.minimalMode === true`: yield `{ type: 'context-degraded', level: 'warning', message: 'Minimal mode activated — functionality restricted', tier }`
   - Minor degradation (steps 1-2: debug/notes removal): silent per D-11

2. **Create AbortManager** — Same as `run()` (lines 69-70):
   ```
   const abortManager = new AbortManager();
   this.currentAbortManager = abortManager;
   ```

3. **Extract context sections** — Filter `optimizedContext.sections` into per-stage groups per D-02:
   - **Planner sections** (D-02): `system_prompt`, `task_instructions`, `tool_schemas`, `workspace_context`, `page_context`, `conversation_history`, `user_input`
   - **Renderer sections** (D-02): `system_prompt`, `task_instructions`, `user_input`, `conversation_history`, `tool_results`, `memory`, `page_context`
   - Build `plannerSystemPrompt` by joining system_prompt + task_instructions sections
   - Build `plannerUserMessage` from user_input + workspace_context + page_context + conversation_history
   - Tool schemas are passed as structured data (not strings) — PlannerService's plan() receives them separately

4. **Determine cost tier** — Map `ModelContextTier` to `CostTierType` for the existing Planner/Renderer:
   - `tiny` → `'haiku'`, `small` → `'flash'`, `medium` → `'sonnet'`, `large` → `'opus'`
   - Use `optimizedContext.inputBudget` to influence tier cap (TIER_CAP[tier])

5. **Planner→Executor loop** — Identical to `run()` lines 77-125:
   ```
   while (plannerCalls < tierCap) { ... }
   ```
   But pass section-distributed prompt instead of raw `systemPrompt` + `userMessage` strings.

6. **Renderer stage** — Identical to `run()` lines 127-151. Build messages from userInput + toolResults. Pass section-derived systemPrompt.

7. **Error handling** — Same as `run()` lines 152-162, with one addition:
   - Catch `ContextTooLargeError` specifically: yield `{ type: 'context-error', code: 'CONTEXT_TOO_LARGE', estimatedTokens: err.estimatedTokens, budget: err.budget, message: err.message }`

8. **Shared helper extraction** — Extract the Planner→Executor loop body and Renderer invocation into private methods that both `run()` and `runWithContext()` call:
   - `private async *executePlannerLoop(tier, preferredProviders, systemPrompt, userMessage, abortManager, tierCap): AsyncGenerator<OrchestratorEvent>` — returns toolResults
   - `private async *executeRenderer(tier, preferredProviders, systemPrompt, userMessage, toolResults, abortManager): AsyncGenerator<OrchestratorEvent>`
   - Refactor `run()` to use these helpers (no behavior change)

9. **Preserve run() exactly** — The existing public `run()` method continues to work identically. Its implementation may be refactored to use the new private helpers, but its public contract (params, return type, behavior) is unchanged per D-01.

10. **debugLog** — Use `[AgentOrchestrator]` prefix consistently. Log when runWithContext is called (with operationId), when degradation events are emitted, when CONTEXT_TOO_LARGE is caught.
