<objective>
Establish the two non-negotiable prerequisites the rest of Phase 1 builds on: (1) confirm the git baseline is clean and canonicalize pnpm as the sole package manager (D-23/D-23-note), and (2) land the two migration-safety changes that can otherwise silently corrupt persisted state later in the phase — the theme storage-key move to `chrome.storage.sync` (D-10's persistence half) and the `useExtensionStore` persist `version`/`migrate` scaffold (D-22's versioning half) — both BEFORE any cosmetic/demo-content strip touches the same stores (addendum §0.4/§4, hard sequencing).

Purpose: every later plan in this phase (messaging tracer, manifest/tailwind, demo-content purge, UI wiring) either reads or writes `useExtensionStore`/`ThemeStore`. If schema versioning and the storage-key move land after those stores already have unversioned or wrong-key persisted data, a later commit's `INITIAL_*` empty-out (Plan 01-04) could silently corrupt an in-progress dev profile with no diffable rollback point. Doing this first, in its own green-per-commit plan, makes every later remediation bisectable.

Output: a clean, single-lockfile git baseline; `ThemeStore` persisting `{mode, pack}` to `chrome.storage.sync.np_theme` instead of `chrome.storage.local.np_theme_store`; `useExtensionStore`'s `np_store` persist config carrying `version: 1` + a no-op `migrate`.
</objective>
