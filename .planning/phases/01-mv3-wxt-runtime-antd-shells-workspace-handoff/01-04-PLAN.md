```ts
// src/services/aiProvider.ts
export type ProviderConnectionResult = { ok: true } | { ok: false; error: string };

// Issues the REAL models fetch (via fetchProviderModels) — replaces the always-success setTimeout.
// MUST NOT interpolate apiKey into any log/message/Error string (T-01-10).
export async function testProviderConnection(
  providerId: ProviderId,
  apiKey?: string,
  proxyUrl?: string,
): Promise<ProviderConnectionResult>;
```

### Ordered implementation steps
1. **`testProviderConnection`:** call the existing real `fetchProviderModels(providerId, apiKey, proxyUrl)` (or the equivalent models endpoint). On a resolved `resp.ok`/non-empty model list → `return { ok: true }`. ### Ordered implementation steps
1. Add `STORAGE_DEBOUNCE_MS = 300` and a module-level `pending: Map<string,string>` + a single `timer` handle.
2. Rewrite `setItem(name, value)`: store `pending.set(name, value)`; (re)start a trailing timer of `STORAGE_DEBOUNCE_MS`; on fire, `chrome.storage.<area>.set(Object.fromEntries(pending)); pending.clear();`. Leave `getItem` and `removeItem` synchronous/immediate (no debounce).
3. Add `flushPendingWrites()`: clear the timer and immediately write+clear `pending`.

### Edge / error behavior
- **Overflow / rapid writes:** many `setItem` calls within 300 ms collapse to one `chrome.storage.set` (write-rate ≤ 30/min steady state).
- **Crash residual (T-01-12):** a hard browser crash before the trailing timer fires can lose the final ≤300 ms of writes — accepted residual risk; the flush handlers cover normal unload/hide.
- **Migration:** version-less WorkspaceStore blob hydrates via `migrate()` without throwing.

### Async ownership: cancellation / cleanup / retry / idempotency / race
- **Cancellation/cleanup:** each new `setItem` resets the single timer; `flushPendingWrites` cancels it.
- **Idempotency:** re-writing the same key coalesces to last-value-wins in `pending`.
- **Race:** `flush` during a scheduled write is safe (clears pending atomically in the JS single thread). `getItem` never returns a stale value it just debounced for its own key? — reads go to `chrome.storage` which may lag by ≤300 ms; document that persisted reads are eventually-consistent within the debounce window (Zustand keeps the in-memory state authoritative, so UI is not affected).
