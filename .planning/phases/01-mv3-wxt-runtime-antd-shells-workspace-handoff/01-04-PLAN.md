<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider connection test -> user-entered API key | testProviderConnection sends the raw key to a real external endpoint; must never echo it back into a logged error string |
| chromeStorageAdapter debounce -> chrome.storage.local | A buggy flush could drop the last few hundred ms of state on tab close if beforeunload/visibilitychange both fail to fire (rare but possible during a forced SW/tab kill) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Information Disclosure | testProviderConnection error messages | high | mitigate | Error strings are built from `resp.status`/`errorData.error?.message` (server-provided text), never from interpolating the raw `apiKey` parameter itself; Task 2's acceptance criteria include a grep-checkable assertion that no `apiKey` variable appears inside a template literal passed to `console.*`/`antMessage.*`/`Error()` in the modified functions |
| T-01-11 | Tampering | simulateStreamResponse silent-fallback removal | high | mitigate | Real fetch failures now call onError with the real message instead of masking them — this is the entire point of D-12; regression-tested by Task 2's behavior tests |
| T-01-12 | Denial of Service | chromeStorageAdapter debounce losing the final write on abrupt termination | medium | mitigate | beforeunload + visibilitychange dual-flush; write-rate test proves steady-state behavior, though a hard browser crash (not a normal close) remains an accepted residual risk consistent with chrome.storage's own documented guarantees |

</threat_model>
