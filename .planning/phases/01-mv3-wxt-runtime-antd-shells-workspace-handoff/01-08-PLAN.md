### Ordered implementation steps
1. **Re-grep (VAI-08):** confirm the `OnboardingWizard` import + mount in `SidepanelChat.tsx` and the `onboardingComplete` read/write.
2. Build `OnboardingModal` as a 4-step AntD `Modal` with internal `step` state (`1..4`). Local state: `providerId`, `apiKey`, `proxyUrl?`, `status: 'idle'|'testing'|'ok'|'error'`, `errorText?`.
3. **Step navigation (D-02):** advance ONLY via an explicit `Next` button (Steps 1→2→3) or a successful test (Step 4). NO `setTimeout`/timer-driven advance anywhere.
4. **Step 4 validation (D-03):** `Connect Provider` sets `status='testing'` (shows "Testing connection…"), calls `const r = await testProviderConnection(providerId, apiKey, proxyUrl)`:
   - `r.ok` → `status='ok'` (show "Connected"), then `onComplete()`.
   - `!r.ok` → `status='error'`, `errorText=r.error`, render `Connection failed: ${r.error}`, keep the modal open, show ghost `Edit key` → back to Step 3. Do NOT treat failure as success.
5. **Skip:** `Skip for now` calls `onSkip()` (leaves `onboardingComplete=false`).
6. **Mount (auto-open on fresh install):** in `SidepanelChat.tsx`, replace the `OnboardingWizard` mount with `<OnboardingModal open={onboardingComplete === false} onComplete={...} onSkip={...} />`. Because the Chat surface renders in both the Side Panel and the Standalone-embedded view, this single mount covers both.
7. `git rm src/components/common/OnboardingWizard.tsx` and remove its imports.

### Edge / empty / error / loading / disabled behavior
- **Loading:** Step 4 disables `Connect Provider` while `status==='testing'` and shows "Testing connection…".
- **Error:** modal stays open; `Connection failed: [error]` + `Edit key`; retry is allowed.
- **Empty:** `Next` on Step 3 is disabled until `apiKey` is non-empty (no blank-key submit).
- **Disabled:** during `testing`, primary CTA disabled to prevent double-submit.
- **Backdrop:** mask click does not dismiss (mask closable false) — user must complete or explicitly Skip.

### Async ownership: cancellation / cleanup / retry / idempotency / race
- **Race/double-submit:** guard `Connect Provider` against re-entry while `status==='testing'`.
- **Unmount during test:** if the modal unmounts mid-test, ignore the resolved result (mounted-ref guard) — no `setState` after unmount.
- **Retry:** `Edit key` → Step 3 → `Connect Provider` again is idempotent (fresh `testProviderConnection`).
- **Security (T-01-22):** `apiKey` is held only in component state; on `onComplete`/`onSkip`/unmount it is dropped. It is NEVER passed to `console.*`, `debugLog`, or interpolated into any string other than the provider request (the `[error]` message contains the provider's error text, never the key).

- `{ok:true}` → shows "Connected" then calls `onComplete`.
- **Key-leak guard:** spy on `console.*`/`debugLog`; assert no argument contains the entered apiKey value.

- **BLOCKING human 4-point pass:** fresh install → modal auto-opens; complete a real provider → "Connected" and modal closes; failure path shows the real error and stays open; Skip leaves the extension usable with onboarding still pending.
