<decisions>
## Implementation Decisions

### @mention Syntax & Unified Reference System (RICH-H-15)
- **D-01 — Unified Reference System with three initial entity types:** @note (NotesDB), @tab (workspaceStore pinned tabs), @prompt (PromptManager templates). Mentions render as styled inline chips within the Sender, use a shared autocomplete experience, and inject referenced resources into AI context via ReferenceToken[] rather than expanding into raw text. Establishes a scalable foundation for future types (@conversation, @memory, @persona).
- **D-02 — Styled inline chips with type-specific treatment:** Each mention type gets a subtle icon and color. Chips behave as atomic objects (backspace removes the whole chip). Clear visual distinction between ordinary text and referenced resources.
- **D-03 — Unified autocomplete popover:** Typing `@` opens a single popover mixing all reference types. Each result includes a type-specific icon and color. Filter by title across all types. No separate per-type prefixes required during search.
- **D-04 — Structured ReferenceToken[] in ContextOptimizerInput:** On send, message payload includes both user text and ReferenceToken[]. ContextOptimizer resolves referenced resources (NotesDB, workspaceStore, PromptManager) and applies context-budget rules. AI pipeline only receives optimized context, never raw mention syntax.
- **D-05 — Minimal ReferenceToken model:** Fields: type, id, title, displayLabel. Token acts as a stable pointer — ContextOptimizer is responsible for content resolution and budget allocation. No content/summaries stored in the token.
- **D-06 — Stale reference handling:** If a referenced resource is deleted, the chip stays visible but switches to a disabled/greyed-out state. ContextOptimizer silently skips unresolvable references at send time. No toasts or blocking errors.
- **D-07 — Factory + registry pattern for extensibility:** ReferenceResolver interface with per-type registrations: autocomplete results, validation, stale-reference checks, context resolution. Adding @conversation or @memory = register a new resolver. No switch/case in core mention logic.

### Persona Editor (RICH-R-04)
- **D-08 — Three preference overrides, no full profile editing:** Expose AI Name (text), Tone (presets), Response Brevity (presets) in a new Options → Persona section. Full PersonaProfile fields (identity, values, emotional-awareness rules, communication principles) remain owned by DEFAULT_PERSONA_PROFILE and are not user-editable.
- **D-09 — Two-tone switch:** Professional / Professional + Approachable. Replace free-text aiTone in PreferenceMemoryStore with a typed enum. Each tone displayed as radio cards with a short preview example.
- **D-10 — Three brevity levels:** Concise / Balanced / Detailed. Balanced = default. Update PreferenceMemoryStore enum from `concise | detailed` to `concise | balanced | detailed`. Displayed as segmented controls with example previews.
- **D-11 — New top-level Options section:** Options → Persona as its own navigation entry (alongside General, Sidebar, Prompts, Slash, MCP, Notes, Addons, Advanced). Three cards: AI Name, Tone, Response Brevity. Changes saved via PreferenceMemoryStore and applied through existing PersonaService.applyOverrides().
- **D-12 — Preview example per setting:** Each setting card includes a small preview showing how a sample response changes based on the selected option. No raw persona prompts or profile internals exposed.

### Voice Input (RICH-H-17)
- **D-13 — Toggle recording mode:** Tap to start, tap to stop. Better for longer dictation than push-to-talk. Uses Web Speech API (SpeechRecognition).
- **D-14 — Conditional button visibility:** Microphone button appears in Sender toolbar only when browser supports Web Speech API. Alongside existing Templates and Attach buttons.
- **D-15 — Insert at cursor:** Transcribed text inserted at current cursor position in the Sender. Preserves existing draft. Users mix typed and dictated text naturally.
- **D-16 — Interim + final results:** Show interim speech-recognition results as visually distinct grey placeholder text while recording. Final transcript replaces interim text when recording stops. Real-time feedback builds trust.

### TL;DR Toggle (RICH-H-18)
- **D-17 — Hard 500-character threshold:** Any assistant response > 500 chars gets a TL;DR toggle. Configurable constant (TLDR_THRESHOLD). Purely presentational — no AI or pipeline changes.
- **D-18 — First sentences as preview:** Collapsed state shows first 1-2 meaningful sentences (~150-250 chars). "Show More" expands to full response; "Show Less" collapses back. No AI-generated summary — zero additional cost.

### Step Checklists (RICH-H-19)
- **D-19 — Auto-detect ordered lists:** Ordered lists (1., 2., 3.) and markdown numbered steps with 2+ actionable items automatically render as interactive ChecklistCardGroup. No special AI output format needed.
- **D-20 — Session-only check state:** Checkbox state maintained in local component state keyed by messageId. Reset when conversation reloads. Checklist state is a temporary reading aid, not persistent task management. Original markdown unchanged in storage.

### Educational Tips (RICH-I-12, I-13, I-14)
- **D-21 — Inline banner above Sender:** Tips render as small, dismissible banners between conversation area and Sender. Non-intrusive, contextual. Not toasts or tooltips.
- **D-22 — Dedicated chrome.storage.local key:** Tip state tracked under `np_edu_tips` (separate from PreferenceMemoryStore). Tracks message counts, session counts, and per-tip dismissal states. Behavioral telemetry, not user preferences.
- **D-23 — Three tips for Phase 7.5:** (1) `/` slash command hint after 3 messages without using slash commands; (2) Agent mode hint after 3 completed conversations without switching to Agent mode; (3) @mention discovery tip after reference system release if user hasn't used @note/@tab/@prompt.

### Conversation Feedback & Saving (RICH-C-10, C-11)
- **D-24 — Feedback persisted to memory:** Conversation feedback (thumbs up/down) stored in MemoryStore as conversation-level telemetry. Anonymized, used for quality tracking. Replaces current console.log-only implementation.
- **D-25 — Save as Note (primary) + Export as File (secondary):** Save action appears in ConversationClosure zone alongside feedback controls when conversation has ≥3 exchanges. Primary: saves full conversation as a note (title + AI-generated summary + full markdown transcript). Secondary: export as Markdown (.md) and JSON (.json) formats.
- **D-26 — Auto-save then open NoteEditor:** One-click save creates the note immediately and opens NoteEditor pre-filled for review. User refines title, summary, or transcript before confirming. Non-blocking — conversation stays open.
- **D-27 — Marked as saved with bidirectional link:** Saved conversations show a bookmark icon in the conversation list. Note links back to source conversation for cross-reference.

### Prompt Starter Unification
- **D-28 — Shared PromptStarter model, separate generation logic:** Welcome Cards, Template Browser, Quick Actions, and Follow-up Suggestions share a common PromptStarter model, category taxonomy (Writing, Analysis, Research, Coding, Support), and ranking signals. Each surface retains independent generation logic.
- **D-29 — Extract from existing sources, don't create new registry:** PromptManager remains source of truth for templates. QuickActionService owns page-context actions. PromptStarterService provides shared recency tracking, usage analytics, and category normalization consumed by all surfaces.
- **D-30 — Dedicated usage store:** PromptStarterUsageStore (np_prompt_usage in chrome.storage.local) tracks usageCount, lastUsedAt, firstUsedAt, and source per promptStarterId. Separate from UserMemoryStore — application analytics, not user memories.

### Memory Visibility & Explainability
- **D-31 — Options → Advanced → Memory section:** Three tabs: (1) User Memory — facts with Confirm/Reject/Delete actions; (2) Conversation Memory — summaries with expand/collapse and delete; (3) Preferences — read-only with links to settings pages.
- **D-32 — Show all facts with confidence indicators:** All memories visible regardless of confidence. Visual indicators: 🟢 High (>0.7), 🟡 Medium (0.4-0.7), 🔴 Low (<0.4). Filtering controls (All / High Confidence / User Confirmed / Inferred). Transparency over filtering.
- **D-33 — Confirm/Reject + Delete actions, no inline editing:** Confirm boosts confidence and marks as user-verified. Reject removes from future use. Delete permanently removes. No freeform editing — memories are evidence-based, not manually editable. UserMemoryStore supports states: inferred, confirmed, rejected.
- **D-34 — Conversation summaries: compact cards with expansion + delete:** Each summary shows title/topic, key outcome, dates. Expandable to full summary text. Delete per-summary and Clear All. Read-only content, user-owned lifecycle.

### Multi-Modal Attachment Strategy
- **D-35 — Unified Attachment model:** Single typed abstraction for images, files, voice transcripts, pasted content. Establishes one ingestion pipeline for all non-message Sender content. Foundation for provider-specific multi-modal routing in future work.
- **D-36 — All content types supported:** Images (pasted, dragged, screenshots), files (documents, code), voice transcripts (from voice input), clipboard text excerpts. Each type has distinct processing but enters through the same pipeline.
- **D-37 — Structured attachments in ContextOptimizerInput:** Attachments flow as structured objects, not pre-converted to text. ContextOptimizer decides budget allocation per attachment type and content. Preserves full multi-modal capability for vision-capable providers.

<specifics>
## Specific Ideas

- Mention chips follow Slack/Notion style: colored inline tokens with icon, backspace deletes whole chip
- Voice input toggle with recording indicator — tap on/off, interim text shown in lighter color
- TL;DR collapsed preview extracts first 1-2 sentences deterministically — no AI summarization
- Checklist cards reuse ActionChipGroup styling with checkbox prefix
- Persona editor preview cards show a simulated AI response based on selected tone/brevity
- Memory browser uses antd Table or Card list with confidence badges
- PromptStarter model added to existing types, not a separate module
- Save conversation reuses SaveToNoteDialog pattern but auto-creates note first
- Educational tip banner uses BrandedHeader styling as reference for inline banner design
</specifics>
