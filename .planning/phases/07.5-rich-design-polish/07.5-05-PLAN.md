<objective>
Build six UI components that enhance the Sender input area: @mention autocomplete popover (adapted from WikilinkAutocomplete), styled inline mention chips in the Sender, voice input toggle button, educational tip banners, and QuickActionChips "More" overflow expander.

**Purpose:** These components together transform the Sender from a plain text input into a rich composition surface — referencing notes/tabs/prompts with visual chips, dictating via voice, receiving progressive educational tips, and browsing all quick actions. All components consume the data layer built in Wave 1 (Plans 02-03).

**Output:** Six React components (5 new, 1 modified) ready for ChatPage integration in Wave 3.
</objective>

    **Step A — Create `MentionAutocomplete.tsx` (D-03):**
    Adapt `WikilinkAutocomplete.tsx` (203 lines, identical interaction model):
    - **Trigger detection:** Scan Sender textarea value before cursor for `@` character. Use `onChange` handler on the Sender's value to detect `@` followed by query text (non-whitespace characters). Extract `query` = text between `@` and next whitespace/end-of-string. Use `useMemo` for trigger position calculation.
    - **Data source:** Call `referenceResolver.search(query)` (from Plan 02) instead of `linkParser.search()`. Results are `AutocompleteResult[]` with `token`, `icon`, `color`, `subtitle`.
    - **Keyboard navigation:** ArrowUp/ArrowDown for item selection, Enter/Tab to select, Escape to close. Ctrl/Cmd+Enter should NOT trigger selection (reserved for Sender submit). Follow WikilinkAutocomplete `handleKeyDown` pattern (L88-109).
    - **Click-outside:** `mousedown` listener on `document` with `containerRef.contains()` check (follow L112-120).
    - **Dropdown positioning:** Absolute-positioned popover below cursor, `maxHeight: 300`, `overflowY: 'auto'`, `zIndex: 1050` (follow L140-156).
    - **Results rendering:** Each item shows icon (antd `@ant-design/icons` dynamic component — use a simple lookup table mapping icon strings to components), title (bold), subtitle (secondary, truncated), and type badge. Highlight `selectedIndex` with `colorPrimary` background.
    - **Selection handler:** On select, (1) replace `@query` text in textarea with `@type:title` plain text, (2) add `ReferenceToken` to `mentionTokens` array in parent state, (3) close popover.
    - Props: `value: string` (current Sender text), `onSelect: (token: ReferenceToken, replacement: string) => void`, `cursorPosition?: number`.

    - Render: antd `Tag` with `closable={!stale}`, `icon={iconComponent}`. Background: `${color}18` (10% opacity per UI-SPEC). Border: `${color}40`. Text: `token.displayLabel`. Stale state: opacity 0.5, grey tones, no close button.
    - Type-specific colors per UI-SPEC: note → `colorPrimary` tint, tab → `colorInfo` tint, prompt → `colorSuccess` tint.

    **Step C — Create `SenderMentionChips.tsx` (D-02):**
    Container for rendering mention chips in the Sender `header` slot:
    - Props: `tokens: ReferenceToken[]`, `onRemoveToken: (tokenId: string) => void`.
    - Render: antd `Flex` (gap: 4, wrap: 'wrap') of `MentionChip` components.
    - This component renders in the `header` prop of antd Sender, alongside `attachmentHeader` (D-01: chips are visual indicators, not in textarea — Pitfall 2).

    **Step D — Backspace behavior (D-02):**
    The Sender's `onChange` handler in ChatPage detects when the textarea value loses a `@type:title` pattern (user pressed backspace on chip text). Implement in the parent (ChatPage) — mention chip removal logic: scan textarea for `@(note|tab|prompt):([^\s]+)` patterns; if a previously-present pattern is gone, remove corresponding token from `mentionTokens` state. This is parent-level logic, not in MentionAutocomplete — noted here as dependency for Wave 3 integration.
