<objective>
Build the Unified Reference System core — a factory-pattern registry with three initial resolver implementations (@note, @tab, @prompt) that enable @mention syntax in the Sender. Establishes a scalable foundation for future reference types per D-01/D-05/D-07.

**Purpose:** The reference system is the data backbone for @mention autocomplete (RICH-H-15). All three resolvers query existing stores (NotesDB, workspaceStore, PromptManager) — no new storage or APIs needed. The registry pattern ensures future types (@conversation, @memory) can be added without modifying core logic.

**Output:** ReferenceToken minimal type, ReferenceResolver interface, singleton registry, and three resolver implementations.
</objective>

    **Step A — Create `ReferenceToken.ts`:**
    Per D-05, a minimal model with exactly four fields:
    ```
    export interface ReferenceToken {
      type: string;       // 'note' | 'tab' | 'prompt'
      id: string;         // stable identifier (NotesDB id, tab id, PromptManager template id)
      title: string;      // user-facing title for display
      displayLabel: string; // formatted label, e.g. '@note:My Note'
    }
    ```

    **Step B — Create `ReferenceResolver.ts` interface:**
    Per D-07, define the `ReferenceResolver` interface with four methods:
    - `search(query: string): Promise<AutocompleteResult[]>` — returns matching items for autocomplete. Each `AutocompleteResult` includes `token: ReferenceToken` plus `icon`, `color`, `subtitle?`.
    - `validate(token: ReferenceToken): Promise<{ valid: boolean; reason?: string }>` — staleness check per D-06. Returns `{ valid: false }` if resource was deleted.
    - `resolve(token: ReferenceToken): Promise<{ title: string; content: string; metadata?: Record<string, unknown> } | null>` — resolves content for ContextOptimizer. Returns null if unresolvable (D-06: silent skip).
    - `getType(): string` — returns the type string this resolver handles.

    Export `AutocompleteResult` type:
    ```
    export interface AutocompleteResult {
      token: ReferenceToken;
      icon: string;          // antd icon component name for rendering
      color: string;         // CSS color for chip tinting
      subtitle?: string;     // e.g., note preview snippet, prompt category
    }
    ```

    **Step C — Create `referenceResolver.ts` singleton registry:**
    Class `ReferenceResolverRegistry` with private `#resolvers: Map<string, ReferenceResolver>`.
    - `register(type: string, resolver: ReferenceResolver): void` — throws on duplicate type
    - `unregister(type: string): boolean`
    - `search(query: string): Promise<AutocompleteResult[]>` — calls `search()` on all registered resolvers, flattens results. Returns results from all types mixed together (D-03: unified popover).
    - `validate(token: ReferenceToken): Promise<{ valid: boolean; reason?: string }>` — delegates to `resolverMap.get(token.type)?.validate(token)`. Unknown type → `{ valid: false }`.
    - `resolve(token: ReferenceToken): Promise<... | null>` — delegates to resolver, returns null for unknown types.
    - `getTypes(): string[]` — returns all registered type keys.
    - `getResolverType(type: string): ReferenceResolver | undefined`

    Export singleton `referenceResolver`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NotesDB → NoteResolver | Note titles/content are user-controlled — must escape when rendering in autocomplete popover (React Text handles this) |
| workspacestore → TabResolver | Tab titles/URLs originate from browser pages — URL could contain XSS payloads (React Text auto-escapes) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.5-03 | Spoofing | referenceResolver.resolve() | medium | mitigate | resolve() returns null for stale/deleted resources; ContextOptimizer silently skips null results (D-06); no fallback to potentially-stale content |
| T-07.5-04 | Information Disclosure | NoteResolver.resolve() | low | accept | Resolving note content sends it to AI pipeline — same trust model as existing Notes Q&A; user explicitly @mentions the resource |
| T-07.5-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages; existing deps audited |
</threat_model>
