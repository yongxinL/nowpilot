# Phase 07.5: RICH Design Polish - Research

**Researched:** 2026-07-19
**Domain:** UI polish / UX enhancement for AI chat interface (Chrome Extension)
**Confidence:** HIGH

## Summary

Phase 07.5 polishes the RICH experience with 21 P2 nice-to-have enhancements spanning 7 major feature areas: persona editor, @mention syntax (Unified Reference System), voice input, TL;DR toggle, step checklists, educational tips, and enhanced markdown rendering — plus secondary areas: conversation feedback persistence, saved conversations, prompt starter unification, memory visibility browser, and multi-modal attachment model. All features extend existing Ant Design X 2.8.0 Sender/Bubble/XMarkdown components and Zustand stores established in Phases 7.3-7.4. No new npm packages are required — every feature uses components and APIs already in the project's dependency tree (antd 6.5.1, @ant-design/x 2.8.0, zustand 5.0.14, motion 12.42.2, zod 4.4.3).

**Primary recommendation:** Build each feature as an independent component or service module integrated into existing ChatPage Sender/Bubble pipeline. Adapt the WikilinkAutocomplete pattern (`src/components/notes/WikilinkAutocomplete.tsx`, 203 lines) for @mention autocomplete — change trigger from `[[` to `@`, swap data source from LinkParser to ReferenceResolver registry, render type-specific icons/colors. Use custom `useVoiceInput` hook wrapping Web Speech API with Sender's `prefix` slot for the microphone button (Sender's built-in `allowSpeech` is push-to-talk, not toggle — Context7 confirmed SpeechConfig.recording disables built-in for custom implementations). Use Zustand `persist` middleware `migrate` function for PreferenceMemoryStore enum changes (adding `'balanced'` to responseBrevity, migrating free-text aiTone to typed enum). All new stores (EduTipsStore, PromptStarterUsageStore) follow the RightPaneStore pattern (`src/core/stores/RightPaneStore.ts`, 62 lines): Zustand `create` + `persist` + `createJSONStorage(chrome.storage.local)` + `np_` key prefix + `partialize` for transient fields.

## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01 — Unified Reference System with three initial entity types:** @note (NotesDB), @tab (workspaceStore pinned tabs), @prompt (PromptManager templates). Mentions render as styled inline chips within the Sender, use a shared autocomplete experience, and inject referenced resources into AI context via ReferenceToken[] rather than expanding into raw text. Establishes a scalable foundation for future types.
- **D-02 — Styled inline chips with type-specific treatment:** Each mention type gets a subtle icon and color. Chips behave as atomic objects (backspace removes the whole chip). Clear visual distinction between ordinary text and referenced resources.
- **D-03 — Unified autocomplete popover:** Typing `@` opens a single popover mixing all reference types. Each result includes a type-specific icon and color. Filter by title across all types. No separate per-type prefixes required during search.
- **D-04 — Structured ReferenceToken[] in ContextOptimizerInput:** On send, message payload includes both user text and ReferenceToken[]. ContextOptimizer resolves referenced resources (NotesDB, workspaceStore, PromptManager) and applies context-budget rules. AI pipeline only receives optimized context, never raw mention syntax.
- **D-05 — Minimal ReferenceToken model:** Fields: type, id, title, displayLabel. Token acts as a stable pointer — ContextOptimizer is responsible for content resolution and budget allocation. No content/summaries stored in the token.
- **D-06 — Stale reference handling:** If a referenced resource is deleted, the chip stays visible but switches to a disabled/greyed-out state. ContextOptimizer silently skips unresolvable references at send time. No toasts or blocking errors.
- **D-07 — Factory + registry pattern for extensibility:** ReferenceResolver interface with per-type registrations: autocomplete results, validation, stale-reference checks, context resolution. Adding @conversation or @memory = register a new resolver. No switch/case in core mention logic.
- **D-08 — Three preference overrides only:** Expose AI Name (text), Tone (presets), Response Brevity (presets) in Options → Persona. Full PersonaProfile fields (identity, values, emotional-awareness rules, communication principles) remain owned by DEFAULT_PERSONA_PROFILE and are not user-editable.
- **D-09 — Two-tone switch:** Professional / Professional + Approachable. Replace free-text aiTone in PreferenceMemoryStore with a typed enum. Each tone displayed as radio cards with a short preview example.
- **D-10 — Three brevity levels:** Concise / Balanced / Detailed. Balanced = default. Update PreferenceMemoryStore enum from `'concise' | 'detailed'` to `'concise' | 'balanced' | 'detailed'`. Displayed as segmented controls with example previews.
- **D-11 — New top-level Options section:** Options → Persona as its own navigation entry (alongside General, Sidebar, Prompts, Slash, MCP, Notes, Addons, Advanced). Three cards: AI Name, Tone, Response Brevity. Changes saved via PreferenceMemoryStore and applied through existing PersonaService.applyOverrides().
- **D-12 — Preview example per setting:** Each setting card includes a small preview showing how a sample response changes based on the selected option. No raw persona prompts or profile internals exposed.
- **D-13 — Toggle recording mode:** Tap to start, tap to stop. Better for longer dictation than push-to-talk. Uses Web Speech API (SpeechRecognition).
- **D-14 — Conditional button visibility:** Microphone button appears in Sender toolbar only when browser supports Web Speech API. Alongside existing Templates and Attach buttons.
- **D-15 — Insert at cursor:** Transcribed text inserted at current cursor position in the Sender. Preserves existing draft. Users mix typed and dictated text naturally.
- **D-16 — Interim + final results:** Show interim speech-recognition results as visually distinct grey placeholder text while recording. Final transcript replaces interim text when recording stops.
- **D-17 — Hard 500-character threshold:** Any assistant response > 500 chars gets a TL;DR toggle. Configurable constant (TLDR_THRESHOLD). Purely presentational — no AI or pipeline changes.
- **D-18 — First sentences as preview:** Collapsed state shows first 1-2 meaningful sentences (~150-250 chars). "Show More" expands to full response; "Show Less" collapses back. No AI-generated summary — zero additional cost.
- **D-19 — Auto-detect ordered lists:** Ordered lists (1., 2., 3.) and markdown numbered steps with 2+ actionable items automatically render as interactive ChecklistCardGroup. No special AI output format needed.
- **D-20 — Session-only check state:** Checkbox state maintained in local component state keyed by messageId. Reset when conversation reloads. Original markdown unchanged in storage.
- **D-21 — Inline banner above Sender:** Tips render as small, dismissible banners between conversation area and Sender. Non-intrusive, contextual. Not toasts or tooltips.
- **D-22 — Dedicated chrome.storage.local key:** Tip state tracked under `np_edu_tips` (separate from PreferenceMemoryStore). Tracks message counts, session counts, and per-tip dismissal states.
- **D-23 — Three tips for Phase 7.5:** (1) `/` slash command hint after 3 messages without using slash commands; (2) Agent mode hint after 3 completed conversations without switching to Agent mode; (3) @mention discovery tip after reference system release if user hasn't used @note/@tab/@prompt.
- **D-24 — Feedback persisted to memory:** Conversation feedback (thumbs up/down) stored in MemoryStore as conversation-level telemetry. Replaces current console.log-only implementation.
- **D-25 — Save as Note (primary) + Export as File (secondary):** Save action in ConversationClosure zone when ≥3 exchanges. Primary: saves full conversation as a note (title + AI-generated summary + full markdown transcript). Secondary: export as Markdown (.md) and JSON (.json).
- **D-26 — Auto-save then open NoteEditor:** One-click save creates the note immediately and opens NoteEditor pre-filled for review. Non-blocking — conversation stays open.
- **D-27 — Marked as saved with bidirectional link:** Saved conversations show a bookmark icon in the conversation list. Note links back to source conversation.
- **D-28 — Shared PromptStarter model, separate generation logic:** Welcome Cards, Template Browser, Quick Actions, and Follow-up Suggestions share a common PromptStarter model, category taxonomy (Writing, Analysis, Research, Coding, Support), and ranking signals. Each surface retains independent generation logic.
- **D-29 — Extract from existing sources, don't create new registry:** PromptManager remains source of truth for templates. QuickActionService owns page-context actions. PromptStarterService provides shared recency tracking, usage analytics, and category normalization.
- **D-30 — Dedicated usage store:** PromptStarterUsageStore (`np_prompt_usage` in chrome.storage.local) tracks usageCount, lastUsedAt, firstUsedAt, and source per promptStarterId. Separate from UserMemoryStore.
- **D-31 — Options → Advanced → Memory section:** Three tabs: (1) User Memory — facts with Confirm/Reject/Delete actions; (2) Conversation Memory — summaries with expand/collapse and delete; (3) Preferences — read-only with links to settings pages.
- **D-32 — Show all facts with confidence indicators:** All memories visible regardless of confidence. Visual indicators: 🟢 High (>0.7), 🟡 Medium (0.4-0.7), 🔴 Low (<0.4). Filtering controls (All / High Confidence / User Confirmed / Inferred).
- **D-33 — Confirm/Reject + Delete, no inline editing:** Confirm boosts confidence and marks as user-verified. Reject removes from future use. Delete permanently removes. UserMemoryStore supports states: inferred, confirmed, rejected.
- **D-34 — Conversation summaries: compact cards with expansion + delete:** Each summary shows title/topic, key outcome, dates. Expandable. Per-summary delete + Clear All.
- **D-35 — Unified Attachment model:** Single typed abstraction for images, files, voice transcripts, pasted content. Establishes one ingestion pipeline for all non-message Sender content.
- **D-36 — All content types supported:** Images (pasted, dragged, screenshots), files (documents, code), voice transcripts (from voice input), clipboard text excerpts. Each type has distinct processing but enters through the same pipeline.
- **D-37 — Structured attachments in ContextOptimizerInput:** Attachments flow as structured objects, not pre-converted to text. ContextOptimizer decides budget allocation per attachment type and content.

### Anti-Patterns to Avoid
- **ContentEditable for mention chips:** Don't use contentEditable divs for the Sender input. The Sender uses a textarea internally (antd \@ant-design/x). Mention chips MUST render in the `header` slot as visual indicators, with plain text `@type:title` in the textarea value. Attempting contentEditable would break the controlled input model and cause state desync (Pitfall 2).
- **New prompt template registry:** Don't create a second template registry for PromptStarter unification. PromptManager is the single source of truth (D-29). PromptStarterService adds metadata/categories/usage tracking on top of existing template IDs.
- **Storing checklist state beyond session:** Don't persist checklist state to storage. D-20 explicitly scopes this to session-only (local component state keyed by messageId). Persisting would create stale state on reload.
- **TL;DR toggle during streaming:** Don't render TL;DR toggle while `item.streaming === true`. Character count crosses threshold mid-stream, causing premature collapse. Only show toggle after streaming completes (Pitfall 5).
- **Inline `components` object in XMarkdown:** Don't define `components={{ ol: ChecklistCardGroup }}` inline in JSX. Creates new object reference every render, causing re-mount of all custom renderers and breaking streaming state. Use module-level constant or `useMemo` (Pitfall 4).

## Common Pitfalls

### Pitfall 1: Web Speech API Not Available in Content Scripts
**What goes wrong:** Attempting to access `SpeechRecognition` from a content script or background service worker fails because it requires a secure context and window object.
**Why it happens:** Chrome extensions' content scripts run in the page context where SpeechRecognition may not be available; background SW has no DOM.
**How to avoid:** Only instantiate SpeechRecognition in the Side Panel or Full App Tab contexts (both are `chrome-extension://` pages with full window access). Guard with `typeof window !== 'undefined' && ('SpeechRecognition' in window || 'webkitSpeechRecognition' in window)`.
**Warning signs:** `SpeechRecognition is not defined` errors in console.

### Pitfall 2: Mention Chips Break Sender Controlled Input
**What goes wrong:** Trying to render mention chips inside the Sender's textarea (contentEditable, overlays) breaks the controlled `value`/`onChange` contract.
**Why it happens:** Ant Design X Sender manages its own `<textarea>` element. Foreign DOM manipulation inside it will cause state desync between the React-controlled value and the DOM.
**How to avoid:** Render mention chips in the Sender `header` prop, which is already used for attachment preview at `ChatPage.tsx:2076`. Keep textarea value as plain text with `@type:title` syntax. Chips are visual indicators only — actual references passed via `ReferenceToken[]` in submit handler. Backspace removal of chip = scan textarea value for `@type:title` pattern and remove it programmatically via `setDraft`.
**Warning signs:** Sender value gets out of sync, cursor position jumps, duplicate characters.

### Pitfall 3: Zustand Migration Not Idempotent in Multi-Surface Chrome Extension
**What goes wrong:** Running a migration across multiple extension surfaces (Side Panel + Full App Tab) could double-transform data or lose values.
**Why it happens:** Both Side Panel and Full App Tab load `usePreferenceStore` independently; the `migrate` function runs on each surface's first store hydration. The persist middleware updates `version` in storage after first successful migration, so subsequent loads skip migration — but the first load on each surface runs independently.
**How to avoid:** Make `migrate` idempotent — check field types before transforming. After first surface writes the migrated state with `version: 1`, the second surface reads `version: 1` from storage and skips migration entirely. Example guard: `if (typeof persisted.aiTone === 'string' && !['professional', 'professional_approachable'].includes(persisted.aiTone)) { /* map */ }`. Zustand's persist middleware stores version in the same key — it's atomic within a single chrome.storage.local write.
**Warning signs:** Duplicate enum values, corrupted preferences in chrome.storage.local.

### Pitfall 4: XMarkdown `components` Prop Rebuilds on Every Render
**What goes wrong:** Inline object in `components` prop causes XMarkdown to re-mount all custom renderers on every render, breaking streaming state.
**Why it happens:** React component identity — `{ ol: ChecklistCardGroup }` is a new object reference each render unless memoized. XMarkdown streaming state depends on component identity stability for `hasNextChunk` animation.
**How to avoid:** Define `MARKDOWN_COMPONENTS` at module level (outside React component) for stable references. If runtime state is needed in components (e.g., ChecklistCardGroup needs messageId for session-only state), pass it via a wrapper component that reads from context or props.
**Warning signs:** Checklist items flicker during streaming, "Warning: unmounting component while streaming" in console.

### Pitfall 5: TL;DR Collapse Hides Streaming Content Mid-Flow
**What goes wrong:** TL;DR toggle renders while the message is still streaming — character count crosses 500-char threshold mid-stream, triggering auto-collapse while tokens are still arriving.
**Why it happens:** The `TLDRThreshold` is checked on content length, which increases during streaming. The threshold may be crossed mid-stream.
**How to avoid:** Only render TL;DR toggle AFTER streaming completes (`!item.streaming === true`). Defer the threshold check to when `hasNextChunk` is false. This is a one-line guard: `{!item.streaming && charCount > TLDR_THRESHOLD && <TLDRToggle ... />}`.
**Warning signs:** Message collapses while still generating; users think the response was cut off.

### Pitfall 6: chrome.storage.local QUOTA_BYTES_PER_ITEM Limit
**What goes wrong:** Storing large objects (e.g., full conversation transcripts) in chrome.storage.local hits the per-item size quota (~8KB per key, varies by Chrome version).
**Why it happens:** `chrome.storage.local` is designed for small configuration data, not large documents.
**How to avoid:** PromptStarterUsageStore stores lightweight counters (usageCount, lastUsedAt) — well under 1KB. EduTipsStore tracks message/session counts + per-tip booleans — also under 1KB. Saved conversations go to IndexedDB (NotesDB), not chrome.storage.local. Export files (.md/.json) are downloaded via Blob URL, not stored.
**Warning signs:** `QUOTA_BYTES_PER_ITEM` error in console, store silently fails to persist.

### Voice Input Hook Using Web Speech API (D-13, D-15, D-16)
```typescript
// Source: MDN Web Speech API [VERIFIED: https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition]
// Adapted for Chrome Extension toggle recording mode (D-13: tap start/stop)
// Guard per D-14: conditional button visibility

import { useState, useRef, useCallback, useEffect } from 'react';

interface UseVoiceInputOptions {
  onTranscript: (text: string, isFinal: boolean) => void;
  lang?: string;
}

export function useVoiceInput({ onTranscript, lang = 'en-US' }: UseVoiceInputOptions) {
  const [isRecording, setIsRecording] = useState(false);
  const [interimText, setInterimText] = useState('');
  const recognitionRef = useRef<SpeechRecognition | null>(null);

  // D-14: Check browser support (guard for conditional button visibility)
  const isSupported = typeof window !== 'undefined' &&
    ('SpeechRecognition' in window || 'webkitSpeechRecognition' in window);

  useEffect(() => {
    if (!isSupported) return;
    const SpeechRecognition = (window as any).SpeechRecognition || (window as any).webkitSpeechRecognition;
    const recognition = new SpeechRecognition();
    recognition.continuous = true;    // D-13: toggle mode — keep listening between pauses
    recognition.interimResults = true; // D-16: interim + final results
    recognition.lang = lang;

    // D-16: Handle interim (grey) and final (replace) results
    recognition.onresult = (event: SpeechRecognitionEvent) => {
      let interim = '';
      let final = '';
      for (let i = event.resultIndex; i < event.results.length; i++) {
        const result = event.results[i];
        if (result.isFinal) {
          final += result[0].transcript;
        } else {
          interim += result[0].transcript;
        }
      }
      if (final) {
        onTranscript(final, true);
        setInterimText('');
      } else if (interim) {
        setInterimText(interim);
        onTranscript(interim, false);
      }
    };

    recognition.onerror = (event: SpeechRecognitionErrorEvent) => {
      console.error('[VoiceInput] Speech recognition error:', event.error);
      setIsRecording(false);
      setInterimText('');
    };

    recognition.onend = () => {
      setIsRecording(false);
      setInterimText('');
    };

    recognitionRef.current = recognition;
    return () => { recognition.abort(); };
  }, [isSupported, lang, onTranscript]);

  // D-13: Toggle recording mode — tap to start, tap to stop
  const toggle = useCallback(() => {
    if (!recognitionRef.current) return;
    if (isRecording) {
      recognitionRef.current.stop();
    } else {
      recognitionRef.current.start();
      setIsRecording(true);
    }
  }, [isRecording]);

  return { isRecording, interimText, isSupported, toggle };
}
```

### Known Threat Patterns for React/Chrome Extension UI

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| XSS via @mention chip titles from untrusted sources | Tampering | Mention titles come from user-controlled sources (note titles from NotesDB, tab titles from workspaceStore, prompt names from PromptManager). Render as `Typography.Text` children (text content) — NOT `dangerouslySetInnerHTML`. antd Typography.Text auto-escapes React children. |
| XSS via voice transcript inserted into Sender | Tampering | SpeechRecognition returns plain text strings. Inserted into Sender textarea as controlled `value` — textarea inherently renders as text, not HTML. No `innerHTML`/`dangerouslySetInnerHTML` path. |
| XSS via exported Markdown/JSON | Tampering | Export uses `JSON.stringify` (safe — produces valid JSON, no HTML injection). Markdown export uses template string concatenation of conversation text — text content is user-generated but rendered as plain text in the .md file. No unescaped user HTML. |
| chrome.storage.local quota exhaustion | Denial of Service | PromptStarterUsageStore uses bounded data (max ~200 entries × ~100 bytes = ~20KB). EduTipsStore uses fixed-size object (messageCount, sessionCount, per-tip booleans = ~1KB). No unbounded arrays or file storage. |
| Stale reference tokens pointing to deleted resources | Spoofing | D-06: ContextOptimizer re-resolves ReferenceTokens on every send. Deleted resources are silently skipped. Chip renders in disabled/greyed state if resolver reports resource as deleted. No fallback to raw text. |
| Microphone permission abuse | Information Disclosure | Web Speech API requires explicit user permission via browser-level prompt (one-time per origin). Sender only activates on user tap — no background/automatic recording. `chrome-extension://` origin gets its own permission grant. |
