# Phase 07.5: RICH Design Polish - Research

**Researched:** 2026-07-19
**Domain:** UI polish / UX enhancement for AI chat interface (Chrome Extension)
**Confidence:** HIGH

## Summary

Phase 07.5 polishes the RICH experience with 21 P2 nice-to-have enhancements spanning 7 major feature areas: persona editor, @mention syntax, voice input, TL;DR toggle, step checklists, educational tips, and enhanced markdown rendering — plus secondary areas: conversation feedback persistence, saved conversations, prompt starter unification, memory visibility, and multi-modal attachment strategy. All features extend existing Ant Design X 2.8.0 Sender/Bubble/XMarkdown components and Zustand stores already established in Phases 7.3-7.4. No new npm packages are required — every feature uses components and APIs already in the project's dependency tree.

**Primary recommendation:** Build each feature as an independent component or service module that integrates into existing ChatPage Sender/Bubble pipeline. Adapt the WikilinkAutocomplete pattern for @mention autocomplete. Use the built-in `allowSpeech` SpeechConfig on Sender for voice input rather than building a custom Web Speech API wrapper. Leverage Zustand `migrate` for PreferenceMemoryStore enum changes. All new stores (EduTipsStore, PromptStarterUsageStore) follow the RightPaneStore pattern (Zustand + chrome.storage.local + `np_` key prefix).

### Pattern 1: Autocomplete Popover (Adapt WikilinkAutocomplete)

**What:** WikilinkAutocomplete provides a battle-tested pattern for inline autocomplete — trigger detection, keyboard nav, click-outside-close, dropdown positioning. Adapt for @mentions by changing trigger from `[[` to `@`, switching data source from LinkParser to ReferenceResolver registry, and rendering type-specific icons/colors.

**When to use:** For @mention autocomplete (RICH-H-15). NOT for slash commands (already implemented in ChatPage).

### Pattern 6: Zustand `migrate` for Enum Changes

**What:** When changing an enum in a persisted store, use Zustand's `migrate` function in the persist config to transform old values to new values on load.

**When to use:** For PreferenceMemoryStore enum changes — adding `'balanced'` to `responseBrevity` and changing `aiTone` from free-text to typed enum.

**Example:**
```typescript
// Source: Context7 /pmndrs/zustand persist migration docs
persist(
  (set) => ({ /* state */ }),
  {
    name: 'np_preferences',
    storage: chromeLocalStorage,
    version: 2, // bump from 1 to trigger migration
    migrate: (persisted: any, version) => {
      if (version < 2) {
        // Migrate responseBrevity: keep 'concise' and 'detailed', nothing to map
        // Migrate aiTone: map free-text to new enum values
        if (typeof persisted.aiTone === 'string') {
          const toneMap: Record<string, string> = {
            'Professional + approachable': 'professional_approachable',
            'Professional': 'professional',
          };
          persisted.aiTone = toneMap[persisted.aiTone] || 'professional_approachable';
        }
      }
      return persisted as PreferenceState;
    },
  },
)
```

### Anti-Patterns to Avoid
- **Custom Web Speech API wrapper when Sender has `allowSpeech`:** Sender 2.8.0 has built-in `allowSpeech` (boolean | SpeechConfig) with recording state management. Building a custom wrapper duplicates framework functionality. However, for the toggle (tap to start/stop) behavior specified in D-13, a custom hook wrapping SpeechRecognition directly may be needed since Sender's built-in voice is push-to-talk. Use `SpeechConfig` to disable built-in and provide custom button via `prefix` slot. [VERIFIED: Context7 /ant-design/x SenderProps.SpeechConfig]
- **ContentEditable for mention chips:** Don't use contentEditable divs for the Sender input. The Sender uses a textarea internally; mention chips should render in the `header` slot as visual indicators, with plain text `@note:title` in the textarea value. Attempting contentEditable would break Sender's controlled input model.
- **New prompt template registry:** Don't create a second template registry for PromptStarter unification. PromptManager is the single source of truth. PromptStarterService adds metadata/categories/usage tracking on top of existing template IDs.
- **Storing checklist state beyond session:** Don't persist checklist state to storage. D-20 explicitly scopes this to session-only (local component state keyed by messageId). Persisting would create stale state on reload.

## Common Pitfalls

### Pitfall 1: Web Speech API Not Available in Content Scripts
**What goes wrong:** Attempting to access `SpeechRecognition` from a content script or background service worker fails because it requires a secure context (HTTPS) and window object.
**Why it happens:** Chrome extensions' content scripts run in the page context where SpeechRecognition may not be available; background SW has no DOM.
**How to avoid:** Only instantiate SpeechRecognition in the Side Panel or Full App Tab contexts (both are `chrome-extension://` pages with full window access). Guard with `typeof window !== 'undefined' && ('SpeechRecognition' in window || 'webkitSpeechRecognition' in window)`.
**Warning signs:** `SpeechRecognition is not defined` errors in console.

### Pitfall 2: Mention Chips Break Sender Controlled Input
**What goes wrong:** Trying to render mention chips inside the Sender's textarea (contentEditable, overlays) breaks the controlled `value`/`onChange` contract.
**Why it happens:** Ant Design X Sender manages its own textarea. Foreign DOM manipulation inside it will cause state desync.
**How to avoid:** Render mention chips in the Sender `header` prop (already used for attachment preview). Keep textarea value as plain text with `@type:title` syntax. Chips are visual indicators only — actual references passed via ReferenceToken[] in submit handler.
**Warning signs:** Sender value gets out of sync, cursor position jumps, duplicate characters.

### Pitfall 3: Zustand Migration Not Idempotent
**What goes wrong:** Running a migration twice (e.g., on multiple extension surfaces) could double-transform data or lose values.
**Why it happens:** Both Side Panel and Full App Tab load the store independently; the `migrate` function runs each time if `version` mismatches.
**How to avoid:** Make `migrate` idempotent — check field types before transforming. After migration, `persist` middleware updates the stored version so subsequent loads skip migration. Example: `if (typeof persisted.aiTone === 'string' && !['professional', 'professional_approachable'].includes(persisted.aiTone)) { /* map */ }`.
**Warning signs:** Duplicate enum values, corrupted preferences in chrome.storage.local.

### Pitfall 4: XMarkdown `components` Prop Rebuilds on Every Render
**What goes wrong:** Inline object/function in `components` prop causes XMarkdown to re-mount all custom renderers on every render, breaking streaming state.
**Why it happens:** React component identity — `{ ol: ChecklistCardGroup }` is a new object reference each render unless memoized.
**How to avoid:** Use `useMemo` or define `components` outside the component (module level) for stable references. XMarkdown streaming depends on component identity stability for `hasNextChunk` state.
**Warning signs:** Checklist items flicker, streaming resets, "Warning: unmounting component while streaming" in console.

### Pitfall 5: TL;DR Collapse Hides Streaming Content Mid-Flow
**What goes wrong:** TL;DR toggle renders while the message is still streaming — collapse immediately, truncating visible content unexpectedly.
**Why it happens:** Character count crosses 500-char threshold mid-stream, triggering auto-collapse while tokens are still arriving.
**How to avoid:** Only show TL;DR toggle AFTER streaming completes (`!item.streaming`). Defer the threshold check to when `hasNextChunk` is false.
**Warning signs:** Message collapses while still generating; users think the response was cut off.

### Pitfall 6: chrome.storage.local 8KB Per-Item Limit
**What goes wrong:** Storing large objects (e.g., full conversation transcripts, many checklist states) hits chrome.storage.local's per-item size quota.
**Why it happens:** chrome.storage.local has a ~8KB per-key limit (varies). Large arrays or nested objects can exceed it.
**How to avoid:** PromptStarterUsageStore stores lightweight counters (usageCount, lastUsedAt) — well under 1KB. EduTipsStore tracks message/session counts and per-tip booleans — also under 1KB. Saved conversations go to IndexedDB (NotesDB), not chrome.storage.local.
**Warning signs:** `QUOTA_BYTES_PER_ITEM` error in console, store silently fails to persist.

### Voice Input Hook Using Web Speech API
```typescript
// Source: MDN Web Speech API docs [VERIFIED: https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition]
// Adapted for Chrome Extension toggle behavior (D-13)

import { useState, useRef, useCallback, useEffect } from 'react';

interface UseVoiceInputOptions {
  onTranscript: (text: string, isFinal: boolean) => void;
  lang?: string;
}

export function useVoiceInput({ onTranscript, lang = 'en-US' }: UseVoiceInputOptions) {
  const [isRecording, setIsRecording] = useState(false);
  const [interimText, setInterimText] = useState('');
  const recognitionRef = useRef<any>(null);

  // Check browser support
  const isSupported = typeof window !== 'undefined' &&
    ('SpeechRecognition' in window || 'webkitSpeechRecognition' in window);

  useEffect(() => {
    if (!isSupported) return;
    const SpeechRecognition = (window as any).SpeechRecognition || (window as any).webkitSpeechRecognition;
    const recognition = new SpeechRecognition();
    recognition.continuous = true;   // toggle mode — keep listening after phrase
    recognition.interimResults = true; // show interim results
    recognition.lang = lang;

    recognition.onresult = (event: any) => {
      let interim = '';
      let final = '';
      for (let i = event.resultIndex; i < event.results.length; i++) {
        const result = event.results[i];
        if (result.isFinal) {
          final += result[0].transcript;
        } else {
          interim += result[0].transcript;
        }
      }
      if (final) {
        onTranscript(final, true);
        setInterimText('');
      } else if (interim) {
        setInterimText(interim);
        onTranscript(interim, false);
      }
    };

    recognition.onerror = (event: any) => {
      console.error('[VoiceInput] Speech recognition error:', event.error);
      setIsRecording(false);
    };

    recognition.onend = () => {
      setIsRecording(false);
      setInterimText('');
    };

    recognitionRef.current = recognition;
    return () => { recognition.abort(); };
  }, [isSupported, lang, onTranscript]);

  const toggle = useCallback(() => {
    if (!recognitionRef.current) return;
    if (isRecording) {
      recognitionRef.current.stop();
    } else {
      recognitionRef.current.start();
      setIsRecording(true);
    }
  }, [isRecording]);

  return { isRecording, interimText, isSupported, toggle };
}
```

### ChecklistCardGroup via XMarkdown `components` Prop
```typescript
// Source: Inspired by ChatPage.tsx code block renderer pattern (L1552-1568)
// XMarkdown 'components.ol' override for step checklists (D-19, D-20)

import { useState, useCallback } from 'react';
import { Card, Checkbox, Flex, Typography } from 'antd';

interface ChecklistCardGroupProps {
  children?: React.ReactNode;
  start?: number;
}

export function ChecklistCardGroup({ children, start = 1 }: ChecklistCardGroupProps) {
  const [checked, setChecked] = useState<Set<number>>(new Set());

  const items = React.Children.toArray(children)
    .filter((child) => React.isValidElement(child) && child.type === 'li');

  // Only render as checklist if items look actionable
  if (items.length < 2) {
    return <ol start={start}>{children}</ol>; // fallback to normal list
  }

  const toggleItem = useCallback((index: number) => {
    setChecked(prev => {
      const next = new Set(prev);
      next.has(index) ? next.delete(index) : next.add(index);
      return next;
    });
  }, []);

  const total = items.length;
  const completed = checked.size;
  const progress = total > 0 ? Math.round((completed / total) * 100) : 0;

  return (
    <Flex vertical gap={8} style={{ margin: '12px 0' }}>
      {/* Progress indicator */}
      <Flex align="center" gap={8}>
        <Typography.Text type="secondary" style={{ fontSize: 12 }}>
          {completed}/{total} completed
        </Typography.Text>
        <div style={{
          flex: 1, height: 4, background: 'var(--ant-color-fill-secondary)',
          borderRadius: 2, overflow: 'hidden',
        }}>
          <div style={{
            width: `${progress}%`, height: '100%',
            background: 'var(--ant-color-primary)',
            transition: 'width 0.3s ease',
          }} />
        </div>
      </Flex>

      {/* Step cards */}
      {items.map((item, index) => {
        const isChecked = checked.has(index);
        return (
          <Card
            key={index}
            size="small"
            styles={{
              body: {
                padding: '10px 14px',
                opacity: isChecked ? 0.6 : 1,
                textDecoration: isChecked ? 'line-through' : 'none',
              },
            }}
          >
            <Flex align="flex-start" gap={8}>
              <Checkbox
                checked={isChecked}
                onChange={() => toggleItem(index)}
              />
              <Typography.Text style={{ flex: 1, fontSize: 13 }}>
                {item.props.children}
              </Typography.Text>
            </Flex>
          </Card>
        );
      })}
    </Flex>
  );
}
```

## Open Questions

1. **Sender's built-in `allowSpeech` vs custom voice hook tradeoff**
   - What we know: Sender 2.8.0 has `allowSpeech` (boolean | SpeechConfig) with built-in recording UI. D-13 specifies "toggle recording mode: tap to start, tap to stop."
   - What's unclear: Whether Sender's built-in speech supports toggle mode or only push-to-talk. The `SpeechConfig.recording` prop suggests custom control is possible.
   - Recommendation: Test Sender's built-in speech behavior first. If it's push-to-talk only, use custom `useVoiceInput` hook + Sender `prefix` slot button. Set `allowSpeech={false}` and render custom button.

2. **XMarkdown `components` prop object identity during streaming**
   - What we know: XMarkdown streaming relies on component identity stability. ChatPage already handles this for code blocks.
   - What's unclear: Whether adding `ol: ChecklistCardGroup` to the same `components` object as `code: CodeBlockActions` will cause re-render issues with code blocks.
   - Recommendation: Test with streaming content that has both code blocks and ordered lists. If issues arise, separate the component maps or use `React.memo` wrappers.

3. **PreferenceMemoryStore migration for `aiTone` enum — free-text to typed values**
   - What we know: Current `aiTone` is `string | undefined`. D-09 requires two-tone enum. D-11 says "Replace free-text with typed enum."
   - What's unclear: What existing free-text values exist in user stores. The default `DEFAULT_PERSONA_PROFILE.languageStyle.tone` is `'Professional + approachable — technically accurate, direct, practical, friendly'` — a long string, not a preset.
   - Recommendation: Map known values in migrate (see Pattern 6). For unknown values, default to `'professional_approachable'`. Add a console.warn for unmapped values to aid debugging.

4. **ChecklistCardGroup detection heuristic for "actionable" lists**
   - What we know: D-19 says "ordered lists with 2+ actionable items automatically render as ChecklistCardGroup."
   - What's unclear: What constitutes "actionable" — any ordered list with >1 item? Lists with imperative verbs? Lists with checkable tasks?
   - Recommendation: Start with simple heuristic: ordered list with 2+ items where average item length exceeds 15 characters (filtering out short index entries). The heuristic can be tuned later without API changes.

### Known Threat Patterns for React/Chrome Extension UI

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| XSS via voice transcript inserted into Sender | Tampering | Voice transcript is plain text; Sender textarea handles it as text content (not HTML). No innerHTML/dangerouslySetInnerHTML. |
| XSS via @mention chip rendering | Tampering | Mention titles from user-controlled sources (note titles, tab titles, prompt names). Render as text content in antd Typography.Text, not innerHTML. |
| XSS via exported Markdown/JSON | Tampering | Export uses turndown (already sanitized) and JSON.stringify (safe). No user-generated HTML in exports. |
| chrome.storage.local quota exhaustion | Denial of Service | PromptStarterUsageStore and EduTipsStore use small, bounded data structures. No unbounded arrays or large objects. |
| Stale/changed reference tokens in messages | Spoofing | ContextOptimizer re-resolves ReferenceTokens on every send. Deleted resources are silently skipped (D-06). |
| Microphone permission abuse | Information Disclosure | Web Speech API requires explicit user permission (browser-level prompt). Sender only activates on user tap. No background recording. |
