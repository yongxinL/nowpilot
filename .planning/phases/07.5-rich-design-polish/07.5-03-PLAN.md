<objective>
Build three supporting data-layer features for Phase 7.5: the voice input hook (`useVoiceInput`) for toggle-mode dictation via Web Speech API; the unified PromptStarter data model with usage tracking and shared recency/normalization; and the Educational Tips system with Zustand-backed persistence, tip definitions, and eligibility evaluation. Also extend UserMemoryStore with memory state management (confirm/reject/delete).

**Purpose:** These three features share a common characteristic — they are data layer and hook factories consumed by UI components in Wave 2. Building them together avoids three separate plans for what are relatively lightweight modules.

**Output:** useVoiceInput hook, PromptStarter types + service + store, EduTipsStore + definitions + eligibility service, enhanced UserMemoryStore.
</objective>

    **Step A — Create `useVoiceInput.ts` hook:**
    Follow the RESEARCH.md code example (lines 555-632). Key implementation details:
    - Vite build time guard: `typeof window !== 'undefined'` before accessing `SpeechRecognition` — avoids build failures in WXT's service-worker bundling where window is undefined.
    - Run-time feature detection: at mount time inside a `useEffect`, check `('SpeechRecognition' in window || 'webkitSpeechRecognition' in window)` — set `isSupported` derived state.

    - `onTranscript(text, isFinal)` callback: final transcripts replace interim; interim shows as grey text (D-16). The hook itself only manages recording state and speech events — the caller (VoiceInputButton or Sender integration) decides how to compose `onTranscript` with `setDraft`/cursor insertion (D-15: insert at cursor).
    - `recognition.onerror`: set `isRecording = false`, `interimText = ''`
    - `recognition.onend`: set `isRecording = false`, `interimText = ''`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Web Speech API → useVoiceInput | Audio from microphone — browser-managed permission; transcript is plain text inserted into textarea |
| UserMemoryStore → Memory Browser UI | Fact content displayed in Options → Advanced → Memory — no sanitization needed (plain text stored, React auto-escapes) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.5-05 | Information Disclosure | SpeechRecognition | low | accept | Browser-managed mic permission prompt; chrome-extension:// origin gets own grant; no background recording |
| T-07.5-06 | Denial of Service | EduTipsStore / PromptStarterUsageStore | low | accept | Bounded data: EduTips ~1KB fixed fields; PromptStarterUsage ~20KB for 200 entries; no unbounded growth |
| T-07.5-07 | Tampering | UserMemoryStore.confirm/reject | low | mitigate | confirm/reject only modify status + confidence — content is immutable per D-33 ("no inline editing"); delete is permanent with confirmation dialog in UI (Wave 2) |
</threat_model>
