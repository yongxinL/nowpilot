    Constructor: call `this.rebuildIndex()` to populate MiniSearch from existing MemoryDB data on startup (Research open question #2).

    **search(query, tier):** Two-pass retrieval per D-11.
    - Pass 1: `miniSearchIndex.search(query, 20)` → top-20 candidates
    - Pass 2: For each candidate, compute matchedTags (tags present in query keywords), call `memoryScorer.score({ fact, keywordScore: candidate.score }, query, matchedTags)` → array of ScoredFact
    - Call `memoryScorer.tieBreak(scoredFacts)` → sorted

    - Return `Array<MemoryScore>` (fact + keywordScore + finalScore)
    - try/catch + debugLog → return []

    **upsert(fact):** Pass through conflict resolution.
    - Validate fact against `userMemoryFactSchema` (strip unknown fields via .parse())
    - Fetch existing active facts from MemoryDB via memoryDB.getAllUserFacts() → filter status === 'active'
    - Call `conflictResolver.resolve(newFact, existingFacts, observationCount)`
    - For each resolved fact:
      - If status='active': `memoryDB.putUserFact(resolvedFact)`, `miniSearchIndex.replaceFact(resolvedFact)`
      - If status='superseded': `memoryDB.putUserFact(resolvedFact)`, `miniSearchIndex.replaceFact(resolvedFact)` (keep in index but filtered at search)
    - try/catch + debugLog

    **getFact(id):** memoryDB.getAllUserFacts() → find by id. try/catch → return undefined.

    **rebuildIndex():** Fetch all facts from memoryDB.getAllUserFacts() → filter status='active' → call `miniSearchIndex.rebuild(activeFacts)`. Called at construction time.

    **evictFact(id):** For D-23/D-24 — called by MemoryEngine during extraction cap/pruning check.
    - `miniSearchIndex.removeFact(id)` — remove from search index
    - `memoryDB.putUserFact({ ...fact, status: 'superseded' })` — soft delete in DB

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User message → MiniSearch query | User input feeds into MiniSearch search queries — benign (inverted index, no injection risk) |
| MemoryExtractor output → UserMemoryStore.upsert | AI-generated fact JSON crosses this boundary — validated by userMemoryFactSchema.parse() before storage |
| ConversationMemoryStore.summarize LLM summary → putSummary | LLM-generated summary text stored directly — treated as trusted internal data (no user-facing sanitization needed) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Tampering | UserMemoryStore.upsert unsanitized fact content | medium | mitigate | userMemoryFactSchema Zod validation on all facts before upsert. Unknown fields stripped via .parse(). |
| T-05-08 | Information Disclosure | Stale MiniSearch index returning superseded facts | low | mitigate | UserMemoryStore.search filters status !== 'active'; rebuildIndex only loads active facts. Superseded facts removed from search via miniSearchIndex.replaceFact. |
| T-05-09 | Denial of Service | ConversationMemoryStore unbounded summary growth | low | accept | D-18 keep-tail-drop-middle limits stored messages. D-22 caps active conversations at 10 and archived at 100. MemoryEngine enforces both caps. |
</threat_model>
