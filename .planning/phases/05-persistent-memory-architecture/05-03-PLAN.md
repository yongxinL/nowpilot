    Create src/core/memory/conflictResolver.ts.

    Import type { UserMemoryFact } from './memoryTypes'.

    Export pure functions (no class):

    **resolve(newFact, existingFacts, observationCount):**
    Receives a newly extracted UserMemoryFact (partial, with fact/category/confidence/tags), an array of existing active UserMemoryFacts from MemoryDB, and an observationCount (number of independent observations supporting the new fact).

    Logic:
    1. Find conflicting existing fact: same category AND where existing.active → content is semantically contradictory. Use `factMatchScore(existing, newFact)` > 0.7 as the similarity threshold for conflict detection.
    2. If no conflict found → return `[{ fact: newFact, status: 'active' }]`.
    3. If conflict found:
       a. Compute cumulative confidence of newFact's observations vs existing fact's confidence.
       b. If observationCount >= 2 AND cumulativeConfidence(newFact.observations) > existing.confidence → supersede: existing gets status='superseded', newFact gets status='active'. Return both.
       c. Otherwise → newFact is dropped (doesn't meet evidence threshold). Return existing fact unchanged.

    **computeCumulativeConfidence(confidences: number[]):**
    Implements D-17 cumulative confidence formula: `1 - product(1 - c_i for each confidence c_i)`.
    Example: [0.4, 0.5, 0.3] → 1 - (0.6 * 0.5 * 0.7) = 1 - 0.21 = 0.79.

    **factMatchScore(a, b):**
    Private helper. Simple Jaccard-like overlap of significant words (split by whitespace, lowercase, filter words > 3 chars). Returns overlap / union. Used for detecting if two facts are about the same thing.

    All functions are synchronous (no I/O). Caller handles persistence.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MiniSearch query input → index | User message text feeds into MiniSearch queries — untrusted but MiniSearch handles it safely (no injection risk in inverted index) |
| conflictResolver fact content → state transitions | Fact similarity detection uses Jaccard word overlap — could be tricked by adversarial fact content, but D-16's 2+ observation threshold limits single-injection impact |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Spoofing | conflictResolver fact similarity (Jaccard) | low | accept | D-16 requires 2+ independent observations to supersede — a single adversarial extraction cannot flip an existing fact. Jaccard-based matching is sufficient for v0.1 scale (≤500 facts). |
| T-05-06 | Denial of Service | MiniSearchIndex unbounded add | low | accept | MiniSearch index size is bounded by D-23's 500-fact cap enforced in MemoryEngine.extract(). Max ~500 documents in-memory — trivially fast. |
</threat_model>
