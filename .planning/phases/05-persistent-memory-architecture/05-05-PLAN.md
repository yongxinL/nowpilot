    Import { generateText } from 'ai', debugLog from '../utils/debugLog'.

    Define EXTRACTION_PROMPT template constant:
    ```
    You are a memory extraction system. Analyze the conversation and extract user facts.

    Output ONLY valid JSON matching this schema:
    {
      "facts": [
        {
          "fact": "string — concise statement about the user",
          "category": "string — one of: preference, pattern, knowledge, goal, identity",
          "confidence": number (0.0-1.0),
          "tags": ["string array — keywords for retrieval"]
        }
      ],
      "summary": "string — optional conversation summary"
    }

    Rules:
    - Extract only facts about the USER, not the assistant
    - Confidence reflects how certain the fact is (0.9 = explicit statement, 0.5 = implied, 0.3 = guess)
    - Tags should be lowercase, single-concept keywords for search retrieval
    - Do NOT extract transient conversation details (what was said now)
    - Do NOT extract facts the user has already told us before (check previous facts context if provided)
    - Max 5 facts per extraction
    ```

    Class MemoryExtractor with constructor `constructor(private modelAccessor: (tier: ModelContextTier) => { provider: string, model: unknown })`.
    Constructor DI pattern matching ContextCompressor (lines 15-16).

    **extract(messages, tier = 'small'):** Async, returns MemoryExtractionResult.
    - Resolve model via this.modelAccessor(tier)
    - Build prompt: EXTRACTION_PROMPT + "\n\nConversation:\n" + messages.map(m => `${m.role}: ${m.content}`).join('\n')
    - Call generateText({ model, system: EXTRACTION_PROMPT, prompt: conversationText, maxTokens: 300, temperature: 0 }) — low temperature for deterministic extraction
    - Parse response.text as JSON
    - Validate against extractionResultSchema using .safeParse() (not .parse() — use safeParse to avoid throwing)
    - If validation succeeds: debugLog('info', '[MemoryExtractor] extracted N facts', { count: result.data.facts.length }), return result.data
    - If validation fails: debugLog('warn', '[MemoryExtractor] invalid output, discarding', { error: result.error }), return { facts: [], summary: undefined }
    - try/catch around the entire AI call + parsing:
      - First failure: debugLog('warn', '[MemoryExtractor] retrying'), retry once with same params
      - Second failure: debugLog('error', '[MemoryExtractor] extraction failed after retry', { error: err }), return { facts: [], summary: undefined }
    - NEVER throw — always return a valid MemoryExtractionResult per D-04

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI output (generateText) → MemoryExtractor.parse | Untrusted LLM text crosses here — must be JSON-parsed and Zod-validated before any fact enters the system |
| User-provided conversation text → MemoryExtractor prompt | User messages included in extraction prompt — could contain prompt injection attempts if the extraction prompt is poorly constructed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10 | Tampering | MemoryExtractor LLM output injection | high | mitigate | extractionResultSchema.safeParse() validates ALL AI output. Invalid JSON or missing fields ⇒ facts discarded, logged. |
| T-05-11 | Spoofing | Prompt injection via conversation text | medium | mitigate | Extraction prompt instructs LLM to extract FACTS only (no code execution, no tool calls). maxTokens=300 limits blast radius. extractionResultSchema strips unknown fields. |
| T-05-12 | Information Disclosure | PreferenceStore reads from other stores | low | accept | PreferenceMemoryStore reads public theme/surface state — no sensitive data. All data stays local (chrome.storage). |
| T-05-13 | Denial of Service | MemoryExtractor blocking render pipeline | medium | mitigate | MemoryEngine.extract() is fire-and-forget (NOT awaited). MemoryExtractor has maxTokens=300 cap. Retry only once (2 attempts max). D-04 explicitly prohibits blocking. |
</threat_model>
