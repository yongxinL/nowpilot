# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3 (Cost-Effective AI Runtime + Persona seed). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Source-of-truth artifacts: `.planning/DESIGN_SYSTEM.md` (§5–§13), `.planning/phases/01-*/01-UI-SPEC.md` (approved Phase-1 contract), `.planning/phases/03-cost-effective-ai-runtime-persona-seed/03-CONTEXT.md` (D-01…D-03, D-21), `.planning/PRODUCT_SPEC_v0_1.md` §18 Phase 3 + Appendix I/J.1/J.2 + §17.5/§17.6, `.planning/STACK.md` / `AGENTS.md` (approved stack + banned list).

> **Scope honesty note (must be preserved by the planner):** Phase 3 ships the **minimal functional streaming chat surface** — Bubble/Sender send+stream with ChunkBuffer text — nothing more. The RICH layer (Welcome, Prompts, clarification/follow-up chips, persona header, stage indicators, chat-history list, Agent toggle, action panels, composer toolbar, status bar, model selector, provider dialog) is fenced to Phase 7 (03-CONTEXT D-03, D-10, D-21). The contract below binds ONLY what Phase 3 renders. Do not let RICH polish leak in.

## Spacing Scale

Layout spacing constrained to the Phase-1 locked grid (01-UI-SPEC §Spacing): **4 / 8 / 16 / 24 / 32** active; 48 / 64 reserved-but-declared. 12 px and 20 px remain AntD component-internal defaults, **never** top-level layout tokens (override via the `Size` token if a component ships them). Hairlines (1–2 px) are borders, not spacing — see Border/Stroke Tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 px | Icon gaps, inline padding, dense row spacing. |
| sm | 8 px | Compact element spacing (bubble-to-bubble vertical gap, send-button gutters). |
| md | 16 px | Default element spacing (conversation area padding, Sender inner gutters, Standalone bubble margins). |
| lg | 24 px | Section padding (Standalone conversation column gutters). |
| xl | 32 px | Reserved (declared for parity; not used by the Phase-3 minimal chat). |
| 2xl | 48 px | Reserved (not used in Phase 3). |
| 3xl | 64 px | Reserved (not used in Phase 3). |

Exceptions:

- **Touch targets ≥ 32 px (Side Panel / compact) / ≥ 36 px (Standalone)** — every interactive element (send button, Retry action) per DESIGN_SYSTEM.md §12.
- **No 48 / 64 px steps at layout level in Phase 3** — active grid is 4 / 8 / 16 / 24 / 32.
- **12 / 20 px** are component-internal AntD defaults; do not use them in custom layout rules.

## Border / Stroke Tokens

| Token | Value | Usage |
|-------|-------|-------|
| hairline | 1 px | `colorBorder` — assistant bubble outline (DESIGN_SYSTEM.md §6.3), card hairlines, dividers. |
| hairline-thin | 2 px | Focus ring on interactive elements (Sender, send button, Retry) — `colorPrimary` (DESIGN_SYSTEM.md §12). |

Borders are `border-width`/`outline-width`, not spacing tokens.

## Typography

Phase-3 declares the Phase-1 locked **2-weight cap** — 400 (body, captions, placeholder) and 600 (identity labels, primary actions). No 500-weight role is introduced (AntD `Button.fontWeight` overridden in `NOWPILOT_COMPONENTS` to 400/600 — DESIGN_SYSTEM.md §13).

Base sizes: Side Panel **13 px** (compact); Standalone **14 px** (default). Steps: 12 / 13 / 14 / 16 / 20 / 24 / 30. Body line-height 1.5; headings 1.3. Never below 12 px. Captions use `colorTextTertiary`.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13 px (SP) / 14 px (SA) | 400 | 1.5 | Streamed assistant text, user bubble text, empty-state cue, error line. |
| Label / caption | 12 px | 400 (600 only for the active/identity case below) | 1.5 | Sender placeholder, muted helper lines, offline notice. |
| Identity label | 13 px (SP) / 14 px (SA) | 600 | 1.3 | Assistant bubble name **"NowPilot"** (muted `colorTextSecondary`; DESIGN_SYSTEM.md §6.3 name row). |
| Heading | 16 px | 600 | 1.3 | Not used by the Phase-3 minimal chat (page titles already exist in the shells; no new headings). |

Additional rules (DESIGN_SYSTEM.md §5 + 01-UI-SPEC):

- **Mono (JetBrains Mono)** reserved for code, operation IDs, model IDs — the Phase-3 chat does not render any (no model tag, no Thought process — fenced D-03). If an error caption ever needs the §C.2 code, it renders mono — but the Phase-3 contract sends codes to `debugLog`, not the UI (R-10; see Error state).
- **`motion`-driven text reveals are forbidden on streamed chat** (spec §12.6) — no typewriter effect. ChunkBuffer rAF flushing is the only text animation.

## Color

Phase-1 60/30/10 contract (DESIGN_SYSTEM.md §6.2 + 01-UI-SPEC) is inherited verbatim; every colour is an AntD v6 design token, **no hex in components**. The values below are the `default` pack seeds.

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `colorBgBase` — light `#FCFCFD` / dark `#0E1117` | Conversation-area fill behind the bubbles; app background. |
| Secondary (30%) | `colorBgContainer` — light `#FFFFFF` / dark `#161A22` | Assistant bubbles (`variant="filled"`), Sender input surface. |
| Accent (10%) | `colorPrimary` — light `#3B82F6` / dark `#5B9BFF` | See "Accent reserved for" list below. |
| Semantic — Error | `colorError` — light `#EF4444` / dark `#F87171` | Failed-stream error line in the assistant bubble (semantic, not destructive). |
| Text | `colorTextBase` — light `#1F2430` / dark `#E6E8ED` | Body text. |
| Secondary text | `colorTextSecondary` | Assistant identity name "NowPilot", empty-state cue. |
| Tertiary text | `colorTextTertiary` | Sender placeholder, offline notice, muted helper copy. |
| Border | `colorBorder` — light `#E7E9EE` / dark `#252B36` | Assistant bubble 1 px outline, dividers. |

### Accent reserved for (EXCLUSIVE list — Phase-3 subset of the Phase-1 list)

`colorPrimary` is reserved for these Phase-3 surfaces **only**:

1. **Send button enabled state** — circular send inside the Sender, bottom-right, `colorPrimary` when the input is non-empty **and** idle (DESIGN_SYSTEM.md §8.1d). Disabled state is neutral `colorFillTertiary`, never accent.
2. **Focus ring** — visible 2 px `colorPrimary` ring on the Sender, send button, and Retry action (DESIGN_SYSTEM.md §12, WCAG AA).
3. **Streaming tail caret** — X `Bubble streaming` caret at `colorPrimary` 60% alpha (DESIGN_SYSTEM.md §6.3). **Never a spinner.**
4. **Retry text action** — the failed-bubble Retry action renders as `colorPrimary` text link (same pattern as the "Set up" link text, DESIGN_SYSTEM.md §8.6/§9).
5. **Active composer accent** — focused Sender ring at `colorPrimary` 30% alpha (DESIGN_SYSTEM.md §8.1d).

**Not accent:** hover on plain text, disabled controls, the empty-state cue, the offline notice, neutral borders, bubble fills (assistant = `colorBgContainer`, user = `colorPrimaryBg`/`colorPrimary` @18%, which are fills, not accent surfaces).

### User bubble fill (semantic, not accent)

User bubble: `colorPrimaryBg` (light) / `colorPrimary` @18% alpha (dark) — this is a **fill** recipe (DESIGN_SYSTEM.md §6.3), not the accent reservation.

### Destructive colour usage

**No destructive user action in Phase 3** (no delete, no clear, no irreversible write). `colorError` is used only for the **semantic error line** in the failed assistant bubble (matching the Phase-1 E2/E3 pattern: streamed-response errors surface inline in `colorError`). No destructive confirm flow exists this phase.

### Persona-copy implications (Phase-3 persona seed)

The persona pipeline (PersonaProfile + PersonaInjector + `np_persona` accessor, D-09) is a **prompt-side** deliverable — its UI (persona editor, header) is Phase 7 (D-10). UI contract:

- The assistant identity in the UI is **always "NowPilot"** — never the persona name (persona header fenced D-03; DESIGN_SYSTEM.md §6.3 name row). Persona `name` overrides affect only the model prompt.
- Persona overrides (name/tone/brevity) apply **invisibly** — zero UI presence in Phase 3. No persona chip, no persona error surface.

## Visual Hierarchy & Focal Points

### Phase-3 minimal chat (both surfaces, top → bottom in reading order)

1. **Conversation area (fills, scrolls)** — the primary visual field. In the empty state, the centered one-liner "Start a conversation" is the only anchor. In use, the most recent assistant message (streaming tail) is the anchor; `overflow-anchor:none` keeps the tail pinned (DESIGN_SYSTEM.md §8.1b).
2. **Sender (fixed bottom)** — the last scan target and the only interactive focus in Phase 3: pill input (radius 12, `colorBgContainer`, focus ring `colorPrimary` @30%) with the circular send button inside bottom-right. No toolbar, no status bar, no model selector (all Phase 7).

### Streaming focal point

During a stream the assistant tail bubble is the focal point — its `streaming` caret (`colorPrimary` @60%) is the only motion; text grows in place via ChunkBuffer. The Sender send button flips to disabled. Nothing else moves (no spinners, no stage pills — stage indicators fenced D-03).

### Icon-only control accessibility

| Control | Surface | `aria-label` / tooltip |
|---------|---------|------------------------|
| Send | Sender (bottom-right, circular) | "Send" |
| Retry | Failed assistant bubble (text link) | Text label "Retry" (not icon-only; no aria-label needed) |

All controls meet the **≥ 32 px (compact) / ≥ 36 px (standalone)** touch-target rule (DESIGN_SYSTEM.md §12).

### Accessibility (inherited, binding)

- **aria-live:** the bubble list is `role="log"` with `aria-live="polite"` (spec §17.6) — streamed text announces politely, never assertively.
- **Focus:** 2 px `colorPrimary` ring on the Sender + send + Retry.
- **Colour is never the only signal:** the failed bubble pairs `colorError` text with the "Provider error." copy + a labeled Retry action — never colour alone.

## Interaction Contract — Minimal Streaming Chat (Bubble/Sender composition)

Locked by 03-CONTEXT D-01 (AntD X `Bubble` + `Sender`; ChunkBuffer + co-located hook on the `useStreamingLLM` path, 3-state lifecycle skeleton → minimal → full; Phase 7 promotes the hook to `src/hooks/useStreamingLLM.ts`), D-02 (send via `runAgentTurn` with a hand-built `OptimizedContext` from a core helper — never React-side prompt assembly), D-03 (fencing), and spec §17.5 (one stream per session).

### ChatPage composition (shared by both shells)

```
ChatPage (ErrorBoundary-wrapped)
├── Conversation area   — flex-1, overflow-y: auto, overflow-anchor: none
│   ├── [loading]     ChatPageSkeleton (avatar + 3 paragraph rows)
│   ├── [empty]       centered one-liner STR.chat.empty (colorTextTertiary)
│   └── [populated]   X BubbleList — role="log", aria-live="polite"
│       ├── user bubble      placement="end", variant="filled", fill colorPrimaryBg (light)
│       │                    / colorPrimary @18% (dark), radius 12
│       └── assistant bubble placement="start", variant="filled", fill colorBgContainer,
│                            radius 12, 1px colorBorder, name="NowPilot"
│                            (no model id, no Thought process — fenced D-03)
└── Sender (fixed bottom)   — pill radius 12, colorBgContainer, focus ring colorPrimary @30%
    ├── placeholder STR.chat.askPlaceholder
    ├── value/onChange controlled; onSubmit → co-located hook send(userInput)
    └── send button: circular SendOutlined bottom-right; colorPrimary when non-empty AND idle
```

Composer ownership: the Sender lives **inside ChatPage** (D-01), which both shells render. The Side Panel shell's Phase-1 disabled `Input` footer placeholder is **replaced** when a provider is active (no double composer); the shell keeps only the no-provider gate (Alert) for the unconfigured case. The Standalone Chat page renders the same ChatPage at default density (DESIGN_SYSTEM.md §8.2 "reuses the §8.1 composer/bubble recipes").

### Stream state machine (surface contract)

State source: the co-located hook's stream state (Appendix J.2 reference shape — `idle / streaming / completed / failed`, with `operationId`; §20.6 `ActiveStreamState` minus `preparing`/`waiting-for-permission`/`aborting` variants, which Phase 3 does not render).

| Surface state | Trigger | What renders | Sender behavior |
|---------------|---------|--------------|-----------------|
| idle (empty) | no run, zero bubbles | centered "Start a conversation" cue | send disabled (input empty) |
| idle (populated) | no run, bubbles present | last completed bubbles, tail anchored | send `colorPrimary` when input non-empty |
| streaming | send → `runAgentTurn` starts | assistant Bubble appended **immediately** with `streaming=true` → caret `colorPrimary` @60%; text grows via ChunkBuffer flush (rAF ≤ 16 ms, 8 kB/s → 33 ms rule, Appendix J.1); tail scrolls into view | **send disabled** (one stream per session, spec §17.5; no stop control — abort UI is Phase 7a MM-03) |
| completed | `AgentTurnOutput.streamedText` fully flushed | final text in the assistant bubble; caret removed | send re-enabled |
| failed | thrown error (code/message) | assistant bubble retains any partial text; below it an inline error line: **"Provider error."** (`colorError`) + **Retry** action (`colorPrimary` text link); §C.2 code → `debugLog` (R-10) | send re-enabled |
| offline | NETWORK-class failure after router retries (D-17) | muted inline notice "No network. Retrying when back online." (`colorTextTertiary`, 12 px) above the Sender; Retry path unchanged | send enabled (retry re-sends) |
| provider-unconfigured | registry has no active provider — incl. `PROVIDER_KEY_UNREADABLE`-disabled providers (D-21) | **ChatPage not rendered**; shell gate Alert "Configure an AI provider in Settings first." (unchanged Phase-1; disabled input) | n/a (surface gated) |

Retry semantics: **Retry re-sends the last user input** through the same `runAgentTurn` path (new operationId). The failed bubble's partial text is replaced by the new attempt's stream. `[Switch Provider]` (the second `STR.chat.errorRetry` token) is **not rendered in Phase 3** — the provider-options forms are Phase 7 (D-10/D-21); the canonical string stays untouched (Golden Rule 2), the action is simply omitted this phase.

### Fenced out of Phase 3 (do not build)

Welcome cards, Prompts, clarification/follow-up chips, persona header, stage indicators (Thought process / model tag), chat-history persistence in the message list (ChatHistoryDB consumers = Phase 7), Agent toggle, action panels (copy/regenerate/quote/like…), composer toolbar (model selector, Attach, History, New chat), status bar, provider dialog, stop/abort control (D-03, D-10, D-21, DESIGN_SYSTEM §8.1f/§8.1g).
