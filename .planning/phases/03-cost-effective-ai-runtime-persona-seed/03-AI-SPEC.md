## 1. System Classification

**System Type:** Hybrid — Conversational chat surface + bounded Planner→Executor→Renderer autonomous loop (one-role, single-agent)

**Description:**
NowPilot's Phase-3 runtime is a local-first, four-provider AI chat assistant living in a Chrome extension (Side Panel and Standalone surfaces). The user types a message; a bounded Planner→Executor→Renderer loop drives it: a cheap "haiku"-tier model decides (`answer` / `run_tool` / `ask_clarification`) against a closed Zod schema, a fully deterministic Executor validates and runs the single safe tool (`get-provider-info`), and a "flash"-tier model streams the final answer into the chat Bubble through a throttled ChunkBuffer. The user picks one of four providers (OpenAI, Anthropic, Gemini, or a local Ollama/OpenAI-compatible endpoint) with keys held in the encrypted vault; a ProviderRouter does cheapest-capable routing with fallback, circuit breaking, and exactly three non-multiplying retry layers, while a persona block (user config, `np_persona`) is injected byte-stably into every prompt so answers match the user's tone and brevity preferences without breaking provider prompt caching. "Good" looks like: a healthy turn costs exactly 2 model calls (planner + renderer), answers arrive streaming with honest failure states, no data leaves the machine except to the provider the user deliberately configured, and the assistant consistently sounds like the persona the user set.

**Critical Failure Modes:**
<!-- The 3-5 behaviors that absolutely cannot go wrong in this system -->
1. **Local data reaches the wrong provider.** A fallback or routing decision sends local-only user content — or a vault-decrypted API key — to a provider/endpoint the user did not configure, or a TraceRedactor bypass logs raw prompts/secrets. Violates the product's core value ("no data leaves the machine unless the user deliberately configures a cloud provider"); destroys user trust irreversibly (D-13, R-10).
2. **Silently truncated stream rendered as a complete answer.** A mid-stream failure (error event, abort, `finishReason !== 'stop'`) is presented to the user as a finished reply; the user acts on an incomplete draft or summary believing it complete (Pitfall 5 — `streamText` never throws mid-stream).
3. **Stacked or unbounded retries multiplying cost.** SDK-internal retries (default `maxRetries: 2`) stack on the ProviderRouter retry layer on flaky networks, or a repair loop re-enters, or tier caps are not enforced — a single turn becomes many paid model calls and the loop does not terminate (R-2, §1.6.1, D-15).
4. **Invalid planner decision executed or silently coerced.** A decision that fails Zod validation is hand-parsed, repaired more than once, or a stray `run_tool` with zero registered tools reaches the Executor — execution runs on unvalidated input (Golden Rule 4, D-05/D-19).
5. **Persona drift or cache-breaking persona block.** The persona block changes byte-wise across turns for the same persona (killing provider prompt-cache hits and multiplying per-turn cost), or the persona silently stops applying mid-session so the assistant's tone/length contradict the user's configured persona (Appendix N.2, RICH-R-02).

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Developer tooling / personal productivity assistant — a privacy-first, local-first consumer Chrome extension (no healthcare/legal/financial regulated vertical)

**User Population:** Individual developer-user or knowledge worker running NowPilot as a personal copilot in the Chrome Side Panel or Standalone tab; single-user workspace on their own machine, with their own notes/pages and their own provider API keys. The practitioner = the user: they evaluate the assistant by whether it helps their own work without leaking their data or draining their API budget.

**Stakes Level:** High — no life-safety and no regulated advice, but the system handles the user's private personal data and spends the user's own money; a privacy breach or a cost blowup is a direct, personal harm that erodes trust in the product's core value (REQUIREMENTS.md: "no data leaves the machine unless the user deliberately configures a cloud provider").

**Output Consequence:** Drafts, summaries, answers, and clarification questions are read and acted on in the user's personal workflow; planner decisions gate tool execution (one tool in Phase 3, `get-provider-info`); every network-touching path carries a privacy consequence because the default promise is local-first — the assistant is trusted with content the user did not intend to send anywhere.

### Known Failure Modes in This Domain

1. **Silent local→cloud failover (the local-first promise breaker).** Fallback chains are designed for availability/cost, but in a local-first assistant they are also a privacy decision. If the chain is traversed on a local-provider failure without consulting `privacyMode` (`'prefer-local'` default), the user's message — and, later phases, their notes — goes to a cloud provider they never configured. The D-13 "no silent local→cloud switch" guarantee must be enforced in ProviderRouter, not left to resolveTier filtering, and every fallback hop should be observable (debugLog) and, where the mode demands it, user-visible.
2. **"Successful-looking" silent failure (the Entropy-class failure).** Agent-systems research (arXiv 2606.08162: 40,000+ trials, 100,000+ interactions) shows failures with no external trigger — no error, no injection — that accumulate as output consistency and task accuracy degrade and are routinely misattributed to bugs or config. In this runtime the concrete instances are: a stream that fails mid-way and renders as complete (Pitfall 5), and a retry that masks a worse response than the original request. Monitoring status codes and token counts cannot see these — the eval must sample the rendered *output*, not just the trace (Tessary.ai monitoring analysis).
3. **Cost blowup on long or flaky sessions.** The circuit breaker opens only after 3 failures in 60s (then 5 min); the monthly budget (AI-04) is deliberately deferred to Phase 6 (D-16). Between those two gaps, the Phase-3 defenses are the only spend control: SDK `maxRetries: 0` (the SDK silently defaults to 2 — a hidden 4th retry layer), explicit `maxTokens`, tier caps at the orchestrator, and prompt-cache preservation via byte-stable sections. Each of these individually failing is a bug; all failing on a flaky network is a real dollar loss the user notices on their provider bill.
4. **Secrets-in-prompt / secrets-in-log.** The privacy-scorecard research found a near-universal industry failure to proactively filter secrets from prompts and logs. This runtime handles vault-decrypted API keys on every turn; any provider-request or debug-log path that bypasses TraceRedactor leaks the key or the prompt body. Because this is the user's own machine and own key, the failure is silent until the key is abused.

### Regulatory / Compliance Context

No sectoral regulation applies (no medical/legal/financial advice). Directly relevant constraints for this deployment context:

- **GDPR (EU) / CCPA (CA) data-minimisation framing:** the local-first default is the product's minimization story — the default path transmits no personal data. Exposure exists only on the cloud path, where the user deliberately supplies their own API key: the user is the data controller and the extension is a local intermediary. The eval should treat any *unintended* transmission (failure modes 1 and 4 above) as a compliance-relevant defect, not merely a bug.
- **Chrome Web Store data-safety disclosure:** an extension that can transmit user data to third-party endpoints (the cloud path) must disclose that in its store listing; the listing's "no data collection" claim is only defensible if the local-only mode genuinely never transmits. Eval must verify the transmission claim matches behavior.
- **Provider terms-of-service transparency:** when the user's own key is used, their content flows to OpenAI/Anthropic/Google under those providers' terms — surfaced at config time (Phase-7 Options UI); eval should verify no silent or undisclosed transmission channel exists.
- Not applicable here: HIPAA, FCA, PCI-DSS, FINRA — no regulated data types are in scope.

## 2. Framework Decision

**Selected Framework:** Vercel AI SDK

**Version:** `ai` ^4 + `@ai-sdk/openai` ^1, `@ai-sdk/anthropic` ^1, `@ai-sdk/google` ^1 (no `@ai-sdk/ollama` — 404, Ollama rides the openai factory, §10.2)

**Rationale:**
The ai-sdk's per-provider LanguageModel adapters give the ProviderRouter exactly the thin unified invocation layer it needs for the four locked provider IDs (`openai` | `anthropic` | `gemini` | `ollama`) plus the OpenAI-compatible custom-baseURL variant (D-12), while leaving provider selection, fallback, circuit breaking, and per-provider `jsonMode` capability entirely under app control (D-18) — matching the spec's `ILLMProvider`/`getAISDKModel` contract verbatim. `streamText` delivers the SSE/text streaming AI-03 requires, and its first-class Zod integration (`generateObject`/`structuredOutput`) underpins Golden Rule 4's `requestJson` path. It is the only candidate that simultaneously satisfies TypeScript-only, model-agnostic, local-ollama support, and the AGENTS.md §7 approved-stack hard constraint. (Confirmed by `gsd-framework-selector`; alternatives table above.)

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain / LangGraph (TS) | Banned by approved stack §7 (package hygiene = hard constraint); graph overhead unnecessary for a bounded single-agent loop; buries the per-provider JSON-mode capability the Router must own (D-18) |
| OpenAI Agents SDK | OpenAI vendor lock-in; weak local-model (ollama) path; four-ID provider enum requires model-agnostic |
| the agent Agent SDK | Claude-only lock-in; violates the four-provider requirement |
| CrewAI / Haystack / Google ADK / AutoGen | Python-only (WXT/TS extension cannot run them) |
| Hand-rolled fetch + SSE + Zod adapter | Would re-implement streaming, retries, native-JSON flags, and tool-calling across four providers — the exact cost the ai-sdk's narrow adapter layer removes |

**Vendor Lock-In Accepted:** No — model-agnostic by design; each provider is a thin per-provider adapter behind the `ILLMProvider` contract, so swapping the SDK layer would not change the routing/cost model.

### Entry Point Pattern

Self-contained: the §10.1 `getAISDKModel` factory switch (the only place provider packages are imported), one Zod-validated Planner decision, one streaming Renderer turn.

```ts
import { createOpenAI } from '@ai-sdk/openai';
import { createAnthropic } from '@ai-sdk/anthropic';
import { createGoogleGenerativeAI } from '@ai-sdk/google';
import { generateObject, streamText, zodSchema, type LanguageModel } from 'ai';
import { z } from 'zod';
import { PROMPTS } from '@/core/prompts'; // Appendix A canonical constants (project module, byte-stable)
import type { PromptSection } from '@/core/ai/types'; // D-07 seed (F-4: callback consumes sections, not a joined string)

/** §10.1 getAISDKModel — one factory switch, shared by all four adapters + OpenAICompat (D-12). */
export function getAISDKModel(
  providerId: 'openai' | 'anthropic' | 'gemini' | 'ollama',
  model: string,
  cfg: { apiKey?: string; baseURL?: string },
): LanguageModel {
  switch (providerId) {
    case 'openai':
      // OpenAI, OpenAI-compatible (DeepSeek…), and Ollama-local all use this factory;
      // baseURL + apiKey differentiate them. 'compatible' = 3rd-party safe (no newer fields sent).
      return createOpenAI({ apiKey: cfg.apiKey, baseURL: cfg.baseURL, compatibility: 'compatible' })(model);
    case 'anthropic':
      return createAnthropic({ apiKey: cfg.apiKey, baseURL: cfg.baseURL })(model);
    case 'gemini':
      return createGoogleGenerativeAI({ apiKey: cfg.apiKey, baseURL: cfg.baseURL })(model);
    case 'ollama': // §10.2: no @ai-sdk/ollama package exists — OpenAI-compatible endpoint
      return createOpenAI({ apiKey: 'ollama', baseURL: cfg.baseURL ?? 'http://localhost:11434/v1', compatibility: 'compatible' })(model);
  }
}

/** Planner decision schema — §1.2 verbatim (discriminated union keeps `action` closed). */
const PlannerDecisionSchema = z.discriminatedUnion('action', [
  z.object({ action: z.literal('answer'), reasonCode: z.string().max(64) }),
  z.object({ action: z.literal('run_tool'), toolName: z.string().max(64), input: z.unknown() }),
  z.object({ action: z.literal('ask_clarification'), question: z.string().max(200), options: z.array(z.string().max(60)).max(4).default([]) }),
]);

/** One planner turn — native JSON mode (D-18). apiKey/baseURL come from the vault-decrypted ProviderConfig (Phase-3 wiring). */
export async function examplePlannerTurn() {
  const model = getAISDKModel('anthropic', 'claude-haiku-4-latest', { apiKey: 'sk-…from-vault' });
  const { object } = await generateObject({
    model,
    schema: zodSchema(PlannerDecisionSchema),      // F-7: always zodSchema()-wrapped (never raw Zod)
    mode: 'auto',                                  // 'auto' | 'json' | 'tool' — resolved by the Router (D-18)
    // F-5: cached [SYSTEM] travels as a CoreSystemMessage carrying the Anthropic cache hint —
    // ai@4's `system: string` CANNOT carry cacheControl (silently dropped), so use messages[].
    messages: [
      { role: 'system', content: PROMPTS.planner.system,   // [SYSTEM: cached], byte-stable (§1.3)
        providerOptions: { anthropic: { cacheControl: { type: 'ephemeral' } } } },
      { role: 'user', content: 'Can you summarize this page?' },   // [USER INPUT] — never cached
    ],
    maxTokens: 256,                                // §1.2 planner cap; explicit, never unbounded
    maxRetries: 0,                                 // CRITICAL: SDK default is 2; Router owns retries (D-17, R-2)
  });
  return object;                                   // typed: { action: 'answer' | 'run_tool' | 'ask_clarification', … }
}

/** One renderer turn — stream deltas for the chat surface (AI-03). */
export async function exampleRendererStream(abortSignal: AbortSignal, onDelta: (d: string) => void) {
  const model = getAISDKModel('gemini', 'gemini-2.5-flash', { apiKey: 'sk-…from-vault' });
  const result = streamText({
    model,
    // F-5: same messages[]+providerOptions cache path (dormant on gemini; correct on an anthropic fallback).
    messages: [
      { role: 'system', content: PROMPTS.renderer.system,   // [SYSTEM: cached] (§1.3)
        providerOptions: { anthropic: { cacheControl: { type: 'ephemeral' } } } },
      { role: 'user', content: '…' },              // assembled OptimizedContext task sections (D-02 helper)
    ],
    maxTokens: 512,                                // §1.2 renderer cap
    maxRetries: 0,
    abortSignal,
  });
  try {
    for await (const delta of result.textStream) onDelta(delta);  // → StreamAdapter → ChunkBuffer
    await result.finishReason;                     // ai@4: members are Promises; await individually to surface stream errors
  } catch (e) {
    // Golden Rule 9: debugLog with a canonical §C.2 code (e.g. STREAM_FAILED) — never swallow
  }
}
```

### Common Pitfalls

1. **`maxRetries` silently defaults to 2 inside the SDK** (verified in `ai@4.3.19` dist: `maxRetries = 2`). Every SDK call re-issues transport failures on its own — a **hidden 4th retry layer** stacked on top of the ProviderRouter retry (D-17), a direct §1.6.1 / R-2 violation and a real cost multiplier on flaky networks. **Pass `maxRetries: 0` in every call the Router constructs**; the Router alone owns retryable TIMEOUT/PROVIDER_5XX/NETWORK/RATE_LIMITED handling.
2. **`@ai-sdk/ollama` is not published** (npm 404, zero versions — verified). Installing it fails the build. The Ollama adapter uses `createOpenAI({ apiKey: 'ollama', baseURL: 'http://localhost:11434/v1', compatibility: 'compatible' })` exactly as §10.2 specifies. Planner task: amend the stale AGENTS.md §7 stack line.
3. **Parameter name is `maxTokens`, not `maxOutputTokens`.** `maxOutputTokens` (and `Output.object()`, and thenable results) are ai@5+ — copying today's ai-sdk.dev v7 docs into this codebase fails typecheck. When in doubt, read `node_modules/ai/dist/index.d.ts`, not the live docs.
4. **Provider line versions must pair with `ai@^4`:** `@ai-sdk/openai@^1` (not `^2`), `@ai-sdk/anthropic@^1`, `@ai-sdk/google@^1`. The `@ai-sdk/*@2.x/4.x` lines target ai@5+ and break `LanguageModelV1` compatibility. Pin the v1 line explicitly in package.json — never `"latest"`.
5. **`streamText` does not throw mid-stream** — errors become stream events (`onError` callback; error part in `fullStream`; `textStream` throws on iteration). A UI that consumes only deltas and never awaits the result promises renders silently-truncated text on failure. Always `await result.finishReason` (or `result.text`) after the loop and route failures through `debugLog` with a canonical §C.2 code (Golden Rule 9). Also: `await result` destructuring does **not** work in ai@4 (not thenable) — await each member individually.
6. **Do not wire SDK tool-calling into the Planner.** ai@4's `generateObject` has **no `tools` parameter**; the spec's loop is app-owned (R-4 — Planner requests, ExecutorService validates + runs, §1.2). Passing `tools`/raising `maxSteps` re-introduces LLM-controlled execution and defeats the deterministic Executor. The `tool()` helper stays unused in v0.1; Phase 8 MCP tools still run through ExecutorService.
7. **Leave `experimental_repairText` / `experimental_repairToolCall` unset.** ai@4 ships experimental SDK-internal repair hooks; wiring them adds a second repair mechanism nested inside the app's single Appendix L repair (D-19, R-2). The app's `requestJson` + one `PROMPTS.repairJson` repair is the only repair.

## 4. Implementation Guidance

**Model Configuration:**

Models are resolved at request time by `TierResolver.resolveTier` (Appendix D) — the tables below are the candidate pools, never hard-coded model names elsewhere (the resolver never invents a model).

| Stage (tier) | Candidates (Appendix D) | maxTokens | temperature | maxRetries |
|---|---|---|---|---|
| Planner (haiku) | `anthropic/claude-haiku-4-latest` · `openai/deepseek-chat` · `ollama/llama3.2:3b` | 256 (decision JSON; §1.2 3s timeout) | 0 (SDK default — set explicitly) | **0** |
| Repair (haiku) | same haiku pool | 256 | 0 | 0 |
| Renderer (flash) | `gemini/gemini-2.5-flash` · `anthropic/claude-haiku-4-latest` · `openai/deepseek-chat` · `ollama/qwen2.5:7b` | 512 (§1.2 renderer cap) | 0 | 0 |
| MemoryExtractor (haiku) | haiku pool (stage accepted by `PersonaInjector.inject` now; call site lands Phase 5, D-11) | 256 | 0 | 0 |

- **`maxRetries: 0` everywhere** — ProviderRouter (D-17) is the single retry layer before the first token; SDK-internal retries would be a hidden 4th layer (R-2, Pitfall 1).
- **`abortSignal`:** the `runAgentTurn` signal (Appendix I) passes unchanged into every call via CallSettings; Appendix L re-parents it into a per-attempt `AbortController` with `timeoutMs` (planner 3s / renderer 5s, §1.2).
- **`temperature: 0`** for all v0.1 stages (deterministic planner/renderer); ollama may ignore it (provider-dependent — acceptable).
- **`headers`:** per-provider headers belong in the adapter's factory options (e.g. `HTTP-Referer` for ollama), not per-call; TraceRedactor (R-10) wraps every provider request/response before logging.

**Core Pattern:**

The runtime is `runAgentTurn` (Appendix I **verbatim** — D-20: no trajectory states, no CompletionEvidence) driving `PlannerService → ExecutorService → RendererService`. The ai-sdk appears in exactly three seams:

**Seam 1 — `getAISDKModel(model, config)` (§10.1).** The single factory switch in Section 3's entry point. All four adapters + OpenAICompat (D-12) return a `LanguageModel`; nothing outside this function imports a provider package.

**Seam 2 — `callProviderJsonMode`, constructed by ProviderRouter (D-18).** The Router resolves the per-provider `jsonMode: 'native' | 'prompt'` capability (Ollama → `'prompt'` unless the model advertises native JSON; OpenAI/Anthropic/Gemini → `'native'`) and closes over the resolved `(providerId, model)`. Consumers (PlannerService, RendererService) stay pure — they just call `requestJson(schema, prompt, ctx)` (Appendix L).

```ts
// src/core/ai/ProviderRouter.ts (implementation sketch — D-18/D-19)
import { generateObject, generateText, zodSchema, type LanguageModel } from 'ai';
import { z } from 'zod';
import type { ProviderId } from './types';

export type JsonMode = 'native' | 'prompt';

/**
 * D-18: only the Router hands out this callback — after a failover the resolved
 * (providerId, model, jsonMode) triple changes, and only the Router knows the
 * new provider's JSON capability. Returns a Promise<string> per Appendix L.
 * `schema` is the Zod schema (native path); `jsonSchema` is used for the prompt path.
 */
// F-4: PromptSection[] signature (NOT a pre-joined string) removes the fragile
// `prompt.split('\n\n')[0]` [SYSTEM] recovery that mis-slices when a cached section
// (persona block, tool schemas) contains a blank line. PromptSection is seeded in
// src/core/ai/types.ts (D-07), so the Router already holds the type.
const CACHED_KINDS: PromptSection['kind'][] = ['system', 'tool_schemas', 'preferences', 'memory'];
const TASK_KINDS:   PromptSection['kind'][] = ['context', 'task', 'user_input'];
const joinSections = (secs: PromptSection[], kinds: PromptSection['kind'][]) =>
  secs.filter(s => kinds.includes(s.kind)).map(s => s.text).join('\n\n');

export function buildCallProviderJsonMode(
  providerId: ProviderId,
  model: LanguageModel,
  jsonMode: JsonMode,
  schema: z.ZodType,
): (sections: PromptSection[], jsonSchema: unknown, signal: AbortSignal) => Promise<string> {
  return async (sections: PromptSection[], jsonSchema: unknown, signal: AbortSignal) => {
    const systemText = joinSections(sections, CACHED_KINDS);   // deterministic [SYSTEM: cached]
    const taskText   = joinSections(sections, TASK_KINDS);     // [CONTEXT]+[TASK]+[USER INPUT]
    if (jsonMode === 'native') {
      // SDK validates against the Zod schema internally; NoObjectGeneratedError on failure.
      const { object } = await generateObject({
        model,
        schema: zodSchema(schema),   // F-7: always zodSchema()-wrapped
        mode: 'auto',                // provider picks 'tool'/'json' best strategy
        // F-5: cached [SYSTEM] travels as a CoreSystemMessage carrying the Anthropic cache hint —
        // ai@4's `system: string` CANNOT carry cacheControl (silently dropped), so use messages[].
        // The Router threads this exact shape; joinSections output goes into the messages, never `system:`.
        messages: [
          { role: 'system', content: systemText,   // [SYSTEM: cached] — built from sections, never string-split
            providerOptions: { anthropic: { cacheControl: { type: 'ephemeral' } } } },
          { role: 'user', content: taskText },     // [TASK] + [USER INPUT]
        ],
        maxTokens: 256,
        maxRetries: 0,               // Router owns retries (D-17)
        abortSignal: signal,
      });
      return JSON.stringify(object); // guaranteed parseable — Appendix L's repair never fires here
    }
    // 'prompt' — Ollama default (D-18): schema embedded in [SYSTEM], raw text back.
    // Appendix L does prompt-only JSON coercion + exactly ONE repair (D-19).
    const { text } = await generateText({
      model,
      // F-5: same messages[]+providerOptions form (inert on ollama — no anthropic cache; consistent shape).
      messages: [
        { role: 'system', content: systemText + '\nReturn JSON only, matching this schema exactly:\n' + JSON.stringify(jsonSchema) },
        { role: 'user', content: taskText },
      ],
      maxTokens: 256,
      maxRetries: 0,
      abortSignal: signal,
    });
    return text;
  };
}
```

Notes on this seam:
- **Structured sections, not a joined string (F-4):** the callback signature is `(sections: PromptSection[], jsonSchema, signal)`. It maps cached kinds (`system`/`tool_schemas`/`preferences`/`memory`) → a `[SYSTEM]` CoreSystemMessage and task kinds (`context`/`task`/`user_input`) → the `[USER INPUT]` message via the pure `joinSections` helper — **replacing** the fragile `prompt.split('\n\n')[0]` recovery, which mis-sliced whenever a cached section (the multi-line persona block, tool schemas) contained a blank line. **Ripple (planner must thread):** Appendix L's `StructuredOutputContext.callProviderJsonMode` and `requestJson` pass the `PromptSection[]` through instead of a pre-joined prompt string; `PromptSection` is already seeded in `src/core/ai/types.ts` (D-07), so no new type is invented.
- **Schema handling (F-7):** native mode passes the Zod schema **always via `zodSchema()`** (never raw Zod, for example-consistency); `zodToJsonSchema` is used only for the prompt-mode `[SYSTEM]` text and the Appendix L repair prompt (`"Schema: <jsonSchema>"`). Never re-hydrate a JSON schema back into Zod.
- **Cache-hint wire path (F-5):** every constructed call uses the **`messages[]` form with a `CoreSystemMessage` carrying `providerOptions.anthropic.cacheControl`** — ai@4's `system: string` **cannot** carry the hint (silently dropped). `system:`/`prompt:` string keys are NOT used on any constructed call (the plans' verify greps assert no `system:` string literal). Below the model's cache minimum (Haiku 4.5 = 4,096 tok) the marker is ignored anyway, so Phase-3 prompts (~300–500 tok) never hit; **byte-stability + hint emission are the testable invariants**, live hits are a Phase-4+ payoff. This matches the F-5 mandate in plans 03-03/03-05/03-06 and the `examplePlannerTurn`/`exampleRendererStream` samples above — the earlier `system:`/`prompt:` seam sketch is superseded.
- **Timeout:** Appendix L's `timeoutMs` AbortController wraps this callback; the SDK's own `abortSignal` is wired to the inner controller.

**Seam 3 — RendererService streaming (AI-03).** `streamText` feeds StreamAdapter, which normalizes deltas to `LLMStreamChunk` before ChunkBuffer:

```ts
// src/core/ai/StreamAdapter.ts (sketch)
import { streamText, type LanguageModel } from 'ai';
import type { LLMStreamChunk } from './types';

export async function* streamTextToLLMChunks(args: {
  model: LanguageModel;
  system: string;                 // §1.3 [SYSTEM: cached] — persona block + PROMPTS.renderer.system
  task: string;                   // assembled OptimizedContext sections (D-02 helper)
  maxTokens: number;              // 512 (§1.2)
  abortSignal: AbortSignal;
}): AsyncIterable<LLMStreamChunk> {
  const result = streamText({
    model: args.model,
    // F-5: cached [SYSTEM] as a CoreSystemMessage carrying the Anthropic cache hint —
    // `system: string` cannot carry cacheControl; the person block must stay cacheable.
    messages: [
      { role: 'system', content: args.system,
        providerOptions: { anthropic: { cacheControl: { type: 'ephemeral' } } } },
      { role: 'user', content: args.task },
    ],
    maxTokens: args.maxTokens,
    maxRetries: 0,
    abortSignal: args.abortSignal,
  });
  try {
    for await (const delta of result.textStream) yield { type: 'text', content: delta };
    await result.finishReason;    // surface stream errors (Pitfall 5); ai@4 members are Promises
    yield { type: 'done', content: '' };
  } catch (e) {
    yield { type: 'error', content: e instanceof Error ? e.message : String(e) };
    // caller's catch: debugLog(code, …) with a canonical §C.2 code (Golden Rule 9)
  }
}
```

`runAgentTurn.finish()` collects `streamedText` from the Renderer, then the co-located hook (D-01) feeds it into `ChunkBuffer` (J.1, 8_000 B/s) for the Bubble UI. **`streamText` is only consumed inside RendererService/StreamAdapter** — PlannerService exclusively uses the awaited `generateObject` path (streaming a decision is useless: partial JSON fails Zod by construction).

**Tool Use:**

- **Exactly one tool in Phase 3:** `get-provider-info` (`dangerous: no`, reads the Phase-3 ProviderRegistry) — defined in `toolSchemas.ts` as a `ToolSchemaRef` (D-04).
- `ExecutorService` narrows `toolName` to a **closed `z.enum`** derived from the registered tools at request time (D-05: zero registered tools → the `run_tool` branch is **omitted** from `PlannerDecisionSchema`; a stray `run_tool` is rejected with `TOOL_REJECTED`).
- **The ai-sdk `tool()`/`tools` machinery is unused** (R-4, Pitfall 6). No `tools`/`maxSteps`/`toolChoice` ever reaches an SDK call; `generateObject` in ai@4 has no `tools` parameter anyway. `get-provider-info` executes deterministically in ExecutorService: reject unknown name → validate input schema → permission policy → capability check → run with timeout → validate output → `ToolExecutionResult` (§1.2 Executor rules).
- Phase 8 MCP tools also run through ExecutorService — SDK tool-calling is not planned even then; governance stays app-owned (§28.5, D-06).

**State Management:**

- **Per-turn, in-memory, per-surface (D-14):** `RouterAttemptState { operationId, attempts, hasStreamedFirstToken, circuitBreakerOpen }` lives on the Router for one `runAgentTurn`; dies on panel close. No persistence, no cross-surface sharing in v0.1.
- `ProviderRegistry` (Phase-1 gate) is **extended in place** (B3/R-1, D-21): provider config presence + the `PROVIDER_KEY_UNREADABLE` error-emission path (decrypt failure / cleared installSecret / tampered ciphertext = one state → `enabled: false`). Stays dependency-free — vault reads happen in the wiring layer (side panel/standalone mount, R-3); the typed error crosses that boundary.
- `OptimizedContext` (D-07) is seeded as a type in `src/core/ai/types.ts` and built by a **core helper** (D-02 — hand-built §2.3-shaped context from operationId/model/userInput/persona prefs/tool schema refs; recorded as a **Phase-4 deletion target**). No React-side prompt assembly (Golden Rule 3).
- **No chat-history persistence (D-03):** the message list is per-session state in the co-located hook; ChatHistoryDB consumers land Phase 7.
- **Persona config:** read-only `np_persona` accessor (D-09) → `PersonaProfileSchema`-validated → injected into `PersonaInjector` as a config provider (not imported); invalid/empty key → `PERSONA_LOAD_FAILED` → `DEFAULT_PERSONA`. Byte-stable serialization preserves prompt caching (§1.3). Zero-change handoff: Phase 5's PreferenceMemoryStore writer swaps only the injected provider (D-10).

**Context Window Strategy:**

- **Prompt shape is the strategy (§1.3):** every call uses the canonical section order `[SYSTEM cached] [TOOL SCHEMAS cached] [USER PREFERENCES compact] [MEMORY compact] [CONTEXT optimized] [TASK small] [USER INPUT current]`. Stable sections are byte-identical across calls → provider-side prompt cache hits (PromptCacheAdapter, Appendix K). The persona block is prepended inside cached `[SYSTEM]` and must stay byte-stable for a given persona (N.2, RICH-R-02).
- **Bounded loop caps bound context growth (§1.4):** AgentOrchestrator enforces plannerCap/toolCap per tier (tiny 1/1 … large 5/3). No unbounded `maxSteps` anywhere — the SDK never loops.
- **`maxTokens` is explicit on every call** (256/512/256) — no unbounded generation in production (4b.3).
- **Ollama default context is 2048 tokens** — the Ollama adapter must warn the user (Flow 5, §10.2); TierResolver treats it as tiny-tier unless `contextWindow` from ProviderConfig says otherwise.
- **Conversation summarisation is deferred wiring** (Phase 7 persistence) but the canonical `conversationSummarizer` prompt (Appendix A, haiku tier) is ready; when history grows it compacts prior turns into `[MEMORY: compact]` before the current `[USER INPUT]`. Context expansion/degradation beyond the window is Phase 4 (ContextOptimizer, §2.4) — the Phase-3 seed keeps sections ≤ `inputBudget` by construction (D-02 helper).
- **`ask_clarification` avoids wasted turns:** the planner returns one focused question + 0–4 chips in a single call (§1.2 note) — no full renderer turn spent on ambiguous input.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice. Adapted to TypeScript: the template's "Pydantic" role is played by **Zod** (`zod@^3` + `zod-to-json-schema@^3`, approved stack).

### Structured Outputs with Zod (Pydantic-equivalent in TypeScript)

**Output model = Zod schema, single source of truth.** For this system: the Planner decision (discriminated union, §1.2) and any structured renderer outputs.

```ts
import { z } from 'zod';
import { zodToJsonSchema } from 'zod-to-json-schema';

// Planner decision — §1.2 verbatim; the discriminated union keeps `action` closed
export const PlannerDecisionSchema = z.discriminatedUnion('action', [
  z.object({ action: z.literal('answer'), reasonCode: z.string().max(64) }),
  z.object({ action: z.literal('run_tool'), toolName: z.string().max(64), input: z.unknown() }),
  z.object({
    action: z.literal('ask_clarification'),
    question: z.string().max(200),
    options: z.array(z.string().max(60)).max(4).default([]),
  }),
]);
export type PlannerDecision = z.infer<typeof PlannerDecisionSchema>;

// Native path (openai/anthropic/gemini): ai@4 validates model output against the
// schema internally (generateObject), and requestJson re-validates at the boundary
// (Golden Rule 4: never hand-parse JSON; never trust raw strings).
//
// Prompt path (ollama, D-18/D-19): requestJson(PlannerDecisionSchema, plannerPrompt, ctx)
//   → callProviderJsonMode returns raw text → safeParse (fence-strip + JSON.parse + zod)
//   → fail → ONE repair: PROMPTS.repairJson.system + "Schema: <zodToJsonSchema(schema)>"
//     + "Broken: <first>" → safeParse again
//   → still invalid → throw STRUCTURED_OUTPUT_FAILED { retryable: false, raw: { first, second } }
```

**Framework integration (ai@4.3.19, verified):**
- **Native mode:** `generateObject({ model, schema: zodSchema(schema), mode: 'auto', maxRetries: 0 })` → `result.object` is typed + validated. On parse/validation failure it **throws `NoObjectGeneratedError`** — catch with `NoObjectGeneratedError.isInstance(err)`, log `err.text`/`err.usage` via `debugLog` (redacted, R-10), then let the Router's fallback/circuit-breaker decide (provider-level failures are the Router's domain, D-17).
- **Prompt mode:** `generateText` with the JSON schema embedded in `[SYSTEM]`; the raw string returns to `requestJson` for coercion + one repair (never `JSON.parse` directly on model output elsewhere).
- **`zodToJsonSchema`** is needed only for (a) the prompt-mode `[SYSTEM]` schema text and (b) the Appendix L repair prompt. Native mode passes the Zod schema directly — never serialize-then-rehydrate.

**Retry discipline (Golden Rule 4 + §1.6.1 / R-2):** exactly **one** repair attempt per request (`requestJson`); a second failure throws `STRUCTURED_OUTPUT_FAILED` (canonical §C.2 code, `retryable: false`) — never re-enter the repair loop, never let the SDK's `experimental_repairText` run (Pitfall 7). Log per step: first attempt OK/FAIL, repair OK/FAIL, final code. Surface only the final error code to the UI; raw payloads stay in redacted logs.

### Async-First Design

**How async works here:** ai@4 is fully Promise/stream based. `generateObject`/`generateText` are awaited; `streamText` starts the request eagerly and returns a result whose `textStream` is an `AsyncIterable<string>` (consume with `for await`) and whose `text`/`usage`/`finishReason` are **Promises to await individually** (ai@4 result is NOT thenable — `const { text } = await result` is a v5+ pattern). ChunkBuffer (J.1) is rAF/setTimeout-driven and pure — it never blocks the stream.

**The one common mistake in this codebase:** consuming `textStream` and **not** awaiting a terminal promise (`result.finishReason` / `result.text`) afterwards — mid-stream errors are delivered as stream events, not thrown, so a UI that renders deltas and returns looks successful on a failed turn (Pitfall 5). Corollaries: never `await result.text` twice (wasteful re-read); never start `streamText` and abandon it (leaks the request); never `await chrome.storage.session` writes *inside* the per-chunk consume loop (the hook sets session state before/after the turn, not per-chunk).

**Stream vs. await:** `streamText` for the Renderer/UI path (first-token latency is the UX; ChunkBuffer throttles display at 8_000 B/s). `generateObject` (awaited) for every validation-critical decision — Planner decisions and any output that gates execution — because a streaming partial object is un-validatable (incomplete data fails Zod by construction).

### Prompt Engineering Discipline

- **System vs. user separation (canonical, §1.3):** `[SYSTEM]` = PROMPTS constants (Appendix A — byte-stable, cacheable, tier-tagged) + persona block (PersonaInjector, N.2) + tool schemas. `[USER INPUT]` = the current turn only. Never interpolate the user's raw input into `[SYSTEM]` — it breaks prompt caching and lets the user steer the persona (injection surface).
- **Persona block is byte-stable for a given persona** (RICH-R-02): `buildPersonaBlock` produces ordered, stable serialization, so a persona change is the *only* thing that invalidates the cached `[SYSTEM]` section.
- **Few-shot:** inline, hand-authored examples for stable tasks (the planner's single JSON-decision format is self-demonstrating via the schema — no per-turn examples needed); dynamic retrieval-based few-shot is Phase 4 (ContextOptimizer). Do not grow `[SYSTEM]` per turn with conversational history — that belongs in `[MEMORY: compact]`.
- **`maxTokens` is always explicit** (planner 256 / renderer 512 / repair 256). Unbounded generation is forbidden in production — it risks runaway cost and stalls the bounded loop.
- **Canonical prompts are verbatim** (Appendix A): do not paraphrase `planner`/`renderer`/`repairJson`; `PROMPTS.repairJson.system` is quoted byte-for-byte in Appendix L.

### Context Window Management

This is a **Hybrid** system (conversational surface + bounded autonomous loop); the strategy splits by surface:

- **Autonomous loop (Planner→Executor→Renderer):** context growth is *bounded by construction* — §1.4 tier caps (1–5 planner calls, 1–3 tool calls) enforced only by AgentOrchestrator (Appendix I), and every stage call carries a fixed `maxTokens`. The SDK's `maxSteps` is never raised (no tools passed → stays 1). "Compaction" = the three non-multiplying retry layers (§1.6.1) + deterministic fallback to `{ action: 'answer', reasonCode: 'planner_failed' }` after a failed planner — the loop always terminates.
- **Conversational surface:** when history persistence lands (Phase 7), prior turns compact into `[MEMORY: compact]` via the canonical `conversationSummarizer` prompt (haiku tier) instead of replaying raw turns — decisions/preferences/open-tasks survive, verbosity doesn't. Phase 3's surface is single-turn (`[USER INPUT]` only), so nothing accumulates.
- **RAG (Phase 5/5a):** reranking/truncation will live in the `[CONTEXT: optimized]` section under ContextOptimizer (Phase 4); the seed's `inputBudget` is already part of `OptimizedContext` (D-07).
- **Provider floor:** ollama's 2048-token default context (Flow 5) forces tiny-tier behavior — warn the user; let TierResolver pick cloud candidates when the task needs more (privacy permitting, D-13).

### Cost and Latency Budget

**Per-call estimate (worst case, one turn):** planner 1 call + renderer 1 call + at most 1 repair + ≤1 fallback retry — all under the §1.4 caps. With `maxRetries: 0` and the Router's single retry layer, a healthy turn is exactly **2 model calls** (planner + renderer) regardless of provider.

| Model (Appendix D candidate) | Role | Order-of-magnitude cost/turn (~2K in + 0.5K out) | Notes |
|---|---|---|---|
| `claude-haiku-4-latest` | planner/renderer (cloud) | ~$0.004–0.01 | cheap tier; verify current list price at planning time |
| `deepseek-chat` | planner/renderer (via `openai` id + custom baseURL, D-12) | ~$0.002 | OpenAI-compatible; cheapest cloud candidate |
| `gemini-2.5-flash` | renderer (flash) | ~$0.002 | flash-tier workhorse |
| `llama3.2:3b` / `qwen2.5:7b` | local (ollama) | $0 (local) | latency: first token depends on local GPU/CPU |

> Prices are order-of-magnitude and move frequently — the planner must verify current list prices. The **bound** matters more than the number: three retry layers max, per-stage `maxTokens` caps, per-loop tier caps.

- **Caching:** (1) *Prompt caching* — the big win: byte-stable `[SYSTEM]`/`[TOOL SCHEMAS]` sections hit provider-side prompt caches on every repeated call (PromptCacheAdapter, Appendix K; hit/miss surfaced as debugLog); (2) *exact-match cache* — identical `[USER INPUT]` + section hash within a session returns the previous result without a call (keep the Router seam; harden Phase 4); (3) *semantic caching* is deferred (no vector store until Phase 5).
- **Sub-task routing (Appendix D):** haiku tier → planner, repair, memoryExtractor; flash tier → renderer. The cheap model does classification/routing; the flash candidate only renders the final answer. `resolveTier` + `fallbackChain` picks the cheapest *capable* provider — never inventing model names (Appendix D rule).
- **Latency guardrails:** circuit breaker (3 failures / 60s → open 5 min, D-17) stops hammering a dead provider; `hasStreamedFirstToken` freezes the provider mid-stream (§1.5 — never switch after the first token); planner 3s / renderer 5s timeouts (Appendix L `timeoutMs`) bound worst-case per-turn latency.
- **Monthly aggregate budget (AI-04) is Phase 6** (D-16): the Phase-3 seam is the no-op `budgetGuard` hook on ProviderRouter — do not build a ledger now.

## 5. Evaluation Strategy

**Strategy shape:** Phase 3 is a **test-suite-driven** phase — the §18 create-list ships 8 required test files under `tests/core/ai/**`, and every domain rubric ingredient in Section 1b is a *deterministically checkable invariant* (Zod validation outcomes, model-call counts, redaction assertions, byte-stability hashes, stream terminal states). Human review is the developer-user's real-usage sampling plus privacy-reviewer sign-off (Section 1b expert roles).

| **Privacy boundary honesty** (safety — user-facing) | **PASS:** With `privacyMode: 'prefer-local'` and a dead local (ollama) provider, the fallback chain is NOT traversed to a cloud provider — the turn ends in a visible provider-failure state and the hop refusal is debugLogged (redacted); TraceRedactor strips vault keys / prompt bodies / tool output from every provider-path debugLog line on all four adapters. **FAIL:** A dead local provider silently fails over to a cloud endpoint with the user's message in flight; a debugLog line contains a raw API key, prompt body, or tool output. | **Code** — ProviderRouter.test.ts fallback-chain assertions under `privacyModeFromPrefs` (D-13) with mock-fetch dead-local + healthy-cloud; TraceRedactor redaction assertions over a captured log sink on every provider path | **Critical** |
| **Cost discipline per turn** (cost/token adherence — agentic) | **PASS:** A healthy turn = exactly 2 model calls (planner + renderer) for every provider; planner failure falls back deterministically to `{action:'answer', reasonCode:'planner_failed'}` with no re-invocation; every SDK call carries `maxRetries: 0` and explicit `maxTokens` (256/512); retry layers never nest (≤3, one retry per layer); same-persona repeated turns hit the prompt cache (byte-stable `[SYSTEM]` hash). **FAIL:** One flaky-network turn becomes 4–6 paid calls (SDK-internal retry stacked on Router retry); a repair loop re-enters; tier caps (plannerCap/toolCap) exceeded; `[SYSTEM]` hash changes across turns with no persona change. | **Code** — AgentOrchestrator.test.ts model-call-count spies (exactly 2 on the healthy path); ProviderRouter.test.ts `RouterAttemptState` attempt-tracking (≤3 non-multiplying, `maxRetries: 0` asserted on constructed call settings); PromptCacheAdapter hash-equality assertions | **High** |

## 6. Guardrails

**Design rule:** every guardrail below is a deterministic, in-process, zero-LLM check — each adds ~0 latency and requires no network round-trip. Online guardrails protect the catastrophic failure modes (privacy breach, cost blowup, invalid execution); everything else is an offline flywheel signal.

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Privacy-mode fallback gate** (Critical) | Local (ollama) provider request fails AND `privacyMode === 'prefer-local'` (D-13 default) | **Block** any cloud hop in the fallback chain; terminate the turn in a visible provider-failure state; debugLog the refusal (redacted). Enforces "no silent local→cloud switch" (D-13) in ProviderRouter — never a resolveTier filter |
| **Retry-budget gate** (Critical) | `RouterAttemptState.attempts` would exceed the non-multiplying budget: SDK `maxRetries: 0` on every constructed call (Pitfall 1), one Router retry per retryable code, ≤3 layers total (R-2, §1.6.1) | **Block** further attempts; terminate the turn with a terminal `reasonCode`; never re-enter repair or fallback. A flaky-network turn is capped at budget — never 4–6 paid calls |
| **TraceRedactor boundary gate** (Critical) | Any debugLog / persist / UI / export write of a provider request, response, or tool output (R-10) | **Flag** = zero tolerance: redaction is applied at the boundary before the write; a redaction violation is a test-asserted failure and a sampled-review CRITICAL (Section 7) |
| **maxTokens / tier-cap gate** (High) | A call would exceed stage `maxTokens` (planner 256 / renderer 512 / repair 256) or the tier's plannerCap/toolCap (§1.4) | **Block** the call; terminate the loop with a cap-exhausted terminal state — never an unbounded or falsely-"completed" turn |
| **Streamed-completion gate** (High) | Stream ends with `finishReason !== 'stop'` or an error chunk (Pitfall 5 — `streamText` never throws mid-stream) | **Flag** → convert to the failed bubble state (visible `colorError`); never render as complete. `abortSignal` threaded through every call so cancel stops generation and no orphaned request bills tokens |

### Offline (Flywheel)

v0.1 reality: the flywheel is a **sampled batch review** of TraceRedactor-gated debugLog transcripts (operationId-attributed, canonical §C.2 codes), `RouterAttemptState` snapshots, and the Phase-2 ErrorStore IDB sink — there is no server telemetry to stream. Each degradation signal feeds the fixture matrix (a new regression fixture) and, where warranted, the §1.5 breaker parameters.

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| Per-turn model-call count (healthy = 2) | 100% of turns attribute calls via operationId in debugLog (cheap, in-process); weekly review of turns flagged > 2 | Retry-nesting suspected → add regression fixture to ProviderRouter/AgentOrchestrator tests; audit Router retryable-code classification (D-17) |
| Prompt-cache hit ratio per session (PromptCacheAdapter debugLog) | Sampled long sessions (≥ 20 turns) | Drop > 20% vs session baseline → persona byte-stability drift; add hash-drift fixture to PersonaInjector tests (RICH-R-02) |
| Circuit-breaker open/close + fallback-hop events | All breaker transitions debugLogged; fallback hops sampled | Over-hammering before open (full 60s window) → tighten failure threshold or surface provider-config fix; add fixture |
| Error-code distribution (`STRUCTURED_OUTPUT_FAILED` · `STREAM_FAILED` · `TOOL_REJECTED` · `PROVIDER_KEY_UNREADABLE` · `PERSONA_LOAD_FAILED` · `PLANNER_FAILED`) | ErrorStore sink (Phase 2), sampled review | Frequency spike → add failure-mode fixture; review repair/planner prompts (Appendix A verbatim rule) |
| Rendered-output completion honesty (Entropy-class silent failure, §1b) | Manual sampling: rendered streamed text vs chunk-log terminal state | Truncated-as-complete detected → add streaming-failure fixture; tighten ChunkBuffer/UI state machine (D-01 3-state lifecycle) |

## 7. Production Monitoring

**Tracing Tool:** **No external telemetry in v0.1 — explicit override of the ai-evals.md Arize Phoenix default.** Rationale: this is a local-first Chrome extension with no server, no production traffic, and no telemetry infrastructure; R-10 mandates TraceRedactor *before* any persist/UI/export; and structured tracing lands in Phase 6 (DIAG-01 `AITransactionLog`). The v0.1 baseline is **TraceRedactor-gated `debugLog`** (operationId-attributed, canonical §C.2 codes per Golden Rule 9) + in-memory `RouterAttemptState` (D-14) + the Phase-2 **ErrorStore** IDB sink.

**Deferred default (documented for Phase 6 DIAG-01 — not installed now):**
```python

# provider = TracerProvider()
# trace.set_tracer_provider(provider)
# Instrument the AITransactionLog write path (Phase 6), NOT provider calls directly.
```

**Key Metrics to Track:**
1. **Per-turn model-call count** — healthy = exactly 2 (planner + renderer); anything > 3 is a retry-nesting suspect
2. **First-token latency** — planner 3s / renderer 5s timeouts (Appendix L `timeoutMs`); renderer first-token is the UX-bound
3. **Circuit-breaker state transitions + fallback-hop count** — 3 failures / 60s → open 5 min (D-17); hops under `prefer-local` are privacy-relevant
4. **Prompt-cache hit ratio per session** — byte-stability proxy (RICH-R-02); drift = per-turn cost multiplier
5. **Redaction-violation count** — must stay **0** (R-10); any instance is a privacy-breach signal
6. **Error-code counts** — `STRUCTURED_OUTPUT_FAILED` / `STREAM_FAILED` / `TOOL_REJECTED` / `PROVIDER_KEY_UNREADABLE` / `PERSONA_LOAD_FAILED` / `PLANNER_FAILED`

**Alert Thresholds:** (v0.1 = log-scan triggers reviewed in-session / by the user, not paging — there is no server)
- **CRITICAL:** any redaction violation; any retry nesting > 3 layers; any local→cloud hop under `prefer-local`
- **HIGH:** turn model-call count > 3; renderer first-token > 5s; `STREAM_FAILED` without a visible error bubble
- **WARNING:** circuit breaker opens (flaky provider config); `STRUCTURED_OUTPUT_FAILED` rate rising
- **MEDIUM:** prompt-cache hit ratio drops > 20% vs session baseline (persona byte-stability drift)

**Smart Sampling Strategy:** weight human review toward interactions with concerning signals (ai-evals.md): (1) turns logged with any error code, (2) turns with > 2 model calls, (3) any fallback traversal (especially under `prefer-local`), (4) aborted/cancelled turns, (5) long sessions (≥ 20 turns) for the cache-hit trend. Plus the Entropy-class guard (Section 1b / Tessary insight): **sample the rendered output, not just the trace** — a batch of streamed Bubble texts compared against their chunk-log terminal states catches "successful-looking" silent truncation that status codes cannot. Phase-6 handoff seam: the no-op `budgetGuard` hook on ProviderRouter (D-16) is where the monthly ledger pre-flight plugs in without a rebuild.
