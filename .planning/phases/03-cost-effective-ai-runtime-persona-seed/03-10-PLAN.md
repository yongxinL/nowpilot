<objective>
Close VERIFICATION.md gap 1 (CR-01): the R-2 attempt budget starves the renderer stage on legitimate tool-loop turns.

Purpose: `ROUTER_MAX_ATTEMPTS = 3` is currently enforced as a total per-operation SDK-call counter (`attemptCount` = every `recordAttempt`), so a medium-tier turn using the ALLOWED 2 tool calls consumes 3 attempts on the planner loop alone and the renderer stage resolution throws `no_candidate` — the documented `*_cap_reached` terminals are unreachable and toolCap>1 never works in the integrated path. This plan scopes the R-2 budget to **router-owned retries only** (per 03-REVIEW.md CR-01): legitimate sequential stage calls and structured-output repairs never consume the budget; exactly the D-17 retried call does. A permanent regression test reproduces the pre-fix failure (real Router + real budget, generateObject mocked) and asserts the 2-tool turn completes with an answer.

Output: retryCount field + retry-scoped budget gates in ProviderRouter.ts, updated unit budget tests, and a new orchestrator-level regression test file.

Housekeeping (mandate): `tests/core/ai/zz-verify-cr01.test.ts` was a throwaway temp reproduction (imports `@/core/ai` aliases). It must be absent before this plan's regression tests land (the permanent regression replaces it). Task 1 verifies/ensures its removal.
</objective>
