<objective>
Close VERIFICATION.md gap 3 (WR-03): the per-attempt timeout in StructuredOutput.ts aborts the SAME controller the outer abortSignal propagates into, so the SDK rejects with a bare AbortError, `classifyProviderError` maps it to `{ code: 'UNKNOWN', retryable: false }`, and `TIMEOUT` (which IS in `RETRYABLE_CODES`) can never be produced — the D-17 retry never fires on timeouts and the hook silently swallows a planner timeout to 'idle'.

Purpose: separate the timeout abort from the user abort (03-REVIEW.md WR-03 fix sketch): the per-attempt controller keeps relaying `ctx.abortSignal` (added/removed per attempt), a `timedOut` flag is set by the timeout callback before aborting, and the attempt catch throws a typed TimeoutError (shared carrier, no import cycle) for timeout-origin failures. `classifyProviderError` then maps the carrier to `{ code: 'TIMEOUT', retryable: true }` BEFORE the isAbortError branch — user cancels stay `UNKNOWN`/never-retried, timeouts become retryable and surface a visible planner_failed answer instead of silent idle.

Output: new `src/core/error/TimeoutError.ts` carrier, timeout-origin separation in StructuredOutput.attempt(), TIMEOUT classification in ProviderRouter, and regression tests in both suites.
</objective>
