# Phase 5a — UI Design Contract

> Visual and interaction contract for Phase 5a (LLM-Wiki & Filesystem Sync). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Source-of-truth artifacts: `.planning/DESIGN_SYSTEM.md` (§5–§13), the approved 01/03/04a/04b/05 UI-SPECs (inherited contract), `.planning/phases/05a-llm-wiki-filesystem-sync/05a-CONTEXT.md` (D-05a-01…17 locked decisions), `05a-RESEARCH.md` (stack + pitfalls), `05a-AI-SPEC.md` (AI contract), `.planning/PRODUCT_SPEC_v0_1.md` §27 (lines 3818–3914) + §18 Phase 5a (lines 2792–2833), `.planning/ROADMAP.md` Phase 5a (SC#1–5), `AGENTS.md` (approved stack + banned list + R-3/R-8/R-9/R-10).

> **Scope honesty note (must be preserved by the planner):** Phase 5a adds four **conservative, non-disruptive** surfaces (P5a-1) to the Phase-5 notes workspace — (1) the **inline suggestion bar** in the note editor (D-05a-01…04), (2) the **Ask-notes inline search + answer card** in the Notes toolbar (D-05a-05…08), (3) the **Save-to-note overflow action + SaveToNoteDialog modal** on assistant messages (D-05a-09…12), and (4) the **filesystem-sync chrome** — status Tag + permission banner in Notes, `NotesSection` + `ImportExportSection` cards in Options (D-05a-14…17). It is **NOT** the full §8.3 four-column workspace: the Directory tree stays a *lightweight category grouping* of the existing list column (CAT-02, no collapsible 4-column chrome — NOTES-COL-01…03 remain deferred), and the Inspector column (AI Summary card, Note Details, Quick Actions) remains deferred to later phases. **No bidirectional sync, no live folder watch, no embeddings, no LLM wikilink autocomplete, no restore-history/undo** (§27.9). BacklinksPanel / NoteGraphView / WikilinkAutocomplete / NotePreview are **untouched** (§27 surfaces note). Side Panel gets ONLY the "Save to note" affordance (R-3): no sync UI, no picker, no folder config in the panel.

### Accent reserved for (EXCLUSIVE list — Phase-5a surfaces)

`colorPrimary` is reserved for these 5a surfaces **only** (in addition to the inherited Phase-5 list — resolved wikilinks, primary CTAs, active Segmented segment, selected card, search focus, autocomplete active item, graph selected node — which is unchanged):

1. **"Accept all" primary action** in the suggestion bar (small primary Button — the ONLY primary button in the bar).
2. **Accepted-state suggestion chips** — a chip with its accept toggle engaged renders the check glyph in `colorPrimary` (`CheckCircleFilled`), signaling "will be applied"; unaccepted chips are neutral (secondary-surface, `colorTextSecondary` label).
3. **Category-path input focus ring** + valid-state border (AntD default focus). The proposed-category pre-fill text renders neutral; accent marks the *editable, accepted* state only.
4. **Citation chips in the answer card** — clickable Tags with `colorPrimary` border/text (click → open the cited note). The markdown answer body itself is neutral (never accent).
5. **"Find context" link** on orphan note cards + the **"Regenerate tags/summary"** text action in the suggestion bar (link-style, ChatPage Retry-link precedent).
6. **Primary actions in modals:** SaveToNoteDialog **Save note**; restore preview **Import**; permission-banner **Re-select folder** (primary, small).
7. **Assistant-bubble overflow affordance hover** — the `MoreOutlined` icon's hover state (colorTextSecondary → colorPrimary, DESIGN_SYSTEM §9 message-action-panel recipe).

**Not accent:** suggestion chips' unaccepted state, summary snippet, backup status Tags (success/default/error), answer-card surface, banner surface (warning), orphan badge (tertiary/muted), restore counts, Configure button (ghost), category-path invalid state (error).

### Destructive colour usage

**One destructive confirmation flow in 5a: the external-change guard** (SYNC-06). When a per-save write or delete-on-sync targets a file whose `lastModified` is newer than the last sync (+2 s tolerance), a `Modal.confirm`-style dialog shows `STR.notes.externalChange` with **Overwrite** (danger `colorError` — it destroys the user's external edits) and **Skip** (default — focus lands on Skip, the safe default per SYNC-06 "default Skip"). `colorError` also appears on the "Backup: Error" status Tag and the invalid category-path border. No other destructive flows are introduced (delete-note flow is unchanged from Phase 5; deletion never triggers on the sync path without the same guard).

## Interaction Contract

Locked by 05a-CONTEXT D-05a-01…17, LLM-WIKI-01…11, CAT-01…05, SYNC-01…11, NMEM-01…03, and DESIGN_SYSTEM.md §9/§12.

### Suggestion bar (D-05a-01…04, LLM-WIKI-01/02/04/08/11, CAT-03/05)

- **Trigger:** after a successful note save, `handleSave` fires `void NoteTagger.analyze()` (NEVER awaited — §22.1 "save never waits", P5a-2). Displayable results arrive version-stamped `{noteId, version}`; the bar renders only when the version still matches the current draft (LLM-WIKI-11 stale-version guard — a slow response never applies to newer content) AND at least one item survives the confidence gate.
- **Confidence gating (LLM-WIKI-11, core-owned):** items < `0.60` are silently discarded before display (never shown, never stored); at most 5 tags / 3 memoryFacts, descending confidence, overflow dropped. **The UI only ever renders gated output** — no threshold logic in components.
- **Tag chips:** each proposed tag renders as a chip with an `Accept` check toggle (per-item, D-05a-02). Toggle on → check fills `colorPrimary` (accepted); toggle off → neutral. **Accept all** applies the whole pending batch (primary small). Accepted items are applied to the draft metadata and persist into the note (fire-and-forget `putNote` of the metadata update — content untouched, `updated`/`version` advance per the store contract); the bar stays visible showing only the remaining unaccepted items.
- **Rejections (D-05a-04):** per-item rejections are remembered as suppression markers per `{noteId, version}` — a rejected tag is never re-suggested for the same content. Bar-level Dismiss is a **batch** dismissal (not a permanent rejection): re-suggests on the next save/content change.
- **Category (D-05a-03, CAT-01/03/05):** an inline path input pre-filled with the proposed `categoryPath` (segments joined by `/`). Three controls: **Accept** (keep proposed), **Edit** (focus the input, freely edit segments), **Dismiss** (discard the proposal, field clears). On save, segments normalize per CAT-01 (strip leading/trailing slashes, collapse duplicates, trim); invalid segments (empty, `.`, `..`) flag the input with the `colorError` border + `categoryInvalid` caption (CAT-05) — validated on edit/blur, never while typing.
- **Summary (LLM-WIKI-03):** proposed summary renders as a 2-line-clamped snippet with Accept / Dismiss. Accepted summary persists; the NoteList card secondary line then shows the summary (replacing the content snippet) — the agent's-discretion item is resolved to **inline** (not hover): low-noise, glanceable, consistent with the existing snippet slot.
- **Staleness (LLM-WIKI-08, D-05a-04):** when `updated` > `summaryGeneratedAt`/`tagsGeneratedAt`, the bar slot shows `STR.notes.stale` with a **Regenerate tags/summary** action (link-style) that re-runs NoteTagger in place and re-populates the bar.
- **Non-blocking contract (P5a-2):** the bar is display-only — it never blocks typing, saving, or navigation. While tagging runs, a slim skeleton + `analyzing` caption fills the slot. On failure, `taggerFailed` + Retry (Retry re-runs the tagger on the current version). Bar is dismissible; dismissed bar does not reappear until the next save/content change.
- **Interaction with dirty state:** accepting suggestions marks the draft dirty (metadata changed but not yet persisted) — the Save button enables; the accepted metadata is applied to the draft AND persisted via the fire-and-forget update so the list reflects it on next refresh. Planner discretion on the exact dirty-flag semantics, but the bar must never silently change note content without the user seeing it in the draft.

### Ask-notes (D-05a-05…08, LLM-WIKI-05/06, NMEM-01)

- **Merged input:** the toolbar search input runs MiniSearch live (unchanged filter behavior). AI synthesis engages per D-05a-07; the answer card appears below the header. Plain search results in the list column are **unaffected** — the card is additive.
- **Answer card states:** hidden (no query / dismissed) → `askLoading` caption + skeleton (NoteQA in flight) → populated (`answer` markdown rendered via `PortableMarkdown` — DOMPurify, R-10; citation Tags row below; `aiEnhanced` caption when synthesis ran) → zero-hit (`askEmpty`, NO provider call, D-05a-08) → error (`askError` prefix + Retry, ChatPage stripActionToken precedent). Tiny mode → the card renders plain top-5 MiniSearch results (titles, click → open) with NO LLM call and NO "AI-enhanced" caption.
- **Citations (LLM-WIKI-06, D-05a-06):** clickable `Tag` chips from the validated `{noteId, title}` contract; click → `handleOpenNote(noteId)`. Unreachable citations (noteId no longer exists) are dropped pre-render (AI-SPEC D2).
- **Ephemeral (R-10, §27.6):** answers are never persisted; dismissing or re-querying discards. No session-cache UI (the AI-SPEC session LRU is core-internal, invisible).
- **Orphan "Find context" (D-05a-13):** clicking the action on an orphan card runs the NoteQA RAG path seeded with that note and opens the answer card populated with the result — same card, same citations, same dismissal.

### Save-to-note (D-05a-09…12, LLM-WIKI-07, NMEM-03)

- **Trigger:** hover-only `MoreOutlined` overflow on assistant bubbles → "Save to note". Not a chat toolbar button (D-05a-09).
- **Dialog lifecycle:** opens with the drafting skeleton (`drafting` caption) while NoteChatConverter (haiku, conversation excerpt + `assemble()` facts) produces `{title, content, tags ≤ 5, categoryPath, wikilinks}`; fields populate as completed content (no streaming — AI-SPEC "Stream vs. await"). Draft failure → the dialog stays open with raw source content pre-filled + `draftFallback` notice (user never blocked, P5a-2).
- **Edit-in-modal (D-05a-10):** title (borderless 20/600, editor-title precedent), content (PortableMarkdown preview), tags (editable chip row, same mechanics as the editor tag row), category (path input, same CAT-01/05 rules), wikilinks (display-only chip row — suggested links resolve against real vault titles, never invented). **Save note** (primary) → `putNote` → `note:saved` → the note appears in Standalone on its next refresh (D-05a-12). **Cancel** (ghost) discards the draft. No navigation to the Notes editor.
- **Page capture (D-05a-11):** identical dialog, drafted from `PageContext` (Phase 4a). Side panel drafts in place (D-05a-12) — the modal renders within the side-panel surface (compact density: touch targets ≥ 32 px).

### Filesystem sync chrome (D-05a-14…17, SYNC-01…11, CAT-04)

- **Folder picker:** `showDirectoryPicker({ mode: 'readwrite' })` **Standalone only** (SYNC-01 — extension popup/side-panel contexts are unreliable, RESEARCH Pitfall 1), inside a click handler (transient activation). Entry points: Notes toolbar Configure + Options NotesSection "Set backup folder". The handle persists in the `notes_backup_config` IndexedDB store (D-08) — never chrome.storage, never the background SW (R-3).
- **Status Tag (SYNC-08, D-05a-15):** green `Backup: On` / gray `Backup: Off` / red `Backup: Error` in the Notes toolbar + NotesSection. Tooltip on the Tag shows the last sync error (SYNC-08) — error text is a redacted-safe summary (R-10: never raw paths). **No notification spam** on state changes (D-05a-15) — the Tag is the only persistent indicator.
- **Permission-loss banner (SYNC-02, D-05a-16):** on mount, `queryPermission()` not granted → warning `Alert` "Backup folder not accessible." with **Re-select folder** (primary → picker) + **Dismiss** (ghost). Sync stays disabled until re-selected. **No auto-reprompt on every mount** — Dismiss hides it until the next mount/state change; a subsequent failed mount re-shows it.
- **External-change guard (SYNC-06):** per-save write or delete-on-sync detects `lastModified` newer than last sync (+2 s) → `Modal.confirm` `externalChange`, **Overwrite** danger / **Skip** default focus. Only fires on actual detection (rare); fire-and-forget writes never block the save path (§22.1).
- **Restore (SYNC-09/10, D-05a-17):** Options → Import/Export → **Restore from folder** → picker → walk tree → parse frontmatter → preview modal with token-substituted counts; **Import** runs the additive upsert (id exists → update preserving newer `updated`; id missing → create; local notes not in the folder are never deleted — SYNC-10, ROADMAP SC#5). Category structure reconstructed from folder paths. **No restore-history/undo** (§27.9).
