> **Scope honesty note (must be preserved by the planner):** Phase 5 ships the **atomic-note core UI** — Notes list + editor + wikilink autocomplete + note graph + backlinks + MiniSearch search — replacing the Phase-1 E5 placeholder on `NotesPage.tsx` (D-05-16/17). It is **NOT** the full §8.3 four-column workspace: **Directory (col 1)** needs `categoryPath` (Phase 5a CAT-02), the **Inspector (col 4)** needs AI Summary/Note Details/Quick Actions (Phase 5a LLM-WIKI-03/04), and the rich-text **formatting toolbar** (Body▾/undo/redo/B/I/…) is the §8.8 Write-page/5a blueprint. The memory engine (KNW-04/05) is **core-only, zero UI** — the existing 04b content-trust card already shipped; Phase 5 adds **no Options sections** (D-05-18 context). Do not let UI polish leak into the core-only memory surfaces.

No 500-weight role (AntD `Button.fontWeight` overridden in `NOWPILOT_COMPONENTS`; DESIGN_SYSTEM.md §13). Base size Standalone **14 px** (default). Steps: 12 / 13 / 14 / 16 / 20 / 24 / 30. Body line-height 1.5; headings 1.3. Never below 12 px. Captions use `colorTextTertiary`.

**Phase-assignable size scoping (checker FLAG-4 closure, 04a/04b precedent):** only the role rows below are assignable in Phase 5 — 12 px (caption), 14 px (body/list/toggle), 16 px (page-adjacent heading/labels), 20 px (editor title input). 13 px is the compact body base (not used in 5 — Notes is Standalone-only). ### Accent reserved for (EXCLUSIVE list — Phase-5 surfaces)

`colorPrimary` is reserved for these Phase-5 surfaces **only**:

1. **Resolved wikilinks** in the rendered note body — clickable `[[Title]]` links (opens the target note).
2. **Primary buttons:** "New note" (page header), "Save" (editor header).
3. **Active view toggle** — the active segment of the Notes/Graph `Segmented` control (DESIGN_SYSTEM.md §9 "header segmented toggles colorPrimary when active").
4. **Selected note card** in the list — `colorPrimaryBg` fill pill + `colorPrimary` title text (DESIGN_SYSTEM.md §9 active-item pattern).
5. **Search focus ring** + clear affordance on the search `Input` (AntD default).
6. **WikilinkAutocomplete:** highlighted/active dropdown item background (`colorPrimaryBg`) and the "Create note" action link on unresolved links in the rendered body (WIKI-ID-03 affordance).
7. **NoteGraphView:** node fill for the **selected/current note**; hover node stroke; the backlink count badge accent.

**Not accent:** search placeholder text, note-card surfaces, star (warning), unresolved links (tertiary + dashed), destructive buttons (error), captions.

### Destructive colour usage

**One destructive flow in Phase 5: note deletion** (KNW-01 "delete notes"). `colorError` appears only on the `Popconfirm` OK button ("Delete") and the delete-failed `notification.error` toast. Everything else in the delete flow uses neutral tokens. Deletion is **irreversible** (WIKI-ID-04: the note's row is removed from NotesDB; referencing edges dangle back to `unresolvedLinks[]` at next save/rebuild) → typed-name confirmation is **not** required (the 04b note: spec §28.5 typed-name barrier stays forward-compat for Phase 7/8); a `Popconfirm` with the note title quoted is the confirmation contract.

### Notes page — one focal surface: the list → editor reading flow

`NotesPage.tsx` is rewritten: the E5 placeholder (`Card` + `Empty` + no-op CTA) is replaced by the real notes workspace. Two sub-views switched by the header `Segmented` (Notes | Graph). Notes is the default view.

    ├── [Segmented: Notes | Graph]  (view toggle, active = colorPrimary)

No collapsible columns in 5 (NOTES-COL-01…03 are 5a — the inline collapse chevrons and header Directory/Notes/Inspector toggles are NOT built here).

### Icon-only control accessibility

Every icon-only control in 5 carries `aria-label` + `Tooltip` (DESIGN_SYSTEM.md §12): star toggle (Star/Unstar), `⋯ More` overflow (Delete only in 5), backlinks collapse chevron, tag-chip close (antd Tag closable has its own label via title/aria), search clear (antd Input allowClear). All controls meet the **≥ 36 px (Standalone)** touch-target rule.

### Graph visual contract (NoteGraphView, d3-force ^3)

- **Data:** derived, no separate graph store (D-05-17) — `NoteGraph` computes edges from `links[]` + a backlink index on demand; the view rebuilds on `note:saved` / mount.
- **Nodes:** `Circle` per note, radius ~10–14 px, fill `colorPrimary` for the **selected/current** note and `colorFillTertiary` for others; label = note title (12 px, `colorTextSecondary`, truncated) rendered beside the node; isolated notes (no edges) render at reduced opacity (`colorTextQuaternary`-family fill) but remain visible — an isolated note is still a note.
- **Edges:** `Line`/`Path` per `links[]` entry, stroke `colorBorder`, arrowless (undirected visual for a directed semantic — acceptable for v0.1; direction is discoverable via the backlinks panel).
- **Layout:** d3-force params are planner discretion (CONTEXT "the agent's Discretion"); recommended seed: `forceLink` distance ~80, `forceManyBody` strength ~-200, `forceCenter` on viewport, charge/centering only — no simulation text animation beyond layout settling.
- **Interaction:** node click → open that note (select it + switch to Notes view — the single navigation contract, D-05-17); node hover → `Tooltip` with the full title; pan/zoom (d3-zoom) recommended, planner discretion; `< 3` notes → the graphEmpty copy instead of the simulation (spec §12 "Create at least 3 notes to see the graph").
- **Reduced motion:** respect `prefers-reduced-motion` — run the force simulation to equilibrium but skip the animated settling (render the final layout directly); keep opacity, drop movement (DESIGN_SYSTEM.md §11).

## Interaction Contract — Notes Workspace (Standalone)

Locked by 05-CONTEXT D-05-12 (MiniSearch lifecycle), D-05-13 (New note from page), D-05-14 (wikilink tie-break + unresolved + reconciliation), D-05-15 (save pipeline: parseLinks → resolveLinks → NotesDB.put → `note:saved`), D-05-16 (editor UX), D-05-17 (graph + backlinks, click → open), and DESIGN_SYSTEM.md §8.3 (Notes blueprint subset) + §12 (state matrix).

### Search field (MiniSearch over notes)

- **Index lifecycle:** `MiniSearchIndex` builds/rebuilds from `NotesDB` on Notes view mount; incremental add/remove on note CRUD (D-05-12). In-memory only — no durable index store in 5.
- **Behavior:** typing filters the list column live (query matched over `title + content + tags`; field weights/fuzzy options are planner discretion per CONTEXT). Results within **< 50 ms over 1,000 notes** (spec §22.1). The field is `allowClear`; clearing restores the full list (sorted `updated` desc). Non-empty query → results-count line "[n] notes"; zero hits → `STR.notes.searchEmpty` empty state in the list column.
- **Relationship to the search-notes tool:** the same index powers the §9.8 `{query, limit}` tool seam (D-05-11) — the UI field is a filter surface, not the tool surface; no tool invocation happens here.

### New note / New note from page (create)

- **New note** (primary CTA): creates an **unsaved draft** in the editor (empty title, empty body, `crypto.randomUUID()` assigned at first save, `source.kind: 'manual'`); focus lands on the title input. The draft is NOT written to NotesDB until the first Save (avoids empty rows in the list). Save runs the D-05-15 pipeline.
- **New note from page** (ghost CTA, visible only when `currentPageContext` exists): drafts a note pre-filled with the page title → note title and page markdown → body, `source.kind: 'page-export'` (D-05-13 — satisfies ROADMAP SC#5 end-to-end Page → PageContentService → Note → MiniSearch). User remains gatekeeper: the draft opens in the editor for review before Save; no LLM involved (the 5a SaveToNoteDialog is the LLM-drafted variant, NOT built here).

### Note list (select / star / reflow)

- Cards sorted by `updated` desc (NotesDB `by-updated` index). Click anywhere on a card body → select → editor loads that note. Selected card = `colorPrimaryBg` pill + `colorPrimary` title (DESIGN_SYSTEM.md §9 active pattern; never colour alone — the pill fill + weight also change).
- **Star** toggle on each card and in the editor header: persists membership in **`WorkspaceStore.workspace.selectedNotes: string[]`** — the D-18 declared field (inert since Phase 1; Phase 5 activates it as the favorites set — no type widening, no new storage key). Starred = `StarFilled` `colorWarning`; unstarred = `StarOutlined` neutral. Favorites *filtering* (Directory "Favorites") is 5a; Phase 5 only toggles.
- **Card overflow:** titles ellipsize 1 line; snippets clamp 2 lines (CSS line-clamp); tag chips truncate with `+N`; timestamps relative ("10m ago" — antd/Intl.RelativeTimeFormat, planner discretion).

### Editor (edit / save / dirty / delete)

- **Title:** borderless `Input` at 20/600; empty title allowed while editing, Save falls back to "Untitled" on persist.
- **Edit | Preview segmented:** body renders markdown source in a `TextArea` (Edit) or `PortableMarkdown` (Preview). Preview resolves `[[Title]]` via the current note's `links[]`/`unresolvedLinks[]` (D-05-14): resolved → clickable `colorPrimary` link (opens target note); unresolved → `colorTextTertiary` + dashed underline + "Create note" action (drafts a new note titled `Title`; after its first save, the bounded reconciliation promotes the matching unresolved entry — D-05-14, never blocks save).
- **Save:** explicit primary `Save` button + `Cmd/Ctrl+S` (planner may bind via keydown handler; no global shortcut system this phase). Disabled when the draft is not dirty. Pipeline: `parseLinks` → `resolveLinks` (tie-break: exact title → `updated` desc → `id` asc, ≤ 20 ms) → `NotesDB.put` → `EventBus 'note:saved'` → MiniSearch incremental add + graph/backlinks re-derivation (D-05-12/15/17). Write paths never throw (Golden Rule 9; GR-9 codes to `debugLog`); failure → `STR.notes.saveFailed` inline retry.
- **Dirty guard:** switching selection (or toggling to Graph view) with a dirty draft → `Popconfirm` `STR.notes.discard` (Discard danger / Keep editing). The dirty indicator is the "Unsaved changes" caption + `Badge` dot in the editor header.
- **Delete:** `⋯ More` → Delete → `Popconfirm` `STR.notes.deleteConfirm` (title quoted; OK = Delete, danger `colorError`) → NotesDB row removed → `note:saved`-adjacent rebuild. Referencing edges dangle back into `unresolvedLinks[]` on other notes at their next save/rebuild (WIKI-ID-04 — no source-body rewrites, no cascade).

### WikilinkAutocomplete (inline `[[` combobox)

- **Trigger:** while the caret is in the body `TextArea` (Edit mode) and the user types `[[` (prefix `[[`), a dropdown lists matching existing note titles (MiniSearch title matching, **< 50 ms p95 ≤ 5,000 notes**, spec §22.1). Serves D-05-16 (manual `[[` autocomplete; LLM suggestions NOT in v0.1, D-04).
- **Item:** title (14 px) + optional tag chip; highlight via `colorPrimaryBg` on the active item.
- **Keyboard:** ↑/↓ move the active item, Enter/Tab inserts `[[Title]]` at the caret, Esc closes. Mouse click inserts. **No matches → the dropdown closes silently** — the user may finish `[[Whatever]]` freely; it becomes an unresolved link (WIKI-ID-03), no blocking state, no error.
- **A11y:** combobox pattern — the input announces `aria-haspopup="listbox"`, `aria-expanded`, `aria-activedescendant` on the active option; the listbox has `role="listbox"` with `role="option"` items; insertion is announced politely. Widget choice (antd `AutoComplete` vs. custom anchored popover) is planner discretion; the a11y contract is binding either way.

### BacklinksPanel (in-links)

- Derived per current note: notes whose `links[]` contains the current note's id (D-05-17, computed on demand via `NoteGraph`/backlink index). Rows: title (14 px) + 1-line snippet; click → select that note (switches the editor). Collapsible section below the body; empty → `STR.notes.backlinksEmpty`; section title "Backlinks" (16/600). Backlink count may badge the section header (planner discretion, accent = `colorPrimary`).
- **Note:** the full Inspector (col 4) with Links Count/Backlinks under "Note Details" is 5a (DESIGN_SYSTEM.md §8.3 col 4); Phase 5 hosts BacklinksPanel in the editor column so the component ships per the §18 create list (`src/components/notes/BacklinksPanel.tsx`). 5a may relocate it into the Inspector without changing this component (spec §27: "Not touched: BacklinksPanel…").
