  <action>
    Create `CircuitBreaker` class. Export class only — NO singleton (each ProviderRouter creates its own instance, or one shared global). Follow RESEARCH.md code example lines 751-827 exactly.

    **State machine:**
    ```
    CLOSED → (3 failures in 60s) → OPEN → (5min cooldown) → HALF_OPEN → (probe) → CLOSED/OPEN
    ```

    **Configuration (constructor-settable, defaults per D-10):**
    ```typescript
    constructor(config?: Partial<CircuitBreakerConfig>) {
      this.failureThreshold = config?.failureThreshold ?? 3;
      this.failureWindowMs = config?.failureWindowMs ?? 60_000;
      this.cooldownMs = config?.cooldownMs ?? 5 * 60_000;
    }
    ```

    **Private state:** `Map<string, ProviderCircuit>` where `ProviderCircuit = { state: 'CLOSED' | 'OPEN' | 'HALF_OPEN'; failures: number[]; openedAt: number | null }`

    **Methods:** `isOpen(providerId)`, `recordFailure(providerId)`, `recordSuccess(providerId)`, `getState(providerId)`, `reset(providerId)`.

    - `recordFailure`: In CLOSED → push Date.now(), prune old (>failureWindowMs). If count >= threshold → transition to OPEN. In HALF_OPEN → transition to OPEN (probe failed).
    - `recordSuccess`: In CLOSED → clear failures. In HALF_OPEN → transition to CLOSED (probe succeeded).
    - `isOpen`: OPEN → check cooldown elapsed → if yes, transition to HALF_OPEN and return false (allow probe). HALF_OPEN or CLOSED → return false.

    No `debugLog` calls (caller — ProviderRouter — handles logging).

    **Test file:** `tests/core/ai/router/CircuitBreaker.test.ts` — use `vi.useFakeTimers()` to control time. Test all state transitions, per-provider isolation, failure window pruning, cooldown timing.
  </action>

  </verify>
  <done>CircuitBreaker class created; all state transitions tested (CLOSED→OPEN→HALF_OPEN→CLOSED, HALF_OPEN→OPEN); per-provider isolation verified; fake timers used for cooldown testing</done>

    **TierResolver** (`src/core/ai/router/TierResolver.ts`):
    - Class exported without singleton (created internally by ProviderRouter)
    - Constructor: `constructor(private registry: ProviderRegistry)`
    - `resolve(tier: CostTier, preferredProviders: string[]): Array<{ providerId: string; modelId: string }>` — queries `registry.getModelsForTier(tier)`, sorts by preferredProviders order, returns sorted array
    - Pure lookup logic — no async, no side effects, no external calls

    **ProviderRouter** (`src/core/ai/router/ProviderRouter.ts`):
    - Class+singleton export per PATTERNS.md item 5
    - Constructor DI: `constructor(private registry: ProviderRegistry, private breaker: CircuitBreaker, private tierResolver: TierResolver)`
    - `async selectModel(tier: CostTier, preferredProviders: string[]): Promise<{ instance: any; modelId: string; providerId: string } | null>`:
      1. Get fallback chain via `tierResolver.resolve(tier, preferredProviders)`, capped at 3 entries
      2. Iterate chain: for each { providerId, modelId }:
         - Skip if `breaker.isOpen(providerId)` → continue
         - Call `registry.getProvider(providerId)` → if undefined, continue
         - On success → `breaker.recordSuccess(providerId)`, return `{ instance, modelId, providerId }`
         - On error → `breaker.recordFailure(providerId)`, `debugLog('warn', ...)`, continue
      3. If chain exhausted → return null
    - `getRetryableErrors(): string[]` → returns ['TIMEOUT', 'NETWORK', 'PROVIDER_5XX', 'RATE_LIMITED'] per D-09
    - `isRetryableError(error: unknown): boolean` → checks error type/message against retryable list

    **Singleton wiring:**

    ```typescript
    const tierResolver = new TierResolver(providerRegistry);
    export const providerRouter = new ProviderRouter(providerRegistry, sharedBreaker, tierResolver);
    ```
