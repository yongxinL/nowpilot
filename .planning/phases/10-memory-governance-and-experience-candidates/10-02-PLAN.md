    Create the ProceduralExperience module that manages the verification+approval lifecycle (per D-129, MEM-05). Records flow: proposed → verified → approved/rejected. Only approved records are visible to MemoryEngine.

    **Step 1 — Create `src/core/memory/ProceduralExperience.ts`**:
    Export `ProceduralExperienceStore` as an object-form namespace with:
    - `async create(record: Omit<ProceduralExperience, 'id' | 'createdAt' | 'updatedAt' | 'status'>): Promise<ProceduralExperience>` — insert with status='proposed', generate id (crypto.randomUUID()), set createdAt/updatedAt = Date.now()
    - `async verify(id: string): Promise<ProceduralExperience | undefined>` — automated verification:
      1. Read record from procedural_experiences store
      2. Check: steps is non-empty array, no step is empty string, no contradictions (steps don't contain conflicting actions — simple heuristic: no step is the exact negation of another)
      3. If valid: set status='verified', verifiedAt = Date.now()
      4. If invalid: leave status='proposed', return undefined
    - `async approve(id: string): Promise<ProceduralExperience | undefined>` — user approval (Phase-15 UI calls this):
      1. Read record, check status === 'verified'
      2. Set status='approved', approvedAt = Date.now()
      3. Reject if status !== 'verified' (must be verified first)
    - `async reject(id: string): Promise<ProceduralExperience | undefined>` — set status='rejected'
    - `async getById(id: string): Promise<ProceduralExperience | undefined>` — read from store
    - `async listByStatus(status: ProceduralExperience['status']): Promise<ProceduralExperience[]>` — filter by status
    - `async listApproved(): Promise<ProceduralExperience[]>` — convenience: listByStatus('approved')
    - `async delete(id: string): Promise<void>` — hard delete from store

    All mutations gate on isPrimaryWriter() and journal via WriteJournal.

    **Step 2 — Create `tests/core/memory/governance/ProceduralExperience.test.ts`**:

    - Test: verify — valid steps (non-empty, no contradictions) → status='verified', verifiedAt set
    - Test: verify — invalid steps (empty array or empty string step) → returns undefined, status stays 'proposed'
    - Test: approve — verified record → status='approved', approvedAt set
    - Test: approve — proposed record (not verified) → rejected, returns undefined
    - Test: reject — status → 'rejected'
    - Test: listByStatus — filters correctly for each status
    - Test: listApproved — returns only approved records
    - Test: full lifecycle: create → verify → approve → listApproved includes it
    - Test: non-primary — all mutations are no-ops when isPrimaryWriter returns false
