## Phase 7 → Later-Phase UI Contracts

The three surfaces this phase ships are **data contracts**, not components. Locked shapes (sources: 07-CONTEXT.md D-93…D-102, D-94/D-95/D-102; spec Appendix C.1 4878-4900; spec Appendix O.3 6363-6389):

### Contract A — L6 user-disclosure signal (→ Phase 15 disclosure UI)
- **Shape:** `untrustedDataPresent: boolean` — a **flag on the derived receipt surface** (not per-item). Locked by orchestrator objective; CONTEXT.md discretion item resolved to the boolean flag (D-98: "signal only here, UI in Phase 15").
- **Semantics:** `true` when any `ContextReceiptEntry` (or any packed section) carries `trust: 'untrusted' | 'retrieved'` with `instructionAuthority: false` forced by `applyTrustPolicy` (O.3). Computed at receipt derivation (D-95), never persisted (derived view).
- **Consumption:** Phase 15 renders the disclosure banner (copy in `## Copywriting Contract`) using `colorWarning` amber per the semantic mapping above. It is **informational**, never modal, never blocking.

### Contract B — CTX-06 derived context-quality metrics surface (→ Phase 11 DiagnosticsSection)
- **Shape:** derived **aggregate metrics only** — section count; trust-mix counts per `TrustLevel`; truncation/omission counts (+ `omitReason`); compression counts; token utilization ratio (original→final); `minimalMode` flag (D-102).
- **Boundary (hard):** **no raw section text, no raw sensitive text** — aggregates over the manifest/receipt only; mirrors the Phase-5 D-77 derived-trace surface. Phase 11 lifts into `PromptTrace` additively.
- **Consumption:** Phase 11 DiagnosticsSection renders label/value rows (copy pre-locked above). Error state = metrics derivation failure (e.g., malformed manifest) → "Context metrics unavailable." + [Retry].

### Contract C — `ContextReceiptEntry[]` (→ Phase 11 Prompt Inspector / CTX-03)
- **Shape (verbatim spec 4892-4900, derived per D-95):** `{ sourceId, included, originalTokens, finalTokens, compression?: 'summarise'|'structural'|'topk', cacheEligible, omitReason? }`.
- **Derivation rules (locked, D-95/D-96):** `cacheEligible` = `section.stable`; `included` = !truncated-with-omission (by-design omission → `included:false` + `omitReason`); `compression` maps from manifest `compressionApplied`; `originalTokens` = pre-degradation count retained inside `assemble` (D-96); `finalTokens` = manifest `record.tokens`. Manifest schema stays verbatim (D-77/D-95 — do NOT add receipt fields to it).
- **Consumption:** Phase 11 Prompt Inspector reconstructs packing decisions from a transaction id using these entries (CTX-03 SC#3).

### Contract D — Progressive skill disclosure mechanism (→ Phase 15 RICH skill catalog)
- **Shape:** disclosure registry/selector consumes candidate skills' `trigger` + one-line `description`; injects **trigger + one-liner** for inactive skills, **full instructions only for the active skill** — irrelevant full instructions consume zero prompt tokens (CTX-05 SC#4, D-101). Shape aligned to `ISkill` (spec 1826-1856).
- **Consumption:** Phase 15 real skill manifests + RICH command catalog consume the seam; Phase 15 UI renders the disclosed trigger/description (e.g., RICH-I-09 template catalog). No UI authored here.

### Type placement note (planner hint, not a UI decision)
O.3 (spec 6369) imports `ContextItem`/`TrustLevel` from `@/types/harness`; `src/types/harness.ts` is the established canonical home for C.1 types (Phase-4 precedent). Receipt surface types must be importable by Phase 11/15 consumers — placement is the planner's discretion per CONTEXT.md, but `@/types/harness` is the spec-named default.
