**WXT content script entrypoint composing four extraction modules, Background SW page-extraction message routing, getPageContentTool and pinTabTool registered in ToolRegistry — wire all Phase 07.2 modules into working end-to-end pipeline**

## Accomplishments

- **WXT content script entrypoint** (`src/entrypoints/content.ts`) composes PageExtractor, PageContextBridge, SPANavigationWatcher, and ContentChangeWatcher into a single ISOLATED-world pipeline (D-01, D-05)
- **Three extraction triggers** implemented: DOMContentLoaded (initial injection), SPA navigation (300ms debounced via SPANavigationWatcher), and visibilitychange (hidden → visible, D-03, D-25)
- **URL blocklist** runs FIRST before any extraction, rejecting chrome://, chrome-extension://, edge://, about:, view-source:, devtools://, file://, and NowPilot-owned pages (D-26)
- **Background SW message routing** added: PAGE_CONTEXT_UPDATED → workspaceStore.setCurrentPageContext(); GET_PAGE_CONTEXT_REQUEST → relay to active tab's content script (D-04, D-15)
- **getPageContentTool** (MCP #1): fresh extraction for active tab via content script relay, cached PageContext for pinned tabs by tabId (D-20)
- **pinTabTool** (MCP #5): pin/unpin with max-10 enforcement, chrome.tabs.get for metadata, constructs TabContext with current page context (D-21, D-30)
- **ToolRegistry** registers both tools at import time — not lazily (RESEARCH.md anti-pattern)
- **wxt.config.ts** updated with `activeTab` permission
- **27 new tests** pass: 10 getPageContentTool + 8 pinTabTool + 9 isolation tests (CONT-04)

## Decisions Made

- **WXT auto-generates content_scripts manifest entry** from `defineContentScript()` — explicit content_scripts block in wxt.config.ts not needed; only `activeTab` permission added manually
- **Background SW message routing** uses try-catch around validateEnvelope to allow non-envelope messages (FETCH_PROXY) to fall through unchanged — preserves backward compatibility
- **getPageContentTool wraps chrome.tabs.sendMessage in Promise** for ExecutorService async compatibility — matches the callback-based Chrome API with modern async/await
- **pinTabTool builds minimal PageContext fallback** when workspaceStore.currentPageContext is null (tab has no prior extraction) — ensures pin succeeds even without prior extraction
