## Decisions Made

- **textContent over innerText**: `doc.body?.innerText` is undefined in jsdom. Used `textContent` instead for DOM fallback extraction — provides equivalent visible text for extraction purposes
- **Class-based @mozilla/readability mock**: `vi.fn()` mock doesn't work with `new Readability()` constructor call. Used ES6 class syntax in mock factory to correctly simulate the Readability constructor
- **Cleanup test approach**: `.bind()` creates new function references each call, making `toBe()` identity checks unreliable. Used callability + `not.toThrow()` assertion to verify History API restoration
- **Pre-existing test adaptation**: runtimeEnvelope test used 'content-script' as the invalid source example. Updated to 'malicious-spoof' and added a new test verifying 'content-script' acceptance — no breaking behavior change

## Issues Encountered

- **jsdom innerText limitation**: `doc.body?.innerText` is undefined in jsdom — a known jsdom quirk. `textContent` provides equivalent text for extraction. Future content scripts running in real Chrome tabs will use native `innerText` if needed, but `textContent` is adequate for extraction purposes.
- **vi.fn() constructor limitation**: Vitest's `vi.fn()` mock doesn't work well with `new` keyword in Vite-transform context. ES6 class syntax in mock factory resolves the issue cleanly. This pattern should be preferred for constructor mocks going forward.
