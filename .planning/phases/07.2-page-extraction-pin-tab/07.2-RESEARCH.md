# Phase 07.2: Page Extraction & Pin Tab - Research

**Researched:** 2026-07-17
**Domain:** Chrome Extension Content Scripts, DOM Extraction, Cross-Context Messaging, MCP Tool Integration
**Confidence:** HIGH

## Summary

Phase 07.2 wires page context awareness into NowPilot by implementing a content-script-based extraction pipeline and a pin tab system. Content scripts run in `ISOLATED` world and extract page metadata (url, title, meta, markdown) via `@mozilla/readability` + `turndown`, communicating through `chrome.runtime.sendMessage` with `RuntimeEnvelope<T>` envelopes relayed by the Background Service Worker. The extracted `PageContext` is persisted to `workspaceStore` (backed by `chrome.storage.local` via Zustand persist + WriteJournal) and flows into every AI call through the existing `ContextOptimizer` pipeline, which already allocates 10% budget to `page_context` and applies structural compression at step 4 of the degradation pipeline.

The phase also registers two new MCP tools (`get-page-content`, `pin-tab`) in the existing `ToolRegistry` singleton and executes them via `ExecutorService`. A PinTabBar component (AntD Tag chips) lives in the Side Panel footer, showing the active page and pinned tabs (max 10). Both `useChat` and `useAgent` hooks are extended to read `workspaceStore.currentPageContext` and pass it into `ContextOptimizerInput.pageContext`.

**Primary recommendation:** Build the four content-script modules under `src/core/content/` as pure TypeScript modules (no React/JSX), register a single `content.ts` entrypoint via `defineContentScript`, use `@mozilla/readability` with `isProbablyReaderable()` gate and `turndown` for HTML-to-Markdown conversion, and communicate via stateless `chrome.runtime.sendMessage` with `RuntimeEnvelope` — no long-lived ports. Wire `workspaceStore` type migration first (Wave 0), then content scripts, then MCP tools, then PinTabBar UI.

### Pattern 1: Content Script Entrypoint (WXT)

**What:** Single `content.ts` entrypoint using `defineContentScript()` that composes four internal modules. WXT handles manifest `content_scripts` registration automatically from the file-based entrypoint.

**When to use:** All content script injection for page extraction.

**Example:**
```typescript
// src/entrypoints/content.ts
// Source: WXT official docs (github.com/wxt-dev/wxt)
import { defineContentScript } from 'wxt/utils/define-background';

export default defineContentScript({
  matches: ['<all_urls>'],
  runAt: 'document_idle',
  world: 'ISOLATED',
  main(ctx: ContentScriptContext) {
    // Compose internal modules
    const watcher = new SPANavigationWatcher(handleNavigation);
    const extractor = new PageExtractor();
    const bridge = new PageContextBridge();

    // Extract on initial load
    extractAndSend(extractor, bridge);

    // Watch for SPA navigation
    watcher.watch(() => extractAndSend(extractor, bridge));

    // Listen for explicit extraction requests from SW
    chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
      if (msg.type === 'GET_PAGE_CONTEXT_REQUEST') {
        extractAndSend(extractor, bridge).then(ctx => sendResponse(ctx));
        return true; // async response
      }
    });
  },
});
```

### Pattern 2: Readability Extraction with Fallback

**What:** Attempt `@mozilla/readability` extraction first; if `isProbablyReaderable()` returns false or the extracted markdown is too short (< 100 chars), fall back to visible DOM text extraction.

**When to use:** Whenever extracting page content from a tab.

**Example:**
```typescript
// Source: @mozilla/readability README.md + turndown docs
import { Readability, isProbablyReaderable } from '@mozilla/readability';
import TurndownService from 'turndown';

const turndown = new TurndownService({ headingStyle: 'atx', codeBlockStyle: 'fenced' });

function extractMarkdown(doc: Document): string | null {
  if (isProbablyReaderable(doc)) {
    const clone = doc.cloneNode(true) as Document;
    const article = new Readability(clone).parse();
    if (article && article.content && article.textContent.length >= 100) {
      // Convert Readability's cleaned HTML to Markdown
      return turndown.turndown(article.content);
    }
  }
  // Fallback: visible text from body
  return extractVisibleText(doc);
}
```

### Pattern 3: Stateless SW Message Router

**What:** Background SW `chrome.runtime.onMessage` listener routes typed messages by `type` field. No in-memory caching — all state flows through `workspaceStore` → `chrome.storage.local`.

**When to use:** All content-script-to-SW and panel-to-SW communication.

**Example:**
```typescript
// src/entrypoints/background.ts extension
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  const env = validateEnvelope(message);
  switch (env.type) {
    case 'PAGE_CONTEXT_UPDATED': {
      const ctx = env.payload as PageContext;
      const store = useWorkspaceStore.getState();
      store.setCurrentPageContext(ctx);
      sendResponse({ success: true });
      return true;
    }
    case 'GET_PAGE_CONTEXT_REQUEST': {
      // Relay to active tab's content script
      chrome.tabs.query({ active: true, currentWindow: true }, ([tab]) => {
        if (tab?.id) {
          chrome.tabs.sendMessage(tab.id, env, sendResponse);
        } else {
          sendResponse({ error: 'No active tab' });
        }
      });
      return true;
    }
  }
});
```

### Pattern 4: Zustand Store Type Migration

**What:** Change `currentPageContext: string | null` to `currentPageContext: PageContext | null` and `pinnedTabs: string[]` to `pinnedTabs: TabContext[]`. Setter signatures update accordingly. Persisted type changes are backward-compatible because `chrome.storage.local` stores JSON — the shape changes but old `null`/`[]` values deserialize correctly as the new types' default values.

**When to use:** Wave 0 — before any content script or MCP tool implementation.

**Example:**

### Anti-Patterns to Avoid
- **Long-lived chrome.runtime.connect ports:** WXT's MV3 SW lifecycle means ports disconnect silently on SW termination. Use stateless `sendMessage` instead per D-02. [VERIFIED: WXT docs]
- **Running Readability on the live DOM:** Readability mutates the document. Always `document.cloneNode(true)` before passing to Readability. [CITED: github.com/mozilla/readability/README.md]
- **Skipping `isProbablyReaderable()` check:** Calling `parse()` on non-article pages (dashboards, SPAs) produces garbage. Use the gate function to decide extraction strategy. [CITED: github.com/mozilla/readability/README.md]
- **Storing HTML in chrome.storage.local:** The 10MB per-extension quota can exhaust quickly with full HTML. Store only `markdown` and structured metadata in PageContext. [ASSUMED]
- **Registering tools after ToolRegistry construction:** ToolRegistry initialization happens in module scope. Register new tools at import time alongside existing ones, not lazily.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| HTML → Markdown conversion | Custom regex/DOM walker | `turndown` 7.2.4 | Handles 50+ HTML elements (headings, lists, tables, code blocks, links, images), edge cases (nested formatting, whitespace), configurable output styles |
| Article content extraction | Custom heuristics (text density, link ratio) | `@mozilla/readability` 0.6.0 | Firefox Reader View algorithm — 10+ years of battle-testing across millions of sites; false positives are rare with `isProbablyReaderable()` gate |
| SPA navigation detection | `setInterval` polling on URL | `SPANavigationWatcher` with History API + title observer | Polling wastes CPU and misses transitions; History API monkey-patching catches `pushState`/`replaceState`/`popstate`/`hashchange` with zero overhead |
| Tab metadata fetching | Direct `chrome.tabs` API in content scripts | Background SW relay via `chrome.runtime.sendMessage` | Content scripts lack `chrome.tabs` API access; SW is the only context that can query tabs |
| Message validation | `any` type casting | `RuntimeEnvelope<T>` with Zod validation | Untyped messages are a runtime error vector; Zod schemas catch malformed messages at the boundary per HARD-05 |

**Key insight:** The extraction-to-markdown pipeline is a well-solved problem. `@mozilla/readability` + `turndown` is the same stack used by Firefox Reader View and Obsidian Web Clipper. Do not attempt to build custom extraction — the edge cases (RTL text, nested tables, code blocks, CJK content, SVG in articles) are unmanageable without a battle-tested library.

## Common Pitfalls

### Pitfall 1: Readability Mutates the Live DOM
**What goes wrong:** Calling `new Readability(document)` without cloning mutates the page's DOM tree (removes elements, inserts reader-mode markup), causing visual artifacts and broken page interactivity.
**Why it happens:** Readability is designed to process a document and produce clean reader output — it modifies the input document in-place as part of its algorithm.
**How to avoid:** Always `const clone = document.cloneNode(true) as Document` before passing to Readability. The clone is a detached document — mutations don't affect the live page.
**Warning signs:** Elements disappearing from the page after content script injection; layout shifts when opening the side panel.

### Pitfall 2: chrome.storage.local Quota Exhaustion
**What goes wrong:** Persisting full HTML or very large markdown documents in `PageContext` fills the 10MB `chrome.storage.local` quota, causing writes to silently fail.
**Why it happens:** WorkspaceStore persists `currentPageContext` and `pinnedTabs` (up to 10 entries) to `chrome.storage.local`. 10 full-page HTML documents can easily exceed 10MB.
**How to avoid:** Store only `markdown` (not raw `html` from Readability) in persisted `PageContext`. Set a ceiling of ~100KB per page context entry. Truncate and mark `extractionQuality: 'minimal'` if exceeded. For pinned tabs, store full `PageContext` in workspace but trim before persistence if approaching quota (D-07).

### Pitfall 3: SW Termination During Content Script Message Relay
**What goes wrong:** Background SW terminates between receiving a `GET_PAGE_CONTEXT_REQUEST` and the content script's response, dropping the message.
**Why it happens:** MV3 service workers terminate after ~30s of inactivity. If the SW relays a request to a content script and terminates before the response, the `sendResponse` callback is lost.
**How to avoid:** Keep message handling synchronous where possible. For async operations (tab query, content script relay), use `return true` in the listener and call `sendResponse` within 5 minutes (Chrome's limit). The SW won't terminate while `return true` listeners are pending.
**Warning signs:** Intermittent "No response" errors from `get-page-content` tool; timeout errors after ~30s of idle.

### Pitfall 4: SPA Router Interference with History API Patching
**What goes wrong:** Monkey-patching `history.pushState`/`replaceState` breaks the SPA's own routing library if not done correctly.
**Why it happens:** Many SPA routers (React Router, Vue Router) also wrap the History API. If content script's monkey-patch replaces the router's wrapper, navigation breaks.
**How to avoid:** Save references to original methods BEFORE the page's scripts load (use `runAt: 'document_start'`). Call the original method first, then dispatch the custom event. Never replace — always wrap and delegate.
**Warning signs:** SPA navigation stops working; back/forward buttons break; console errors from React Router/Vue Router.

### Pitfall 5: PinTabBar Re-renders on Every workspaceStore Change
**What goes wrong:** PinTabBar subscribing to the entire workspaceStore causes re-renders on conversation ID changes, draft updates, and other unrelated state mutations.
**Why it happens:** Zustand's default `useWorkspaceStore()` re-renders on any store change. PinTabBar only needs `currentPageContext` and `pinnedTabs`.
**How to avoid:** Use Zustand selectors: `useWorkspaceStore(s => s.currentPageContext)` and `useWorkspaceStore(s => s.pinnedTabs)`. This is the established pattern in `useChat.ts` (line 250-253).
**Warning signs:** Side Panel jank when typing in the composer; PinTabBar chips flickering during streaming.

### Pitfall 6: ContextOptimizerInput Schema Validation on PageContext
**What goes wrong:** The existing `contextOptimizerInputSchema` validates `pageContext: z.string().optional()`. Passing a `PageContext` object fails Zod validation.
**Why it happens:** The schema was written when `pageContext` was typed as `string`. A `PageContext` object is not a string.
**How to avoid:** **Option A (recommended):** Change the Zod schema to `pageContext: z.union([z.string(), z.record(z.unknown())]).optional()`. The `ContextCompressor.compressContext()` already handles both types (line 30-35). **Option B:** Serialize `PageContext` to a string before passing to ContextOptimizer. Option A is preferred because `ContextCompressor.structuralExtract()` produces better output from the structured object.

### Content Script with Readability Extraction
```typescript
// Source: @mozilla/readability README.md + WXT docs (github.com/wxt-dev/wxt)
import { defineContentScript } from 'wxt/utils/define-background';
import { Readability, isProbablyReaderable } from '@mozilla/readability';
import TurndownService from 'turndown';

const turndown = new TurndownService({
  headingStyle: 'atx',
  codeBlockStyle: 'fenced',
  bulletListMarker: '-',
});

interface PageContext {
  url: string;
  origin: string;
  hostname: string;
  title: string;
  markdown?: string;
  meta: Record<string, string>;
  extractedAt: number;
  selectedText?: string;
  extractionType: 'readability' | 'visible-content' | 'metadata-only';
  extractionQuality: 'article' | 'generic' | 'minimal';
}

function extractPageContext(doc: Document): PageContext {
  const meta: Record<string, string> = {};
  doc.querySelectorAll('meta[name], meta[property]').forEach(el => {
    const name = el.getAttribute('name') || el.getAttribute('property');
    const content = el.getAttribute('content');
    if (name && content) meta[name] = content;
  });

  const selectedText = window.getSelection()?.toString() || undefined;
  let markdown: string | undefined;
  let extractionType: PageContext['extractionType'] = 'metadata-only';
  let extractionQuality: PageContext['extractionQuality'] = 'minimal';

  if (isProbablyReaderable(doc)) {
    const clone = doc.cloneNode(true) as Document;
    const article = new Readability(clone).parse();
    if (article?.content && article.textContent.length >= 100) {
      markdown = turndown.turndown(article.content);
      extractionType = 'readability';
      extractionQuality = 'article';
    }
  }

  if (!markdown) {
    // Fallback: extract visible text from body
    const bodyText = doc.body?.innerText?.slice(0, 50000) || '';
    if (bodyText.length > 50) {
      markdown = bodyText;
      extractionType = 'visible-content';
      extractionQuality = 'generic';
    }
  }

  return {
    url: doc.URL,
    origin: doc.location.origin,
    hostname: doc.location.hostname,
    title: doc.title,
    markdown,
    meta,
    extractedAt: Date.now(),
    selectedText,
    extractionType,
    extractionQuality,
  };
}
```

### MCP Tool Registration (get-page-content)
```typescript
// Source: ToolDefinition interface (src/core/ai/tools/ToolDefinition.ts)
import { z } from 'zod';
import type { ToolDefinition } from '../ToolDefinition';
import { useWorkspaceStore } from '../../../stores/workspaceStore';

export const getPageContentTool: ToolDefinition = {
  name: 'get-page-content',
  description: 'Get the page content of the active tab or a pinned tab. Fresh extraction for active tab, cached for pinned tabs.',
  inputSchema: z.object({
    tabId: z.number().optional().describe('Tab ID for pinned tab context. Omit for active page.'),
  }),
  outputSchema: z.object({
    success: z.boolean(),
    page: z.object({
      url: z.string(),
      title: z.string(),
      markdown: z.string().optional(),
      meta: z.record(z.string()),
      extractedAt: z.number(),
      extractionType: z.string(),
    }).optional(),
    error: z.string().optional(),
  }),
  category: 'safe',
  requiresPermission: false,
  async execute(input, { abortSignal }) {
    const { tabId } = input as { tabId?: number };
    if (abortSignal.aborted) throw new DOMException('Aborted', 'AbortError');

    if (tabId !== undefined) {
      // Pinned tab → return cached PageContext
      const pinned = useWorkspaceStore.getState().pinnedTabs.find(t => t.tabId === tabId);
      if (!pinned) return { success: false, error: `Pinned tab ${tabId} not found` };
      return { success: true, page: pinned.page };
    }

    // Active page → trigger fresh extraction via content script
    return new Promise((resolve) => {
      chrome.tabs.query({ active: true, currentWindow: true }, ([tab]) => {
        if (!tab?.id) {
          resolve({ success: false, error: 'No active tab' });
          return;
        }
        chrome.tabs.sendMessage(tab.id, { type: 'GET_PAGE_CONTEXT_REQUEST' }, (response) => {
          resolve(response || { success: false, error: 'No response from content script' });
        });
      });
    });
  },
};
```

## Open Questions (RESOLVED)

1. **ContextOptimizerInput Zod schema — union type vs serialization?**
   - What we know: The `contextOptimizerInputSchema` validates `pageContext: z.string().optional()`. The ContextCompressor already handles `string | Record<string, unknown>` (line 30-35). Changing the schema to accept both types is safe.
   - What's unclear: Whether the planner prefers option A (union type in schema) or option B (serialize PageContext to string before passing).
   - Recommendation: Option A — change schema to `z.union([z.string(), z.record(z.unknown())]).optional()`. The compression is better when the object shape is available.

2. **`@mozilla/readability` installation in content script bundle**
   - What we know: Readability is a DOM library — it requires a browser `document` object. WXT bundles content scripts separately and won't tree-shake Readability from the main app bundle.
   - What's unclear: Whether WXT's bundler (vite) correctly handles dynamic `document.cloneNode(true)` calls from Readability in the ISOLATED world context.
   - Recommendation: Verify in Wave 0 by writing a smoke test that does `new Readability(document.cloneNode(true) as Document).parse()` from within the content script entrypoint.

3. **Security blocklist — NowPilot-owned URL detection**
   - What we know: D-26 requires blocking extraction from `chrome://`, `chrome-extension://`, `edge://`, `about:`, `view-source:`, `devtools://`, `file://`, and NowPilot-owned pages.
   - What's unclear: How to detect NowPilot-owned pages (Side Panel, Options, Standalone) at runtime. The extension ID is dynamic in development.
   - Recommendation: Use `chrome.runtime.id` to build the extension URL prefix: `chrome-extension://${chrome.runtime.id}/*`. Match against this at extraction time.

4. **Content script bundle size verification (CONT-04, <50KB)**
   - What we know: `@mozilla/readability` + `turndown` are non-trivial. Bundle size must stay under 50KB.
   - What's unclear: Whether WXT's tree-shaking will include only used exports from Readability (we don't need the command-line or Node.js parts).
   - Recommendation: Add a `tests/isolation/no-content-script-ui.test.ts` that builds the content script bundle and verifies: (a) size < 50KB, (b) no React/AntD/UI code in the bundle.

### Known Threat Patterns for Chrome Extensions + Content Scripts

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Content script injection into sensitive pages (chrome://, file://) | Information Disclosure | Built-in URL blocklist: reject extraction from `chrome://`, `chrome-extension://`, `edge://`, `about:`, `view-source:`, `devtools://`, `file://`, NowPilot-owned pages (D-26) |
| Password field extraction from login pages | Information Disclosure | Strip password fields, hidden inputs, token-bearing elements before constructing PageContext (D-26, D-28). Sanitize during extraction, not post-hoc. |
| Cross-site data leakage via pinned tab sharing | Information Disclosure | Pinned tabs are user-initiated (explicit pin action). Max 10 limit prevents bulk collection. No automatic pinning. |
| Malicious page crafting Readability-exploiting content | Denial of Service | Safety ceiling on extracted markdown size (~100KB). Truncate and mark `extractionQuality: 'minimal'` if exceeded. |
| SW message relay MITM (extension-internal) | Tampering | RuntimeEnvelope Zod validation on all message boundaries. SW validates envelope structure before acting. |
| Content script impersonation (tab ID spoofing) | Spoofing | SW validates `sender.tab?.id` from `chrome.runtime.onMessage` sender info — the browser guarantees sender identity, not the message payload |
