# Phase 7.2: Page Extraction & Pin Tab - Context

**Gathered:** 2026-07-17
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver content-script-based page extraction and a pin tab system. Content scripts run in ISOLATED world (extraction-only, no UI) and communicate via `RuntimeEnvelope<T>` through the Background Service Worker. `@mozilla/readability` extracts article content as markdown; non-article pages fall back to visible DOM text. A pin tab UI in the Side Panel footer lets users pin/unpin tabs (max 10). Two new MCP tools (`get-page-content`, `pin-tab`) are registered in ToolRegistry and executed via the existing ExecutorService pipeline. `workspaceStore.currentPageContext` changes from `string|null` to `PageContext|null` and is wired into `useChat()` and `useAgent()` so page context flows into every AI call through the existing ContextOptimizer.
</domain>

<decisions>
## Implementation Decisions

### Content Script Architecture
- **D-01 — Single WXT entrypoint with four modules:** One `content.ts` entrypoint that composes `PageExtractor` (Readability + DOM parsing), `PageContextBridge` (serialize to `PageContext`), `SPANavigationWatcher` (MutationObserver + history API), and `ContentChangeWatcher` (dormant, reserved for future dynamic-page support). Responsibilities stay cleanly separated through module boundaries while minimizing bundle complexity.
- **D-02 — chrome.runtime.sendMessage with RuntimeEnvelope<T>:** Content scripts communicate through typed, stateless messages sent to the Background Service Worker, which acts as the central relay and coordinator. Matches the event-driven nature of page extraction and keeps MV3 lifecycle management simple. No long-lived port connections.
- **D-03 — Navigation + on-demand extraction triggers:** Content script extracts on `DOMContentLoaded` and SPA navigation events (caching the latest `PageContext` in workspace state). When the AI invokes `get-page-content`, the SW sends an explicit extraction request to the content script for a fresh result. No polling.
- **D-04 — Background SW as typed message router:** The SW maintains a lightweight typed message router: listens for `PAGE_CONTEXT_UPDATE` from content scripts (persists to workspaceStore), and `GET_PAGE_CONTEXT_REQUEST` from panels (relays to active tab's content script). Stateless, no in-memory caching — relies on workspaceStore persistence.
- **D-05 — ISOLATED world only for v7.2:** `chrome.scripting` injection uses `ISOLATED` world exclusively. All required data (DOM, URL, title, meta, Readability extraction) is accessible from ISOLATED. MAIN world access for platform globals (e.g., ServiceNow `window.g_ck`) is deferred to Phase 8.

### PageContext Extraction Scope
- **D-06 — Readability-first with structured fallback:** Always extract `url`, `title`, and `meta`. Attempt `@mozilla/readability` extraction first; use the resulting markdown when quality is sufficient. For non-article pages (dashboards, complex SPAs), fall back to extracting cleaned visible content from the DOM.
- **D-07 — Optimizer-owned compression with safety ceiling:** Content script extracts the fullest reasonable representation; ContextOptimizer owns compression and degradation. The extractor enforces only a very high safety limit (e.g., max text size) and marks the result as truncated if exceeded.
- **D-08 — SelectedText as separate field, always captured:** Whenever extraction runs, capture the user's current text selection (if any) into a dedicated `selectedText` field within `PageContext`. ContextOptimizer can prioritize it over page content when present.
- **D-09 — Auto-detect page type with quality classification:** Use `@mozilla/readability` and content characteristics to classify extracted content. Store both `extractionType` (`readability`, `visible-content`, `metadata-only`) and `extractionQuality` (`article`, `generic`, `minimal`) in `PageContext` for downstream decisions.
- **D-10 — Full spec type with forward-compatible placeholders:** Implement the PRODUCT_SPEC `PageContext` interface (`url`, `origin`, `hostname`, `title`, `html`, `markdown`, `meta`, `extractedAt`) and extend with Phase 7.2 fields (`selectedText`, `extractionType`, `extractionQuality`). `addonId` and `addonFields` remain as optional/null placeholders for Phase 8.

### Pin Tab UI & Behavior
- **D-11 — Hybrid footer strip + management popover:** Pin UI lives as a compact, always-visible strip above the Side Panel composer area. Shows the current page chip + pinned tab chips (with overflow count). Clicking opens a popover/drawer with full pinned-tab management.
- **D-12 — Compact chips with favicon + title + actions:** Each pinned tab is a compact chip showing its favicon and truncated title. Pinned chips include a small unpin (×) action; the current-page chip exposes a pin action when not already pinned. Popover provides full management: reorder, unpin, view details.
- **D-13 — Persist closed pins as inactive:** A pinned item represents retained context, not a live browser tab. When the pinned tab is closed, keep its cached `PageContext` and metadata, mark it as inactive ("Tab Closed"), and continue showing it in the list. Future visits to the same URL can reactivate it.
- **D-14 — workspaceStore.pinnedTabs as TabContext[]:** Replace the current `string[]` implementation with a structured `TabContext[]` model containing tab metadata, pin status, timestamps, and a cached `PageContext`. Persisted through the existing WorkspaceStore → `chrome.storage.local` pipeline.

### Context Wiring
- **D-15 — workspaceStore as single source of truth:** Content scripts publish `PAGE_CONTEXT_UPDATED` events → Background SW updates `workspaceStore.currentPageContext` → persisted to `chrome.storage.local` → `useChat()`/`useAgent()` read from workspaceStore and pass to `ContextOptimizerInput.pageContext`. Fresh extraction only on explicit `get-page-content` tool call.
- **D-16 — Always include active page, conditionally include pinned tabs:** Active page context is included in every AI call (dedicated 10% budget allocation). Pinned tabs are also supplied to the optimizer but treated as lower-priority context — summarized, compressed, or dropped depending on remaining budget.
- **D-17 — Use existing ContextOptimizer pipeline:** Pass `pageContext` directly into `ContextOptimizerInput.pageContext` without introducing a separate pre-processing LLM step. The existing degradation pipeline (step 4: compress page context) handles all budget management.
- **D-18 — Change store type to PageContext | null:** Replace `currentPageContext: string | null` with `currentPageContext: PageContext | null` in workspaceStore. `PageContext` is a plain serializable JSON object — no serialize/deserialize at boundaries needed.
- **D-19 — Wire both useChat and useAgent:** Both hooks consume `workspaceStore.currentPageContext` and pass it into `ContextOptimizerInput.pageContext`. The only difference between Chat and Agent should be the UI presentation layer, not the available context.

### MCP Tool Contracts
- **D-20 — get-page-content: fresh for active, cached for pinned:** `get-page-content({ tabId?: number })` triggers a fresh extraction when targeting the active page (default), but returns the cached `PageContext` from `workspaceStore.pinnedTabs` when a pinned tab is requested by `tabId`. Keeps active-page analysis accurate while pinned tabs remain useful even after closure.
- **D-21 — pin-tab with explicit action parameter:** `pin-tab({ tabId, action })` where `action` is `"pin"` or `"unpin"` (defaulting to `"pin"`). The SW validates tab existence, enforces max 10, updates `workspaceStore.pinnedTabs`, and returns a structured result. Deterministic and easy for agents to reason about.
- **D-22 — Register in ToolRegistry + execute via SW:** Both tools are registered as standard tools in `ToolRegistry` and executed through the existing `ExecutorService` pipeline. The Background SW performs actual execution (tabs API access, content-script messaging, workspace updates). Automatically integrates with permissions, diagnostics, retries, and ThoughtChain visibility.

### Navigation Detection
- **D-23 — URL-based detection via History API + title observer:** `SPANavigationWatcher` monitors `history.pushState`, `history.replaceState`, `popstate`, `hashchange`, and `<title>` changes. When URL changes without full page reload, triggers re-extraction. Covers React Router, Vue Router, Angular Router without DOM-mutation heuristics.
- **D-24 — 300ms debounce:** After detecting SPA navigation, wait ~300ms before triggering extraction. Allows routing transitions and content rendering to settle. Full page loads bypass the debounce.
- **D-25 — Three extraction triggers:** Extract on `DOMContentLoaded` (content script injection), SPA navigation (300ms debounced), and Tab visibility change (hidden → visible, conditional refresh). Catches major page lifecycle events without polling.

### Security & Privacy
- **D-26 — Built-in blocklist with secure defaults:** Never extract from `chrome://`, `chrome-extension://`, `edge://`, `about:`, `view-source:`, `devtools://`, `file://`, or any NowPilot-owned page (Side Panel, Options, Standalone). Strip password fields, hidden inputs, tokens, session identifiers, and credential-like values before constructing `PageContext`.
- **D-27 — Persist active and pinned context only:** Store `currentPageContext` and pinned-tab `PageContext` snapshots via workspaceStore persistence. No historical archive of extracted pages. Content stays comfortably within extension storage budget (max 10 pins).
- **D-28 — Text-only extraction + field stripping:** Extract only text/markdown content — never executable page content. `@mozilla/readability` provides primary sanitization boundary; additionally strip password fields, hidden inputs, and credential patterns. No DOM sanitization (DOMPurify) needed since data is consumed as structured text, not rendered HTML.

### Pinned Content Budget
- **D-29 — Active page priority + pinned summaries:** Active page receives the primary page-context allocation. Pinned tabs are represented as lightweight summaries (title + first ~200 chars of markdown each) and may be compressed or dropped early during degradation. Keeps AI focused on the active page.
- **D-30 — Max 10, reject at limit:** Retain the product-spec limit of 10 pinned tabs. When at max, new pin attempts are rejected with a clear error message and a shortcut to manage existing pins. Pinned tabs represent intentional user-selected context and should never be silently removed.
- **D-31 — Full PageContext in store, summaries for AI:** Each pinned tab stores its full `PageContext` in `workspaceStore.pinnedTabs`. When assembling AI context, represent pinned tabs as lightweight summaries that `ContextOptimizer` can compress or drop as needed.

### the agent's Discretion
- Exact message type names and `RuntimeEnvelope` subtypes for page extraction communication.
- Internal `PageExtractor` implementation — Readability integration, turndown conversion, fallback extraction logic.
- `SPANavigationWatcher` internal implementation — history API monkey-patching details, title observer wiring.
- `PinTabBar` component implementation — AntD Tag/chip styling, popover layout, drag-to-reorder.
- `workspaceStore` type migration from `string[]` to `TabContext[]` for `pinnedTabs`.
- Content script registration in `wxt.config.ts` (WXT handles the manifest `content_scripts` entry).
- `ContentChangeWatcher` skeleton (dormant, no active observers).
</decisions>

## Existing Code Insights

### Reusable Assets
- **WorkspaceStore (Zustand + persist middleware):** Already has `currentPageContext` and `pinnedTabs` fields with setters. Type changes only — no new store needed.
- **ContextOptimizer:** Already handles `pageContext` in `ContextOptimizerInput` and allocates 10% budget. The degradation pipeline (8 steps) already compresses page context at step 4.
- **RuntimeEnvelope:** Already used for cross-context message validation. Content script messages use the same envelope pattern.
- **Background SW:** Already handles `PROXY_FETCH` messages. Add page extraction message types to the existing router.
- **ToolRegistry + ExecutorService:** Already support registering and executing tools with Zod validation, permission checks, and timeouts.

### Established Patterns
- **Zustand for state:** All shared state uses Zustand stores with `chrome.storage.local` persistence via `persist` middleware. Follow this for PageContext storage.
- **Stateless SW relay:** Background SW routes messages, never caches state in memory (MV3 termination risk). Use `chrome.storage` as the durable layer.
- **WXT entrypoints:** Each surface gets its own directory under `src/entrypoints/`. Content scripts follow same pattern.
- **Zod for validation:** Tool schemas use Zod v4. Message payloads use Zod validation via `RuntimeEnvelope`.

### Integration Points
- **`wxt.config.ts`:** Add `content_scripts` entry with `matches: ['<all_urls>']`, `runAt: 'document_idle'`. Add `activeTab` permission.
- **`src/entrypoints/background.ts`:** Add `PAGE_CONTEXT_UPDATED` and `GET_PAGE_CONTEXT_REQUEST` message handlers.
- **`src/hooks/useChat.ts` line 387-402:** Add `pageContext: workspaceStore.currentPageContext` to `contextInput`.
- **`src/hooks/useAgent.ts`:** Same wiring as useChat.
- **`src/core/stores/workspaceStore.ts`:** Change `currentPageContext` type and add `TabContext` type. Migrate `pinnedTabs` type.

## Deferred Ideas

- **MAIN world content script injection** — Deferred to Phase 8 (ServiceNow `window.g_ck`, Jira globals, platform-specific APIs). Leave extension point for site-specific extractors.
- **ContentChangeWatcher activation** — Dormant in Phase 7.2. Reserved for future dynamic-page support when specific applications require non-URL-based content refresh detection.
- **Per-site extraction opt-out (user-configurable blocklist)** — Deferred. Phase 7.2 uses a built-in blocklist only. User-configurable blocklist is a future enhancement.
- **CONT-06 (Right-click → "Ask AI")** — Removed from scope. Not needed.
- **DOMPurify sanitization** — Not needed in Phase 7.2. Extracted data is consumed as structured text, not rendered as HTML. If raw HTML display becomes a requirement in future phases, add DOMPurify at that time.
