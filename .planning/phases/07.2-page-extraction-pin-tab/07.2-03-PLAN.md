**Implementation details per locked decisions:**

- **D-01 (Single entrypoint):** Compose `new PageExtractor()`, `new PageContextBridge()`, `new SPANavigationWatcher()`, `new ContentChangeWatcher()` in `main()`.

- **D-26 (URL blocklist):** `shouldExtract(url)` helper that rejects `/^(chrome|chrome-extension|edge|about|view-source|devtools|file):\/\//i` AND `url.startsWith('chrome-extension://${chrome.runtime.id}')`. Run FIRST — if blocked, `return` immediately without registering any observers.

- **D-03, D-25 (Three triggers):**
  1. `if (document.readyState !== 'loading') { extractAndSend(); } else { document.addEventListener('DOMContentLoaded', extractAndSend, { once: true }); }`
  2. `navWatcher.watch((_url, _title) => { extractAndSend(); });`
  3. `document.addEventListener('visibilitychange', () => { if (document.visibilityState === 'visible') { extractAndSend(); } });`

- **extractAndSend() helper:** async function that calls `extractor.extract(document)` → `bridge.sendPageContextUpdate(pageContext)`. Wrap in try-catch with `debugLog('error', ...)`.

- **GET_PAGE_CONTEXT_REQUEST handler (D-03):** Listen on `chrome.runtime.onMessage`. When `message.type === 'GET_PAGE_CONTEXT_REQUEST'`, call `extractAndSend()` then respond with the extracted context. MUST `return true` for async `sendResponse` (RESEARCH.md Pitfall 3: SW termination risk).

- **Cleanup:** `ctx.onInvalidated(() => { navWatcher.destroy(); changeWatcher.destroy(); });`

```typescript
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  // NEW: Page extraction message routing (D-04)
  if (message && typeof message === 'object') {
    try {
      const env = validateEnvelope(message);

      // NEW: Handle PAGE_CONTEXT_UPDATED
      if (env.type === PAGE_CONTEXT_UPDATED) {
        const ctx = env.payload as PageContext;
        useWorkspaceStore.getState().setCurrentPageContext(ctx);
        sendResponse({ success: true });
        return true;
      }

      // NEW: Handle GET_PAGE_CONTEXT_REQUEST (relay to content script)
      if (env.type === GET_PAGE_CONTEXT_REQUEST) {
        chrome.tabs.query({ active: true, currentWindow: true }, ([tab]) => {
          if (tab?.id) {
            chrome.tabs.sendMessage(tab.id, message, (response) => {
              if (chrome.runtime.lastError) {
                sendResponse({ success: false, error: chrome.runtime.lastError.message });
              } else {
                sendResponse(response);
              }
            });
          } else {
            sendResponse({ success: false, error: 'No active tab' });
          }
        });
        return true; // async — keep channel open
      }
    } catch {
      // Invalid envelope — fall through to existing handlers
    }
  }

  // EXISTING: FETCH_PROXY handler (unchanged)
  if (message && typeof message === 'object' && message.type === 'FETCH_PROXY') {
    // ... existing code unchanged ...
  }

  return true;
});
```

**Key details per RESEARCH.md:**
- **D-15:** `PAGE_CONTEXT_UPDATED` → `useWorkspaceStore.getState().setCurrentPageContext(ctx)` — store is the single source of truth.
- **D-04:** Stateless relay — no in-memory caching. Uses workspaceStore persistence.
- **Pitfall 3:** `return true` for async operations (`chrome.tabs.query` + `sendMessage`). Keeps message channel open.
- **`chrome.runtime.lastError`:** Check after `chrome.tabs.sendMessage` — content script may not be injected (non-matching URL, blocked page).
- **Zod validation:** `validateEnvelope(message)` throws on invalid envelopes → caught by try-catch → falls through.
- `_sender` prefix on unused parameter to avoid lint warnings.

Do NOT modify the existing FETCH_PROXY handler. Add new cases before it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Content script → Background SW | Extracted page data crosses process boundary via chrome.runtime.sendMessage |
| Background SW → workspaceStore | PageContext written to chrome.storage.local via WriteJournal |
| MCP tool → chrome.tabs API | Tools execute in SW context with chrome.tabs privileges |
| AI → ToolRegistry → ExecutorService | get-page-content/pin-tab tools invoked by AI with user permission |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.2-07 | Spoofing | Content script tab ID in message sender | medium | mitigate | SW uses `sender.tab?.id` from `chrome.runtime.onMessage` sender info (browser-guaranteed), not from message payload. Pin-tab uses `chrome.tabs.get(tabId)` — browser validates tab existence. |
| T-07.2-08 | Denial of Service | Content script extraction on rapid navigation | medium | mitigate | 300ms debounce on SPA navigation (D-24). `shouldExtract` URL blocklist prevents extraction on sensitive pages. `chrome.runtime.lastError` handling for uninjectable tabs. |
| T-07.2-09 | Information Disclosure | get-page-content returns page content to AI | medium | accept | Tool returns extracted markdown/metadata — same data already persisted to workspaceStore. Active tab extraction is fresh, pinned tab returns cached snapshot. AI sees only what user has explicitly allowed via pinning. |
| T-07.2-10 | Elevation of Privilege | pin-tab tool executed by AI | medium | mitigate | Tool is category: 'safe', requiresPermission: false (D-22). Executes through ExecutorService with Zod validation. Max-10 limit enforced by workspaceStore.addPinnedTab. Pin action is user-reversible via UI. |
</threat_model>
