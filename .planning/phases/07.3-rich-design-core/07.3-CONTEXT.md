# Phase 7.3: RICH Design Core - Context

**Gathered:** 2026-07-18
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver the 17 P0 RICH design must-haves: AI persona profile and injection, branded visual identity, interactive Welcome Card capability discovery, context-aware quick action chips, AI-initiated clarification chips, proactive follow-up suggestions, code block inline actions, and richer streaming stage indicators. All work is primarily additive UI (new components, enhanced rendering) with one new core module (persona subsystem). Every foundational dependency is already in place — PlannerService supports `ask_clarification`, PromptManager has 22 builtin templates, UserMemoryStore supports preference tracking, workspaceStore provides currentPageContext, and the Think component exists for stage indicators.
</domain>

<decisions>
## Implementation Decisions

### Persona Architecture (RICH-R-01, R-02, R-11)
- **D-01 — Static profile + storage-ready service:** PersonaProfile.ts is a data-only file (structured definition of identity, values, tone, emotional-awareness rules). Access through PersonaService abstraction, which returns the static profile in v7.3 but enables storage-backed profiles in 7.4/7.5 without pipeline changes.
- **D-02 — Single inject() API:** PersonaInjector exposes one public method: `inject(systemPrompt: string): string`. Internally uses a structured prompt composer to build the PERSONA block. Callers (useChat, AgentOrchestrator) pass their raw system prompt and receive the enhanced version.
- **D-03 — Structured PERSONA block near start of prompt:** PersonaInjector generates a dedicated PERSONA section containing identity, core values, communication style, and behavioral preferences. Composed with task/tool/safety/output sections by the prompt builder. Keeps persona visible, avoids competing with tool schemas.
- **D-04 — Identity:** "NowPilot — Your AI work co-pilot." Broader identity than ServiceNow-only. ServiceNow expertise lives in the domain-expertise section.
- **D-05 — Visual avatar:** Bunny SVG as AI avatar (reuse existing asset from `UserAvatarMenu.tsx` lines 11-26). Used consistently across Chat, Agent, Welcome, Options surfaces. Existing sparkle icon remains as an action/accent symbol.
- **D-06 — Emotional awareness via persona rules:** Three explicit behaviors defined in PersonaProfile: frustration acknowledgment (acknowledge, validate, redirect to solutions), progress celebration (positive reinforcement), humble error recovery (brief apology, alternative approach). Rendered as prose rules in the PERSONA block by PersonaInjector. No separate classifier or LLM call.
- **D-07 — Fixed PERSONA block + optional contextual hints:** Core PERSONA block is fixed across all calls. PersonaInjector may accept optional behavioral hints (`user_frustrated`, `user_succeeded`, `user_corrected_ai`) that append a brief context-specific instruction. No adaptive persona engine needed.
- **D-08 — Response style:** Concise by default with task-aware expansion. Defaults to the shortest answer that fully resolves the request. Expands for explanations, planning, architecture, troubleshooting, or when user requests detail.
- **D-09 — Tone:** Professional + approachable — technically accurate, direct, practical, friendly. Uses clear everyday language, avoids corporate jargon, recommendation-first communication.
- **D-10 — Safety boundaries:** PERSONA block includes a safety-boundary rule describing the refusal style (polite, concise, constructive, offers safe alternatives). Actual refusal decisions remain the model's responsibility. No fixed refusal template.
- **D-11 — Capability discovery response:** When user asks "What can you do?" or "Help me", respond with a structured capability overview using the same categories as Welcome Cards (Research, Writing, Analysis, Coding, Support).
- **D-12 — Per-call injection:** `PersonaInjector.inject()` called every AI call — both `useChat()` system prompt assembly and `AgentOrchestrator.run()` system prompt. No caching. No stale-persona risk.
- **D-13 — Three-file structure:** `src/core/ai/persona/PersonaProfile.ts` (data model), `PersonaService.ts` (retrieval abstraction), `PersonaInjector.ts` (block generation + prompt injection). No separate PersonaPromptBuilder in v7.3.
- **D-14 — Integration point:** Replace static `'You are a helpful AI assistant.'` at `useChat.ts:433` and equivalent in AgentOrchestrator with `PersonaInjector.inject()`.

### Welcome Cards (RICH-I-01, I-02, I-04)
- **D-15 — Six curated capability cards:** Summarize This Page, Research a Topic, Draft a Response, Explain Code or Errors, Write a Script, Analyze Data. Stable capability anchors with context-aware ordering.
- **D-16 — Three-tier sorting:** (1) Most-used capabilities from PromptManager/UserMemoryStore usage history, (2) Contextual relevance boost from current page URL/hostname, (3) Curated default order when no history exists. Deterministic, lightweight.
- **D-17 — Replace ChatPage empty state:** WelcomeCards component renders inline in the existing ChatPage empty-state area (currently static text at line 1165-1182). Not an overlay or modal. Reuses PromptManager template definitions.
- **D-18 — Persistent dismiss:** `welcomeCardsDismissed` flag in user preferences/UserMemoryStore. Once dismissed, never shown again. Re-enable from Options or onboarding reset. Respects power users.
- **D-19 — Complementary to onboarding:** OnboardingModal remains responsible for first-run setup. Once complete, user reaches Chat and sees Welcome Cards. Onboarding = "How do I get started?", Welcome Cards = "What can I do next?"
- **D-20 — Component + service split:** `WelcomeCards.tsx` (presentation: grid rendering, click handling) + `WelcomeCardService.ts` (business logic: card generation from PromptManager, usage tracking, contextual scoring, ranking).
- **D-21 — Show on every new conversation:** Welcome Cards render on every empty chat, not just first visit. Users who dismiss see the persona greeting (RICH-C-14) instead.
- **D-22 — Hostname-based contextual ranking in v7.3:** Lightweight `hostname → capability boost` mapping table. `servicenow.com` → boost Summarize/Research; `github.com` → boost Explain Code/Write Script. No LLM required.

### Clarification (RICH-C-01, C-02, C-03, C-04)
- **D-23 — Planner-driven:** PlannerService already supports `ask_clarification` as a native action. When context is insufficient, returns `ask_clarification` with a question + 2-4 suggested response options. No separate pre-processor.
- **D-24 — Three explicit triggers + planner judgment:** Must trigger on: (1) missing required target (no pinned page, no quoted message), (2) ambiguous reference (multiple pinned tabs), (3) under-specified request (no language/purpose). Planner may also invoke when confidence is low.
- **D-25 — Two rounds max, then best-effort:** Track clarification rounds in conversation metadata. After round 2, proceed with best available assumptions, clearly stating them. Only refuse when a required target is completely unavailable.
- **D-26 — ClarificationAction UI:** Dedicated `ClarificationAction` component renders AntD Button chips (outline, small) in the Bubble. Planner returns structured data (question + options). Clicking a chip injects the selected text into the Sender.

### Follow-up Suggestions (RICH-C-05, C-06, C-07, C-08)
- **D-27 — Heuristic-first + optional Haiku:** Generate follow-up suggestions using client-side heuristics for common response types (summaries, code, translations, rewrites). For high-value outputs (research, planning, analysis), optionally invoke a Haiku-tier call (max ~30 tokens, non-blocking, 3s timeout). Graceful degradation — no suggestions on timeout.
- **D-28 — Quality-gated:** Only generate suggestions when the response naturally creates useful next steps. Simple eligibility heuristic; otherwise skip.
- **D-29 — FollowUpAction UI:** Button chips + visual divider + "Follow up" label. Reuses the same ActionChip pattern as ClarificationAction. Tapping sends as next user message.
- **D-30 — Chat-layer integration:** `FollowUpService.generateSuggestions()` called asynchronously after stream completion. Non-blocking — suggestions render when ready. No pipeline changes.

### Context-Aware Quick Actions (RICH-I-05, I-06)
- **D-31 — Static hostname mapping:** `QuickActionService` reads `workspaceStore.currentPageContext.hostname`, maps to category via a deterministic table, returns 2-3 predefined action chips. No LLM call. Instant, predictable.
- **D-32 — Reusable ActionChip component:** Quick actions, clarification chips, and follow-up chips all use a shared `ActionChip` / `ActionChipGroup` component. Allows minor visual variants (icons for quick actions) while keeping interaction behavior consistent.
- **D-33 — Three primary chips + horizontal scroll:** Highest-ranked 3 chips visible. Container scrolls horizontally for additional actions. No "More" popover in v7.3 (deferred to 7.5).
- **D-34 — Above Sender in ChatPage:** Renders as a conversational action strip between the message area and the Sender. Consumes workspaceStore state. PinTabBar stays focused on pin management.

### Streaming Stage Indicators (RICH-H-08)
- **D-35 — Enhanced Think pill labels:** Extends existing Think component to render context-aware stage pills: "Reading page context…" (when pinned tabs exist), "Planning response…" (during planner execution), "Generating…" (during main stream). Pills shown above the streaming bubble.
- **D-36 — Pipeline event-driven:** ContextOptimizer emits "Reading page context…" stage, PlannerService emits "Planning response…", RendererService emits "Generating…". Think component is a presentation layer — stages are driven by actual pipeline events, not Think output parsing.
- **D-37 — Slow-stream indicator:** If >3s since last token during generation, show "Still working…" below the stage pill with a subtle pulse animation. No progress bar or ETA (pipeline cannot reliably estimate completion).
- **D-38 — Chat mode only:** Agent mode uses ThoughtChain for step-by-step visibility; stage indicators would be redundant. Agent mode uses "NowPilot is working…" branding treatment instead.

### Code Block Actions (RICH-H-04)
- Note: Code block inline actions (Copy code, Insert into page, Save as macro) are specified in the requirements doc but were not a discussion topic. The agent has discretion over the specific implementation — reuse existing copy action, add new Insert and Save-as-macro buttons on detected code fences.

### the agent's Discretion
- Exact internal API of `PersonaService` — static profile return shape, method names.
- `PersonaInjector` internal prompt composer — how the PERSONA block is formatted (prose structure).
- `WelcomeCardService` implementation details — scoring weights, hostname mapping table entries.
- `QuickActionService` hostname → category mapping table content (ServiceNow, GitHub, etc.).
- `FollowUpService` heuristic rules for eligibility detection.
- `ClarificationAction` / `FollowUpAction` / `ActionChip` component props and variant styling.
- Stage indicator emission — exact event names and payloads in the pipeline.
- `PersonaProfile` data structure — field names, nested objects for emotional rules.
- Code block action button implementation — detection of markdown code fences, button placement.

## Existing Code Insights

### Reusable Assets
- **PromptManager** (`src/core/prompts/PromptManager.ts`): 22 builtin templates with categories — data source for Welcome Cards and template browser. Use `getAllTemplates()` for card generation.
- **UserMemoryStore** (`src/core/memory/UserMemoryStore.ts`): MiniSearch-backed preference/usage tracking — store `welcomeCardsDismissed` flag, tip-dismissal tracking.
- **workspaceStore** (`src/core/stores/workspaceStore.ts`): `currentPageContext` (PageContext with hostname/url), `pinnedTabs` — used by QuickActionService and WelcomeCardService for contextual ranking.
- **Bunny SVG** (`src/components/common/UserAvatarMenu.tsx:11-26`): Existing bunny avatar — reuse for AI identity across all surfaces.
- **Think component** (`@ant-design/x` Think): Already used in ChatPage for stage indication — extend with richer pipeline-driven labels.
- **ChatPage empty state** (lines 1165-1182): Currently static greeting text — injection point for WelcomeCards component.
- **PinTabBar** (`src/components/sidepanel/PinTabBar.tsx`): Existing chip strip above Sender — QuickActionChips rendered separately above Sender (not inside PinTabBar).

### Established Patterns
- **Zustand stores + chrome.storage.local persistence:** workspaceStore pattern for state that persists across sessions. WelcomeCards dismiss flag follows this pattern.
- **Ant Design X Bubble/Sender:** Chat presentation uses `@ant-design/x` 2.8.0 components. Action chips render inside Bubble; stage indicators above Bubble.
- **PlannerService action enum:** `answer | run_tool | ask_clarification` — clarification is already a first-class pipeline action. UI needs to handle the `ask_clarification` case.
- **Fire-and-forget async operations:** `useChat.ts:267-277` pattern for `memoryEngine.extract()` after stream — FollowUpService follows the same pattern.

- **ChatPage.tsx:1165-1182** — Empty state → WelcomeCards component
