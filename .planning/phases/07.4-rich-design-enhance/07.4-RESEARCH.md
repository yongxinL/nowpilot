# Phase 07.4: RICH Design Enhance - Research

**Researched:** 2026-07-19
**Domain:** React UI enhancement — chat UX, split-pane layout, persona onboarding, template browsing, inline confirmation, clipboard integration
**Confidence:** HIGH

## Summary

Phase 07.4 extends the Phase 7.3 RICH foundation with 22 P1 should-have enhancements across all four RICH pillars. Every feature builds on existing component primitives (Sender, Bubble, BrandedHeader, ActionChipGroup, WelcomeCards) and core services (PersonaService, PermissionService, PromptManager, PreferenceMemoryStore). No new external dependencies are required — all new UI uses antd v6.5.0 and @ant-design/x v2.8.0 primitives, with Zustand v5.0.14 for client-side state.

The phase introduces three new Zustand stores (RightPaneStore for pane UI state, extended PreferenceMemoryStore for persona/displayName fields, and a lightweight TemplateBrowserService wrapping PromptManager), two new React hooks (useGreeting, useConversationClosure), and one new core service (GreetingService as a pure function module). The PermissionService interface gains a ConfirmationLevel tiered model (AutoExecute / ConfirmInline / RequirePermission) that gates tool execution in both Chat and Agent modes.

**Primary recommendation:** Execute in two waves: Wave 1 builds data-layer extensions (ConfirmationLevel, RightPaneStore, PreferenceMemoryStore fields, TemplateBrowserService, GreetingService) and stateless components (TemplateBrowser, InlineConfirmationCard, MeetNowPilotStep, StructuredOutputActions, ConversationClosure). Wave 2 integrates everything into the existing ChatPage, StandaloneRoot, BrandedHeader, and OnboardingModal. This ordering ensures all UIs have their data dependencies ready before integration.

### Pattern 1: Zustand Store with Persistent + Transient State (RightPaneStore)

**What:** Zustand store with `persist` middleware and `partialize` to persist only UI layout state (activeTab, visible, width) while transient search/selection state remains in-memory only.

**When to use:** Any store where some fields should survive page reload (layout preferences) but others should reset (search queries, selected items).

**Example:**
```typescript
// Source: /pmndrs/zustand docs — persist middleware partialize
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';

interface RightPaneState {
  // Persisted
  activeTab: 'context' | 'notes' | 'tools';
  visible: boolean;
  width: 'compact' | 'expanded';
  // Transient (not persisted)
  searchQuery: string;
  selectedNoteId: string | null;
  expandedToolId: string | null;
  // Actions
  setActiveTab: (tab: RightPaneState['activeTab']) => void;
  setVisible: (visible: boolean) => void;
  toggleWidth: () => void;
  setSearchQuery: (query: string) => void;
  setSelectedNoteId: (id: string | null) => void;
  setExpandedToolId: (id: string | null) => void;
}

const chromeLocalStorage = createJSONStorage<RightPaneState>(() => ({
  getItem: (name) =>
    chrome.storage.local.get(name).then((r) => (r[name] as string) ?? null),
  setItem: (name, value) => chrome.storage.local.set({ [name]: value }),
  removeItem: (name) => chrome.storage.local.remove(name),
}));

export const useRightPaneStore = create<RightPaneState>()(
  persist(
    (set) => ({
      activeTab: 'context',
      visible: true,
      width: 'compact',
      searchQuery: '',
      selectedNoteId: null,
      expandedToolId: null,
      setActiveTab: (tab) => set({ activeTab: tab }),
      setVisible: (v) => set({ visible: v }),
      toggleWidth: () => set((s) => ({ width: s.width === 'compact' ? 'expanded' : 'compact' })),
      setSearchQuery: (q) => set({ searchQuery: q }),
      setSelectedNoteId: (id) => set({ selectedNoteId: id }),
      setExpandedToolId: (id) => set({ expandedToolId: id }),
    }),
    {
      name: 'np_right_pane',
      storage: chromeLocalStorage,
      partialize: (state) => ({
        activeTab: state.activeTab,
        visible: state.visible,
        width: state.width,
      }),
    },
  ),
);
```

### Pattern 2: @ant-design/x Sender Image Paste Integration

**What:** The `Sender` component provides an `onPasteFile` callback that receives a `FileList` when the user pastes files (including images from clipboard). No raw `ClipboardEvent` parsing needed — the Sender extracts images automatically.

**When to use:** When pasting clipboard images into the chat input.

**Example:**
```typescript
// Source: /ant-design/x v2.8.0 SenderProps
// The Sender wraps the textarea and handles paste events internally,
// extracting any image files from ClipboardEvent.clipboardData.files
// and passing them as a FileList to onPasteFile.

<Sender
  value={draft}
  onChange={(v) => setDraft(v)}
  onSubmit={(msg) => send(msg)}
  onPasteFile={(files: FileList) => {
    const imageFiles = Array.from(files).filter(f => f.type.startsWith('image/'));
    const newAttachments = imageFiles.map((file) => ({
      id: crypto.randomUUID(),
      name: `Pasted-${Date.now()}.png`,
      url: URL.createObjectURL(file),
      type: file.type,
      file,
    }));
    setAttachedFiles((prev) => [...prev, ...newAttachments]);
    // Note: onPasteFile in Sender v2.x receives FileList as default parameter type
  }}
  header={attachmentHeader}  // Shows attachment thumbnails
  prefix={/* TemplateBrowser trigger button */}
/>
```

### Pattern 3: antd Popover as Template Browser

**What:** A controlled `Popover` with `trigger="click"` and `placement="top"` that contains `Input.Search` for filtering + categorized accordion sections of prompt templates. Selecting a template calls the insertion callback.

**When to use:** Browsing and selecting prompt templates to populate the Sender.

**Example:**
```typescript
// Source: /ant-design/ant-design v6.5.0 Popover component
import { Popover, Input, Button } from 'antd';
import { TemplateOutlined } from '@ant-design/icons';

function TemplateBrowser({ onInsert }: { onInsert: (template: string) => void }) {
  const [open, setOpen] = useState(false);
  const [search, setSearch] = useState('');

  const content = (
    <div style={{ width: 360 }}>
      <Input.Search
        placeholder="Search templates..."
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        style={{ marginBottom: 12 }}
      />
      {/* Categorized accordion sections */}
      {categories.map((cat) => (
        <CategorySection key={cat.name} category={cat} onSelect={(tpl) => {
          onInsert(tpl.template);
          setOpen(false);
        }} />
      ))}
    </div>
  );

  return (
    <Popover
      content={content}
      trigger="click"
      open={open}
      onOpenChange={setOpen}
      placement="top"
    >
      <Button
        type="text"
        icon={<TemplateOutlined />}
        aria-label="Browse templates"
      />
    </Popover>
  );
}
```

### Pattern 4: ConfirmationLevel Tiered Permission Model

**What:** Extend the existing `PermissionService` interface with a `ConfirmationLevel` enum and a `canAutoExecute()` method. The `ConfirmationPolicy` static mapping determines which tools map to which level.

**When to use:** Gating tool execution in both Chat mode (inline confirmation) and Agent mode (PermissionDialog modal).

**Example:**
```typescript
// Source: Existing PermissionService.ts interface pattern + D-18 decision
export enum ConfirmationLevel {
  AutoExecute = 'auto',
  ConfirmInline = 'inline',
  RequirePermission = 'require',
}

export interface PermissionService {
  canExecute(toolName: string, toolInput: Record<string, unknown>): Promise<boolean>;
  getConfirmationLevel(toolName: string): ConfirmationLevel;
}
```

**Key insight for ChatPage rendering:**
- `AutoExecute` — tool runs silently, no UI
- `ConfirmInline` — render `InlineConfirmationCard` in Bubble with Proceed/Cancel chips
- `RequirePermission` — delegate to existing Agent `PermissionDialog` modal

### Anti-Patterns to Avoid

- **Re-creating attachment pipeline for image paste:** Paste events feed into the EXISTING `attachedFiles` state and `attachmentHeader` — do not create a separate image paste pipeline.
- **Putting domain data in RightPaneStore:** D-07 is explicit — RightPaneStore manages only UI state (activeTab, visible, width). Domain data (pinned tabs, notes, MCP config) is read from existing stores (workspaceStore, NotesDB, MCP config).
- **Direct PromptManager calls from TemplateBrowser UI:** D-15 mandates TemplateBrowserService as the intermediary. The UI component consumes TemplateBrowserService, not PromptManager directly.
- **Using `navigator.clipboard.read()` for image paste:** The Sender's `onPasteFile` handler uses `ClipboardEvent.clipboardData.files` which works without the `clipboard-read` permission. `navigator.clipboard.read()` requires the async Clipboard API permission which Chrome extensions may not have.
- **Persisting conversation closure decisions:** D-19 explicitly forbids persistent memory for chat confirmations. One-time, per-action only.
- **Auto-showing/hiding right pane based on content:** D-02 mandates user-controlled visibility. Never auto-show/hide.

## Common Pitfalls

### Pitfall 1: RightPaneStore Transient State Leaking to Persistence

**What goes wrong:** Developers accidentally include `searchQuery`, `selectedNoteId`, or `expandedToolId` in the `partialize` function, causing search terms to persist across page reloads and creating confusing UX.

**Why it happens:** The `partialize` function is easy to forget to update when adding new fields to the store. If `partialize` is omitted entirely, ALL state (including transient search queries) is persisted.

**How to avoid:** Always pass explicit `partialize: (state) => ({ activeTab, visible, width })` — whitelist rather than implicit. Write a unit test that verifies `searchQuery` is NOT present in the persisted state after `setSearchQuery` and reload.

**Warning signs:** Search query persists after closing and reopening the right pane; selected note remains highlighted after navigating away.

### Pitfall 2: onPasteFile Double-Firing

**What goes wrong:** Adding both `onPasteFile` on the Sender AND `onPaste` on the wrapper div causes duplicate attachment creation.

**Why it happens:** The Sender's `onPasteFile` fires when images are detected; the wrapper's `onPaste` would also fire for the same event if both handlers are active. The existing ChatPage wrapper div already has `onDrop` for drag-drop.

**How to avoid:** Use ONLY `onPasteFile` on the Sender component. Remove any `onPaste` handler from the wrapper div. The Sender's internal paste handling extracts images automatically.

**Warning signs:** Duplicate thumbnail entries appearing for a single paste action.

### Pitfall 3: Template Popover Placement Conflict with Sender Auto-Resize

**What goes wrong:** The template browser Popover with `placement="top"` overlaps the Sender or gets cut off when the Sender auto-resizes (grows taller as content is typed).

**Why it happens:** antd Popover position is calculated relative to the trigger element at open time. If the Sender's height changes (autoSize), the Popover position becomes stale.

**How to avoid:** Use `placement="topLeft"` with sufficient offset. Pass `destroyTooltipOnHide` or close the Popover on any Sender value change (`onChange` → `setOpen(false)`).

**Warning signs:** Popover appearing behind or overlapping the Sender; Popover not repositioning when Sender height changes.

### Pitfall 4: PersonaService getActiveProfile() Deep Merge Complexity

**What goes wrong:** A shallow merge of preference overrides onto DEFAULT_PERSONA_PROFILE loses nested fields; a recursive deep merge causes unexpected mutations to the canonical profile object.

**Why it happens:** The PersonaProfile has nested objects (identity, languageStyle, emotionalAwareness). Shallow spread `{ ...default, ...overrides }` only merges top-level keys.

**How to avoid:** Create a new profile object from DEFAULT_PERSONA_PROFILE, then apply only the fields that are present in preference overrides. Use explicit field-level assignment rather than `Object.assign` or spread on nested objects. Freeze DEFAULT_PERSONA_PROFILE to catch accidental mutations in tests.

**Warning signs:** Custom `aiName` not appearing in prompts; `aiTone` override being silently ignored.

### Pitfall 5: Right Pane Drawer Degradation at Wrong Breakpoint

**What goes wrong:** The Drawer appears too early (usable space remains) or too late (inline pane is squeezed to <200px and unreadable).

**Why it happens:** The breakpoint must consider: viewport width, sider width (56px or 240px), required minimum chat area (~400px), and right pane compact width (320px). Simple `window.innerWidth < X` fails when sider is collapsed.

**How to avoid:** Calculate available width as `containerRef.current.offsetWidth - (collapsed ? 56 : 240)`. When available width < 320 (right pane width) + 400 (minimum chat) = 720px → degrade. Use `ResizeObserver` on the content container, not `window.resize`.

**Warning signs:** Right pane content clipped or unreadable at moderate window widths; Drawer triggering at full screen on large monitors.

### Image Paste Integration in ChatPage Sender

```typescript
// Source: CONTEXT.md D-30, D-31, D-32 + /ant-design/x SenderProps
// Integration point: ChatPage.tsx Sender wrapper (line 1839-2054)

// The Sender's onPasteFile handles clipboard image extraction.
// Pasted images feed into the EXISTING attachedFiles state and attachment pipeline.

<Sender
  value={draft}
  loading={isStreaming}
  onChange={(v) => setDraft(v)}
  onSubmit={(msg) => {
    let finalMsg = msg;
    const attachmentsData = attachedFiles.map((f) => ({
      id: f.id, name: f.name, url: f.url, base64: f.base64, type: f.type,
    }));
    if (attachmentsData.length > 0) {
      const attachmentsInfo = attachmentsData
        .map((f) => `<attachment name="${f.name}" type="${f.type}">${f.base64}</attachment>`)
        .join('\n');
      finalMsg = `${finalMsg}\n\n${attachmentsInfo}`;
    }
    send(finalMsg, { attachments: attachmentsData });
    clearAttachedFiles();
  }}
  onCancel={abort}
  placeholder="Ask anything, @ models, / prompts..."
  autoSize={{ minRows: 4, maxRows: 8 }}
  header={attachmentHeader}
  prefix={
    <TemplateBrowser
      onInsert={(tpl) => setDraft((prev) => prev + tpl)}
    />
  }
  onPasteFile={(files: FileList) => {
    const imageFiles = Array.from(files).filter(f => f.type.startsWith('image/'));
    if (imageFiles.length === 0) return;
    // Enforce existing limit (5 max, D-31)
    const remaining = 5 - attachedFiles.length;
    const toAdd = imageFiles.slice(0, remaining);
    if (toAdd.length < imageFiles.length) {
      debugLog('info', `[ChatPage] Image paste: ${imageFiles.length - toAdd.length} files dropped (limit 5)`);
    }
    const newAttachments = toAdd.map((file) => ({
      id: crypto.randomUUID(),
      name: file.name || `Pasted-${Date.now()}.png`,
      url: URL.createObjectURL(file),
      type: file.type,
      file,
    }));
    setAttachedFiles((prev) => [...prev, ...newAttachments]);
  }}
/>
```

### GreetingService Pure Function

```typescript
// Source: D-21, D-22, D-24
// File: src/core/greeting/GreetingService.ts

export interface GreetingInput {
  displayName?: string;
  pageTitle?: string;
}

export interface Greeting {
  greeting: string;        // e.g., "Good morning, George"
  timeOfDay: 'morning' | 'afternoon' | 'evening';
  tagline: string;         // "Your AI work co-pilot"
  contextualLine?: string; // e.g., "You're working on: INC0012345"
}

export function generateGreeting(input: GreetingInput): Greeting {
  const hour = new Date().getHours();
  const timeOfDay = hour < 12 ? 'morning' : hour < 17 ? 'afternoon' : 'evening';
  const timePrefix = timeOfDay === 'morning' ? 'Good morning'
    : timeOfDay === 'afternoon' ? 'Good afternoon'
    : 'Good evening';

  const greeting = input.displayName
    ? `${timePrefix}, ${input.displayName}`
    : `${timePrefix}! How can I help?`;

  const contextualLine = input.pageTitle
    ? `You're working on: ${input.pageTitle}`
    : undefined;

  return {
    greeting,
    timeOfDay,
    tagline: 'Your AI work co-pilot',
    contextualLine,
  };
}
```

## Open Questions

1. **ConfirmationPolicy: which tools map to which ConfirmationLevel?**
   - What we know: D-18 specifies three tiers. Read-only local → AutoExecute. External lookups → ConfirmInline. Side-effect actions → RequirePermission.
   - What's unclear: Exact mapping for the ~12 built-in MCP tools + external MCP tools.
   - Recommendation: The agent has discretion per CONTEXT.md. Default mapping: page extraction tools (AutoExecute), web_search/web_fetch (ConfirmInline), all CRUD/send tools (RequirePermission). This is easily tuned post-implementation.

2. **Responsive breakpoint for Drawer degradation — exact pixel value?**
   - What we know: D-04 specifies "below ~900px right pane width" — this means available width for the right pane area, not viewport width.
   - What's unclear: Whether "~900px" means total viewport width or the right-pane-allocated space.
