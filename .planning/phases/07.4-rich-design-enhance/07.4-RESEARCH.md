## Summary

Phase 07.4 extends the Phase 7.3 RICH foundation with 22 P1 enhancements across all four pillars (Role, Intention, Conversation, Hybrid UI). All work is additive UI built on top of existing 7.3 components and services — PersonaService, PersonaInjector, BrandedHeader, WelcomeCards, ActionChipGroup, Sender (already using `@ant-design/x` Sender), and the attachment pipeline. No new npm packages are required; every dependency is already in `package.json`.

The primary architectural challenge is the split-pane layout which requires a new column in `StandaloneRoot.tsx` and a new `RightPaneStore` (Zustand) following the project's established pattern for chrome.storage.local persistence. All other features integrate into existing component surfaces: OnboardingModal Step 1 replacement, ChatPage empty state greeting, Sender toolbar popover, Bubble inline content, and attachment pipeline.

**Primary recommendation:** Build all features using existing `@ant-design/x` Sender/Bubble components and `antd` Popover/Tabs/Drawer — the Sender already supports `onPaste`/`onPasteFile`/`prefix`/`header` props, eliminating any need for custom input handling.

### Pattern 1: Zustand Persist Store (RightPaneStore)

**What:** Lightweight Zustand store with chrome.storage.local persistence for UI-only state. Follows existing workspaceStore and preferenceStore patterns exactly.

**When to use:** Every new persistent store in this project.

**Example:**
```typescript
// Source: Existing pattern from workspaceStore.ts and preferenceStore.ts
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';

interface RightPaneState {
  activeTab: 'context' | 'notes' | 'tools';
  visible: boolean;
  width: 'compact' | 'expanded';
  searchQuery: string;
  selectedNoteId: string | null;
  expandedToolId: string | null;
  setActiveTab: (tab: RightPaneState['activeTab']) => void;
  setVisible: (visible: boolean) => void;
  setWidth: (width: RightPaneState['width']) => void;
  setSearchQuery: (query: string) => void;
  setSelectedNoteId: (id: string | null) => void;
  setExpandedToolId: (id: string | null) => void;
}

const chromeLocalStorage = createJSONStorage<RightPaneState>(() => ({
  getItem: (name: string) =>
    chrome.storage.local.get(name).then((result) => (result[name] as string) ?? null),
  setItem: (name: string, value: string) => chrome.storage.local.set({ [name]: value }),
  removeItem: (name: string) => chrome.storage.local.remove(name),
}));

export const useRightPaneStore = create<RightPaneState>()(
  persist(
    (set) => ({
      activeTab: 'context',
      visible: true,
      width: 'compact',
      searchQuery: '',
      selectedNoteId: null,
      expandedToolId: null,
      setActiveTab: (tab) => set({ activeTab: tab }),
      setVisible: (visible) => set({ visible }),
      setWidth: (width) => set({ width }),
      setSearchQuery: (query) => set({ searchQuery: query }),
      setSelectedNoteId: (id) => set({ selectedNoteId: id }),
      setExpandedToolId: (id) => set({ expandedToolId: id }),
    }),
    {
      name: 'np_right_pane',
      storage: chromeLocalStorage,
      partialize: (state) => ({
        activeTab: state.activeTab,
        visible: state.visible,
        width: state.width,
        // transient state NOT persisted: searchQuery, selectedNoteId, expandedToolId
      }),
    },
  ),
);
```

### Pattern 2: Service + Hook + Component (GreetingService)

**What:** Pure function service computes greeting data; React hook calls it reactively; BrandedHeader renders the result. Follows WelcomeCardService + WelcomeCards pattern.

**When to use:** Computed data that depends on multiple stores (PreferenceMemoryStore, workspaceStore).

**Example:**
```typescript
// Source: Pattern from WelcomeCardService + WelcomeCards (Phase 7.3)
// 1. Service — pure functions, no React dependency
export const GreetingService = {
  getGreeting(prefs: { displayName?: string }, context: { pageTitle?: string }): Greeting {
    const hour = new Date().getHours();
    const timeOfDay = hour < 12 ? 'morning' : hour < 17 ? 'afternoon' : 'evening';
    const greeting = timeOfDay === 'morning' ? 'Good morning' :
                     timeOfDay === 'afternoon' ? 'Good afternoon' : 'Good evening';
    const name = prefs.displayName;
    const contextualLine = context.pageTitle ? `You're working on: ${context.pageTitle}` : undefined;
    return { greeting, name, timeOfDay, contextualLine, tagline: 'Your AI work co-pilot' };
  },
};

// 2. Hook
export function useGreeting(): Greeting {
  const prefs = usePreferenceStore((s) => ({ displayName: s.displayName }));
  const pageContext = useWorkspaceStore((s) => s.currentPageContext);
  return useMemo(
    () => GreetingService.getGreeting(prefs, { pageTitle: pageContext?.title }),
    [prefs.displayName, pageContext?.title],
  );
}
```

### Anti-Patterns to Avoid

- **Anti-pattern: Embedding full domain data in RightPaneStore.** D-07 explicitly limits RightPaneStore to presentation state. Domain data reads from existing stores (workspaceStore, NotesDB, MCP config). Violating this creates stale-data bugs and store synchronization problems.
- **Anti-pattern: Using antd Layout.Sider for the right pane.** Layout.Sider is designed for navigation sidebars with fixed positioning. The right pane should be a flex column with `overflow: auto` — simple CSS divs, not a Sider.
- **Anti-pattern: Calling `navigator.clipboard.read()` for image paste.** Chrome extensions in content-security-policy contexts may not have clipboard-read permission. Use the `paste` DOM event's `clipboardData.files` instead — this is the standard, permissionless approach already confirmed by the Sender's `onPasteFile` prop.
- **Anti-pattern: Adding `chrome.identity` permission for user name.** D-21 and Deferred Ideas both explicitly reject this. Use the optional `displayName` preference field instead.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Image paste detection | Custom clipboard event handler on textarea wrapper | Sender's built-in `onPasteFile` prop from `@ant-design/x` | Sender already imported and used in ChatPage; `onPasteFile` handles cross-browser clipboard API quirks |
| Template popover UI | Custom dropdown/modal with search | antd `Popover` + `Input.Search` + categorized sections | Popover handles positioning, focus trapping, and click-outside-dismiss; building custom is fragile |
| Split-pane drag-resize | Custom mouse-event resize logic | CSS flex columns + two preset widths toggled by button | D-03 explicitly defers freeform drag-resize; presets eliminate hundreds of lines of resize event handling, boundary clamping, and RTL support |
| Right pane tab state persistence | Custom localStorage wrapper | Zustand `persist` middleware with `createJSONStorage` + chrome.storage.local | Already used by workspaceStore and preferenceStore — consistent pattern, battle-tested hydration |
| Blob→File conversion for pasted images | Manual File constructor with MIME type guess | `new File([blob], filename, { type: blob.type })` — built-in, no library | File constructor is standard ES6; blob.type provides MIME; no library needed |

## Common Pitfalls

### Pitfall 1: Right Pane Causes Layout Shift on Small Screens

**What goes wrong:** Adding a third column to StandaloneRoot causes the chat area to become unusably narrow on smaller standalone windows (~900-1100px).

**Why it happens:** StandaloneRoot is a flex row with fixed-width sider (240px) + flexible center + new right pane. At small widths, three columns compete for space.

**How to avoid:** Implement D-04: use a CSS media query or `ResizeObserver` on the root element. When available width for the right pane drops below ~320px (compact mode), switch from inline column to antd `Drawer` overlay. The transition point is when `window.innerWidth - 240 (sider) - 300 (minimum chat) < 320`. Use `useRightPaneStore` to track the mode.

**Warning signs:** Chat messages become single-word lines, Sender wraps awkwardly, horizontal scrollbars appear in the chat area.

### Pitfall 2: Chrome Storage Quota for RightPaneStore

**What goes wrong:** Adding another chrome.storage.local key (`np_right_pane`) alongside existing np_workspace, np_preferences, np_providers, np_prompt_templates, np_slash_commands, np_mcp_permissions — exceeding the 10MB quota.

**Why it happens:** Chrome enforces a manifest-level `storage.managed_schema` quota. While 10MB is generous for JSON, large accumulated stores (especially chat history + notes) can approach the limit.

**How to avoid:** RightPaneStore stores only 4 small fields (activeTab, visible, width — strings/booleans) — less than 100 bytes. Transient state (searchQuery, selectedNoteId) uses `partialize` to exclude from persistence. The risk is negligible.

**Warning signs:** `chrome.storage.local.set` returning quota errors in console.

### Pitfall 3: ConfirmationLevel Enum Breaks Existing PermissionService Consumers

**What goes wrong:** ExecutorService currently calls `permissionService.canExecute(toolName, toolInput)` and expects a boolean. Adding `ConfirmationLevel` changes the return type, breaking all callers.

**Why it happens:** Phase 3 ExecutorService treats any non-false return as "allow". Adding a three-value enum changes the semantics.

**How to avoid:** Keep `canExecute()` returning `Promise<boolean>` unchanged. Add a separate method `canAutoExecute(toolName): Promise<ConfirmationLevel>` that returns the tier. Existing code paths continue to use `canExecute()` for the boolean gate; chat-mode inline confirmation uses `canAutoExecute()` for three-tier decisions. This is the pattern D-18 specifies — "Extend PermissionService" not "replace."

**Warning signs:** TypeScript compilation errors in ExecutorService or AgentOrchestrator about incompatible return types.

### Pitfall 4: Onboarding Step 1 Replacement Shifts All Subsequent Step Indices

**What goes wrong:** OnboardingModal uses numeric `step` state (0-7). Replacing Step 1 (step 0) with "Meet NowPilot" could shift existing provider setup steps if not careful.

**Why it happens:** Step transitions use `setStep((s) => Math.max(0, s - 1))` and `setStep((s) => Math.min(7, s + 1))`. Adding steps changes the max/min bounds and the skip logic.

**How to avoid:** D-12 confirms "Steps 2–8 remain unchanged." Insert the Meet NowPilot step as step 0 (current Welcome step becomes Step 1), and adjust the step count from 8 to 9 (max becomes 8). The skip-on-step-4 logic (`if (s === 4) return 2`) remains correct because it skips the verified screen relative to provider setup steps which haven't shifted in the sequence.

**Warning signs:** Onboarding flow jumping to wrong step; Continue going to wrong screen.

### Pitfall 5: Sender onPasteFile Interferes with Existing Drag-Drop Handler

**What goes wrong:** ChatPage has an existing `onDrop` handler on the Sender wrapper div (line 1843-1862). Adding `onPasteFile` to the Sender component itself could create duplicate attachment handling or conflicting file processing.

**Why it happens:** Both handlers create attachments from files and add them to `attachedFiles` state. If the Sender's `onPasteFile` and the wrapper's `onDrop` both fire for the same operation, users see duplicate thumbnails.

**How to avoid:** `onPasteFile` fires only for paste events; `onDrop` fires only for drag-drop. They trigger on different DOM events and don't overlap. Both feed into the same `setAttachedFiles` pipeline — no conflict. Ensure the paste handler generates unique IDs (use `crypto.randomUUID()`) to distinguish from drag-drop files.

**Warning signs:** Duplicate thumbnail entries; error about duplicate keys in the attachment array.

### Inline Confirmation Card Component

Source: Existing ActionChipGroup pattern [VERIFIED: codebase] + Context7 Bubble contentRender [VERIFIED: Context7]
```typescript
// src/components/chat/InlineConfirmationCard.tsx
import { Typography, theme } from 'antd';
import { ActionChipGroup, type ChipAction } from '../common/ActionChipGroup';

interface InlineConfirmationCardProps {
  action: string;       // e.g., "I'll search the web for that."
  rationale: string;    // e.g., "External lookups require your confirmation."
  onProceed: () => void;
  onCancel: () => void;
  collapsed?: boolean;  // after proceed — shows compact summary
  loading?: boolean;
}

export function InlineConfirmationCard({
  action, rationale, onProceed, onCancel, collapsed, loading,
}: InlineConfirmationCardProps) {
  const { token } = theme.useToken();

  if (collapsed) {
    return (
      <div style={{
        display: 'flex', alignItems: 'center', gap: token.marginXS,
        padding: `${token.paddingXS}px ${token.paddingSM}px`,
        background: token.colorFillSecondary, borderRadius: token.borderRadius,
        fontSize: 12, color: token.colorTextSecondary,
      }}>
        {loading ? <Spin size="small" /> : null}
        <span>Searched the web</span>
      </div>
    );
  }

  const chips: ChipAction[] = [
    { key: 'proceed', label: 'Proceed', value: 'proceed' },
    { key: 'cancel', label: 'Cancel', value: 'cancel' },
  ];

  return (
    <div style={{
      border: `1px solid ${token.colorWarningBorder}`,
      borderRadius: token.borderRadius,
      padding: token.paddingSM,
      marginTop: token.marginSM,
      background: token.colorWarningBg,
    }}>
      <Typography.Text style={{ fontSize: 13 }}>{action}</Typography.Text>
      <Typography.Text type="secondary" style={{ fontSize: 11, display: 'block', marginTop: 2 }}>
        {rationale}
      </Typography.Text>
      <div style={{ marginTop: token.marginXS }}>
```

```typescript
import { usePreferenceStore } from '../../memory/PreferenceMemoryStore';
import { DEFAULT_PERSONA_PROFILE, type PersonaProfile } from './PersonaProfile';

export class PersonaService {
  // Existing static profile retrieval (unchanged)
  getProfile(): PersonaProfile {
    return DEFAULT_PERSONA_PROFILE;
  }

  // NEW: Merge preference overrides onto default profile (D-11)
  getActiveProfile(): PersonaProfile {
    const prefs = usePreferenceStore.getState();
    const profile = { ...DEFAULT_PERSONA_PROFILE };

    if (prefs.aiName) {
      profile.identity = { ...profile.identity, name: prefs.aiName };
    }
    if (prefs.aiTone) {
      profile.languageStyle = { ...profile.languageStyle, tone: prefs.aiTone };
    }
    if (prefs.responseBrevity) {
      profile.languageStyle = {
        ...profile.languageStyle,
        responseStyle: prefs.responseBrevity,
      };
    }
    return profile;
  }
}
```

```typescript
onPasteFile={(files: FileList) => {
  const imageFiles = Array.from(files).filter(
    (f) => f.type.startsWith('image/')
  );
  if (imageFiles.length === 0) return;

  const newAttachments = imageFiles.map((file) => ({

    name: file.name || `pasted-image-${Date.now()}.png`,
    url: URL.createObjectURL(file),
    type: file.type,
    file, // raw File for upload pipeline
  }));

  setAttachedFiles((prev) => {
    // Respect existing attachment count limits (same as drag-drop)
    const combined = [...prev, ...newAttachments];
    // Max 5 attachments — same limit as existing file upload
    return combined.slice(0, 5);
  });
}}
```

## Open Questions

1. **ConfirmationPolicy tier-to-tool mapping**
   - What we know: Tools fall into three tiers — AutoExecute (read-only local), ConfirmInline (external lookups), RequirePermission (side effects). PermissionService interface already exists.
   - What's unclear: Exact tool-to-tier mapping for all 12+ built-in MCP tools + dynamically registered tools. Which tools count as "external lookups" vs "side effects"?
   - Recommendation: The agent has discretion per CONTEXT.md. Define a `ConfirmationPolicy.ts` with a static mapping table (toolName → ConfirmationLevel). Default unknown tools to `ConfirmInline` (safe default). Planner should include a task to audit this mapping against the tool registry.

2. **RICH-H-05 structured output actions — table detection scope**
   - What we know: Markdown tables need "Copy as table" and "Export as CSV" buttons. XMarkdown renders tables.
   - What's unclear: Whether to detect tables by parsing the raw markdown string or by walking the rendered DOM. Regex-based detection is fragile for nested tables, cell content with pipes, and alignment syntax.
   - Recommendation: Parse raw markdown for GFM pipe tables using a regex that handles the standard format `| cell | cell |` with optional alignment `|:---|:---:|`. This covers 95%+ of AI-generated tables. Edge cases (nested tables, embedded HTML tables) can be deferred.

3. **Conversation closure idle timer duration**
   - What we know: D-25 specifies "10-15s idle" as the heuristic. The hook needs to track: no pending clarifications, no active follow-up interactions, latest assistant message appears resolved.
   - What's unclear: The "latest assistant message appears resolved" heuristic — how to detect resolution without LLM call?
   - Recommendation: Use simple heuristics: message stream has completed, no `ask_clarification` action in the last assistant message, no `FollowUpAction` interaction pending, and 12s of user inactivity. This is the agent's discretion per D-26.

### Known Threat Patterns for Ant Design X / Chrome Extension

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| XSS via markdown in Bubble content | Tampering | XMarkdown (from @ant-design/x-markdown) sanitizes input — already in use; inline confirmation card renders static text only, no user-controlled HTML |
| Clipboard data exfiltration via paste handler | Information Disclosure | Image paste handler only reads `clipboardData.files` (images), not text content from clipboard; no clipboard read API used; user-initiated paste only |
| Unauthorized tool execution via spoofed ConfirmationLevel | Elevation of Privilege | ConfirmationLevel is determined server-side (PermissionService), not client-side; UI components cannot override the level — they only render based on the returned value |
| chrome.storage.local tampering via other extensions | Tampering | PreferenceMemoryStore values are user-facing preferences only — no security-sensitive data; RightPaneStore is UI state only; existing ASVS mitigations for sensitive stores (EncryptedStorage for API keys) unchanged |
