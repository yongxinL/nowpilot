## Split-Pane Layout

| Option | Description | Selected |
|--------|-------------|----------|
| Replace sider, right pane tabs | Right pane replaces standalone sider nav | |
| Three-column with collapsible right pane | Sider + chat + right pane, pane collapsible | ✓ |
| Right pane as overlay/drawer | Chat full-width, pane slides over | |

**User's choice:** Three-column layout with collapsible right pane. Keep the existing standalone navigation Sider unchanged and introduce a separate right-hand Context Pane containing Context, Notes, and Tools tabs. The centre column remains the Chat/Agent workspace, while the right pane acts as an auxiliary workspace that can be collapsed when users want maximum conversation width. On smaller resolutions, the pane can automatically degrade into a Drawer-style experience.

### Tab selection behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Context-aware auto-tab | Active tab driven by user action | |
| User-selectable, persisted | User picks tab, persists across sessions | ✓ (partial) |
| Chat-driven context only | Pane scoped to current conversation | |

**User's choice:** User-selected and persisted, with explicit-intent auto-switching. The right pane should remember the user's last-selected tab and restore it across sessions. However, when the user performs an action with clear intent — such as opening a wikilinked note, clicking a pinned tab, or viewing tool details — the pane may temporarily switch to the relevant tab and focus the requested item. Background AI activity should never change the active tab automatically.

### Tab interactivity

| Option | Description | Selected |
|--------|-------------|----------|
| Lightweight read-only views | Quick-reference summaries only | |
| Full interactive mini-apps | Full management within pane | |
| Hybrid — Context lightweight, Notes/Tools interactive | Context compact, Notes search+preview, Tools live status | ✓ |

**User's choice:** Hybrid. Context tab lightweight reference. Notes tab search and inline note preview. Tools tab live MCP/server status with expandable details. Full editing in dedicated pages.

### Data access

| Option | Description | Selected |
|--------|-------------|----------|
| Same stores, shared views | Thin views over existing domain stores | |
| Pane has its own lightweight store | RightPaneStore for UI state, domain stores for data | ✓ |
| Content scripts feed pane directly | Direct content-script subscriptions | |

**User's choice:** Shared domain stores with a lightweight RightPaneStore. Context, Notes, and Tools tabs consume data from their existing domain stores (workspaceStore, NotesDB/MiniSearch, MCP/tool stores). Introduce a small RightPaneStore solely for pane presentation state.

### Visibility

| Option | Description | Selected |
|--------|-------------|----------|
| Always visible, user collapses | Visible by default, toggle to collapse | ✓ |
| Auto-hide when empty | Auto-collapses when no content | |
| Always collapsed by default | Starts collapsed, user opens on demand | |

**User's choice:** Always visible, user collapses manually. Right pane is a core standalone workspace feature, visible by default. Persistent toggle, state stored in RightPaneStore. Never auto-appear/disappear based on content.

### Resize behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed 60/40 ratio | No drag resize | |
| Draggable divider | Min/max constraints, freeform drag | |
| Two preset widths, toggled | Compact (320px) + Expanded (~45-50%) | ✓ |

**User's choice:** Two preset widths. Compact (~320px) and Expanded (~45–50% of available workspace), switched via toggle in the divider and persisted in RightPaneStore.

### Page availability

| Option | Description | Selected |
|--------|-------------|----------|
| Chat/Agent only | Hidden on other pages | |
| Context tab only on non-Chat pages | Context on Notes, hidden on Options | ✓ |
| Available on all pages | Pane always present | |

**User's choice:** Context tab only on Notes, hidden elsewhere. Full right pane on Chat/Agent. Context tab only on Notes page. Hidden on Options, Diagnostics, and configuration pages.

## Inline Confirmation UX

| Option | Description | Selected |
|--------|-------------|----------|
| Inline Bubble chips, reuses ActionChipGroup | Proceed/Cancel as conversation element | |
| Same as Agent PermissionDialog, smaller inline | Reuse modal but render inline | |
| Minimal — single Proceed/Cancel pair | Compact chip pair | |

**User's choice:** Inline Confirmation Action Card. Dedicated inline confirmation card within the conversation with action description, rationale, and ActionChipGroup (Proceed/Cancel).

### Confirmation trigger

| Option | Description | Selected |
|--------|-------------|----------|
| Tool-call based | Any execute_tool or external action | |
| Category-based | Safe tools skip, others confirm | |
| Policy-driven: ConfirmationPolicy | Tiered evaluation (auto-execute/confirm-inline/require-permission) | ✓ |

**User's choice:** Policy-driven confirmation engine. Central ConfirmationPolicy evaluates planned action and returns tiered ConfirmationLevel. Read-only local = auto-execute, external lookup = confirm-inline, side-effect = require-permission.

### Architecture placement

| Option | Description | Selected |
|--------|-------------|----------|
| New ConfirmationPolicy.ts | Standalone policy module | |
| Extend existing PermissionService | Add canAutoExecute() + ConfirmationLevel | ✓ |
| Integrate into ExecutorService | Centralized enforcement | |

**User's choice:** Extend the existing PermissionService. Single service for all permission/confirmation decisions. Chat and Agent share the same enforcement logic with different UI presentations.

### Memory/persistence

| Option | Description | Selected |
|--------|-------------|----------|
| Show once per action, no memory | Fresh confirmation each time | ✓ |
| Offer 'Always allow' for chat too | Persistent allow-list across modes | |
| Session-only 'Don't ask again' | Session-scoped suppression | |

**User's choice:** Show once per action, no memory. Chat-mode confirmations are lightweight, conversational, and non-persistent. Persistent permission grants remain exclusive to Agent mode.

### Post-Proceed visual

| Option | Description | Selected |
|--------|-------------|----------|
| Proceed → execute action normally | Standard execution flow | |
| Proceed → show brief 'Working…' placeholder | Status message with spinner | |
| Proceed → collapse card, show result inline | Collapsed record with audit trail | ✓ |

**User's choice:** Collapsed confirmation record with execution status. Card collapses to compact approved-action summary with spinner. Tool result renders below when complete.

## the agent's Discretion

Areas where the agent has implementation flexibility:
- RightPaneStore internal API — exact state shape, action names, persist key
- SplitPane divider component implementation — CSS-based or lightweight library
- Responsive breakpoint for Drawer degradation — exact pixel value
- GreetingService time-of-day logic — exact hour thresholds, string composition
- TemplateBrowserService internal ranking algorithm — scoring weights, recency decay
- TemplateBrowser popover component — antd Popover layout, category tab/section UX
- ConfirmationPolicy tier-to-tool mapping — which tools map to which ConfirmationLevel
- Inline confirmation card component — exact layout, spacing, animation
- ConversationClosure idle timer — exact duration, reset conditions
- Image paste blob-to-File conversion — MIME type detection, filename generation
- Resolution preference toggle in Options — exact placement in UI
- RICH-H-05 (structured output actions) — Copy as table / Export as CSV button implementation
- RICH-H-06 (save to note promotion) — Move from dropdown menu to visible button on assistant messages
