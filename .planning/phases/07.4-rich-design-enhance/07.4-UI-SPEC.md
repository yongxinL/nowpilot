## Spacing Scale

This project uses antd's built-in `DesignToken` spacing via `theme.useToken()`, not a custom 4px scale. The following token values are the de-facto spacing contract consumed by all Phase 7.4 components:

| Token | Approx Value | Usage in Phase 7.4 |
|-------|-------------|---------------------|
| `token.marginXS` | 8px | ActionChipGroup chip gaps, InlineConfirmationCard icon-to-text gap, collapsed confirmation row gap |
| `token.marginSM` | 12px | BrandedHeader vertical padding, InlineConfirmationCard margin-top, TemplateBrowser category section gap |
| `token.margin` | 16px | Default element spacing |
| `token.paddingXS` | 8px | Collapsed confirmation row padding, compact elements |
| `token.paddingSM` | 12px | InlineConfirmationCard inner padding, RightPane tab content padding, TemplateBrowser category header padding |
| `token.padding` | 16px | BrandedHeader horizontal padding |
| `token.borderRadius` | 6px | Standard antd component rounding |
| `token.borderRadiusLG` | 8px | InlineConfirmationCard border radius |

**Phase-specific layout dimensions (not from antd tokens):**

| Dimension | Value | Usage |
|-----------|-------|-------|
| Right pane — compact | 320px | Default right pane width (D-03) |
| Right pane — expanded | 45% of `(window.innerWidth - 240px navbar)` | Expanded right pane width (D-03) |
| Standalone navbar — expanded | 240px | Existing, unchanged (D-01) |
| Standalone navbar — collapsed | 56px | Existing, unchanged |
| Right pane Drawer breakpoint | 320px available width | Below this, inline pane → Drawer overlay (D-04) |
| Template browser popover width | 360px | antd Popover with Input.Search + categorized sections |
| Inline confirmation card max-width | 480px | Prevents card from stretching full Bubble width |
| Split-pane divider | 1px solid `token.colorBorderSecondary` | Visual separator between chat and right pane |

**Touch target exception:** None for this phase — all interactive elements are mouse/keyboard (desktop Chrome extension). No mobile/tablet touch targets required.

## Typography

Phase 7.4 inherits antd's default typography (14px body at 1.5 line-height) and extends it with the following phase-specific overrides. All sizes use antd `Typography.Text` or raw `fontSize` style where needed.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5715 (antd default) | Chat messages, Sender input, all paragraph text |
| Secondary / Meta | 12px | 400 (regular) | 1.333 | BrandedHeader tagline, InlineConfirmationCard rationale, ConversationClosure hint, RightPane tab metadata |
| Label / Chip | 13px | 400 (regular) | 1.4 | ActionChipGroup buttons, InlineConfirmationCard action text, TemplateBrowser template titles |
| Heading | 16px | 600 (semibold) | 1.375 | BrandedHeader name, InlineConfirmationCard action title, Meet NowPilot step title, RightPane tab labels |
| Display | 20px | 600 (semibold) | 1.3 | Meet NowPilot persona name in onboarding card, BrandedHeader greeting when displayName is present |

**Weight contract: exactly 2 weights — 400 (regular) and 600 (semibold).** No other font weights appear in this phase.

**Font size exceptions:**
- `11px / 400 / 1.33` — InlineConfirmationCard rationale secondary line (only if 12px is too large in the compact card layout)
- `24px / 600 / 1.25` — Meet NowPilot onboarding step title (persona name introduction)

**Monospace:** Inherited from antd (`'SFMono-Regular', Consolas, 'Liberation Mono', Menlo, Courier, monospace`) for code blocks and template variable placeholders.

## Color

### 60/30/10 Split (light mode)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `token.colorBgContainer` (#ffffff) | StandaloneRoot content shell background, ChatPage background, Meet NowPilot card background |
| Secondary (30%) | `token.colorFillSecondary` (rgba ~5% black) | ActionChipGroup chip background, collapsed confirmation row, RightPane tab bar, TemplateBrowser category headers |
| Accent (10%) | `token.colorPrimary` (#e0582e) | **Reserved for:** BrandedHeader bunny avatar border ring, primary CTA buttons (Proceed, Continue), Sender send button active state, ThoughtChain active step indicator, selected template highlight |

### Dark Mode

All colors auto-adapt via antd `darkAlgorithm`. No manual dark-mode values needed. The 60/30/10 split proportions are maintained by the algorithm.

### Semantic Colors

| Color | Token | Usage |
|-------|-------|-------|
| Warning | `token.colorWarningBorder` / `token.colorWarningBg` | InlineConfirmationCard border and background (signals "needs your attention") |
| Success | `token.colorSuccess` | Collapsed confirmation check icon after Proceed |
| Destructive | `token.colorError` | Cancel button hover state, "Action cancelled" text in confirmation flow |
| Text primary | `token.colorText` | All body text |
| Text secondary | `token.colorTextSecondary` | Rationale text, taglines, timestamps, metadata |
| Border secondary | `token.colorBorderSecondary` | BrandedHeader bottom border, split-pane divider, InlineConfirmationCard border (non-warning state) |

### Accent Reserved-For List

`token.colorPrimary` (#e0582e) is reserved for these specific elements and NOTHING else:

1. **BrandedHeader** — Avatar border ring (2px solid)
2. **Primary CTAs** — Proceed button (InlineConfirmationCard), Continue button (OnboardingModal), Send button active state (Sender)
3. **Template browser** — Selected/hovered template item highlight, active category indicator
4. **Right pane** — Active tab indicator underline
5. **ThoughtChain** — Active step dot/indicator in Agent mode
6. **BunnyAvatar** — Accent color in the SVG itself (ears, nose)

**Explicitly NOT accented:** Dividers, borders, hover states of non-primary elements, icons (use `currentColor`), status badges (use semantic colors).

## Copywriting Contract

### Primary CTAs

| Context | Copy | Notes |
|---------|------|-------|
| Meet NowPilot onboarding | **"Continue"** | Proceeds to provider setup Step 2. Also a subtle "Skip" text link for power users (D-10). |
| Inline confirmation — Proceed | **"Proceed"** | Confirms a side-effect action in chat mode (D-17) |
| Inline confirmation — Cancel | **"Cancel"** | Declines the proposed action; shows "Action cancelled." |
| Conversation closure — thumbs up | **"👍"** | Positive feedback |
| Conversation closure — thumbs down | **"👎"** | Negative feedback |
| Template browser — Insert | (implicit — clicking template inserts into Sender) | No explicit "Insert" button; the click is the action (D-16) |
| Save to note | **"Save to note"** | Promoted from dropdown to visible Bubble footer button (RICH-H-06) |

### Empty States

| Component | Heading | Body |
|-----------|---------|------|
| ChatPage (no conversations, with displayName) | **"Good morning, {displayName}"** or **"Good afternoon, {displayName}"** or **"Good evening, {displayName}"** | Persona tagline: "Your AI work co-pilot". Optional contextual line: "You're working on: {pageTitle}" (D-22, D-23) |
| ChatPage (no conversations, no displayName) | **"Good morning! How can I help?"** (time-of-day variant) | Persona tagline: "Your AI work co-pilot". Optional contextual line. |
| TemplateBrowser (no recent templates) | (section omitted) | Full category view shown; no "empty" state needed — categories always visible |
| RightPane Notes tab (no notes) | **"No notes yet"** | **"Create a note from any chat message using 'Save to note'"** |
| RightPane Tools tab (no MCP tools) | **"No tools configured"** | **"Connect MCP servers in Options to see tools here"** |
| RightPane Context tab (no pinned tabs) | **"No page context"** | **"Pin a tab using the pin icon in the Side Panel to see context here"** |

### Error States

| Scenario | Problem | Solution Path |
|----------|---------|---------------|
| Image paste exceeds attachment limit | "Maximum 5 files allowed" | Existing limit-enforcement rules apply; excess images silently dropped with console debugLog (D-31) |
| TemplateBrowser fails to load templates | "Couldn't load templates" | "Try reopening the template browser" — PromptManager is always available locally; failure is extremely rare |
| GreetingService cannot read preferences | Falls back to generic greeting "Good morning! How can I help?" | Graceful degradation — no error UI needed (D-21) |
| ConversationClosure idle timer fires during active stream | Timer reset | Timer resets on any new message or stream activity (D-26) |
| RightPane fails to read NotesDB / MCP config | Tab shows "Unable to load" with retry link | Domain stores are local IndexedDB/chrome.storage — failures are transient (quota, corruption) |

### Destructive / Irreversible Actions

| Action | Confirmation Approach |
|--------|----------------------|
| Cancel — InlineConfirmationCard | Removes the card and shows "Action cancelled." No undo. Low stakes — action was not yet executed. |
| Dismiss — BrandedHeader close | Header dismissed for this session; reappears on new conversation. No confirmation dialog. |
| Delete note — (right pane preview, if exposed) | **Not in Phase 7.4 scope.** Right pane Notes tab is read-only preview. Full CRUD in NotesPage unchanged. |

## Interaction Contracts

### Split-Pane Behavior (RICH-H-11, H-12)

| Trigger | Behavior |
|---------|----------|
| Page load | Right pane visible by default (D-02) |
| Toggle button click | Cycles: compact (320px) → expanded (45%) → collapsed (hidden + tab strip) → compact (D-03) |
| Tab strip click (collapsed state) | Re-expands to last used width (compact or expanded) |
| Window resize < breakpoint | Right pane auto-degrades to antd `Drawer` overlay from right edge (D-04) |
| Window resize > breakpoint | Drawer closes, right pane returns to inline column |
| Tab click | Switches active tab, persists selection via RightPaneStore (D-06) |
| Auto-switch | Only on explicit user action — opening a wikilinked note, clicking a pinned tab, viewing tool details (D-06) |
| Page navigation away from Chat/Agent | Right pane hidden (D-08) |
| Page navigation to Chat/Agent | Right pane restored with persisted state |

### Inline Confirmation Flow (RICH-C-12, C-13)

| State | Visual | User Action |
|-------|--------|-------------|
| `ConfirmInline` event received | InlineConfirmationCard renders in Bubble with warning border, action text, rationale, [Proceed] [Cancel] chips | — |
| User clicks Proceed | Card collapses to compact row: green check icon + action summary ("Searched the web") + Spin spinner | Cannot undo |
| Tool execution completes | Spinner replaced with tool result rendered below collapsed row | — |
| User clicks Cancel | Card removed, "Action cancelled." text in its place for 3s then fades | Cannot undo |
| `AutoExecute` | Tool runs silently; no card rendered | — |
| `RequirePermission` | Delegated to existing Agent PermissionDialog modal (unchanged) | — |

### Template Browser (RICH-I-09, I-10)

| Trigger | Behavior |
|---------|----------|
| Click Templates icon (Sender prefix) | Opens 360px Popover positioned above Sender |
| Type in search | Real-time filter across all template names and descriptions (D-14) |
| Click template (no variables) | Inserts template content into Sender, closes Popover — user reviews before sending |
| Click template (has variables) | Inserts template with `{{placeholder}}` highlighted; focus moves to first placeholder; Tab cycles between placeholders (D-16) |
| Recently used section | Shows last 5 used templates at top if any (D-15) |
| Click outside / Escape | Closes Popover (antd default behavior) |

### Image Paste (RICH-H-16)

| Trigger | Behavior |
|---------|----------|
| Ctrl+V / Cmd+V with image in clipboard | Sender `onPasteFile` fires → image added to attachment thumbnail strip |
| Multiple images in clipboard | All images attached (up to 5 max, excess dropped) (D-31) |
| Text paste | Normal Sender behavior unchanged |
| After paste | Focus stays in Sender; user can continue typing (D-32) |
| Thumbnail | Appears in existing attachment strip above Sender — same appearance as drag-dropped images (D-32) |
| Image processing | Same pipeline as drag-drop: max 800px, JPEG quality 0.85 (D-33) |
| "Preserve original resolution" preference enabled | Skips resize pipeline (D-33) |

### Personalized Greeting (RICH-C-14, RICH-I-03)

| Condition | Greeting |
|-----------|----------|
| Morning (<12pm) + displayName set | "Good morning, {displayName}" |
| Afternoon (12-5pm) + displayName set | "Good afternoon, {displayName}" |
| Evening (>5pm) + displayName set | "Good evening, {displayName}" |
| Any time + no displayName | "Good morning!", "Good afternoon!", or "Good evening!" (no name) |
| Page context available | Additional line: "You're working on: {pageTitle}" (D-22) |
| Greeting renders inside BrandedHeader | Above persona tagline "Your AI work co-pilot" (D-23) |
| WelcomeCards render below BrandedHeader | Independent component — dismissing WelcomeCards does not remove greeting (D-23) |

### Conversation Closure (RICH-C-09)

| Condition | Behavior |
|-----------|----------|
| Stream completed + 12s user idle + no pending clarification + no active follow-up + message appears resolved | ConversationClosure component appears below last assistant Bubble |
| Show once per conversation | After first appearance, not shown again for same conversation (D-25) |
| Click 👍 or 👎 | Feedback logged to conversation metadata; component fades to "Thanks for your feedback!" then disappears |
| User sends new message | Timer resets; closure component hidden if visible (D-26) |
