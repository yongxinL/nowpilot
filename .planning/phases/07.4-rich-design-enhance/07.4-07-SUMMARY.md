**6 integration points delivered in ChatPage.tsx: personalized greeting via useGreeting, TemplateBrowser icon in Sender prefix, clipboard image paste via onPasteFile, InlineConfirmationCard in Bubble area, ConversationClosure after idle, and first-message branding with BunnyAvatar**

## Accomplishments

- **Personalized greeting (RICH-C-14, RICH-I-03):** Empty state BrandedHeader receives `userGreeting` and `contextualMessage` from `useGreeting` hook — time-of-day greeting with optional displayName. BrandedHeader stays visible when WelcomeCards are dismissed (D-23).
- **Template browser (RICH-I-10):** `TemplateBrowser` rendered as Sender `prefix` prop — icon button in toolbar opens categorized template popover; selecting a template appends to draft via `setDraft`.
- **Image paste (RICH-H-16):** Sender `onPasteFile` handler extracts clipboard image files, respects 5-file limit, appends to existing `attachedFiles` state — feeds into existing attachment pipeline (no separate paste pipeline per RESEARCH.md anti-pattern).
- **Inline confirmation (RICH-C-12):** `InlineConfirmationCard` renders after assistant Bubble when `item.metadata.confirmation` is present — action description, rationale, Proceed/Cancel chips (D-17). onProceed/onCancel stubs for tool execution dispatch.
- **Conversation closure (RICH-C-09):** `useConversationClosure` hook manages 12s idle timer; `ConversationClosure` renders below bubble list with feedback buttons (D-25, D-26).
- **First-message branding (RICH-H-02 / D-28):** First assistant message gets BunnyAvatar with accent border ring + "NowPilot" branded header via Bubble `avatar`/`header` props. Tracked via `firstAssistantIndex` useMemo.

## Decisions Made

- **Greeting in BrandedHeader, not separate component:** Per D-23, the greeting lives inside BrandedHeader (identity surface) with WelcomeCards below — independent components. BrandedHeader is always visible; only WelcomeCards respond to dismissal.
- **TemplateBrowser as Sender prefix, not suffix:** Per RESEARCH.md state-of-the-art note and PATTERNS.md pattern — prefix is the left-side Sender toolbar area where templates naturally belong.
- **Inline first-message branding, not ChatMessage component:** ChatPage uses inline `<Bubble>` rendering (not ChatMessage.tsx). First-message branding applied directly to the Bubble's `avatar`/`header` props — avoids replacing the entire bubble rendering chain which would risk breaking existing features (StageIndicator, ClarificationAction, FollowUpAction, CodeBlockActions).
- **ConversationClosure after bubble list, not inside:** Renders as a sibling after the bubble list div rather than inside each Bubble — natural position for end-of-conversation feedback.
- **onPasteFile feeds existing attachment pipeline:** Per RESEARCH.md anti-pattern prohibition — no separate paste pipeline created. Images flow through `setAttachedFiles` and the shared attachmentHeader/thumbnail strip.
