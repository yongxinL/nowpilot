| Property | Value |

| Animation | motion ^12.23.24 |

**Theming strategy:** One root `ConfigProvider` wrapping all entrypoints. Theme mode (light/dark/auto) stored in `WorkspaceStore`, applied via `ConfigProvider theme.algorithm` — switching between `theme.defaultAlgorithm`, `theme.darkAlgorithm`, or system-preference-aware auto. Both surfaces react to the same store key for immediate cross-surface updates (SHELL-04).

**Seed token overrides:** None. Use antd v6 defaults (`colorPrimary: #1677ff`, `borderRadius: 6`, `controlHeight: 32`).

## Spacing Scale

Declared values (antd v6 defaults, multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight groupings |
| sm | 8px | Compact element spacing, button groups |
| md | 12px | Intermediate spacing, form item gaps |
| base | 16px | Default element spacing, card padding |
| lg | 20px | Section padding, panel inner spacing |
| xl | 24px | Layout gaps, section margins |
| 2xl | 32px | Major section breaks |
| 3xl | 48px | Page-level spacing |

### Spacing Exceptions

The following spacing tokens deviate from the standard `{4, 8, 16, 24, 32, 48, 64}` set. Both are antd v6 native token values and maintain grid alignment (both are multiples of 4). These are preserved for design system fidelity with antd v6's built-in spacing system — overriding them would break alignment with antd component internals that rely on these exact values.

| Token | Value | antd v6 Token | Justification |
|-------|-------|---------------|---------------|
| md | 12px | `paddingMD` | antd v6 native intermediate spacing; used by Form item gaps, Tabs ink-bar offsets, and component-level internal padding |
| lg | 20px | `paddingLG` | antd v6 native section padding; used by Modal content padding, Card body padding, and layout-level section gaps |

All other spacing values (`xs=4px`, `sm=8px`, `base=16px`, `xl=24px`, `2xl=32px`, `3xl=48px`) conform to the standard set.

Additional layout constraints (not spacing tokens):

- Side Panel default width: ~400px (Chrome Side Panel constraint)
- Command palette width: 560px max, centered in viewport

## Color

| Role | Percentage | Value | Usage |
|------|-----------|-------|-------|
| Dominant (60%) | 60% | `colorBgContainer` / `colorBgLayout` | Page background, content surfaces (algorithm-derived: `#ffffff` light / `#000000` dark) |
| Secondary (30%) | 30% | `colorBgElevated` / `colorFillSecondary` | Sidebar, panel headers, command palette backdrop, skeleton cards |
| Accent (10%) | 10% | `colorPrimary` (`#1677ff`) | Primary buttons (e.g., "Get Started"), focus rings, selected command palette item, toggle active state, links |
| Destructive | — | `colorError` (`#ff4d4f`) | Reserved for destructive actions (none in Phase 1; declared for consistency) |

**Accent reserved for:** `colorPrimary` applies only to:
1. Primary action buttons ("Get Started" CTA in onboarding)
2. Active/selected state on command palette items (`Cmd+K` active selection highlight)
3. Focus rings on interactive elements
4. Theme toggle active state indicator

**Dark mode:** Uses `theme.darkAlgorithm` — generates dark surface/text colors from the same seed tokens. No custom dark palette overrides.

**Auto mode:** Uses `window.matchMedia('(prefers-color-scheme: dark)')` to select algorithm. Listens for `change` events to toggle dynamically.

## Visual Hierarchy

### Side Panel (~400px)

- **Focal point:** Active tab label → tab content area. The selected `Tabs` tab anchors user attention with `colorPrimary` underline; the content area below it is the primary interaction zone and receives the highest visual weight.
- **Hierarchy (top-to-bottom):**
  1. Header bar (theme toggle icon + app logo) — compact, subtle, utilitarian
  2. Tab navigation bar (Chat / Agent / Write / TeamGQM) — prominent, active tab underlined in `colorPrimary`
  3. Content area — fills remaining viewport height, the primary interaction surface
  4. Footer action ("Open in Full Tab" button) — secondary weight, always visible at bottom
- **Scan pattern:** Vertical F-pattern — header scanned left-to-right, tabs scanned left-to-right, then content consumed top-down.

### Full App Tab (full viewport)

- **Focal point:** Sidebar navigation → content area. The sidebar (80px collapsed / 256px expanded) anchors the left edge; the expansive content area to the right receives the bulk of user attention and dominates visual weight.
- **Hierarchy (left-to-right):**
  1. Sidebar (collapsed, 80px) — icon-only nav items, subtle visual weight, compact
  2. Sidebar (expanded, 256px) — icon + label nav items on hover, secondary prominence
  3. Content area header — section title, moderate weight
  4. Content body — full remaining viewport, primary interaction zone
- **Scan pattern:** Left column scan (sidebar icons) → rightward movement to content header → vertical scan of content body.

### Command Palette (Modal overlay)

- **Focal point:** Search input (auto-focused on open) → first result. The blinking cursor in the search field is the immediate entry-point focal point; below it, the `colorPrimary`-highlighted command result draws the eye next.
- **Hierarchy (top-to-bottom):**
  1. Backdrop overlay (muted, dark) — reduces background distraction
  2. Modal container (elevated surface, 560px max-width, centered)
  3. Search input — prominent, auto-focused, with placeholder text
  4. Results list — scrollable, keyboard-navigable, active item highlighted
  5. Keyboard hint footer — subtle, low contrast, non-interactive

## Interaction Patterns

### Theme Toggle
- **Trigger:** Icon button (sun/moon icon) in shell header on both surfaces.
- **Behavior:** Cycles through light → dark → auto (system preference). Clicking shows antd `Tooltip` with next mode hint ("Switch to dark mode" / "Switch to light mode").
- **Cross-surface sync:** Theme mode stored in `WorkspaceStore.theme`. Both surfaces subscribe — update on either surface applies immediately to both (SHELL-04).
- **Auto mode:** Listens to `prefers-color-scheme: dark` via `matchMedia`. Changes when OS preference changes.
- **Persisted:** Theme preference saved to `chrome.storage.local` via workspace persistence.

### Command Palette (Cmd+K)
- **Trigger:** `Cmd+K` (Mac) / `Ctrl+K` (Windows/Linux) keyboard shortcut on both surfaces.
- **Display:** Antd `Modal` centered on screen, 560px max-width, dark backdrop overlay.
- **Input:** Search input with "Search commands…" placeholder, auto-focused on open. Fuzzy search matches command names.
- **Results:** Scrollable list with keyboard navigation (↑/↓ arrows, Enter to select, Esc to close). Active item highlighted with `colorPrimary`. No results shows "No matching commands — try a different search term" empty state with action guidance.
- **Phase 1 commands:** Limited set — "Toggle Theme", "Open in Full Tab", "Reload Extension". Full command set arrives in Phase 7.

### Onboarding Flow
- **Trigger:** First install detection — workspace state flag `onboardingComplete: false` (default).
- **Display:** Multi-step walkthrough using antd `Steps` + `Card` components, shown on Side Panel open.
- **Steps:** 3 cards (Chat with AI → Capture Knowledge → Your Workspace, Your Way) with illustration placeholders + descriptive copy.
- **Navigation:** "Previous Step" / "Next Step" buttons. Final step shows "Start Exploring" — closes onboarding, sets `onboardingComplete: true`.
- **Skip:** Optional "Skip Onboarding" link for users who want to go directly to the shell.

### Dual-Surface Handoff
- **Trigger:** "Open in Full Tab" button in Side Panel.
- **Behavior:** Opens Full App Tab via `chrome.tabs.create`. Workspace state serialized from Side Panel's `WorkspaceStore`, handed off via `BroadcastBus` message. Full App Tab receives state and initializes from it.
- **Deduplication:** If Full App Tab already open, `chrome.tabs.update` focuses existing tab instead of creating a duplicate. State re-sync via `BroadcastBus`.

### Shell (Post-Onboarding)
- **Side Panel (~400px):** Top: theme toggle + header. Main area: `Tabs` with Chat, Agent, Write, TeamGQM tabs (all disabled placeholders with skeleton content). Bottom: "Open in Full Tab" button.
- **Full App Tab (full viewport):** Left: collapsed sidebar (`Layout.Sider`, 80px collapsed / 256px expanded) with nav icons. Right: content area with skeleton placeholders.
