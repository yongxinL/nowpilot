        sections: PromptSection[],

    **Degradation steps (defined as an ordered array of step objects within the class):**

    Each step has a `name` string and an `apply(sections, ctx)` method. The steps are:
    `['drop-debug', 'drop-secondary', 'summarise-history', 'compress-page', 'trim-tools', 'reduce-memory', 'minimal-mode']`

    1. **drop-debug:** Remove sections where sourceId starts with 'debug.' or section text contains debug markers. Implementation: `sections.filter(s => !s.sourceId.startsWith('debug.'))`.

    2. **drop-secondary:** Remove sections with sourceId containing 'secondary' or 'optional'. Implementation: `sections.filter(s => !s.sourceId.includes('secondary') && !s.sourceId.includes('optional'))`.

    3. **summarise-history:** For history sections (kind: 'context' with history-like sourceId), truncate text to ~500 chars and append a truncation marker `"\n[... history summarized]"`. Recalculate tokens with tokenBudget.estimateTokens(). Record compressionApplied hint for provenance. Preserve the most recent turns (take last portion of text before truncation).

    4. **compress-page:** For page context sections (sourceId: 'context.page.current'), extract key metadata (title, URL, headings) and drop the body text. Replace with structured summary: `"Page: {title}\nURL: {url}\nKey headings: {headings}\n[content compressed]"`. Recalculate tokens.

    5. **trim-tools:** For tool_schemas sections, parse the JSON array of tool schemas. Keep only essential tools: filter to those with `dangerous !== true` first, then take top-N by priority. For tiny tier, keep 1; for small, keep 3; for medium, keep 5; for large, keep all. Re-serialize and recalculate tokens.

    6. **reduce-memory:** For memory sections, parse the JSON array. Keep top-K entries: tiny → top-1, small → top-3, medium → top-5, large → top-5. If the memory section is already small (≤3 entries), skip this step. Recalculate tokens.

    7. **minimal-mode:** Apply the §2.5 restrictions:
       - System prompt: truncate to ≤200 tokens of compact system text. Extract first 200 tokens of system section text.
       - Preferences: keep as compact JSON (already small — skip if under 50 tokens).
       - Memory: keep top-3 max (already handled by reduce-memory, but enforce cap).
       - Tool schemas: keep exactly 1 tool schema (the first/safest).
       - History: keep only last 1-2 turns; conversation summary ≤200 tokens.
       - Page context: drop entirely (sourceId: 'context.page.current' → removed).
       - Set a flag `minimalModeActive = true` (returned via context in the result).
       Set all section tokens to recalculated values.

    **Degradation loop (within compress()):**
    ```typescript
    const stepsApplied: string[] = [];
    let currentSections = [...sections];

    for (const step of this.STEPS) {
      // Compute total tokens before this step
      const totalBefore = currentSections.reduce((sum, s) => sum + s.tokens, 0);
      if (totalBefore <= budget) break; // already under budget, stop early

      // Apply step
      currentSections = step.apply(currentSections, { tier });
      stepsApplied.push(step.name);

      // Recalculate total after step
      const totalAfter = currentSections.reduce((sum, s) => sum + s.tokens, 0);
      // If under budget, stop (but mark step as applied for provenance)
    }

    // AI summarization overflow (D-06, D-08): if still over budget and compressionModelProvider is available
    const finalTotal = currentSections.reduce((sum, s) => sum + s.tokens, 0);
    if (finalTotal > budget && compressionModelProvider) {
      // Call AI summarization: pass the over-budget sections to the compression model
      // The compression model returns a condensed version
      // This is a separate code path — the AI handles what local techniques couldn't
      stepsApplied.push('ai-summarisation');
      // NOTE: The actual AI call implementation is a Code Example placeholder;
      // the EXACT implementation (which prompt, which model, how to parse) is deferred
      // to the executor's discretion based on ProviderRouter.getCompressionModel().
      // For now, the compressor throws CONTEXT_TOO_LARGE if AI is unavailable.
    }

    if (currentSections.reduce((sum, s) => sum + s.tokens, 0) > budget) {
      // Still over budget after all steps — this is where CONTEXT_TOO_LARGE is thrown
      // The ContextOptimizer (caller) throws the error, not the compressor
    }

    return { sections: currentSections, stepsApplied };
    ```

    **Key implementation constraints:**
    - All section mutations create NEW section objects (shallow clone) — never mutate the input sections array or its elements (preserves the original sections for provenance comparison).
    - Each step recalculates `tokens` on modified sections using `tokenBudget.estimateTokens(section.text)`.
    - The `stable` flag is NEVER modified — it is read-only metadata per D-14.
    - The compressor does NOT throw CONTEXT_TOO_LARGE itself — it returns the compressed sections and the caller (ContextOptimizer) decides whether to throw.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ContextCompressor → AI summarization | When local degradation fails, ContextCompressor may call an AI model for summarization — untrusted compression model output must be validated before use |
| Degraded sections → ContextProvenanceManifest | Degradation decisions (which sections were truncated/compressed) feed into provenance — must be accurate for auditability |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07 | Tampering | Degradation step order manipulation | medium | mitigate | The steps array is a private static constant in ContextCompressor (readonly). No external input can reorder or skip steps. The stepsApplied array is append-only per D-07. |
| T-04-08 | Denial of Service | AI summarization infinite loop | medium | mitigate | AI summarization is a single call — not iterative. After AI summarization, one final budget check determines CONTEXT_TOO_LARGE or success. No retry loop on summarization failure. |
| T-04-09 | Tampering | Malformed AI summarization output | low | mitigate | If AI summarization returns non-string or empty result, the compressor logs the error and proceeds with pre-summarization sections (graceful degradation, no crash). The CONTEXT_TOO_LARGE error is the fallback. |
| T-04-10 | Information Disclosure | Debug sections not fully dropped | low | accept | Debug sections are internal metadata (sourceId: 'debug.*'). If drop-debug fails, the consequence is slightly larger context (extra tokens) — not a security issue. No user data in debug sections. |
| T-04-11 | Tampering | Budget recalculation after compression | medium | mitigate | TokenBudget.estimateTokens() is called on every section after every compression step. If the estimation is wrong, the pipeline may prematurely throw CONTEXT_TOO_LARGE or under-compress. Mitigation: use the same TokenBudget.estimateTokens() for both pre-compression estimation and post-compression recalculation to ensure consistency. |
</threat_model>
