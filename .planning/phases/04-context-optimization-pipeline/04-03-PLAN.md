<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stable sections → cacheKeyHash | The stable sections' text content is hashed via FNV-1a to produce cacheKeyHash — any change in persona, system prompt, or tool schemas invalidates the hash |
| Cache health state → AgentOrchestrator | Per-provider cache health (missStreak, disabledUntil) is stored in-memory only — after a service worker restart, health resets (acceptable per RESEARCH.md Pitfall 3) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-12 | Tampering | cacheKeyHash collision | low | accept | FNV-1a is non-cryptographic — collisions are possible but the consequence is a cache miss (not a security breach). The hashed content is system prompts and tool schemas — not user data. Collision probability is ~1/2^32 per hash pair. |
| T-04-13 | Denial of Service | Cache disabled state prevents re-enable | low | mitigate | disabledUntil uses timestamp comparison (Date.now() >= disabledUntil). If the system clock jumps backward, the disabledUntil check could fail. Mitigation: use monotonic clock where available (performance.now() is monotonic but not suitable for long durations — Date.now() is the pragmatic choice). The worst case is 60s of disabled cache — acceptable per §19.13. |
| T-04-14 | Information Disclosure | Cache health leaks provider usage patterns | low | accept | missStreak and disabledUntil reveal which providers are experiencing cache misses. This information is only available in-memory (never persisted, never sent externally). Runtime-only exposure is acceptable. |
| T-04-15 | Tampering | Malformed CacheResponseMetadata | low | mitigate | Validate metadata fields before processing: providerId must be a valid PipelineProviderId, cacheHit and cacheWrite must be booleans. Invalid metadata is logged and discarded (graceful no-op). |
</threat_model>
