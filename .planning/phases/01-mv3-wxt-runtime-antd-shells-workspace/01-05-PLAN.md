    **CommandPalette** (`src/core/commands/commandPalette.tsx`):
    - Define `Command` interface: `{ id: string; label: string; action: () => void; shortcut?: string }`
    - Define `CommandPaletteProps`: `{ open: boolean; onClose: () => void; commands: Command[] }`
    - State: `query` (string), `selectedIndex` (number)
    - Compute `filtered` array: `commands.filter(c => c.label.toLowerCase().includes(query.toLowerCase()))`
    - Keyboard navigation via `useEffect` with `window.addEventListener('keydown', ...)`:
      - ArrowDown: `setSelectedIndex(i => Math.min(i + 1, filtered.length - 1))`
      - ArrowUp: `setSelectedIndex(i => Math.max(i - 1, 0))`

    - Reset effect: when `open` changes to `true`, reset `query` to `''` and `selectedIndex` to `0`
    - Use memoized `useCallback` for `handleSelect` to avoid recreating the keyboard handler on every render
    - Render: AntD `Modal` with `open={open}`, `onCancel={onClose}`, `footer={null}`, `closable={false}`, `width={560}`, `styles={{ body: { padding: 0 } }}`
      - Inside: AntD `Input` with `size="large"`, `placeholder="Type a command..."`, `value={query}`, `onChange` resets `selectedIndex` to 0, `autoFocus`, `bordered={false}`, `style={{ padding: '12px 16px' }}`
      - Below input: AntD `List` with `dataSource={filtered}`, `renderItem` renders a `List.Item` with `onClick={() => handleSelect(item)}` and conditional background color: `background: index === selectedIndex ? 'var(--ant-color-bg-text-hover)' : undefined`
      - Each item displays `item.label` and optionally `item.shortcut` in a secondary-colored span

    Write tests first (RED phase). Use `@testing-library/react` to render the component with mock commands. Simulate keyboard events via `fireEvent.keyDown(window, ...)` and verify filtering/selection behavior. Then implement (GREEN phase).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User keyboard input → CommandPalette | Keyboard events on `window` — but CommandPalette only acts on Arrow/Enter when open |
| Provider selection + API key → WorkspaceStore | Onboarding captures provider choice and API key — temporarily in-memory in Phase 1 (Phase 2 adds AES-GCM encryption) |
| chrome.sidePanel.open() → Side Panel | Popup and Command Palette trigger side panel opening — no data passes, just navigation |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-05-KEY | Information Disclosure | OnboardingModal.tsx | high | mitigate | API key input uses `Input.Password` (masked by default with visibility toggle). Key stored in-memory placeholder in Phase 1 — Phase 2 (STOR-02) replaces this with AES-GCM encrypted storage via PBKDF2 + per-key salt/IV. Document the placeholder clearly in providerStore.ts. |
| T-05-CMD | Elevation of Privilege | CommandPalette | low | accept | Command palette executes arbitrary `action()` callbacks — but all commands are defined in the core codebase (not user-supplied). No command injection risk in Phase 1. In Phase 8 when add-ons can register commands, the KeymapRegistry will need a permission model. |

**Threat disposition summary:** 2 threats — 1 mitigated, 1 accepted, 0 transferred.
