## Top 3 Priority Fixes

1. **The shipped Default theme is the Claude-warm prototype palette, not the contract's seed tokens** — every reachable appearance (Default × Light and Dark) renders a terracotta accent `#cc6b49`/`#da7756` and warm parchment/charcoal surfaces instead of `#3B82F6`/`#5B9BFF` and `#FCFCFD`/`#0E1117`, so the phase's AA-verification basis and the entire accent-reserved contract describe a UI that does not exist, and the `claude-warm` overlay becomes indistinguishable from Default. **Fix:** re-seed `src/theme/semanticTokens.ts` to `DESIGN_SYSTEM.md` §6.2 (`colorPrimary #3B82F6/#5B9BFF`, `colorBgBase #FCFCFD/#0E1117`, `colorBgContainer #FFFFFF/#161A22`, `colorSuccess #10B981/#34D399`, `colorWarning #F59E0B/#FBBF24`, `colorError #EF4444/#F87171`, `colorTextBase #1F2430/#E6E8ED`), keep the Claude-warm values only inside the `claude-warm` pack overlay, and add a `tests/core/theme/antdConfig.test.ts` case pinning `getDesignToken(getAntdConfig({pack:'default'})).colorPrimary` to the contract value — or, if the warm palette really is the intent, amend `01-UI-SPEC.md` § Color and `DESIGN_SYSTEM.md` §6.2 as an explicit operator decision (the `01-MIGRATION-INVENTORY.md:143` KEEP row is not a design authority).
2. **The per-surface type scale is not the contract's, and the 12 px floor is broken in the shipped compact tree** — measured with antd's own `getDesignToken` on the shipped seed (`fontSize: 13`): Standalone derives `fontSize 13 / fontSizeSM 10 / lineHeight 1.62`, and the Side Panel's `compactAlgorithm` rebases the whole font map to `fontSize 10 / fontSizeSM 8 / lineHeight 1.80`; `SidePanelShell.tsx:288` therefore renders the status-bar caption at 8 px — the exact case `01-UI-SPEC.md:162` names as the floor — and `SidePanelShell.tsx:199,248` render the workflow label and the composer at 10 px instead of the 13 px compact base; Inter (the declared face) is never loaded or set on the token. **Fix:** set the seed so the compact tree derives 13 px (or pass an explicit post-algorithm token override), re-assert `fontSize` after the algorithm, set `token.fontFamily` to the Inter stack and `fontFamilyCode` to JetBrains Mono, then pin the derived values in `tests/core/theme/antdConfig.test.ts` (`compact: true` → `fontSize === 13 && fontSizeSM >= 12`; `compact: false` → `fontSize === 14`).
3. **The pinned handoff interaction contract and the focus/error-recovery behaviours are not implemented on the Phase-1 live paths** — the pending state shows the inline literal `Opening standalone view…` (`src/entrypoints/sidepanel/main.tsx:74`) instead of `workspace.handoffPending`, the pinned `workspace.handoffComplete` toast never renders (both keys have zero consumers), the failure toast shows no `Retry` label and self-dismisses after 4 s, `message.config({ maxCount: 3, duration: 5 })` is absent entirely, the composer textarea removes focus indication (`outline: 'none'`, `SidePanelShell.tsx:251`), and the shell-error `Reload` only re-mounts the failing subtree (`ErrorBoundary.tsx:36-39`). **Fix:** resolve both handoff keys through `t()`, render `Retry` as the toast's action (AntD message supports `content` with a `Typography.Link`, the pattern `ThemeSync.ts:158-172` already uses), add `message.config({ maxCount: 3, duration: 5 })` at both roots, switch acknowledgement errors to `duration: 0`, restore a visible focus ring on the composer (`boxShadow: 0 0 0 2px colorPrimaryBorder` on focus, or `outline: 2px solid colorPrimary`), and make `Reload` call `chrome.runtime.reload()` (or `window.location.reload()`) rather than reset local state.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**What holds.** `src/core/i18n/strings.ts` is the strongest artefact in the phase: every UI-SPEC-pinned key is present verbatim (`chat.empty`, `chat.emptyBody`, `chat.noProvider`, `standalone.openFailed`, `standalone.minWidth`, `theme.syncFailed`/`theme.syncRetry`, `shell.error*`, `provider.credentialsCleared` + `Dismiss`, `commands.*`, all `onboarding.*`, `deferred.*`, `common.continue`/`common.notNow`, `command.reloadExtension.confirm`), `format()` is total, the table is frozen, and `tests/core/i18n/strings.test.ts` pins exactness over the whole record (16 cases, proven non-vacuous by three deliberate violations). On Phase-1 surfaces every string resolves through `t()` except the one literal below; the palette's placeholder / zero-results / category labels are all map-resolved; no AntD locale default is reachable (`Continue`/`Not now`/`Select an AI provider`/`Close` all pinned).

**Findings.**

1. **WARNING — the handoff pending state renders an inline, divergent literal.** `src/entrypoints/sidepanel/main.tsx:74` calls `antMessage.loading({ content: 'Opening standalone view…', … })`. The pinned string is `workspace.handoffPending` = `Opening workspace in standalone view...` (`strings.ts:31`) — different wording, different actor ("standalone view" vs "workspace in standalone view"), and a Unicode ellipsis where the contract's copy uses three ASCII periods (`01-UI-SPEC.md:234`). The key is dead: `grep` finds `workspace.handoffPending` only in `strings.ts`.
2. **WARNING — the pinned Complete-state success toast never renders.** `01-UI-SPEC.md:649` pins `Workspace opened in standalone view.` for the Complete state; `src/entrypoints/sidepanel/main.tsx:83` only calls `antMessage.destroy('open-standalone')`. `workspace.handoffComplete` (`strings.ts:32`) has zero consumers, so the user gets no completion claim at all — and the "no success is claimed until a validated acknowledgement" rule is satisfied only in the negative direction.
3. **WARNING — the handoff failure path never renders its pinned next-step label.** `01-UI-SPEC.md:219` requires every Phase-1 error path to name its problem *and* its next step with the action label pinned (`Retry`). `src/entrypoints/sidepanel/main.tsx:88-93` renders only `t('standalone.openFailed')` with an invisible whole-toast `onClick` retry — there is no `Retry` text anywhere in the rendered output (`grep` finds `onboarding.retry` and `theme.syncRetry` only, plus doc comments).
4. **WARNING — the required toast configuration is missing.** `01-UI-SPEC.md:461-465` ("Toast / notification configuration (§17.4, **required in Phase 1**)") pins `message.config({ maxCount: 3, duration: 5 })` and `notification.error({ duration: 0 })` for acknowledgement-requiring errors. `grep -rn "message.config\|maxCount" src/` returns nothing, and all three error toasts are `duration: 4` self-dismissing `message.error` calls (`sidepanel/main.tsx:91`, `standalone/main.tsx:150`, `core/theme/ThemeSync.ts:176`), so a missed handoff/side-panel/theme error leaves no recoverable affordance.
5. **Recorded, not counted.** Preserved-page inline copy (`Submit`, `Save`, `Cancel`, `Export as Markdown`, …) is the operator-accepted IN-05 override owned by Phase 15/17 (`01-REVIEW.iter2.md:241-245`), so it is not scored against this pillar.

### Pillar 2: Visuals (3/4)

**What holds.** Composition is deliberate on both surfaces: Side Panel header (mark + wordmark left, exactly two trailing icon buttons), a centred empty state with a title/body hierarchy, a three-band composer block, and a 28 px status row with a neutral dot plus caption; Standalone has the canonical Sider with fill+weight active states, a 56 px top bar, and a centred content column. Every icon-only control on a Phase-1 surface carries `aria-label` + `Tooltip` (Side Panel header ×2, composer ×3, send, status bar ×2, Sider items, Sider Options, collapse toggle, top-bar back, global search, palette close), and the fixture/deferred marking is uniform (`DeferredNotice` block alerts on the two deferred pages; warning `Tag`/`Alert` inline elsewhere; 43 marked regions, all literal-valued).

**Findings.**

1. **WARNING — the declared motion layer is entirely absent.** `01-UI-SPEC.md:684-698` pins six interactions (panel/page 150–200 ms fade + 8 px slide; modal 160 ms fade + scale 0.98; Sider collapse 150–200 ms; card hover lift; chip/button press; instant theme switch) and `01-UI-SPEC.md:681` requires `prefers-reduced-motion` to drop slides/scales. `grep -rn "from 'motion'" src/` returns nothing (the approved package is unused), no component in `src/components/sidepanel` / `standalone/StandaloneShell.tsx` / `src/components/common` declares a transition beyond the preserved `ActionPanel` hover fades, and `prefers-reduced-motion` appears nowhere in `src/` (no media query in `src/index.css`). The shipped interactions are AntD defaults, so the design language for panel/modal/collapse motion does not exist.
2. **WARNING — the sub-1024 px notice uses a deprecated AntD prop.** `src/components/standalone/StandaloneShell.tsx:318-324` passes `message={t('standalone.minWidth')}` to `Alert`; `antd@6.5.2` deprecates `message` in favour of `title` (`node_modules/antd/es/alert/Alert.js:87`), and `OnboardingFlow.tsx:402-409` already uses `title` for the same element type. The notice renders, but it logs a deprecation on every narrow viewport and sits on a prop scheduled for removal.
3. **Limitation, not a finding — no rendered evidence exists for the current tree.** No dev server was running, and extension surfaces cannot be captured by a static screenshot pass, so contrast, spacing rendering, focus appearance and the annotated-reference comparison are unverified here. Independently, `01-VERIFICATION.md:157,365` records that the operator's 2026-09-22 acceptance ran against a `.output/chrome-mv3` that predates the review-fix commits (`CR-02` broke the real-browser handoff; `WR-05/WR-06/WR-07/WR-09` changed rendered UI), so the shipped rendering has never been observed post-fix. This is why the pillar cannot reach 4.
4. The empty-state focal element renders `NowPilotAvatar` (`SidePanelShell.tsx:168`, `size={64}`) rather than an explicitly named Q-Octo artboard. Whether the asset is the mascot could not be established without a browser, so no claim is made either way.

### Pillar 3: Color (1/4) — BLOCKER

**The core finding.** The whole reachable appearance diverges from the approved seed tokens.

`src/theme/semanticTokens.ts:47-96` defines the shipped seeds, `src/theme/packs/claudePlus.ts:10-45,50-84` assembles them, and `src/core/theme/antdConfig.ts:55-70` merges the selected pack **over** that blob — so `getAntdConfig({ pack: 'default' })` renders the Claude Plus palette:

| Role | Contract (`01-UI-SPEC.md:173-200`, `DESIGN_SYSTEM.md:105-115`) | Shipped Default |
|---|---|---|
| Accent `colorPrimary` | `#3B82F6` light / `#5B9BFF` dark | `#cc6b49` / `#da7756` (`semanticTokens.ts:48,66`) |
| Dominant `colorBgBase`/`bgLayout` | `#FCFCFD` / `#0E1117` | `#fbfaf7` / `#181715` (`:55,72`) |
| Secondary `colorBgContainer` | `#FFFFFF` / `#161A22` | `#ffffff` / `#21201d` (`:56,73`) |
| `colorSuccess` | `#10B981` / `#34D399` | `#2e7d32` / `#4ade80` (`:84,101`) |
| `colorWarning` | `#F59E0B` / `#FBBF24` | `#d97706` / `#fbbf24` (`:85,102`) |
| `colorError` | `#EF4444` / `#F87171` | `#dc2626` / `#f87171` (`:86,103`) |
| `colorTextBase` | `#1F2430` / `#E6E8ED` | `#262422` / `#ece8de` (`:68,85`) |

Consequences: (a) the accent-reserved list (`01-UI-SPEC.md:180-191`) is unverifiable against the intended accent; (b) the pack contract is inverted — Default *is* the warm palette, so the `claude-warm` overlay (`ThemeConfig.ts:85-88`, `colorBgBase: '#FAF7F2'`) is nearly indistinguishable from Default and the "only Default is reachable" claim loses meaning; (c) the phase's AA verification basis (`01-UI-SPEC.md:206`) was never performed against the declared tokens. `01-MIGRATION-INVENTORY.md:143` KEEPs `claudePlus.ts` as "Phase 1 default pack source", but an inventory classification is not a design decision — the UI-SPEC is the approved contract and it explicitly builds *away* from the Claude-Warm reference (`01-UI-SPEC.md:713`).

**Further findings.**

1. **BLOCKER (same root) — hard-coded hex in components, 215 occurrences.** `01-UI-SPEC.md:171` states hard-coded hex in a component is a defect and names the prototype's values as the defect class. Live examples: `#6035f5` (`src/components/options/PromptModal.tsx:289,330,419,488`), `#2563eb` (`src/components/options/PromptsOptionsTab.tsx:307,331,431`), `#3b82f6` (`src/components/chat/FollowupSuggestions.tsx:62,80`; `src/components/chat/PinnedTabsBar.tsx:57,147`), `#9ca3af` (`PromptsOptionsTab.tsx:445,670`), and a CSS-variable fallback string `var(--np-primary, #1677ff)` (`src/components/options/OptionsPage.tsx:1021`) — the exact "CSS-variable fallback" pattern the palette contract calls a defect (`01-UI-SPEC.md:332`). All sit in preserved fixture pages (`data-np-backing` marked, owners 8/15/17/18), but they are in the Phase-1 build and none of them track `theme.useToken()`.
2. **WARNING — a parallel CSS-variable colour system.** 18 component files consume 443 `var(--…)` references (152 × `--muted-foreground`, 118 × `--border`, 81 × `--foreground`, 40 × `--muted`) resolved from `src/index.css` and `applyClaudePlusCssVars` (`src/theme/packs/claudePlus.ts:94+`) rather than AntD tokens, so preserved pages render from a second, hand-maintained colour source that the theme switch keeps in step only by convention (`ThemeStore.applyThemeDom`).
3. **WARNING — accent-list violation on a Phase-1-owned component.** `src/components/common/LegacyCredentialCleanupNotice.tsx:78` renders `Dismiss` as a filled `type="primary"` accent button, while `01-UI-SPEC.md:186` classifies `Dismiss` as an inline text link / secondary action; the accent primary-button list (`:182`) names only `Continue`, `Check connection`, `Finish setup`, `Retry`.
4. **Recorded decision, not a defect:** `applyThemeDom` toggles the `document.documentElement` `.dark` class (`ThemeStore.ts:84`), which contradicts `01-UI-SPEC.md:627` ("no `.dark` class manipulation"). H-3/OQ2 recorded the scoped interpretation (`ThemeSync.ts:70-73`), and two suite cases prove the AntD derivation is class-independent — noted so the divergence is not read as an accident.
5. Distribution itself is disciplined: in the Phase-1 shells the accent appears only on primary buttons, the "N" mark, the active Sider pill and the palette's selected row — 60/30/10 roles are respected; the *values* are what is wrong.

### Pillar 4: Typography (1/4) — BLOCKER

Measured with `antd`'s own derivation against the shipped seed (`fontSize: 13` at `claudePlus.ts:44,87`) — `theme.getDesignToken({ algorithm: [defaultAlgorithm, compactAlgorithm], token })`:

| Surface | Derived `fontSize` | `fontSizeSM` | `fontSizeHeading4` | `lineHeight` |
|---|---|---|---|---|
| Standalone (default) | **13 px** (contract 14) | **10 px** (floor 12) | 18 px | 1.62 (contract 1.5) |
| Side Panel (compact) | **10 px** (contract 13) | **8 px** (floor 12) | 14 px | 1.80 |

**Findings.**

1. **BLOCKER — the 12 px floor is breached in the surface the rule names.** `01-UI-SPEC.md:162`: "**12px is the floor.** Nothing renders below 12px — including the command palette's category label and status-bar captions." `src/components/sidepanel/SidePanelShell.tsx:288` renders the status-bar caption at `token.fontSizeSM` = **8 px** on the compact tree, and `src/components/standalone/StandaloneShell.tsx:178` renders the Add-ons group label at 10 px on the default tree. The palette holds the floor (explicit `LABEL_FLOOR_PX = 12`, `CommandPalette.tsx:23,166,213,221`), which shows the intent — the shells do not.
2. **BLOCKER — per-surface base sizes are not the contract's.** Compact `fontSize` resolves to 10 px because AntD's `compactAlgorithm` rebases the font map on `fontSizeSM` (`node_modules/antd/es/theme/themes/compact/index.js:7`), so the Side Panel's workflow label (`SidePanelShell.tsx:199`) and composer text (`:248`) render at 10 px rather than the declared 13 px; Standalone body text derives 13 px rather than 14 (`01-UI-SPEC.md:155,163`). Nothing in the codebase compensates for the algorithm, and no test asserts either base size.
3. **WARNING — the declared font is never applied.** `01-UI-SPEC.md:33` pins Inter (UI/body + display) and JetBrains Mono (code/IDs). `claudePlus.ts:42,85` sets `fontFamily: '-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, …'`; no token sets `fontFamilyCode`; the only mention of Inter is a dead `--font-sans: Inter, sans-serif` in `src/index.css:38`, and no font file or `@font-face` exists in the build.
4. **WARNING — the display/heading role is a different size.** `Title level={4}` maps to `fontSizeHeading4` (18 px default / 14 px compact), not the declared Display 20 px/600 (`01-UI-SPEC.md:158`): `SidePanelShell.tsx:169`, `ChatPage.tsx:35`, `AgentPage.tsx:32`.
5. **WARNING — more than two weights are in use.** `01-UI-SPEC.md:160` allows exactly 400 and 600; the source contains `fontWeight: 700` × 55, `500` × 60 and `800` × 4 (concentrated in preserved pages; the Phase-1 shells use 400/600 and `Typography strong` consistently). The rule is therefore exceeded in the shipped build even though the shells themselves are clean.
6. Line height is AntD-derived (1.62 / 1.80) rather than the declared 1.5 / 1.3 — a consequence of the same seed; recorded here rather than as a separate fix.

### Pillar 5: Spacing (3/4)

**What holds.** Every pinned layout metric is implemented and asserted: Side Panel header 52 / composer toolbar 44 / status bar 28 / composer input `minHeight` 60 (`SidePanelShell.tsx:23-27`, `tests/components/SidePanelShell.test.tsx`); Standalone Sider 240/72, item height 40, top bar 56, `navItemStyle` radius from `token.borderRadius` = 8 (`StandaloneShell.tsx:25-28,103-122`, `tests/components/StandaloneShell.test.tsx`). Composition uses `Flex`-style token reads (`gap`/`padding*`) rather than margin arithmetic, and the 20 px Card-body exception is honoured through `Card.paddingLG: 20` (`componentTokens.ts:101`).

**Findings.**

1. **WARNING — a spacing value outside the declared set.** `SidePanelShell.tsx:250` sets `paddingBottom: 40` on the composer textarea to make room for the send control. 40 is not one of xs/sm/md/lg/xl/2xl/3xl and not one of the two layout exceptions, and `01-UI-SPEC.md:147` states "No component invents a spacing value outside this set." Use `token.paddingLG + token.paddingSM` (24+12) or `token.paddingXL` (32) and reposition the button.
2. **WARNING — 12 px appears outside the compact tree.** `01-UI-SPEC.md:141` permits 12 px **only** inside the Side Panel; `StandaloneShell.tsx:106,109,176` read `token.paddingSM` (= 12) for the Sider item gap, item padding-inline and the Add-ons group padding — i.e. 12 px is used in default density. The command palette (rendered on both surfaces) also hard-codes `marginBottom: 12` (`CommandPalette.tsx:154`) and `padding: '8px 12px'` (`:186`); `padding: '24px 0'` (`:165`) is in-scale.
3. **WARNING — `controlHeight` is 34, not the declared 32.** `01-UI-SPEC.md:62` pins `controlHeight: 32` for `Button` (and the inventory's Input entry implies the same); `src/theme/componentTokens.ts:24,60,91` set `controlHeight: 34` (and `Select`/`Input` 34). Every default-size control therefore renders 2 px taller than declared.
4. **WARNING — the declared container-query fallback does not exist.** `01-UI-SPEC.md:421` requires container queries below 380 px to collapse to a single column; `grep -rn "@container\|container-type" src/` returns nothing. Practical impact is low (the panel is a flex column), but the declared mechanism is absent and unasserted.
5. The palette's `COMMAND_LIST_MIN_HEIGHT/MAX_HEIGHT` (240/320) are unlisted sizing metrics, not spacing values; noted only so a later reader does not read them as scale violations.

### Pillar 6: Experience Design (2/4)

**What holds.** State coverage is the phase's strongest non-visual property. Loading: onboarding validation enters `loading` + `disabled` with `Testing connection...` and no auto-advance (`OnboardingFlow.tsx:433-443`); handoff pending is surfaced (albeit with the wrong copy) and success is ack-gated. Error: onboarding renders `Connection failed: {error}` with `Retry` + `Edit key` for every canonical code (`:465-487`); handoff failure, `sidepanel.openFailed` and the theme-sync failure all have typed codes, logs and pinned strings; `ErrorBoundary` mounts a `Result status="500"` with explicit copy instead of locale defaults. Empty: the Side Panel empty state, the palette's zero-results branch that holds list height (`CommandPalette.tsx:164-169`), the two deferred page shells and nine marked fixture pages. Disabled/marked: 43 `data-np-backing` regions, every later-phase control `disabled` + tooltip, no fabricated signal on Phase-1 surfaces. Destructive: `reload-extension` is dev-gated, bundle-eliminated and requires an explicit confirmation with pinned labels.

**Findings.**

1. **WARNING — the composer's focus indicator is removed with no replacement.** `SidePanelShell.tsx:237-252` sets `outline: 'none'` on the only live input in the Side Panel; no `onFocus`/`boxShadow`/className restores an indicator, and `src/index.css` contains no focus rules. `01-UI-SPEC.md:674` — "visible 2px `colorPrimary` ring on all interactive elements; focus is never removed without an equivalent replacement indicator." (The 2 px `colorPrimary` ring is not implemented anywhere; the shells rely on AntD's default indicators, which is acceptable except where the indicator was explicitly deleted.)
2. **WARNING — the shell-error recovery action does not recover.** `ErrorBoundary.tsx:36-39` handles `Reload` with `this.setState({ hasError: false })`, re-mounting the same subtree that threw, while the pinned body copy says `Reload NowPilot to continue.` (`01-UI-SPEC.md:241-242`). In the common case (a deterministic render error) the fallback re-throws immediately, so the pinned next step is a no-op; there is no `chrome.runtime.reload()` or `location.reload()` path.
3. **WARNING — handoff state changes are not announced.** `01-UI-SPEC.md:680` requires handoff state changes to announce politely via `role="status"` / `aria-live="polite"`. The only live regions in `src/` are the onboarding step indicator (`OnboardingFlow.tsx:517-518`) and the unmounted `MirrorBanner`; the handoff pending/complete/failed transitions live only in toasts with no live region.
4. **WARNING — Standalone hit targets are below the declared minimum.** `01-UI-SPEC.md:678` requires ≥32 px in the compact tree and **≥36 px** in the Standalone tree. The Side Panel's 32×32 icon buttons and `size="small"` (32 px) status-bar buttons comply; in Standalone the collapse toggle, the disabled back chevron and the global search input all render at `controlHeight: 34` (`componentTokens.ts:24,60,91`) — 2 px under the minimum, with the Sider items (40 px) the only controls that clear it.
5. **WARNING — the Sider is not arrow-key reachable.** `01-UI-SPEC.md:679` and the phase's own must-haves (`01-02-PLAN.md:453`, `01-12-PLAN.md:59`) require arrow-key navigation in the Standalone Sider. `StandaloneShell.tsx:154-168` renders native `<button>` items with no key handling and no `Menu`/`role="menu"` semantics, so navigation is Tab-only; nothing asserts arrow reachability.
6. **WARNING — errors that require acknowledgement self-dismiss** (see Pillar 1 finding 4): all three error toasts use `duration: 4`, and the required `message.config` is absent, so the failure affordances can vanish before they are read.
7. **Outstanding evidence, recorded:** `01-VERIFICATION.md:157,365` flags that the manual acceptance set must be re-observed against the post-fix artifact (CR-02/WR-05/WR-06/WR-07/WR-09 changed real-browser behaviour). Until that run happens, several Pillar-6 interactions (palette chord, handoff, theme propagation, gesture-gated panel open) rest on unit evidence only.
8. **Carried informational items (unchanged, outside `fix_scope: critical_warning`):** IN-01 production `console.log` (`src/entrypoints/background.ts:12`), IN-02 three fabricated success toasts on fixture pages, IN-03 unused store bindings, IN-04 fabricated timestamps — plus IN-05, the operator-accepted preserved-page copy override.
