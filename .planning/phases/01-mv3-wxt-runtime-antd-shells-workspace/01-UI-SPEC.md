## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

Declared values are multiples of 4 (sizeUnit = 4, per DESIGN_SYSTEM.md §7 and spec Appendix F). The actual NowPilot scale is a denser 7-step ramp tuned for the 400 px Side Panel and the wider Standalone view; the canonical 2·4·8·12·16·20·24·32 sequence is preserved.

| Token | Value | Usage |
|-------|-------|-------|
| hairline | 2 px | Hairline borders only (`colorBorder` thin separators, divider strokes); not a general padding token. |
| xs | 4 px | Icon gaps, inline padding, dense row spacing. |
| sm | 8 px | Compact element spacing (chip gaps, toolbar icon gutters, list-item vertical padding in compact mode). |
| md | 12 px | Default compact spacing (Side Panel list rows, inline form field gaps, composer toolbar row). |
| lg | 16 px | Default element spacing (Standalone view list rows, card internal gutters, composer row, model-selector pill padding). |
| xl | 20 px | Standalone view section padding (settings card body, drawer content). |
| 2xl | 24 px | Section padding (Standalone Notes column gutters, Inspector card stack gaps). |
| 3xl | 32 px | Layout gaps (Side Panel header→conversation gap, Standalone Sider→content gap). |

Exceptions:

- **Touch targets ≥ 32 px (Side Panel / compact) / ≥ 36 px (Standalone view)** — applies to every interactive element that is not a text input (icon buttons, chips, nav items, segmented toggles). Enforced per DESIGN_SYSTEM.md §12.
- **Composer / Notes toolbar icons** are spaced so adjacent 18 px icons never overlap at 400 px width — minimum `sm` (8 px) gap between icon centers; if container width forces crowding, icons wrap rather than overlap.
- **No 48 / 64 px steps in Phase 1.** The template's `2xl/3xl` rows above map to 24 / 32 px (the actual tokens); 48 and 64 are unused and not declared.

## Typography

Phase 1 declares **3 weights max** (400 body, 600 semibold for headings/display/active states, and the inherited 500 from AntD's defaults — capped to 2 effective weights per the dimension contract). The Standalone view base is 14 px; the Side Panel base is 13 px (compact). Steps: 12 / 13 / 14 / 16 / 20 / 24 / 30.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13 px (Side Panel) / 14 px (Standalone) | 400 | 1.5 |
| Label / caption | 12 px | 400 (status bar captions use `colorTextTertiary`); 600 reserved for active segmented/nav labels | 1.5 |
| Heading | 20 px (h2, page titles) / 16 px (h3, card titles, segmented toggles) | 600 | 1.3 |
| Display | 24 px (h1, OnboardingModal hero) / 30 px (wordmark + display only — not used in Phase 1 page skeletons but reserved for the Onboarding persona card heading per DESIGN_SYSTEM.md §8.6 + Flow 9 RICH-R-03) | 600 | 1.3 |

Additional rules (DESIGN_SYSTEM.md §5):

- Never below 12 px.
- Captions use `colorTextTertiary`.
- Mono (JetBrains Mono) is reserved for code, macros, operation IDs, model IDs (the `⚡ gemma-4-2b-it-4bit` style); never mixed with body weight.
- `motion`-driven text reveals are forbidden on streamed chat (spec §12.6); no typewriter effect anywhere in Phase 1.

## Color

Phase 1 colour contract follows the 60/30/10 split declared by DESIGN_SYSTEM.md §6.2 and Appendix F. Every colour is an AntD v6 design token; **no hex is hard-coded in components** — `getAntdConfig({ mode, pack, compact })` derives the 10-step palettes and the CSS variables cascade across both surfaces live.

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `colorBgBase` — light `#FCFCFD` / dark `#0E1117` | App background; conversation area fill; Standalone view content area; Side Panel main canvas. |
| Secondary (30%) | `colorBgContainer` — light `#FFFFFF` / dark `#161A22` | Cards, settings cards, drawers/bottom sheets, input fields, chat bubbles (assistant, `variant="filled"`), Status bar, header bar, Note cards (placeholder shells for Phase 1). |
| Accent (10%) | `colorPrimary` — light `#3B82F6` / dark `#5B9BFF` | See "Accent reserved for" list below. |
| Semantic — Success | `colorSuccess` — light `#10B981` / dark `#34D399` | Provider Check connection success state (DESIGN_SYSTEM.md §8.7); not used in Phase 1 page skeletons. |
| Semantic — Warning | `colorWarning` — light `#F59E0B` / dark `#FBBF24` | Reserved for Phase 7 RICH clarification chips (Flow 16) and Phase 4b prompt-injection quarantine toasts; not present in Phase 1 surfaces. |
| Semantic — Error / Destructive | `colorError` — light `#EF4444` / dark `#F87171` | Provider-status failure text in the Side Panel status bar (DESIGN_SYSTEM.md §8.1e), provider-validation error inline in the Phase 3 provider dialog (declared for forward compat — no Phase 1 destructive action invokes it yet). |
| Info (tracks primary) | `colorInfo` — light `#3B82F6` / dark `#5B9BFF` | Same hex as `colorPrimary` per Appendix F seed. |
| Text | `colorTextBase` — light `#1F2430` / dark `#E6E8ED` | Body text. |
| Tertiary text | `colorTextTertiary` | Captions, model labels, helper text, status-bar captions. |
| Border | `colorBorder` — light `#E7E9EE` / dark `#252B36` | Dividers, card hairlines, input outlines. |

### Accent reserved for (EXCLUSIVE list — never "all interactive elements")

`colorPrimary` is reserved for these surfaces **only**:

1. **Primary CTAs** — "Configure provider" (Onboarding persona card), "Save" (provider dialog, Phase 3), "Open" / "Add" actions on empty-state placeholders (Notes "New note").
2. **Active nav item pill** — Standalone Sider active entry (DESIGN_SYSTEM.md §8.2: `colorPrimaryBg` pill + `colorPrimary` icon/text).
3. **Focus ring** — visible 2 px `colorPrimary` ring on every interactive element (DESIGN_SYSTEM.md §12, WCAG AA).
4. **Send button enabled state** — circular send inside the Side Panel composer (DESIGN_SYSTEM.md §8.1d); turns `colorPrimary` when the input is non-empty.
5. **Active composer accent** — focused-input ring (composer at 30% alpha per §8.1d) and the model-selector dropdown open state.
6. **Streaming tail caret** — X `Bubble streaming` caret at 60% alpha (DESIGN_SYSTEM.md §6.3).
7. **Settings "Set up" link text + section actions** in the provider grid (DESIGN_SYSTEM.md §8.6).
8. **Wordmark "Pilot" portion** of the two-tone "NowPilot" lockup (DESIGN_SYSTEM.md §3.2) and the mascot cap band (DESIGN_SYSTEM.md §4.1).

**Not accent:** hover on text links, secondary buttons, ghost buttons, disabled state, neutral borders, dividers, list-item hover (use `colorFillTertiary`/`colorBgTextHover` for those).

### Destructive colour usage

Phase 1 has **no destructive user action** (no delete, no clear, no irreversible write — these arrive with Phase 2 WriteJournal and Phase 5 Notes). `colorError` is declared for forward compat so the same token is reused by:

- The provider name in the Side Panel status bar when `activeProvider` is unreachable (DESIGN_SYSTEM.md §8.1e).
- Inline validation feedback in the provider dialog (Phase 3) and theme persistence errors.

Destructive actions are out of scope for Phase 1; this contract declares the token but does not bind it to a destructive confirm flow until a later phase.

### Destructive confirmation

**None in Phase 1.** No destructive actions exist. Forward-compat only: when destructive actions land in later phases, the confirmation pattern is a typed-name confirmation modal (e.g. "Type the conversation title to confirm delete") for irreversible writes (spec §28.5 commit-confirm barrier), not a single-click confirm.
