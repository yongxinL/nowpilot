# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope.** This is a **UI-hinted shell phase**. Phase 1 ships: the MV3/WXT runtime, both surface shells (Chat-only Side Panel at compact density; Standalone workspace at default density), the shared onboarding interaction shell (fixture-backed), the Cmd+K command palette with shell/navigation commands only, the theme contract, and the Standalone handoff. Chat streaming, notes, tools, diagnostics, add-ons, provider setup and every later-phase capability are **not** implemented here; where their presentation is preserved it must be disconnected and marked per `## Fixture-Backed & Deferred Marking Convention`.

**Precedence.** On any conflict: `PRODUCT_SPEC.md` wins for functional rules → `DESIGN_SYSTEM.md` §8 written metrics win over a stale annotated image → this document wins over prototype behaviour (`01-CONTEXT.md` D-01).

**shadcn gate — not applicable, recorded deliberately.** The gate fires on "no design system detected". A design system **is** detected and locked: Ant Design v6 is the primary design system (§7.2, §5.5), `getAntdConfig()` is the single theme derivation point (Appendix F), and `tailwindcss` / `shadcn/ui` / `@radix-ui/*` are **banned packages** enforced by `scripts/verify-no-tailwind.sh` and the Phase-1 banned-import greps. Initialising shadcn would violate a locked project decision, so the gate is closed with `Tool: none` for shadcn and the AntD inventory below is authoritative.

**One provider per surface.** Each surface mounts exactly **one** `XProvider` (which extends `ConfigProvider`) and wraps `AntdApp` inside it (§5.5). Never nest `ConfigProvider` inside `XProvider`. All imperative UI APIs (`message`, `notification`, `Modal.confirm`) are reached through `App.useApp()` — static `message.*` imports are forbidden (§17.3).

## Spacing Scale

Declared values (must be multiples of 4). Source: `DESIGN_SYSTEM.md` §7 (`sizeUnit = 4`), reduced to the steps Phase 1 shells actually use.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, chip inner padding |
| sm | 8px | Compact element spacing, Sider item gap, button/icon group gaps |
| md | 16px | Default element spacing; Standalone card padding; header horizontal padding |
| lg | 24px | Section padding; onboarding step vertical rhythm |
| xl | 32px | Layout gaps; Side Panel composer block gaps |
| 2xl | 48px | Major section breaks (Standalone page headers) |
| 3xl | 64px | Page-level spacing (Standalone onboarding centring) |

Exceptions (all deliberate, all multiples of 4):

- **12px** — compact-density intermediate step. Permitted **only** inside the Side Panel (compact) tree for stacked-control spacing; never in Standalone default density.
- **20px** — Standalone settings-card internal padding and row gaps (DESIGN_SYSTEM §8.6 / §9). Permitted only inside `Card` bodies.
- **2px** — hairline/border and focus-ring width. This is a **border width, not layout spacing**, and is always token-derived (`colorBorderSecondary`, `colorPrimary`) — never used as a margin/padding value.

Non-spacing metrics that are fixed by contract (not part of the scale): Side Panel width 400px · Side Panel header 52px · composer toolbar 44px · composer input min-height 60px · status bar 28px · Standalone Sider 240px expanded / 72px collapsed · Standalone top bar 56px · right drawer 320px · chat-history bottom sheet ≤ ~70% of panel height · options content max-width 1200px · minimum Standalone viewport 1024px.

**Hard rule.** No component invents a spacing value outside this set. AntD `sizeUnit`/`sizeStep` in `getAntdConfig()` must be consistent with it.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px Standalone / **13px Side Panel (compact)** | 400 | 1.5 |
| Label | 12px | 400 | 1.5 |
| Heading | 16px | 600 | 1.3 |
| Display | 20px | 600 | 1.3 |

- Exactly **two weights**: 400 (regular) and 600 (semibold). Weight carries hierarchy; no third weight is introduced.
- Body line-height **1.5**; heading line-height **1.3** (DESIGN_SYSTEM §5).
- **12px is the floor.** Nothing renders below 12px — including the command palette's category label (the prototype's 11px value is a defect) and status-bar captions.
- Per-surface base size is fixed by surface, not by user setting: Side Panel base 13px (compact), Standalone base 14px (default). Font-size preference is an Options concern (OPT-01, Phase 15).
- Captions and tertiary text use `colorTextTertiary`, never a lighter weight or a smaller size.
- Mono (`JetBrains Mono`) is reserved for code blocks, macros, model IDs, operation IDs and storage keys.

## Color

Source: `DESIGN_SYSTEM.md` §6.2 seed tokens. **Token-first, golden rule:** every colour, radius and elevation is an AntD v6 design token. Hard-coded hex in a component is a defect (the prototype's `#52c41a`, `#ff4d4f`, `#999`, `#e6f4ff` must all be replaced with `theme.useToken()` reads).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FCFCFD` light / `#0E1117` dark (`colorBgBase`) | Page and app background; Standalone `Layout` background; Side Panel canvas behind the conversation |
| Secondary (30%) | `#FFFFFF` light / `#161A22` dark (`colorBgContainer`) | Side Panel header bar; Standalone Sider surface and top bar; composer input; cards; onboarding modal body |
| Accent (10%) | `#3B82F6` light / `#5B9BFF` dark (`colorPrimary`) | Reserved-for list below — nothing else |
| Destructive | `#EF4444` light / `#F87171` dark (`colorError`) | Destructive actions, error text and error icons only |

**Accent reserved for — explicit, closed list:**

1. Primary buttons (`Continue`, `Connect Provider`, `Finish setup`, `Retry`) and their hover/active states.
2. The 2px focus ring on every interactive element (`colorPrimary`).
3. Standalone Sider **active item**: `colorPrimaryBg` pill background + `colorPrimary` icon/text (fill **and** weight carry the state — never colour alone).
4. Command palette selected row background (`colorPrimaryBg`).
5. Inline text links (`Set up`, `Configure`, `Retry`, `Back`, `Skip`).
6. The "N" app mark gradient and the optional two-tone wordmark lockup ("Pilot").
7. Composer send button when the draft is non-empty — **Phase 1 renders it disabled**, so this accent never appears in Phase 1.
8. Active `Segmented` selection for the theme mode control (Phase 15, when mounted).

**Accent is never used for:** body or heading text, borders/dividers, card or page backgrounds, the Side Panel header surface, status/health dots, or the Sider's inactive items.

**Semantic colours — usage limits:**

| Token | Light / Dark | Permitted in Phase 1 |
|---|---|---|
| `colorSuccess` | `#10B981` / `#34D399` | Onboarding validation success indicator. **Never** used as a "healthy provider" dot — Phase 1 has no provider runtime |
| `colorWarning` | `#F59E0B` / `#FBBF24` | The `DeferredNotice` marker only (Tag border/text). Not used for generic caution |
| `colorError` | `#EF4444` / `#F87171` | Handoff failure, onboarding validation failure, `ErrorBoundary` result, destructive action |
| `colorInfo` | `#3B82F6` / `#5B9BFF` | Tracks primary; informational `Alert` only |

**Status/health dots.** DESIGN_SYSTEM §8.1e pairs a provider name with a green/red dot. Phase 1 has **no** provider runtime, so the status bar renders a **neutral** dot (`colorTextTertiary`) plus a text caption. A green dot would assert health that does not exist — forbidden. Colour is never the only signal (§12).

**Theme packs.** Default · Liquid Glass · Claude Warm are declared pack-ready but only **Default** is reachable in Phase 1 (APPR-06 is Phase 15). Pack overlays merge on the seed: Default `{}`, Liquid Glass `{ colorBgContainer: 'rgba(255,255,255,0.68)' }` + `backdrop-filter` CSS layer, Claude Warm `{ colorBgBase: '#FAF7F2' }`. `.planning/design/references/themes/stylesheet.css` is an **aesthetic reference for the Claude Warm pack only** — it is Tailwind/shadcn-variable syntax and must be **translated to AntD tokens**, never imported, copied or referenced at runtime.

**Contrast.** WCAG AA minimum (4.5:1 text, 3:1 large text and UI) for every appearance reachable in Phase 1. Because only the Default pack is reachable, Phase 1 must verify AA in Default × Light and Default × Dark.

**What is live in the Standalone shell in Phase 1:**

- Sider navigation between the page shells is live (it is pure shell routing). Arrow-key reachable (§17.6).
- Sider collapse/expand is live; collapsed state persists per user in `chrome.storage.sync`.
- The **global search field renders `disabled`** with `data-np-backing="deferred"` + tooltip (search is Phase 8/15). **Its `⌘K` hint is omitted in Phase 1** — ⌘K is bound to the command palette (FLOW-8/FLOW-10/SP-09/SA-09), and showing `⌘K` on a search field would mislabel the binding.
- The `⋮ More` menu is preserved presentation; if mounted it must be `data-np-backing="deferred"` and its items disabled. Omitting it entirely is also acceptable.
- Page shells (`ChatPage`, `AgentPage`, `NotesPage`, `OptionsPage`) render per `## Fixture-Backed & Deferred Marking Convention`.

**Options routing.** The Options workspace renders **inside the Standalone shell** (§8.6) at `standalone.html?page=options` (§5.4 page navigation). The prototype's separate `options.html` entrypoint and its `options_ui`/`options_page` manifest keys are not canonical (§5.1 lists no options entrypoint) and are REMOVEd via the migration inventory. No surface-to-surface import, no `chrome.tabs.create` from a page component.

### Toast / notification configuration (§17.4, required in Phase 1)

- `message.config({ maxCount: 3, duration: 5 })` — at most 3 visible toasts, 5 s.
- Errors that require acknowledgement use `notification.error({ duration: 0 })` — they persist until dismissed.
- All toast/notification calls go through `App.useApp()`. Static `message.*` / `notification.*` imports are forbidden.

## Fixture-Backed & Deferred Marking Convention

`01-CONTEXT.md` assigns the concrete convention for "clearly mark fixture-backed or deferred functionality" to the researcher's discretion. It must be **consistent, greppable, and must not imply production readiness**. Three coordinated mechanisms, no more:

### 1. Typed marker (code)

A single shared presentation element, `DeferredNotice`, lives in the established shared-presentation home `src/components/common/` (the path already enforced as shared by `tests/isolation/cross-entrypoint-imports.test.ts`; both surfaces may import it, no surface imports the other).

```ts
// src/components/common/DeferredNotice.tsx
export type Phase1Backing = 'fixture' | 'deferred';
```

One file, one type, one component. Do not create a parallel marker module, a second badge component, or per-feature marker variants.

### 2. DOM marker (greppable + testable)

Every region whose behaviour is not production-live carries `data-np-backing="fixture"` or `data-np-backing="deferred"` on its **outermost element**.

- `grep -rn 'data-np-backing' src/` must return exactly the regions the phase intends to mark — it is the single audit surface for this rule.
- Component tests assert **presence** on marked regions and **absence** on live regions (a false marker is as much a defect as a missing one).
- The value is a literal from `Phase1Backing`; no ad-hoc strings.

### 3. Visible presentation

`DeferredNotice` renders one of two AntD elements, both `colorWarning`-toned and both visible **without hover**:

| Variant | Element | When |
|---|---|---|
| Inline | `Tag`, placed immediately adjacent to the affected control (never floating elsewhere) | A single control or row is inert — e.g. a disabled composer action, a disabled search field |
| Block | `Alert` (`type="warning"`, `showIcon`) at the top of the affected region | A whole page/panel is inert — e.g. a page shell, the onboarding validation step |

Every instance carries an `aria-label` holding the **full sentence**, and a `Tooltip` may add detail — but the marker is never tooltip-only.

**Marker copy** (added to `src/core/i18n/strings.ts` under a `deferred` namespace; canonical Appendix B strings are untouched):

| Key | Copy |
|---|---|
| `deferred.tag` | `Not available yet` |
| `deferred.fixtureTag` | `Preview data` |
| `deferred.reasonDeferred` | `This arrives in a later release.` |
| `deferred.reasonFixture` | `This preview does not contact a provider.` |

### Hard rules

1. **No present-but-inert control may appear enabled and functional.** It is either `disabled` + marked, or not rendered at all.
2. **Absent elements need no marker.** Absence makes no claim, so an omitted account block or an omitted Add-ons group is not marked.
3. **No fabricated signal.** No green health dot, no fake provider name, no fake model list, no simulated stream, no timer-driven success, no fixture value presented as user data.
4. **No fixture data reaches a persistent store** — not `chrome.storage` (local/sync/managed/session), not IndexedDB, not `localStorage`/`sessionStorage`, not the URL, not `BroadcastBus`, not `RuntimeEnvelope`, not logs, diagnostics, exports, snapshots or screenshot fixtures. (Extends D-08 and D-14 to all fixture content.)
5. **Markers are removed, not weakened,** when a later phase makes the behaviour live. A stale marker is a defect.
6. The marker is **not** a substitute for the shell's real states: a live control still needs its own loading/error/disabled treatment.

## Onboarding Interaction Shell

Flow 9 / SA-08 / FLOW-9. Fixture-backed per D-05; one shared presentation + flow controller for both surfaces per D-06.

### Structure

- **One shared module** (e.g. `src/components/onboarding/OnboardingFlow.tsx`) + typed application ports. Both surfaces import it; no surface-to-surface imports. The shared module **calls no Chrome API** — each surface supplies navigation/lifecycle adapters through typed props/ports.
- **No automatic surface opening.** Never open the Side Panel or a Standalone tab on install. On the first authorised opening of either surface, read non-secret onboarding state; if UI completion is false/unknown/missing/schema-incompatible, present onboarding **in the surface the user opened**. Never redirect Standalone → Side Panel.
- **One attempt at a time.** The first surface to start onboarding is active; the second must not run a competing flow. Completion in one surface updates the other from the non-secret completion event; cancellation leaves an explicit incomplete state.
- **No separate state machines.** Side Panel and Standalone share steps, state machine, validation result types and copy. Only the canvas differs.

### Steps (4, per Flow 9)

| Step | Title | Contract |
|---|---|---|
| 1 | `Meet NowPilot` | Persona card placeholder (RICH-R-03 ships in Phase 15). `data-np-backing="fixture"` — the card is a preview, not the persona runtime |
| 2 | `Pick a provider` | `Select` over exactly the four canonical provider IDs `'openai' \| 'anthropic' \| 'gemini' \| 'ollama'`. The prototype's `'claude'` id is a defect and must become `'anthropic'`. Persists non-secret metadata only |
| 3 | `Enter your API key` | `Input.Password` with eye toggle (`EyeOutlined`/`EyeInvisibleOutlined`). **Component memory only.** `data-np-backing="fixture"` |
| 4 | `Validate connection` | Fixture-backed validation with the state matrix below. `data-np-backing="fixture"` + block `DeferredNotice` carrying `deferred.reasonFixture` |

A `Step N of 4` caption is always visible. Step 4 is the only step that may auto-advance, and only on a validated fixture success.

### Validation state matrix (deterministic fixtures, D-05)

| Fixture | Typed result | UI |
|---|---|---|
| Success | `{ ok: true }` | `Connected` (canonical) + `Finish setup` primary CTA |
| Invalid credential | `PROVIDER_AUTH` | `Connection failed: [error]` + `[Retry]` + edit-key path |
| Provider unavailable | `PROVIDER_5XX` | same error treatment, typed code differs |
| Network unavailable | `NETWORK` | same error treatment, typed code differs |
| Cancelled validation | no error code | Returns to the idle state; **no** error, **no** success claim |
| Unexpected failure | `PROVIDER_CHECK_FAILED` | same error treatment |

All codes are canonical (Appendix C.2 / §21.6). Phase 1 **does not invent** a new error identifier. The *fixture* disclosure is carried by the `DeferredNotice` copy, not by the error code. No `testProviderConnection`, no provider endpoint, no provider SDK, no generated backend, no MCP server is ever contacted.

### Side Panel vs Standalone presentation

| | Side Panel | Standalone |
|---|---|---|
| Canvas | Compact, one primary step at a time, no navigation rail | Same steps on the larger canvas inside the Standalone shell |
| Exit affordance | `Skip` + **`Switch to Full setup`** (allowed) | `Skip` + back to the shell |
| Width | Fits 400 px without horizontal scroll | Centred, bounded measure |
| Copy / state machine / result types | Identical | Identical |

### Key handling (D-08 — non-negotiable)

- The key value exists **only** in component memory. It never reaches `np_store`, Zustand persistence, `chrome.storage.*`, `localStorage`/`sessionStorage`, IndexedDB, `BroadcastBus`, `MessageBus`, `RuntimeEnvelope`, background messages, diagnostics, logs, analytics, exports, snapshots, screenshot fixtures, URLs or palette state.
- Cleared on completion, cancellation, close, unmount, reload, and any terminal validation state where retention is unnecessary.
- Masked input; **no value echo** in errors, toasts, tooltips, `aria-label`s or test output. Tests use synthetic sentinel values only and assert the sentinel is absent from storage, serialised state, messages, logs and exported diagnostics.
- The eye toggle reveals the field visually only; the value never leaves the component.

### Keyboard & focus

- Modal traps focus; focus lands on the step's first control on each step change; step changes are announced.
- **Escape does not dismiss** the onboarding modal (`closable={false}`, mask not closable) — the user must complete it or choose Skip explicitly. This is deliberate: onboarding is the only path to a usable configuration.
- `Skip` and `Finish setup` are separate callbacks; the modal persists nothing itself.
- After completion, focus moves to the composer (per §12's Onboarding row: `Connected` → focus composer).

### Legacy plaintext credential cleanup (D-07)

Runs on Phase-1 startup, idempotent, redacted. The only user-visible output is the neutral notice — `Provider credentials must be configured again after secure credential storage is available.` — rendered once, dismissible, and **never** revealing whether a value was found or any part of a deleted value.

## Command Palette Contract

Flow 10 / FLOW-8 / SP-09 / SA-09.

- **Surface:** AntD `Modal`, `width={560}`, `centered`, `footer={null}`, `destroyOnHidden`.
- **Search:** `Input` with `autoFocus` and placeholder `Search commands…`. Query state is transient and never persisted.
- **Results:** AntD `List`. Each row = label (`Typography.Text strong`) + description (12px, `colorTextSecondary`) + category label (12px, `colorTextTertiary`). Selected row background `colorPrimaryBg` — read from `theme.useToken()`, never a CSS-variable fallback string.

- The palette is registered on **both** surfaces. On Standalone, `Open Standalone view` resolves to the idempotent focus-existing-tab path (D-09).

## Theme Contract

APPR-03 / APPR-04 / APPR-05 / SP-08. Carried forward from D-15 with no open questions.

- **Single source of truth:** `chrome.storage.sync.np_theme` with values `'auto' | 'light' | 'dark'`. Default `auto`. **No** `themeMode` field on `UserPreferences` — that would create a second source.
- **Propagation:** `chrome.storage.onChanged` (sync area) propagates to **both** surfaces immediately. No reload, no per-surface copy, no polling.
- **Application:** on change, each surface re-derives `getAntdConfig({ mode, pack, compact })`. The switch is real-time through AntD v6 pure CSS variables — **no remount, no `.dark` class manipulation**.
- **Density is fixed per surface and not user-configurable in v0.2:** Side Panel `compact: true`, Standalone `compact: false`. Appearance controls colour scheme only; no density toggle is rendered anywhere.
- **Phase 1 UI surface for theme = the `Toggle theme` palette command only.** It cycles Auto → Light → Dark and writes `np_theme`.
  - The Side Panel header carries **no** theme control — §8.1a allows exactly two trailing icons.
  - The Phase 1 Options shell ships **no** Appearance section (APPR-01/APPR-02 are Phase 15) and **no** pack selector (APPR-06 is Phase 15).
  - `ThemeToggle` (the `Segmented` mode control) is preserved as an **unmounted, typed component** for Phase 15 — the same treatment D-12 gives `MirrorBanner`. It keeps deterministic fixtures for visual/a11y testing and must not depend on Chrome APIs beyond the theme store.
- **Pack-ready, not pack-shipping.** `getAntdConfig` accepts and merges `pack`; Phase 1 always resolves `pack: 'default'` and never renders a pack selector.
- **Local-first on write failure:** if the `sync` write fails, the in-memory mode is **not** rolled back and an actionable toast offers a re-try. A failed sync never silently reverts the visible theme.
- **Token discipline:** no component hard-codes a colour, radius or elevation. Everything reads from `theme.useToken()` / `getAntdConfig()`.

## Handoff Interaction Contract

FLOW-11 / SP-02 / SA-10 / D-13.

### Trigger and states

| State | UI |
|---|---|
| Idle | `Switch to Full chat` in the Side Panel header is enabled |
| Pending | Caption `Opening workspace in standalone view...`; success is **not** claimed until a validated acknowledgement arrives |
| Complete | Non-blocking success toast `Workspace opened in standalone view.`; the Side Panel **remains writable** |
| Failed / timeout | `Failed to open Standalone view` + `[Retry]`; typed `WORKSPACE_HANDOFF_FAILED` or `STANDALONE_OPEN_FAILED`; Side Panel stays writable; the local composer draft is preserved |

### Payload boundaries

- **URL carries only** the minimum non-secret bootstrap identifiers: `workspaceId`, `conversationId` (when available), target route/page, handoff request ID, handoff schema version.
- **URL never carries:** composer draft, message content, page content, note content, attachments, credentials/keys/tokens, tool or MCP payloads, memory content, the complete `WorkspaceState`, hidden or diagnostic state.
- **`BroadcastBus` projection only:** `workspaceId`, `conversationId` (when available), source surface, target surface, active route/view, **composer draft**, request/correlation ID, schema version. The composer draft travels through the validated ephemeral handoff but never through URL parameters or persistent storage.
- Unknown / malformed / oversized / unsupported-version / unauthorised parameters fail through the canonical typed error path.

### Phase 1 prohibitions (D-12, D-14)

- **No `MirrorBanner`.** Do not mount it merely because Standalone opened; do not display it after every open; do not claim writer demotion occurred. Preserve it as an unmounted typed component with deterministic fixtures.
- **No `STR.workspace.mirroringNotice` / `STR.workspace.electionFailed`.** Those are Phase-2 states.
- **No `WorkspaceState` persistence** in Phase 1 — not `chrome.storage.local`, not `sync`, not IndexedDB, not `localStorage`/`sessionStorage`, and no temporary Phase-1 key for Phase 2 to remove.
- **No fabricated election, epoch, writer identity, persistence acknowledgement, demotion or mirroring success.**
- **No duplicate Standalone tabs** — dedupe by scanning existing Standalone tabs in the current window before creating. A repeated request with the same ID must not create a second tab or apply the handoff twice.

## Accessibility & Motion

### Accessibility (§17.6, DESIGN_SYSTEM §12)

- **Contrast:** WCAG AA (4.5:1 text, 3:1 large text / UI) in every appearance reachable in Phase 1 (Default pack × Light and Dark).
- **Focus:** visible 2px `colorPrimary` ring on all interactive elements; focus is never removed without an equivalent replacement indicator.
- **Icon-only controls require `aria-label` + tooltip.** Phase 1 mandatory set: Side Panel header Options, Side Panel header Switch to Full chat, composer Attach, composer Chat history, composer New chat, status-bar Help, status-bar Feedback, Sider collapse chevron, Sider collapsed items, `⋮ More`.
- **Overlays:** command palette and onboarding modal trap focus, restore focus on close, and announce open/close. Escape closes the palette; Escape does **not** dismiss the onboarding modal (explicit Skip required). Scrim click-to-close is never the only affordance.
- **Colour is never the only signal.** Sider active state uses fill + weight; unresolved/disabled states pair colour with a label or icon; the status-bar dot always has a text caption.
- **Hit targets:** ≥ 32px in the compact (Side Panel) tree, ≥ 36px in the Standalone tree. Composer and status-bar icons are spaced so touch targets do not overlap at 400 px.
- **Keyboard:** Tab / Enter / Escape / ⌘K across major flows; Standalone `Menu` items are arrow-key reachable.
- **Live regions:** handoff state changes announce politely (`role="status"`, `aria-live="polite"`). The message list's `aria-live="polite"` contract lands with streaming in Phase 15.
- **Reduced motion:** `prefers-reduced-motion` drops slides and scales, keeps opacity.
- **English only in v0.2**; all strings resolve through `t('key')` in `src/core/i18n/strings.ts` so i18n is a later data change, not a refactor. `ConfigProvider locale={enUS}`.

### Motion (DESIGN_SYSTEM §11)

`motion` v12 only — `framer-motion` is a banned package.

| Interaction | Motion |
|---|---|
| Panel / page transition | 150–200 ms ease-out fade + 8 px slide |
| Modal (palette, onboarding) | 160 ms fade + scale from 0.98 |
| Sider collapse | 150–200 ms width ease-out; content reflows |
| Card hover lift | 120 ms `E1` → `E2` |
| Chip / button press | 80 ms scale 0.98 |
| Theme switch | **Instant** (CSS variables) — never animated |
| Mascot moments | ≤ 400 ms; greet / success / error / empty only |

No motion during streaming (Phase 15). No extra typewriter effect anywhere (§12.6).
