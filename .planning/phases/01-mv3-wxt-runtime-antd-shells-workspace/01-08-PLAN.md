<objective>
Move the global keyboard binding into `KeymapRegistry`, repair the matcher so the chord works on macOS, and land the Phase-1 command set on both surfaces.

Purpose: FLOW-8 names `KeymapRegistry` as the canonical binding owner, but the registry cannot match the chord on macOS at all — it compares a literal `Meta` token that `Cmd` never sets — and it is currently unreferenced with no test. Removing the prototype's per-surface listeners without repairing the matcher would turn a working prototype into a palette that never opens on the primary development platform. This plan fixes the matcher first, ships its suite, then moves the binding and realigns the command set to D-09/D-10, and finally makes `Focus Side Panel` respect the user-gesture requirement the Chrome side-panel API enforces.
Output: a repaired, tested `KeymapRegistry`; the palette bound through it on both surfaces; the four shell/navigation commands plus a dev-gated reload; a token-clean, 12 px-floor palette; and a gesture-correct `Focus Side Panel`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| global keyboard → command execution | The registry turns a keystroke into a command action; a mis-matched chord or a second listener changes what the user's input does. |
| command registry → destructive action | The reload command restarts the extension; reachability in production would be a destructive action one keystroke away. |
| user gesture → `chrome.sidePanel.open()` | The API is gesture-gated; an awaited call before it silently loses the gesture and the action fails intermittently. |
