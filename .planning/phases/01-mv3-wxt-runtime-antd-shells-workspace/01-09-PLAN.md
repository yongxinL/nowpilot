<objective>
Ship the complete onboarding interaction shell behind typed ports, fixture-backed validation, and one shared surface-independent flow controller, with a single typed completion record.

Purpose: SA-08 and FLOW-9 require a first-run onboarding entry point and the four-step persona → provider → key → validate flow. D-05 requires it fixture-backed behind typed ports that Phases 2 and 3 replace without redesigning a component; D-06 requires one shared presentation and flow controller working on whichever surface the user opens first, with no automatic surface opening; D-08 requires the key to exist only in component memory. The prototype does the opposite — it writes the key into persisted state, calls a real provider connection test and keeps two onboarding flags — so this plan replaces that path rather than porting it.
Output: typed `ProviderValidationPort` / `CredentialStorePort` / `PersistedProviderConfig` / `TransientCredentialInput` / `ProviderId`, a deterministic six-case fixture adapter, the shared four-step flow mounted on both surfaces, and a single typed `OnboardingState` record with the legacy boolean migrated away.
</objective>
