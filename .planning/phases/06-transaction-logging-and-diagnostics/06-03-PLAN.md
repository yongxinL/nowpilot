2. Add oldVersion < 3 upgrade block after the oldVersion < 2 block (after line 196):

Create three new object stores with by-operationId indexes:
- transaction_log_cacheTraces: keyPath id, index by-operationId on operationId
- transaction_log_memoryTraces: keyPath id, index by-operationId on operationId  
- transaction_log_writeJournalTraces: keyPath id, index by-operationId on operationId

Add indexes to existing stores:
- transaction_log_transactions: add indexes by-operationId (operationId), by-status (status), by-severity (severity), by-timestamp (startedAt)
- transaction_log_promptTraces: add index by-operationId (operationId)
- transaction_log_toolTraces: add index by-operationId (operationId)
- transaction_log_providerTraces: add index by-operationId (operationId)

IMPORTANT: In idb v8, upgrade callback has signature upgrade(db, oldVersion, newVersion, transaction). The transaction parameter is the IDBTransaction that upgrade is running within. To add indexes to existing stores within the upgrade, use transaction.objectStore(storeName).createIndex(...). Do NOT use db.transaction() inside upgrade — that creates a separate transaction.

Update the NowPilotDB DBSchema interface to add type definitions for the 3 new stores:
- transaction_log_cacheTraces: key string, value with id, operationId, event, section?, providerId?, cacheKey?, estimatedTokenSavings?, timestamp
- transaction_log_memoryTraces: key string, value with id, operationId, phase, conversationId, factsRetrieved?, factsExtracted?, extractionAttempt?, summarized, timestamp
- transaction_log_writeJournalTraces: key string, value with id, operationId, journalId, operation, status, stepsCount, failedSteps?, recovered, timestamp

Also extend existing store value types to match product spec:
- transaction_log_transactions: add sessionId, conversationId, workspaceId, activeSurface, userTurnId, providerId, model, startedAt, endedAt, durationMs, errorCode, severity, parentOperationId, verbosity, privacyMode (all optional except required fields). Keep id, type, status as required.
- transaction_log_promptTraces: replace with operationId, promptTemplateId?, promptHash, tokenBreakdown (object), contextTier, truncated, minimalMode, cacheStats (object), source, timestamp. Keep id required.
- transaction_log_toolTraces: replace with operationId, parentOperationId?, toolName, source, dangerous, permissionDecision, inputSchema?, outputSchema?, status, errorMessage?, durationMs, timestamp. Keep id required.
- transaction_log_providerTraces: replace with operationId, attempts (ProviderAttempt[]), resolvedProviderId, resolvedModel, totalDurationMs, timestamp. Keep id required.

3. Existing v2 data is schemaless at value level — old records survive with old fields. New code reads optional fields with defaults. No destructive migration needed.

4. Ensure the v2 migration comment (lines 194-196) stays intact — the v2 block is a no-op.
