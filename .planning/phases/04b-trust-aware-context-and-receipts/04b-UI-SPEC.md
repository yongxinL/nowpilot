# Phase 4b — UI Design Contract

> Visual and interaction contract for Phase 4b (Trust-Aware Context and Receipts). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Source-of-truth artifacts: `.planning/DESIGN_SYSTEM.md` (§5–§13), `.planning/phases/01-*/01-UI-SPEC.md` (approved Phase-1 contract), `.planning/phases/03-cost-effective-ai-runtime-persona-seed/03-UI-SPEC.md` (approved Phase-3 contract), `.planning/phases/04a-pagecontentservice-knowledge-acquisition/04a-UI-SPEC.md` (approved Phase-4a contract), `.planning/phases/04b-trust-aware-context-and-receipts/04b-CONTEXT.md` (D-4b-00…D-4b-14), `.planning/PRODUCT_SPEC_v0_1.md` §18 Phase 4b + §28.3 CTX-01..06 + §8.6, `.planning/ROADMAP.md` Phase 4b, `AGENTS.md` (approved stack + banned list + R-3/R-5/R-10).

> **Scope honesty note (must be preserved by the planner):** Phase 4b is a **core-infrastructure phase that ships almost NO UI** — the trust envelope (ContextItem/TrustPolicy/classifier), the context receipt (data), and the stable-prefix snapshots are all core-side (`src/core/context/trust/**`, `@/types/harness`), with **zero model calls** in trust evaluation (D-4b-03/05). The **ONLY user-facing surface** is the new **content-trust Options section** — four per-source-type toggles (`page`, `notes`, `memory`, `tool_result`) on `OptionsPage.tsx` (D-4b-07). The context receipt is **data emitted in-memory per-turn** (D-4b-10); the Prompt Inspector is a **Phase-6** visualization over that same data (D-4b-11). There are **no chat-embedded trust controls in 4b** (deferred — Phase 7 RICH), **no quarantine toasts** (quarantine is recorded in the receipt only, D-4b-06/10), **no receipt/inspector UI**, **no trust chips/badges**, and **no readout UI** for CTX-06 counters (D-4b-14). Do not let UI polish leak into the data-only surfaces.

## Visual Hierarchy & Focal Points

### Options page — one new card, no new focal point

`OptionsPage.tsx` currently renders a flat card stack: **Account** then **Appearance** (Phase-1 layout). Phase 4b appends one settings card **after Appearance**:

```
OptionsPage (ErrorBoundary-wrapped)
├── Card "Account"               (existing, unchanged)
├── Card "Appearance"            (existing, unchanged)
└── Card "Content trust"         (NEW — Phase 4b)
    ├── helper caption (12 px, colorTextTertiary)
    ├── [hairline divider]
    ├── Pages            [Switch ON]   ← row: label (14 px, colorTextSecondary) left · Switch right
    ├── Notes            [Switch ON]
    ├── Memory           [Switch ON]
    ├── Tool results     [Switch ON]
    └── structural note (12 px, colorTextTertiary)
```

- The card is standard **settings chrome** — `colorBgContainer`, radius 12, E1, ~20 px padding, hairline row dividers (DESIGN_SYSTEM.md §8.6 settings-card recipe). It is **not** a focal point; it sits below the existing cards in the natural scroll.
- **All four switches default ON** (D-4b-07: page on = active feed; notes/memory/tool_result on-but-structural). The `page` toggle is the only one with a live data feed in 4b (D-4b-01).
- **Section placement rationale:** the DESIGN_SYSTEM §8.6 full left-menu Options shell (General/Notes/Advanced) is **not yet implemented** — the live OptionsPage is a flat card stack. The content-trust card appends to that stack now; if/when the §8.6 left-menu lands (Phase 7+), this section naturally re-groups under **Advanced → Memory** (DESIGN_SYSTEM §8.6 lists Memory under Advanced). The planner must not build the left-menu shell in 4b.
- **No new focal points anywhere else.** The chat surface, Standalone shell, and content scripts are untouched by 4b UI (the receipt is data; the classifier is silent; quarantine is receipt-recorded, never a visible chip/toast — D-4b-06/10).

### Icon-only control accessibility

No icon-only controls ship in Phase 4b. The four `Switch` rows carry **visible text labels** (`aria-label` not required; AntD `Switch` with a sibling label is announced by the label text). All controls meet the **≥ 32 px (compact) / ≥ 36 px (standalone)** touch-target rule (DESIGN_SYSTEM.md §12).

### Accessibility (inherited, binding)

- **Focus:** visible 2 px `colorPrimary` ring on each `Switch` (AntD default; DESIGN_SYSTEM.md §12).
- **Colour is never the only signal:** the Switch ON/OFF state is positionally distinct (AntD thumb position) **and** colour-distinct — never colour alone.
- **Captions:** helper + structural note render in `colorTextTertiary` at 12 px (≥ AA on `colorBgContainer`; verified by the pack contrast gate, DESIGN_SYSTEM.md §12).

## Interaction Contract — Content Trust Controls (Options)

Locked by 04b-CONTEXT D-4b-07 (per-source-type toggles, np_trust, defaults), D-4b-08 (runtime enforcement at the TrustPolicy boundary), D-4b-10/11 (receipt is data; no inspector UI), and DESIGN_SYSTEM.md §8.6 (settings cards, auto-save).

### Component & state model

- **Four `antd` `Switch` rows**, source-type order fixed: **Pages → Notes → Memory → Tool results** (matches D-4b-07's `page, notes, memory, tool_result` enumeration).
- **Persistence:** toggles write-through to a `np_trust` preference in **`chrome.storage.local`** (follows the `np_persona` / `np_addon_settings` local-area precedent — this is a **behavioral** preference, not a cosmetic sync key; D-4b-07: "exact shape = the agent's discretion", so the UI contract binds the *surface behavior*, not the storage schema).
- **Store pattern:** a thin preference store/accessor following the `AddonSettingsStore` precedent (plain zustand + `chrome.storage.local` write-through + `chrome.storage.onChanged` remove-then-add listener + `sanitizeStored` on read; never throws; `debugLog` on every failure path, Golden Rule 9). The exact store module is planner discretion (co-located with the trust core or an Options-side slice) — the contract binds: **render from store state, toggle → write-through, cross-surface sync via onChanged**.
- **Defaults:** all four **true** (page on, others on-but-structural per D-4b-07). If storage is empty/invalid → all-true fallback (safe default: no source is silently excluded; mirror `DEFAULT_PERSONA`-style fallback precedent).
- **Auto-save:** no Save button. A toggle flip persists immediately (DESIGN_SYSTEM.md §8.6 "all changes auto-saved").
- **Runtime enforcement is core-side** (D-4b-08): the Options UI **only writes the preference**; `TrustPolicy`/ContextOptimizer read it at the feed boundary (`ContextOptimizerInput.pageContext` wiring, D-4b-09). Disabled source-type → items excluded with receipt `omitReason: 'trust_disabled'` (D-4b-08). **Golden Rule 3 holds: the component never assembles prompts; it only persists a preference.**

### Surface state machine

| Surface state | Trigger | What renders | Switch behavior |
|---------------|---------|--------------|-----------------|
| hydrating | page mount, store `init()` in flight | card + all four switches render **immediately at default-true** (fast local read; no skeleton — the section is part of the existing OptionsPage which renders synchronously; AddonSettingsStore precedent starts empty then hydrates) | switches show true until hydration flips them to persisted values |
| populated | hydration complete | four labeled Switch rows + helper + structural note, values = persisted np_trust | each Switch independent; toggle → write-through + local optimistic set |
| persisted | toggle flipped | no visual change beyond the Switch state (auto-save; no "saved" indicator) | write-through; `debugLog` on failure |
| failure | write-through rejects (storage error) | **toast**: "Couldn't save your content trust settings. We'll retry on the next change." (`STR.options.trustSaveFailed`, `notification.error`, same pattern as `STR.theme.saveFailed` E5) | switch state reverts to the last persisted value (optimistic set rolled back); next toggle change retries |
| cross-surface sync | `chrome.storage.onChanged` fires (e.g. standalone ↔ side-panel… none in 4b; Options is Standalone-only — but the listener is wired for future surfaces) | state re-hydrated from the change | — |

### Invisible-by-contract (binding negative contract)

- **No quarantine toast/banner** — `colorWarning` reservation stays unused; quarantine surfaces only as receipt data (`omitReason: 'prompt_injection'`, D-4b-06/10).
- **No trust chips, lock/shield icons, or source badges** in the chat surface or elsewhere (all Phase 7 RICH / Phase 6 Inspector).
- **No receipt/inspector UI** — the receipt is in-memory per-turn data (D-4b-10/11); nothing renders it in 4b.
- **No CTX-06 readout UI** — quality counters emit via the receipt/telemetry seam only (D-4b-14).
- **No new MessageType, no background-SW involvement** (R-3) — the trust preference is a plain storage write from Options (Standalone surface only).
- **R-10:** the receipt/counters never persist raw text; the UI never displays raw context or quarantine payloads.

### Fenced out of Phase 4b (do not build)

Per-source-ID trust controls (Phase 5+), chat-embedded trust controls (Phase 7 RICH), Prompt Inspector UI (Phase 6), durable receipt storage / AITransactionLog (Phase 6), per-source-type *per-site* toggles, any trust visualization in the chat message list.
