    ```

      messages: ChatMessage[],

      send: (message: string) => Promise<void>,
      abort: () => void,
      isStreaming: boolean,

    }
    ```

    **Implementation details per RESEARCH.md Pattern 2 and CONTEXT.md D-01 through D-04, D-13 through D-16, D-33 through D-36:**

    **State:** `useState` for messages[], conversations[], activeConversationId, draft (local mirror of workspaceStore.drafts). `useRef` for conversationId. All state management follows D-03 (mutable in-place array updates).

    **send(message):**
    1. Parse slash commands via `slashCommandRegistry.parseCommand(message)`. If match, dispatch to handler and return early (don't invoke pipeline for pure-command messages).
    2. Abort existing stream if isStreaming (CHAT-08).
    3. Get or create conversationId: if no activeConversationId, generate `crypto.randomUUID()`, set as active. Per D-14: create ChatHistoryDB session with placeholder title "New Conversation" on first send (NOT on Chat mount).
    4. Append user message to messages[] and persist via `chatHistoryDB.addMessage({ id: crypto.randomUUID(), sessionId, role: 'user', content: message, timestamp: Date.now() })`.
    5. Append placeholder assistant message with `streaming: true, content: ''`.
    6. Clear draft via workspaceStore.clearDraft(sessionId) — D-36.
    7. Assemble context (D-04): call `memoryEngine.assemble(conversationId, message, tier)` → build `ContextOptimizerInput` with workspace state, memory results, preferences, tool schemas from ToolRegistry, conversation history from ChatHistoryDB. Call `contextOptimizer.optimize(input)` → get OptimizedContext.
    8. Call `useStreamingLLM.startStream(optimizedContext, preferredProviders)`.
    9. Hook into useStreamingLLM callbacks: `onDelta(text)` → update last assistant message in-place via `setMessages(prev => { ...prev[last].content += text })`. `onComplete(fullText)` → mark streaming:false, persist to ChatHistoryDB.addMessage, trigger title generation if first message.

    **Title generation (D-15):** After first assistant response completes, fire non-blocking Haiku-tier LLM call with prompt "Generate a brief title (max 7 words) for this conversation: {userMessage}". Temperature 0, max_tokens 16, timeout 3s. Use ProviderRouter with `costTier: 'haiku'`. On success: `chatHistoryDB.updateSession(conversationId, { title })` and update local conversations state. On failure/timeout: fall back to `userMessage.slice(0, 50)`. Must run in page runtime, NOT in service worker.

    **Conversation management (D-16):** On mount, load `chatHistoryDB.getAllSessions()` sorted by updatedAt desc. `switchConversation(id)` loads `chatHistoryDB.getMessagesBySession(id)`, sets activeConversationId, loads draft. `deleteConversation(id)` removes from local state + IndexedDB (delete messages by session, then delete session). `newConversation()` clears messages, sets activeConversationId to null (D-14: no DB creation until first send).

    **Drafts (D-33 through D-36):** `draft` mirrors `workspaceStore.drafts[activeConversationId]` or ''. `setDraft(text)` uses debounce (300ms via useRef timer) before writing to `workspaceStore.setDraft(conversationId, text)`. `clearDraft()` calls `workspaceStore.clearDraft(conversationId)`. On conversation switch, load draft for new conversation.

    **bubbleItems:** `useMemo` computed from messages[] mapping each message to `{ key: msg.id, role: msg.role, content: msg.content, loading: msg.streaming && !msg.content, streaming: msg.streaming }`. Stable keys throughout stream lifecycle (Pitfall 1 mitigation).

    **Error handling (CHAT-09):** Orchestrator errors surface as `error: string | null`. `error` cleared on next `send()`. Error messages distinguish provider error vs timeout vs context error for UI display.

    **Provider selector (CHAT-05):** Expose `activeProvider` and `setActiveProvider` from useWorkspace.

    **Delete support:** If `ChatHistoryDB` lacks deleteSession/deleteMessages methods, add them in this task: `deleteSession(id: string): Promise<void>` and `deleteMessagesBySession(sessionId: string): Promise<void>`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User message → useChat.send() | Untrusted text enters pipeline via ContextOptimizerInput |
| ChatHistoryDB → ChatPage | Messages read from IndexedDB trusted (written by same extension) |
| LLM response → XMarkdown | Rendered through @ant-design/x-markdown (DOMPurify-sanitized) |
| workspaceStore.drafts → Sender | Draft text comes from chrome.storage.local (trusted storage) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06 | Tampering | XMarkdown rendering | low | accept | @ant-design/x-markdown uses DOMPurify internally per RESEARCH.md. User messages rendered as plain text. |
| T-07-07 | Information Disclosure | useChat context assembly | low | mitigate | ContextOptimizerInput assembled from trusted sources (workspaceStore, MemoryEngine, ChatHistoryDB). No secrets exposed in chat UI. |
| T-07-08 | Denial of Service | Title generation LLM call | low | accept | Non-blocking, 3s timeout, graceful fallback to truncated message. No impact on chat streaming. |
