    ```
    private permissionResolver: PermissionResolver | null = null;

    setPermissionResolver(resolver: PermissionResolver): void {
      this.permissionResolver = resolver;
    }
    ```

    Define `PermissionResolver` type: `(toolName: string, toolInput: unknown, isDangerous: boolean) => Promise<'allow-once' | 'allow-always' | 'deny'>`.

    Modify `executePlannerLoop()` method — before `this.executor.execute()` call (around line 263 in the current file):
    1. Check if `this.permissionResolver` is set.
    2. If set, determine if tool is dangerous: call `this.toolRegistry.get(toolName)` → check `tool.dangerous` or `tool.category === 'dangerous'`. (Note: ToolDefinition may not have a `dangerous` field yet; if not, default to false. The hook will handle dangerous classification separately via PermissionStore.)
    3. Yield `{ type: 'waiting-permission', toolName, toolInput }` event.
    4. `await this.permissionResolver(toolName, toolInput, isDangerous)`.
    5. If result is 'deny': yield `{ type: 'tool-result', toolName, result: { success: false, error: 'Permission denied by user' } }` and `continue` the loop (skip execution).
    6. If result is 'allow-once' or 'allow-always': proceed with executor.execute() as normal.

    **CRITICAL:** Do NOT break backward compatibility. When `permissionResolver` is null (default), the pipeline MUST behave exactly as before — no waiting-permission events, no awaits. Existing tests must pass unchanged.

    **ToolRegistry access:** AgentOrchestrator constructor already receives services. If ToolRegistry is not currently injected, add it as an optional constructor parameter: `private toolRegistry?: ToolRegistry`. Check `this.toolRegistry?.get(toolName)` for dangerous classification.

    **Test file:** Create `tests/hooks/useAgent.test.ts` as a scaffold in this task (only the pipeline extension tests; useAgent hook tests added in Task 2). Mock AgentOrchestrator, verify permission resolver integration, verify backward compatibility.

    IMPORTANT: The test for 'waiting-permission event is yielded' must verify that the event appears BEFORE any tool execution, confirming the pause-point works correctly.

    **send(message):**
    1. Same conversation management as useChat (create session on first message, load history).
    2. Assemble context (same ContextOptimizerInput assembly as useChat).
    3. Set up PermissionResolver on AgentOrchestrator via `orchestrator.setPermissionResolver(async (toolName, toolInput, isDangerous) => { ... })`. Inside resolver:
       - If isDangerous (check `tool.category === 'dangerous'` from ToolRegistry) → always prompt: return `new Promise(resolve => { setPendingPermission(...); permissionResolveRef.current = resolve; })` — D-05.
       - Else: check `permissionStore.getPermission(toolName)` → if 'allow-always' return 'allow-always', if 'deny' return 'deny'. If null → prompt: return `new Promise(...)` — D-06.
    4. Initialize thoughtChainSteps with "Preparing Context" step (status: loading).
    5. Call `useStreamingLLM.startStream(optimizedContext, preferredProviders)`.
    6. Map OrchestratorEvents to step updates:
       - `plan-created`: mark Preparing Context as success, add "Planning" Think step with expandable reasoning content (D-17).
       - `tool-called`: add tool node with tool name, status loading, blink:true (D-18, D-19).
       - `waiting-permission`: update tool node description to "Waiting for permission...", set pendingPermission state (D-05). The stream pauses here (resolver is awaiting the Promise).
       - `tool-result`: update tool node status to success/error based on result, add duration, expandable result summary. If permission denied, show deny badge (D-18).
       - `text-delta`: add/update "Generating Response" step with streaming content.
       - `text-complete`: mark all steps as success, finalize.
       - `error`: add error Think item with message. If recoverable (not context-error), show "Retry" action icon (D-20).
       - `context-degraded`: add info step about degradation.
       - `context-error`: add fatal error step with actionable guidance.

    **resolvePermission(decision):**
    - If 'allow-always': `permissionStore.setPermission(pendingPermission.toolName, 'allow-always')` — D-06.
    - Set pendingPermission to null.
    - Resolve the stored Promise with the decision (unblocks the AgentOrchestrator resolver → stream resumes) — D-07.

    **Pitfall 3 mitigation:** Store `pendingPermission` and `permissionResolveRef` in hook state/refs. In useEffect cleanup: if pendingPermission is set, resolve with 'deny' to prevent zombie promises. The PermissionDialog component (Task 3) is rendered by AgentPage (not the hook) to benefit from React lifecycle.

    **Conversation management:** Same pattern as useChat — ChatHistoryDB for sessions/messages, workspaceStore for drafts. Agent conversations share the same ChatHistoryDB but may store additional metadata for steps (optional).

    **Tool schemas for context:** Call `toolRegistry.list()` to get available tool schemas, pass as `toolSchemas` in ContextOptimizerInput. This enables the planner to know which tools are available (AGNT-02).

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-09 | Spoofing | PermissionResolver | high | mitigate | Dangerous tools (category:'dangerous') ALWAYS prompt regardless of stored permission (AGNT-05). Permission decisions tied to toolName — no wildcard matching. |
| T-07-10 | Elevation of Privilege | PermissionStore | medium | mitigate | Allow Always decisions stored per-tool, not global. User can clear via Options section (future). No auto-elevation path. |
| T-07-11 | Denial of Service | PermissionDialog | low | accept | Pending permission blocks one tool call only. User can deny to continue. Stream continues for other tools in multi-tool plan. |
| T-07-12 | Information Disclosure | ToolCard | low | accept | Tool input/output displayed as truncated JSON. No secrets in tool schemas (API keys managed by ProviderStore). |
