# Requirements: RICH Design Improvements

**Defined:** 2026-07-18
**Source:** Audit against [Ant Design X RICH Design Paradigm](https://x.ant.design/docs/spec/introduce)
**Scope:** Enhance NowPilot v0.1 to meet RICH design best practices across Role, Intention, Conversation, and Hybrid UI pillars.

---

## R — Role 角色设计

AI 扮演了某种身份角色，来匹配用户的意图，保障与用户的互动是顺畅、符合预期的。

### [R-01] AI Personality Profile — 角色人格配置

- [ ] **RICH-R-01**: Define an AI persona profile in `src/core/ai/persona/PersonaProfile.ts` with configurable identity attributes:
  - **Identity**: Name, tagline (e.g., "NowPilot — Your ServiceNow support co-pilot"), domain expertise description
  - **Personality core**: Core values (privacy-first, helpful, precise, humble), behavioral drivers (prefers asking clarifying questions over guessing, cites sources when available)
  - **Language style**: Tone (professional yet warm), vocabulary level (technical but accessible to support engineers), response style preferences (concise by default, offers detail on request)
  - **Emotional repertoire**: Can express empathy for frustrated users, encouragement for progress, curiosity for exploration
- [ ] **RICH-R-02**: Inject persona profile into system prompts via `PersonaInjector` so every AI response reflects the defined personality
- [ ] **RICH-R-03**: Persona profile surfaced in onboarding Step 1 as "Meet NowPilot" — a brief character introduction card (not just technical config)
- [ ] **RICH-R-04**: Persona editor in Options → Persona section allowing users to customize AI name, tone, and response brevity
- [ ] **RICH-R-05**: Developer persona ID stored in `UserMemoryStore` — persona persists across sessions and surfaces

### [R-02] Emotional Awareness — 人情味

- [ ] **RICH-R-06**: Sentiment-aware response framing — when user expresses frustration (e.g., "this isn't working", "I've tried everything"), the AI acknowledges the feeling before providing solutions (e.g., "That sounds frustrating. Let me take a different approach...")
- [ ] **RICH-R-07**: Progress celebration — when user achieves a milestone quality (e.g., "nice, that worked"), the AI provides positive reinforcement ("Glad that worked! Anything else you'd like to tackle?")
- [ ] **RICH-R-08**: Humble error recovery — when the AI makes a mistake or the user corrects it, the AI acknowledges gracefully with a brief apology and alternative approach, not defensive framing

### [R-03] Role Consistency Across Modes — 多模式角色一致性

- [ ] **RICH-R-09**: Chat mode and Agent mode share the same persona profile — no personality discontinuity when switching between modes
- [ ] **RICH-R-10**: Persona-consistent system prompt template for each AI pipeline stage (Planner, Executor, Renderer) — each stage's system prompt references the persona profile for tone consistency
- [ ] **RICH-R-11**: Avatar and visual identity remain consistent across all surfaces (sidepanel, standalone, options) and all interaction modes (chat, agent, notes Q&A)

## I — Intention 意图设计

AI 能够听懂并理解用户的意图，协助用户自动完成方案计划和步骤拆解，进而推动执行。

### [I-01] Welcome Cards & Capability Discovery — 唤醒｜欢迎提示

- [ ] **RICH-I-01**: Replace static empty-state text with interactive Welcome Card grid on first visit to an empty chat:
  - 4-6 example cards illustrating key capabilities (e.g., "Summarize this page", "Draft a response", "Research an incident", "Explain this code", "Write a script", "Analyze sentiment")
  - Each card has an icon, title, and one-line description
  - Clicking a card populates the Sender with the corresponding prompt template
- [ ] **RICH-I-02**: Welcome cards are dynamically sorted — most-used prompts first, then contextually relevant (based on current page URL/hostname)
- [ ] **RICH-I-03**: Welcome cards respect persona profile — if user has customized their persona, greeting reflects it (e.g., "Hi George — I'm NowPilot, ready to help with your ServiceNow cases")
- [ ] **RICH-I-04**: Welcome card grid has a dismiss/don't-show-again toggle — power users who prefer the blank canvas can hide it permanently

### [I-02] Context-Aware Intention Suggestions — 上下文感知意图推荐

- [ ] **RICH-I-05**: When a page is pinned (sidepanel auto-pin), surface 2-3 context-aware quick actions above the Sender:
  - ServiceNow incident page: "Summarize this case", "Draft a work note", "Check similar cases"
  - ServiceNow knowledge base: "Summarize this article", "Check for updates"
  - Generic page: "Summarize this page", "Extract key points"
- [ ] **RICH-I-06**: Quick actions appear as horizontal chip/pill strip between the last message and the Sender — not invasive, scrollable if many
- [ ] **RICH-I-07**: Quick action chips have a "More" expander for additional suggestions
- [ ] **RICH-I-08**: Quick action suggestions are generated by a lightweight intent classifier (simple page-type heuristic: URL pattern matching → suggestion mapping), no LLM call required

### [I-03] Intention Type Browsing — 明确意图类型

- [ ] **RICH-I-09**: Expose prompt templates as a browsable catalog accessible from the empty state and from the Sender toolbar:
  - Categorized view: "Writing", "Analysis", "Research", "Coding", "Support"
  - Each category shows template count and example templates
  - Selecting a template populates the Sender
- [ ] **RICH-I-10**: Sender toolbar adds a "Templates" icon button that opens a popover/dropdown of prompt categories and recent templates
- [ ] **RICH-I-11**: Recently-used templates shown first in the template browser

### [I-04] Progressive Capability Education — 渐进式能力引导

- [ ] **RICH-I-12**: After the user sends their first 3 messages, show a subtle educational tip: "Tip: Type `/` to see available commands like `/summarize`, `/rewrite`, `/translate`"
- [ ] **RICH-I-13**: On the user's 5th chat session, show a one-time hint about Agent mode: "Try Agent mode for complex multi-step tasks — it can research, plan, and execute across tools"
- [ ] **RICH-I-14**: All educational tips have a "Got it" dismiss button and are tracked in memory to avoid repeat showing

## C — Conversation 会话设计

用户的模糊意图通过会话来逐步与 AI 对焦、拆解，用户的指令也结合其中。

### [C-01] AI-Initiated Clarification — 追问｜AI 主动追问

- [ ] **RICH-C-01**: When user intent is ambiguous (detected via prompt classifier or missing required context), the AI should ask a clarifying question before executing, rather than guessing:
  - The response starts with a focused question ("Which incident are you referring to?") followed by a brief set of concrete options as chips/pills the user can click
  - Clarification chips inject their text into the Sender, allowing one-click response
- [ ] **RICH-C-02**: Clarification detection rules:
  - Missing required target (e.g., "summarize this" with no pinned page and no quoted message)
  - Ambiguous reference (e.g., "update the case" with multiple pinned tabs)
  - Under-specified request (e.g., "write a script" with no language or purpose)
- [ ] **RICH-C-03**: At most 2 clarification rounds before the AI makes a best-effort attempt with a caveat disclaimer
- [ ] **RICH-C-04**: Clarification chips render as interactive `Button` components (not markdown) in the Bubble, with 2-4 options maximum

### [C-02] Proactive Next-Step Hints — 提示｜下一步引导

- [ ] **RICH-C-05**: After completing a response, the AI appends 1-3 contextual follow-up suggestions as tappable chips:
  - Example: after a summary → ["Expand on section 3", "Translate to Chinese", "Save as note"]
  - Example: after a code generation → ["Explain line by line", "Add error handling", "Run this script"]
- [ ] **RICH-C-06**: Follow-up chips are clearly separated from the main response with a visual divider (thin rule + "Follow up" label)
- [ ] **RICH-C-07**: Tapping a follow-up chip sends it as the next user message (same behavior as quote follow-up prompts)
- [ ] **RICH-C-08**: Follow-up suggestions are generated by a lightweight suggestion model (haiku tier, non-blocking, optional — degrades gracefully to no suggestions on timeout)

### [C-03] Conversation Closure — 结束｜会话收尾

- [ ] **RICH-C-09**: After the final response in a conversation (detected when user hasn't sent a new message after 5s of stream completion), show a subtle closure indicator:
  - "Did this help?" with 👍/👎 feedback buttons
  - "Anything else?" as a secondary prompt
- [ ] **RICH-C-10**: Feedback (👍/👎) is logged anonymously to MemoryStore for quality improvement — no user-identifiable data
- [ ] **RICH-C-11**: "Save this conversation" quick action appears in the closure zone when a conversation has ≥3 exchanges

### [C-04] Structured Confirmation in Chat Mode — 确认｜操作确认

- [ ] **RICH-C-12**: For chat-mode actions that have side effects (tool calls, external lookups beyond the page), show an inline confirmation chip before executing:
  - "I'll search the web for that. [Proceed] [Cancel]"
  - Permission model aligns with Agent-mode PermissionDialog but uses inline bubbles instead of modals
- [ ] **RICH-C-13**: Read-only actions (page summarization, text rewriting, translation) execute immediately without confirmation

### [C-05] Personalized Greeting — 开始｜个性化开场

- [ ] **RICH-C-14**: Empty-state greeting uses the user's name when available (from Google profile or user settings) and time-of-day context:
  - Morning: "Good morning, George. How can I help with your cases today?"
  - Afternoon/Evening: "Hi George. What would you like to work on?"
- [ ] **RICH-C-15**: Greeting includes 1-2 contextual elements when applicable: current page title, recent conversation summary, or greeting-personalization from user memory

## H — Hybrid UI 混合界面设计

用户的执行动作和机器的结果输出与反馈承载在融合了多种交互方式的界面当中。

### [H-01] AI Branding & Identity — 唤醒｜AI 标识

- [ ] **RICH-H-01**: Add a branded AI header bar above the chat message list (dismissible):
  - Shows AI name ("NowPilot"), avatar (bunny icon), and a one-line tagline
  - Appears on first visit and can be dismissed with a close button
  - Reappears when starting a new conversation (configurable via persona settings)
- [ ] **RICH-H-02**: AI responses have a subtle brand indicator — a small "NowPilot" label or badge next to the assistant avatar in Bubble
- [ ] **RICH-H-03**: In Agent mode, the ThoughtChain header shows "NowPilot is working..." rather than generic "Agent is processing..."

### [H-02] Result Application Actions — 反馈｜结果应用

- [ ] **RICH-H-04**: AI-generated code blocks (detected via markdown code fences) render with inline action buttons:
  - "Copy code" (clipboard icon) — already partially exists via copy action
  - "Insert into page" — when a ServiceNow page is active with a textarea/editor, insert at cursor
  - "Save as macro" — save the code as a reusable macro for future use
- [ ] **RICH-H-05**: AI-generated structured outputs (tables, JSON, lists) render with an "Export as CSV" or "Copy as table" action button
- [ ] **RICH-H-06**: "Save to note" action (already exists) promoted to a first-class button on every assistant message (currently it's in the dropdown menu)
- [ ] **RICH-H-07**: AI suggestion for page text — when pinned page has editable fields, the AI can suggest "Fill this field..." action that sends text back to the page

### [H-03] Rich Generation Process — 确认｜生成过程可视化

- [ ] **RICH-H-08**: Chat mode streaming shows richer stage indicators beyond the Bubble loading spinner:
  - Stage 1: "Reading page context..." (when pinned tabs exist)
  - Stage 2: "Planning response..." (brief, during planner execution)
  - Stage 3: "Generating..." (during main stream)
  - Each stage shown as a small pill/badge above the streaming bubble
- [ ] **RICH-H-09**: Stage indicators have an expand toggle to show detail (e.g., "Analyzing 3 pinned tabs", "Using tool: web_search")
- [ ] **RICH-H-10**: When stream speed is slow (>3s since last token), show a subtle progress indicator: a pulsing "Still working..." label with estimated time remaining (based on token budget)

### [H-04] Parallel Chat + GUI Layout — Do+Chat 均衡布局

- [ ] **RICH-H-11**: Standalone mode supports a split-pane layout:
  - Left pane (60%): Chat/Agent conversation
  - Right pane (40%): Context panel showing pinned tabs, related notes, and active tools
  - Toggle button to show/hide the right pane
- [ ] **RICH-H-12**: Right pane tabs: "Context" (pinned tabs management), "Notes" (quick note browser), "Tools" (available MCP tools and status)
- [ ] **RICH-H-13**: Split-pane layout is persistent across standalone sessions — user's preference is remembered
- [ ] **RICH-H-14**: In notes Q&A mode, the question input and answer area are inline in the notes layout rather than a separate chat page

### [H-05] Sender Rich Input Enhancements — 表达｜用户输入增强

- [ ] **RICH-H-15**: Sender supports `@` mention syntax to reference notes, pinned tabs, or saved prompts:
  - `@note:title` — references a note
  - `@tab:title` — references a pinned tab
  - `@prompt:name` — references a saved prompt template
  - Autocomplete popover appears when typing `@`
- [ ] **RICH-H-16**: Image paste support — when user pastes an image from clipboard, it attaches as a file automatically (already partially supported via file attach)
- [ ] **RICH-H-17**: Voice input button in the Sender toolbar — uses Web Speech API for dictation (push-to-talk, or toggle recording)

### [H-06] Message Result Actions — 反馈｜结果展示增强

- [ ] **RICH-H-18**: Long AI responses (>500 chars) show a "TL;DR" expand/collapse toggle — collapsed view shows first 2-3 sentences with a "Read more" button
- [ ] **RICH-H-19**: AI responses containing numbered lists or step-by-step instructions render each step as a distinct card with a checkmark button — users can check off completed steps
- [ ] **RICH-H-20**: Markdown tables rendered by XMarkdown have sticky headers when table content is tall and horizontal scroll on overflow

## Out of Scope (v0.1)

| Feature | Reason |
|---------|--------|
| Multi-modal AI avatar (animated 3D character) | Over-scoped for v0.1; static visual identity sufficient |
| Sentiment analysis of user messages via separate LLM call | In-scope sentiment framing uses persona prompt, not a separate pipeline |
| Full NLP intent parsing pipeline | URL/hostname pattern matching + keyword heuristics sufficient for v0.1 context-aware suggestions |
| Voice output (TTS of AI responses) | TTS input (RICH-H-17) in scope; output TTS deferred |
| Drag-and-drop GUI builder for macros | Not in v0.1 scope |
| Cross-session conversation resumption with full context replay | Deferred; v0.1 conversations are stateless between sessions |
| Shadow DOM page injection for inline actions | Deferred per §0.2 DO NOT rules |
